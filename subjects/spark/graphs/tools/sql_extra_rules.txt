
DEPTH RULES FOR SQL FILES (these override the node-count rules above for tagged files):
- A file tagged [SHALLOW] in your section: write the file node, and one class node per class/trait/object/interface/enum/case class/protobuf message (give each its own lineRange). Do NOT write function nodes. In each class summary, name the main methods and what they do, in plain words, based on the source. Keep these edges only: contains (file to class, outer class to nested class), inherits, implements, and depends_on or calls from class to class when the source literally names the target. If a file has more than 40 classes, still give every class a node but keep each summary to one or two sentences. You may use extra output parts (part numbers i*10+3, i*10+4, i*10+5 with the same batch index in the file name) when you would pass 60 nodes in one file.
- A file tagged [HUGE] in your section is mostly a long list of settings, functions or error builders: write the file node and one class node for each class/object in it. Do NOT write a node per val, per config entry or per small method. The file summary and the class summary must state the groups of entries (by theme, with line ranges) and quote the literal names of the most important entries. For SQLConf, list the key groups and the literal config key names of the settings that govern the optimizer, adaptive execution, shuffle partitions, codegen, ANSI mode, file sources and Arrow. For functions.scala, group the functions by theme (aggregate, string, date and time, collection, math, window, JSON, UDF and others) and list the literal function names by theme. You may add function nodes for at most 15 of the most central entries.
- Files without a tag follow the normal rules above.
