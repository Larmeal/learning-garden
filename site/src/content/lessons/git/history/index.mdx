## ประวัติหน้าตาเป็นอย่างไร

เรามีโปรเจกต์เล็ก ๆ ที่ Commit ไปห้าครั้ง ลองสั่ง `git log --oneline` ดูกัน (รัน: `exercises/02_history.py`)

```text
$ git log --oneline
e4109b2 c5 add mint
a9945e5 c4 update readme
6ee1606 c3 add basil
c1a5dff c2 add plants
4c0f96e c1 add readme
```

ใหม่สุดอยู่บนสุด แต่ละบรรทัดคือหนึ่ง Commit มีชื่อสั้น ๆ เจ็ดตัวอักษรกับข้อความที่เราเขียนไว้ตอน Commit คำถามที่ตามมาทันทีคือ ถ้าเราอยากพูดถึง Commit `6ee1606` เราต้องจำตัวเลขพวกนี้ทุกครั้งหรือเปล่า คำตอบคือไม่ต้อง Git ให้เรียก Commit เดียวกันได้หลายแบบ

</Step>

## หนึ่ง Commit เรียกได้หลายชื่อ

เราเรียก Commit ด้วยชื่อเต็ม 40 ตัวอักษร (หรือขึ้นต้นสั้น ๆ ก็ได้ ตราบเท่าที่ไม่ซ้ำกับตัวอื่น) ด้วยชื่อ Branch หรือเรียกแบบสัมพัทธ์จากจุดที่เรายืนอยู่ก็ได้ (หนังสือ: VCWG บทที่ 4 หน้า 82 และ 85)

| ชื่อ | ชี้ไปที่ | ผลที่รันได้ |
|---|---|---|
| `HEAD` | Commit ที่เราอยู่ตอนนี้ | `e4109b2` |
| `main` | ปลายของ Branch `main` | `e4109b2` (ตัวเดียวกับ `HEAD` ตอนนี้) |
| `HEAD~1` หรือ `HEAD^` | Parent ของ `HEAD` | `a9945e5` |
| `HEAD~3` | ย้อนไปสามชั้นตาม Parent | `c1a5dff` |
| `e410` | ชื่อเต็มที่ขึ้นต้นด้วยสี่ตัวนี้ | ตัวเดียวกับ `HEAD` เพราะยังไม่มีตัวอื่นที่ขึ้นต้นเหมือนกัน |

ถ้าอยากรู้ว่าชื่อเหล่านี้ชี้ไปที่ชื่อเต็มอะไร ให้ใช้ `git rev-parse` ซึ่งแปลงทุกชื่อเป็นชื่อเต็ม 40 ตัวอักษร นอกจาก Commit แล้ว เครื่องหมาย `:` กับ `^{tree}` ยังใช้ชี้ไปที่ของข้างใน Commit ได้ด้วย เช่น `HEAD:plants.txt` คือเนื้อหาไฟล์ ซึ่งเป็น Blob ส่วน `HEAD^{tree}` คือรายชื่อไฟล์ทั้งหมดของ Commit นั้น ซึ่งเป็น Tree ทั้งหมดนี้แบบฝึกตรวจด้วย `git cat-file -t` แล้ว

<Callout type="tip" title="~ กับ ^ ต่างกันตอนมี Merge">

บน Commit ธรรมดาที่มี Parent เดียว `HEAD~1` กับ `HEAD^` ได้ผลเท่ากัน แต่พอ Commit เป็นผลของการ Merge จะมี Parent สองตัว ตอนนั้น `HEAD^1` คือ Parent ตัวแรก (Branch ที่เราอยู่ตอน Merge) ส่วน `HEAD^2` คือ Parent ตัวที่สอง (Branch ที่เอาเข้ามา) เราจะได้ใช้จริงในบทที่ว่าด้วย Merge

</Callout>

</Step>

## ช่วงของ Commit

บ่อยครั้งเราไม่ได้อยากดู Commit เดียว แต่อยากดู "ตั้งแต่ตรงนั้นถึงตรงนี้" ช่วงเขียนด้วยจุดสองจุด `A..B` ซึ่งอ่านว่า Commit ที่เดินไปถึงจาก B ได้ แต่เดินไปถึงจาก A ไม่ได้ (หนังสือ: VCWG บทที่ 4 หน้า 96)

```text
$ git log --format=%s HEAD~3..HEAD
c5 add mint
c4 update readme
c3 add basil
```

ได้สาม Commit ที่อยู่หลัง `HEAD~3` ซึ่งไม่รวมตัว `HEAD~3` เอง ช่วงแบบนี้เขียนอีกแบบได้ว่า `HEAD ^HEAD~3` ซึ่งหมายถึงเอาจาก `HEAD` แต่ตัดทุกอย่างที่ถึงได้จาก `HEAD~3` และถ้าสลับข้างเป็น `HEAD..HEAD~3` จะได้ว่างเปล่า เพราะไม่มี Commit ไหนที่ถึงได้จาก `HEAD~3` แต่ถึงจาก `HEAD` ไม่ได้

ที่น่าสนใจกว่าคือตอนประวัติแตกเป็นสองสาย สมมติว่าเรามี Branch `left` กับ `right` ที่แตกออกจากจุดเดียวกัน `left` มี Commit `L1` หนึ่งตัว ส่วน `right` มี `R1` กับ `R2`

```text
$ git log --format=%s left..right
R2 right
R1 right

$ git log --format=%s left...right
L1 left
R1 right
R2 right
```

จุดสองจุดตอบว่า "`right` มีอะไรที่ `left` ไม่มี" ส่วนจุดสามจุดตอบว่า "แต่ละฝั่งมีอะไรที่อีกฝั่งไม่มี" และถ้าอยากรู้ว่าสองสายแตกออกจากกันตรงไหน ให้ถาม `git merge-base left right` (ทั้งหมดรัน)

ลองเล่นภาพข้างล่างเพื่อดู Selector แต่ละตัวบนประวัติที่มี Merge อยู่ข้างใน (เป็นประวัติอีกชุดหนึ่ง ไม่ใช่ชุดข้างบน) กดทีละตัวแล้วดูว่า Commit ไหนสว่างขึ้น และเทียบกับผลของ `git rev-list` ที่แสดงใต้ภาพ

## กรองประวัติให้เหลือที่อยากเห็น

ประวัติของโปรเจกต์จริงยาวเกินกว่าจะอ่านทั้งหมด `git log` จึงมีตัวกรองหลายแบบ ลองดูที่แบบฝึกรัน

```text
$ git log --format=%s -- readme.txt
c4 update readme
c1 add readme

$ git log --format=%s --grep=basil
c3 add basil

$ git log --stat --format=%s -n 1
c5 add mint

 plants.txt | 1 +
 1 file changed, 1 insertion(+)
```

`-- readme.txt` ให้เหลือเฉพาะ Commit ที่แตะไฟล์นั้น (สังเกตเครื่องหมาย `--` ที่คั่นระหว่างชื่อ Commit กับชื่อไฟล์) `--grep` ค้นในข้อความของ Commit ส่วน `-n 1` จำกัดจำนวน และ `--stat` บอกว่าแต่ละ Commit แก้ไฟล์ไหนไปกี่บรรทัด นอกจากนี้ `--graph` ยังวาดเส้นของ Branch ให้ด้วย โดยหนึ่ง Commit เป็นดาวหนึ่งดวง (หนังสือ: VCWG บทที่ 4 หน้า 90 และ LG บทที่ 3 หน้า 40)

</Step>

## เทียบสองจุดในประวัติด้วย `git diff`

`git diff` เทียบอะไรกับอะไรก็ได้ที่ชี้ไปถึง Snapshot ได้ เช่นสอง Commit (หนังสือ: VCWG บทที่ 7 หน้า 159)

```text
$ git diff HEAD~2 HEAD~1
diff --git a/readme.txt b/readme.txt
index 93d5621..4220618 100644
--- a/readme.txt
+++ b/readme.txt
@@ -1 +1,2 @@
 Garden notes
+updated
```

Diff ของ `c3` กับ `c4` แตะแค่ `readme.txt` เพราะ `c4` แก้ไฟล์นั้นไฟล์เดียว ถ้าอยากได้แค่รายชื่อไฟล์กับตัวอักษรบอกชนิดการเปลี่ยน ใช้ `--name-status` (ได้ `M` ตามด้วยชื่อไฟล์สำหรับไฟล์ที่ถูกแก้) หรือถ้าอยากได้ภาพรวมเป็นตัวเลข ใช้ `--stat`

</Step>
