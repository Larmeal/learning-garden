## โปรเจกต์ทดลอง

หน้านี้ใช้ `internals/08_output_flags.py` ที่สร้างโปรเจกต์ชั่วคราวไฟล์เดียวมี test สี่ตัว แล้วรัน pytest ด้วย option ต่างๆ (รัน: `internals/08_output_flags.py`)

```python
def deep(n):
    local_total = n * 10
    return 1 // (n - 3)

def test_ok():                 # หลับ 0.02 วินาที
def test_zero_division():      # วน n ตั้งแต่ 0 ถึง 4 เรียก deep(n)
def test_assert():
    total = 30
    assert total == 31
def test_third(): ...
```

ผลปกติคือ `.FF.` และ `2 failed, 2 passed` ต่อไปเป็นสิ่งที่แต่ละ option เปลี่ยน

</Step>

<Step>

## ความยาวของผลรัน: -v, -q, -qq

| option | ผลที่ยืนยัน |
|---|---|
| `-v` | หนึ่งบรรทัดต่อ test พร้อม node id เช่น `test_flags.py::test_ok PASSED [ 25%]` |
| (ไม่ใส่) | มีหัวรายงาน `test session starts` และตัวอักษรหนึ่งตัวต่อ test |
| `-q` | ไม่มีหัวรายงาน เหลือ `.FF.` และสรุป `2 failed, 2 passed in ...` |
| `-qq` | ไม่มีทั้งหัวและบรรทัดสรุป `N passed`: บรรทัดสุดท้ายเป็น `FAILED test_flags.py::test_assert - assert 30 == 31` |

`-q` เหมาะกับ CI ที่ log ยาว และ `-v` เหมาะเมื่อต้องเห็นชื่อเต็มของ test ที่กำลังรัน (เช่น test ที่ค้าง)

</Step>

<Step>

## สไตล์ของ Traceback: --tb

`--tb` เลือกความละเอียดของข้อความตอนล้ม จำนวนบรรทัดของรายงานทั้งหมดสำหรับโปรเจกต์ทดลองคือ `long` 39, `short` 24, `line` 17, `no` 12 (รัน: `internals/08_output_flags.py`)

| ค่า | หน้าตา |
|---|---|
| `long` | โค้ดทั้งฟังก์ชันของทุก frame (ค่าเริ่มต้นคือ `auto`: ตัวแรกและตัวสุดท้ายที่ล้มแบบ `long` ที่เหลือแบบ `short`) |
| `short` | หนึ่งบรรทัดโค้ดต่อ frame เช่น `test_flags.py:12: in test_zero_division` ตามด้วย `    deep(n)` |
| `line` | บรรทัดเดียวต่อความล้ม: `E   ZeroDivisionError: division by zero` และ path:line |
| `native` | แบบเดียวกับ traceback ของ Python (`Traceback (most recent call last)`) |
| `no` | ไม่มีส่วน FAILURES เลย เหลือแค่สรุปสั้นท้ายรายงาน |

`--tb=line` เหมาะกับการ grep ให้เห็นทุกความล้มบนหน้าจอเดียว ส่วน `--tb=no` เหมาะเมื่ออยากเห็นรายชื่อ test ที่ล้มโดยไม่สนเหตุผล

</Step>

<Step>

## ดูตัวแปรด้วย -l

`-l` (หรือ `--showlocals`) พิมพ์ตัวแปรโลคอลของทุก frame ใต้ traceback ในโปรเจกต์ทดลอง รัน `-l --tb=short` ได้ (รัน)

```text
test_flags.py:5: in deep
    return 1 // (n - 3)
E   ZeroDivisionError: division by zero
        local_total = 30
        n          = 3
```

ตอนนี้เห็นทันทีว่ารอบที่ล้มคือ `n = 3` โดยไม่ต้องเพิ่ม `print` ข้อควรระวังคือ `-l` พิมพ์ค่าของทุกตัวแปร ถ้ามี object ใหญ่หรือข้อมูลลับในตัวแปร ก็ถูกพิมพ์ลง log

</Step>

<Step>

## หา Test ที่ช้า: --durations

`--durations=N` พิมพ์ N เฟสที่ช้าที่สุดท้ายรายงาน (รัน)

```text
============================= slowest 2 durations =============================
0.02s call     test_flags.py::test_ok

(1 durations < 0.005s hidden.  Use -vv to show these durations.)
```

เฟสที่เร็วกว่า 0.005 วินาทีถูกซ่อนและนับไว้ใต้รายการ ใส่ `-vv` ถึงจะเห็น ตัวนี้นับ **ทุกเฟส** ไม่ใช่แค่ call (บรรทัดขึ้นต้นด้วย `call`, `setup` หรือ `teardown`) ทำให้เห็นว่า fixture ที่ช้าอยู่ตรงไหน

</Step>

<Step>

## หยุดเมื่อล้ม และเลือกสรุป

- `-x` หยุดหลังล้มตัวแรก และ `--maxfail=N` หยุดหลังล้ม N ตัว ผลของโปรเจกต์ทดลองคือ `1 failed, 1 passed` กับข้อความ `stopping after 1 failures` (รัน)
- `-r` เลือกว่าผลแบบไหนได้บรรทัดในสรุปสั้น ตัวอักษรคือ `f` failed, `E` error, `s` skipped, `x` xfailed, `X` xpassed, `p` passed, `a` ทุกอย่างยกเว้น passed และ `A` ทุกอย่าง `-rfEs` ให้ `FAILED test_flags.py::test_assert` และ `FAILED test_flags.py::test_zero_division` ในผลทดลอง และโปรเจกต์แบบฝึกตั้ง `-ra` ใน `addopts` ไว้แล้ว ([บท 7](/pytest/project/#ตั้งค่าครั้งเดียว-ใน-pyprojecttoml))

</Step>

## Exit Code ทั้งหกค่า

pytest คืนค่าจาก `ExitCode` (source: `_pytest/config/__init__.py`) สี่ค่าแรกในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/#ผลของ-session-และ-exit-code) อธิบายที่มา

| ค่า | ชื่อ | เกิดเมื่อ | ยืนยัน |
|---|---|---|---|
| 0 | `OK` | ผ่านทั้งหมด | รัน: `verify.py` |
| 1 | `TESTS_FAILED` | มี test ล้ม หรือ collection error ที่ใช้ `--continue-on-collection-errors` | รัน: `internals/12_collection_options.py` |
| 2 | `INTERRUPTED` | กด Ctrl+C, `pytest.exit()` หรือ collection error ที่หยุดทั้ง run | รัน: `internals/12_collection_options.py` |
| 3 | `INTERNAL_ERROR` | exception ใน pytest หรือ plugin เช่น hook ที่ชื่อไม่มีจริง | รัน: `internals/11_hook_validation.py` |
| 4 | `USAGE_ERROR` | option ผิด, node id ไม่เจอ, ปิด plugin ที่ปิดไม่ได้ | รัน: `internals/01_startup.py` |
| 5 | `NO_TESTS_COLLECTED` | ไม่มี test ถูกเลือก | รัน: `verify.py` |

CI ที่เช็กแค่ "เลขไม่ใช่ 0" เห็นทั้งหกค่าเป็นความล้มเหมือนกัน ถ้าอยากแยกเหตุ (เช่น ให้ 5 เป็น warning แต่ 1 เป็นความล้ม) ต้องอ่านเลขเอง
