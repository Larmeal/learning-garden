## โปรเจกต์ทดลอง

หน้านี้ใช้ `internals/08_output_flags.py` ซึ่งสร้างโปรเจกต์ชั่วคราวที่มีไฟล์เดียวและมี Test สี่ตัว แล้วรัน Pytest ด้วย Option ต่าง ๆ (รัน: `internals/08_output_flags.py`)

```python
def deep(n):
    local_total = n * 10
    return 1 // (n - 3)

def test_ok():                 # หลับ 0.02 วินาที
def test_zero_division():      # วน n ตั้งแต่ 0 ถึง 4 เรียก deep(n)
def test_assert():
    total = 30
    assert total == 31
def test_third(): ...
```

ผลปกติคือ `.FF.` และ `2 failed, 2 passed` ทีนี้เรามาดูกันว่าแต่ละ Option เปลี่ยนอะไรบ้าง

</Step>

<Step>

## ความยาวของผลรัน: -v, -q, -qq

| Option | ผลที่ยืนยัน |
|---|---|
| `-v` | หนึ่งบรรทัดต่อ Test พร้อม Node id เช่น `test_flags.py::test_ok PASSED [ 25%]` |
| (ไม่ใส่) | มีหัวรายงาน `test session starts` และตัวอักษรหนึ่งตัวต่อ Test |
| `-q` | ไม่มีหัวรายงาน เหลือ `.FF.` และสรุป `2 failed, 2 passed in ...` |
| `-qq` | ไม่มีทั้งหัวและบรรทัดสรุป `N passed`: บรรทัดสุดท้ายเป็น `FAILED test_flags.py::test_assert - assert 30 == 31` |

`-q` เหมาะกับ CI ที่ Log ยาว ส่วน `-v` เหมาะเมื่อต้องเห็นชื่อเต็มของ Test ที่กำลังรัน (เช่น Test ที่ค้าง)

</Step>

<Step>

## สไตล์ของ Traceback: --tb

`--tb` ใช้เลือกความละเอียดของข้อความตอนล้ม สำหรับโปรเจกต์ทดลอง จำนวนบรรทัดของรายงานทั้งหมดคือ `long` 39, `short` 24, `line` 17, `no` 12 (รัน: `internals/08_output_flags.py`)

| ค่า | หน้าตา |
|---|---|
| `long` | โค้ดทั้งฟังก์ชันของทุก Frame (ค่าเริ่มต้นคือ `auto`: ตัวแรกและตัวสุดท้ายที่ล้มแบบ `long` ที่เหลือแบบ `short`) |
| `short` | หนึ่งบรรทัดโค้ดต่อ Frame เช่น `test_flags.py:12: in test_zero_division` ตามด้วย `    deep(n)` |
| `line` | บรรทัดเดียวต่อความล้ม: `E   ZeroDivisionError: division by zero` และ Path:Line |
| `native` | แบบเดียวกับ Traceback ของ Python (`Traceback (most recent call last)`) |
| `no` | ไม่มีส่วน FAILURES เลย เหลือแค่สรุปสั้นท้ายรายงาน |

`--tb=line` เหมาะกับการ Grep ให้เห็นทุกความล้มบนหน้าจอเดียว ส่วน `--tb=no` เหมาะเมื่ออยากเห็นแค่รายชื่อ Test ที่ล้มโดยไม่สนเหตุผล

</Step>

<Step>

## ดูตัวแปรด้วย -l

`-l` (หรือ `--showlocals`) จะพิมพ์ตัวแปรโลคอลของทุก Frame ไว้ใต้ Traceback ถ้ารัน `-l --tb=short` ในโปรเจกต์ทดลองจะได้ผลดังนี้ (รัน)

```text
test_flags.py:5: in deep
    return 1 // (n - 3)
E   ZeroDivisionError: division by zero
        local_total = 30
        n          = 3
```

ตอนนี้เราเห็นทันทีว่ารอบที่ล้มคือ `n = 3` โดยไม่ต้องเพิ่ม `print` แต่ต้องระวังนิดหนึ่งว่า `-l` พิมพ์ค่าของทุกตัวแปร ถ้ามี Object ใหญ่หรือข้อมูลลับอยู่ในตัวแปร ก็จะถูกพิมพ์ลง Log ไปด้วย

</Step>

<Step>

## หา Test ที่ช้า: --Durations

`--durations=N` จะพิมพ์ N เฟสที่ช้าที่สุดไว้ท้ายรายงาน (รัน)

```text
============================= slowest 2 durations =============================
0.02s call     test_flags.py::test_ok

(1 durations < 0.005s hidden.  Use -vv to show these durations.)
```

เฟสที่เร็วกว่า 0.005 วินาทีจะถูกซ่อนและนับไว้ใต้รายการ ต้องใส่ `-vv` ถึงจะเห็น และตัวนี้นับ **ทุกเฟส** ไม่ใช่แค่ Call (บรรทัดขึ้นต้นด้วย `call`, `setup` หรือ `teardown`) เราจึงเห็นได้ด้วยว่า Fixture ที่ช้าอยู่ตรงไหน

</Step>

<Step>

## หยุดเมื่อล้ม และเลือกสรุป

- `-x` จะหยุดหลังล้มตัวแรก และ `--maxfail=N` จะหยุดหลังล้ม N ตัว ผลของโปรเจกต์ทดลองคือ `1 failed, 1 passed` กับข้อความ `stopping after 1 failures` (รัน)
- `-r` ใช้เลือกว่าผลแบบไหนจะได้บรรทัดในสรุปสั้น โดยตัวอักษรคือ `f` Failed, `E` Error, `s` Skipped, `x` Xfailed, `X` Xpassed, `p` Passed, `a` ทุกอย่างยกเว้น Passed และ `A` ทุกอย่าง `-rfEs` ให้ `FAILED test_flags.py::test_assert` และ `FAILED test_flags.py::test_zero_division` ในผลทดลอง ส่วนโปรเจกต์แบบฝึกก็ตั้ง `-ra` ใน `addopts` ไว้แล้ว ([บท 7](/pytest/project/#ตั้งค่าครั้งเดียว-ใน-pyprojecttoml))

</Step>

## Exit Code ทั้งหกค่า

Pytest คืนค่าจาก `ExitCode` (Source: `_pytest/config/__init__.py`) โดยที่มาของสี่ค่าแรกอธิบายไว้ในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/#ผลของ-session-และ-exit-code) แล้ว

| ค่า | ชื่อ | เกิดเมื่อ | ยืนยัน |
|---|---|---|---|
| 0 | `OK` | ผ่านทั้งหมด | รัน: `verify.py` |
| 1 | `TESTS_FAILED` | มี Test ล้ม หรือ Collection Error ที่ใช้ `--continue-on-collection-errors` | รัน: `internals/12_collection_options.py` |
| 2 | `INTERRUPTED` | กด Ctrl+C, `pytest.exit()` หรือ Collection Error ที่หยุดทั้ง Run | รัน: `internals/12_collection_options.py` |
| 3 | `INTERNAL_ERROR` | Exception ใน Pytest หรือ Plugin เช่น Hook ที่ชื่อไม่มีจริง | รัน: `internals/11_hook_validation.py` |
| 4 | `USAGE_ERROR` | Option ผิด, Node id ไม่เจอ, ปิด Plugin ที่ปิดไม่ได้ | รัน: `internals/01_startup.py` |
| 5 | `NO_TESTS_COLLECTED` | ไม่มี Test ถูกเลือก | รัน: `verify.py` |

CI ที่เช็กแค่ "เลขไม่ใช่ 0" จะเห็นทั้งหกค่าเป็นความล้มเหมือนกันหมด ถ้าอยากแยกเหตุ (เช่น ให้ 5 เป็น Warning แต่ 1 เป็นความล้ม) เราต้องอ่านเลขเอง
