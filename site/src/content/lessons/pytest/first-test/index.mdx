## Test คือโค้ดที่เช็กโค้ดให้เรา

ลองนึกถึงตะกร้าสินค้า ใส่แอปเปิล 3 ผล ผลละ 10 บาท ยอดรวมก็ควรเป็น 30 ถ้าตรวจด้วยตาเราก็ทำได้ครั้งเดียว แต่ถ้าต้องแก้โค้ดอีก 50 ครั้งใน 6 เดือน เราคงไม่มีทางเปิดดูทุกครั้งแน่ ๆ **Automated Test** คือโค้ดที่ทำการตรวจนี้ให้เราทุกครั้งที่สั่ง และบอกด้วยว่าอะไรเปลี่ยนไป

Pytest เป็น Test Runner ของ Python ที่ใช้กันมาก จุดเด่นคือ Test เป็นแค่ฟังก์ชันธรรมดากับ `assert` โดยไม่ต้องสืบทอด Class ใด ๆ ตลอดเส้นทางนี้เราจะใช้โค้ดชุดเดียวกันทุกบท คือ Package `shop` (ตะกร้า คูปอง ชำระเงิน) ใน `subjects/pytest/code/src/shop/` และตัวเลขผลรันทุกตัวในบทเรียนก็มาจากการรันจริงด้วย Pytest 9.2.0 (รัน: `verify.py`)

เริ่มจากติดตั้งและรันด้วยคำสั่งนี้

```bash
uv add --dev pytest      # หรือ pip install pytest
uv run pytest            # หรือ python -m pytest
```

## Test แรก

```python
from shop.cart import Cart


def test_new_cart_is_empty():
    cart = Cart()
    assert cart.is_empty()
    assert cart.total() == 0


def test_add_item_increases_total():
    cart = Cart()
    cart.add("apple", price=10, qty=3)
    assert cart.total() == 30
```

เราไม่ต้อง Import อะไรจาก Pytest เลย เพราะ `assert` คือ Assert ธรรมดาของ Python หลัง `assert` เราเขียนเงื่อนไขที่ให้ผลเป็นจริงหรือเท็จ เช่น `cart.total() == 30` ซึ่งก็คือคำถามว่า "ยอดรวมของตะกร้าเท่ากับ 30 ไหม" ถ้าคำตอบคือใช่ (True) Test จะผ่าน ถ้าไม่ใช่ (False) Test จะล้ม ส่วน `assert cart.is_empty()` ก็เขียนได้เหมือนกัน เพราะ `is_empty()` คืนค่า True หรือ False อยู่แล้ว นอกจากนั้น Test ยังล้มได้ถ้าโค้ดที่เรียกอยู่โยน Exception ออกมาก่อนจะถึงบรรทัด `assert` เมื่อรัน `exercises/01_first_test` จะได้ผลดังนี้ (รัน: `exercises/01_first_test`)

```text
exercises/01_first_test/test_cart_basics.py::test_new_cart_is_empty PASSED
exercises/01_first_test/test_cart_basics.py::test_add_item_increases_total PASSED
exercises/01_first_test/test_cart_basics.py::test_adding_the_same_sku_twice_merges_the_lines PASSED
exercises/01_first_test/test_cart_basics.py::TestRemove::test_remove_drops_the_line PASSED
exercises/01_first_test/test_cart_basics.py::TestRemove::test_remove_missing_sku_raises_key_error PASSED
exercises/01_first_test/discount_test.py::test_ten_percent_off_one_hundred PASSED
============================== 6 passed ==============================
```

ชื่อเต็มของ Test เช่น `test_cart_basics.py::TestRemove::test_remove_drops_the_line` เรียกว่า **Node id** ซึ่งใช้สั่งรัน Test ตัวเดียวได้ ([บท 7](/pytest/project/#เลือกรัน-path-node-id-และ--k))

## Pytest หา Test เจอได้อย่างไร

Pytest ไม่ได้รันทุกไฟล์ แต่จะค้นหา Test ตามกติกาชื่อ (**Discovery**)

| อะไร | ต้องตั้งชื่อ | ตัวอย่างในแบบฝึก |
|---|---|---|
| ไฟล์ | `test_*.py` หรือ `*_test.py` | `test_cart_basics.py`, `discount_test.py` |
| ฟังก์ชัน | ขึ้นต้นด้วย `test` | `test_new_cart_is_empty` |
| Class | ขึ้นต้นด้วย `Test` และ Method ขึ้นต้นด้วย `test` | `TestRemove.test_remove_drops_the_line` |

ในโฟลเดอร์เดียวกันมีของสามอย่างที่ **ไม่ถูกรัน** (รัน: `--collect-only` ได้ 6 Tests ตรงกับด้านบน)

- `cart_extra.py` ชื่อไฟล์ไม่เข้ากติกา ต่อให้ Test ข้างในมี `assert 1 == 2` ก็ไม่มีใครรู้
- `make_cart()` เป็น Helper ที่ชื่อไม่ขึ้นต้นด้วย `test`
- `check_total_is_ten()` ขึ้นต้นด้วย `check_` ซึ่งไม่ใช่ Prefix ของ Test เช่นกัน

<Callout type="warn" title="ชื่อผิด = Test หาย โดยไม่มี Error">
ถ้าตั้งชื่อไฟล์เป็น `cart_tests.py` หรือฟังก์ชันเป็น `tets_total` Pytest จะไม่เตือนอะไรเลย ผลจะเป็นสีเขียวเพราะไม่มี Test ให้รัน ดังนั้นเมื่อเขียน Test ใหม่ ให้ดูด้วยว่าจำนวน Test ที่รันเพิ่มขึ้นจริง
</Callout>

มีข้อยกเว้นที่ควรรู้ด้วยนะ ถ้าระบุไฟล์ตรง ๆ บน command line Pytest จะ Collect ไฟล์นั้นโดยไม่สนชื่อ ดังนั้น `pytest exercises/01_first_test/cart_extra.py` จะรัน Test ในไฟล์นั้นและล้ม 1 ตัว (รัน: `verify.py`)

</Step>

## อ่านสัญลักษณ์ในผลรัน

บรรทัดผลแบบย่อมีหนึ่งตัวอักษรต่อหนึ่ง Test

| ตัวอักษร | ความหมาย |
|---|---|
| `.` | ผ่าน |
| `F` | ล้ม (Failed): `assert` เป็นเท็จ หรือมี Exception ใน Test หรือในโค้ดที่ Test เรียก |
| `E` | Error: ปัญหาอยู่ **นอกตัว Test** เช่น Fixture ระเบิดตอน Setup ([บท 3](/pytest/fixtures/#yield-setup-และ-teardown-ในที่เดียว)) |
| `s` / `x` | Skip / Xfail ([บท 5](/pytest/markers/#skip-และ-skipif-ไม่รัน)) |

`demos/01_failures` จงใจให้ล้มสามแบบ ผลที่ได้คือ `FFFE` และสรุปว่า `3 failed, 1 error` (รัน: `demos/01_failures`) ความต่างระหว่าง `F` กับ `E` สำคัญนะ เพราะ `F` บอกว่าโค้ดทำงานผิดจากที่ Test คาด ส่วน `E` บอกว่า Test ยังไม่ทันได้เริ่ม เพราะของที่ต้องใช้ตั้งไม่ขึ้น

</Step>

## อ่าน Traceback ตอน Test ล้ม

กรณีแรก ยอดรวมผิด

```text
    def test_wrong_total():
        cart = Cart()
        cart.add("apple", price=10, qty=3)
>       assert cart.total() == 31
E       assert 30 == 31
E        +  where 30 = total()
```

บรรทัดที่ขึ้นต้นด้วย `>` คือบรรทัดที่ล้ม ส่วนบรรทัด `E` คือสิ่งที่ Pytest เพิ่มให้ ซึ่งก็คือค่าจริงของทั้งสองข้าง (30 กับ 31) โดยที่เราไม่ต้องเขียน Message เอง Pytest ทำได้เพราะมัน **เขียน Assert ใหม่** ก่อนรัน ([บท 2](/pytest/assertions/#assert-ธรรมดา-แต่ได้ข้อมูลมากกว่าที่คิด) จะเล่าเรื่องนี้ต่อ)

กรณีที่สอง เทียบ List

```text
E       AssertionError: assert ['apple', 'pear'] == ['apple', 'banana']
E         At index 1 diff: 'pear' != 'banana'
```

กรณีที่สาม Exception เกิดในโค้ดที่ Test เรียก Traceback ไล่ลงไปถึงบรรทัดในโค้ดจริงให้ด้วย

```text
>           raise ValueError(f"qty must be positive, got {qty}")
E           ValueError: qty must be positive, got 0

src\shop\cart.py:32: ValueError
```

กรณีสุดท้ายคือ Fixture ระเบิด หัวข้อจะเป็น `ERROR at setup of test_uses_a_broken_fixture` และตัว Test จะไม่ถูกรันเลย

วิธีอ่านที่ใช้ได้เสมอคือหา `>` ก่อนว่าบรรทัดไหนล้ม แล้วอ่าน `E` ทีละบรรทัดว่าล้มเพราะอะไร จากนั้นค่อยดูว่าบรรทัดนั้นอยู่ใน Test หรือในโค้ดจริง

</Step>

## Exit Code: สิ่งที่ CI อ่าน

Pytest คืนเลขออกจากโปรแกรมเพื่อให้ Script และ CI ตัดสินใจ (รัน: `verify.py`)

| เหตุการณ์ | Exit Code |
|---|---|
| ผ่านทั้งหมด | 0 |
| มี Test ล้มหรือ Error | 1 |
| ไม่มี Test ถูกเลือกรันเลย (เช่น `-k` ไม่ตรงอะไร) | 5 |

ข้อสุดท้ายสำคัญมาก เพราะชุด Test ที่ไม่ได้รันอะไรเลยไม่ควรนับเป็น "เขียว" Pytest จึงใช้เลขแยกให้

<Callout type="try" title="ลองทำใน Repo นี้">
ลองไปที่ `subjects/pytest/code/` รัน `uv sync` หนึ่งครั้ง แล้วรัน `uv run pytest exercises/01_first_test -v` จากนั้นแก้ `assert cart.total() == 30` เป็น `31` ดูผล แล้วลองเปลี่ยนชื่อ `test_new_cart_is_empty` เป็น `new_cart_is_empty` ดูว่าจำนวน Test ที่รันเปลี่ยนไปอย่างไร
</Callout>

</Step>
