## Collection คือการสร้างต้นไม้

ในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/) เห็นแล้วว่า collection เสร็จทั้งหมดก่อนรัน test ตัวแรก ผลของมันคือต้นไม้ของ **node** ที่ `--collect-only` พิมพ์ออกมา (รัน: `internals/03_collection_tree.py`)

```text
<Dir tmp0eq8na2k>
  <Package shop>
    <Module test_cart.py>
      <Class TestRemove>
        <Function test_drop>
        <Function test_missing>
      <Function test_qty[1]>
      <Function test_qty[2]>
  <Module test_top.py>
    <Function test_top>
```

node มีสองชนิด (source: `_pytest/nodes.py`)

- **Collector** มี method `collect()` ที่คืน node ลูก: `Session`, `Dir`, `Package`, `Module`, `Class`
- **Item** คือใบของต้นไม้ มี `runtest()` ที่รันจริง: `Function` คือ test ที่เราเขียน

node แต่ละตัวมี `parent` และ `listchain()` คืนสายจากรากลงมาถึงตัวมันเอง ในตัวอย่าง `test_drop` ได้ `Session > Dir > Package > Module > Class > Function` (รัน: `internals/03_collection_tree.py`) ส่วน `nodeid` ที่เราคุ้นอย่าง `shop/test_cart.py::TestRemove::test_drop` คือที่อยู่ของ node ในต้นไม้ คั่นด้วย `::`

สายนี้สำคัญกับ[บทถัดไป](/pytest/fixture-engine/): fixture ระดับ module, class และ session ผูกกับ node ในสายนี้ ([บท 11](/pytest/fixture-engine/))

</Step>

## ต้นไม้ถูกเดินอย่างไร

`Session.collect` รับ argument ที่พิมพ์บนบรรทัดคำสั่งทีละตัว แล้วเดินจากรากลงไปทีละชั้น (source: `Session.collect` ใน `main.py`) argument หนึ่งแยกเป็นส่วนๆ ได้ เช่น `shop/test_cart.py::TestRemove::test_drop` คือ path ของโฟลเดอร์, path ของไฟล์, ชื่อ class, ชื่อ test ในแต่ละชั้น pytest เก็บ node ลูกที่ชื่อตรงกับส่วนนั้น แล้วทิ้งที่เหลือ

ผลที่ตามมา

- node id ที่ระบุเจาะจงไม่ต้อง import ทุกไฟล์ pytest import เฉพาะไฟล์ที่อยู่บนเส้นทาง
- ส่วนที่เป็นชื่อ test ไม่ต้องใส่ parameter: `::test_qty` เลือกทุก parameter ส่วน `::test_qty[1]` เลือกตัวเดียว (source: `Session.collect` ตรงที่ตัด `[` ออกก่อนเทียบชื่อ)
- node id ที่ไม่ตรงอะไรเลย (`test_x.py::no_such_test`) ทำให้ pytest จบด้วย exit code 4 และ `ERROR: not found: ...` (รัน: `internals/12_collection_options.py`)

</Step>

## โฟลเดอร์และไฟล์: Hook สองตัวที่ตัดสิน

เมื่อเจอโฟลเดอร์ pytest ถาม hook `pytest_collect_directory` ถ้าโฟลเดอร์มี `__init__.py` ผลคือ `Package` ถ้าไม่มีก็เป็น `Dir` ธรรมดา (source: `pytest_collect_directory` ใน `python.py`) เมื่อเจอไฟล์ถาม `pytest_collect_file` ซึ่งยอมรับเฉพาะ `.py` ที่ชื่อเข้ากับ `python_files` ยกเว้นไฟล์ที่ระบุตรงๆ บนบรรทัดคำสั่งซึ่งไม่ต้องเช็กชื่อ (source: `isinitpath` ในฟังก์ชันเดียวกัน ตรงกับที่บท [First Test](/pytest/first-test/) แสดงด้วย `cart_extra.py`)

การเดินโฟลเดอร์ข้ามบางโฟลเดอร์ตามค่า `norecursedirs` ในแบบฝึก `build/` และ `node_modules/` ไม่ถูกเดินตอนรัน `pytest` เฉยๆ แต่ถ้าระบุ path ในโฟลเดอร์นั้นบนบรรทัดคำสั่ง ก็ถูก collect (รัน: `internals/12_collection_options.py`) ตัวเลือกที่ใช้บ่อย

| option | ทำอะไร | ยืนยัน |
|---|---|---|
| `--ignore=sub` | ไม่ collect path นั้น | ทั้งโฟลเดอร์หายไป |
| `--deselect <node id>` | collect แล้วตัดทิ้ง | `3/4 tests collected (1 deselected)` |
| `-o norecursedirs=sub` | เปลี่ยนรายการโฟลเดอร์ที่ข้าม | โฟลเดอร์ `sub` ไม่ถูกเดิน |

</Step>

## ชื่ออะไรถึงเป็น Test

เมื่อ import ไฟล์ได้แล้ว `PyCollector.collect` ไล่ดู `__dict__` ของ module (หรือของ class) ตามลำดับที่นิยามไว้ และถามทุกชื่อผ่าน hook `pytest_pycollect_makeitem` (source: `PyCollector.collect`) กติกาเริ่มต้นคือ `python_classes = Test`, `python_functions = test` และชื่อต้อง **ขึ้นต้นด้วย** ค่านั้น

```text
Test_Cart            collect เพราะขึ้นต้นด้วย Test
CartTests            ไม่ collect (ขึ้นต้นด้วย Cart)
TestWithInit         ไม่ collect: class ที่มี __init__
test_f               collect
spec_f               ไม่ collect
```

(รัน: `internals/12_collection_options.py` ผลคือ `Test_Cart::test_a` กับ `test_f`) class `TestWithInit` ได้ warning `cannot collect test class 'TestWithInit' because it has a __init__ constructor` เพราะ pytest สร้าง instance ของ class เองโดยไม่ส่ง argument

ค่าเหล่านี้เปลี่ยนได้ (รัน: `internals/12_collection_options.py`)

```toml
python_files = ["check_*.py"]
python_classes = ["Spec"]
python_functions = ["check_*"]
```

ด้วยสามบรรทัดนี้ `check_cart.py` ให้ `Spec::check_a` กับ `check_total` ชื่อที่ขึ้นต้นด้วยค่านั้นผ่านเสมอ และค่าที่มี `*`, `?` หรือ `[` ถูกใช้เป็น glob ด้วย (source: `_matches_prefix_or_glob_option`)

เงื่อนไขอื่นที่ pytest เช็ก (source: `istestfunction`, `istestclass`): ฟังก์ชันที่ถูกตกแต่งด้วย `@pytest.fixture` ไม่ใช่ test, class ที่เป็น abstract ไม่ถูก collect, และ `__test__ = False` ปิดได้ทั้ง class และ module

</Step>

## หนึ่งฟังก์ชัน หลาย Function: Parametrize ทำงานตรงนี้

เมื่อชื่อผ่านเกณฑ์ `_genfunctions` สร้าง `Function` ให้ ขั้นตอนคือ (source: `_genfunctions` ใน `python.py`)

1. สร้าง `FunctionDefinition` เพื่ออ่านว่าฟังก์ชันขอ fixture อะไร (ได้ `fixtureinfo`)
2. สร้าง `Metafunc` แล้วเรียก hook `pytest_generate_tests` สำหรับ plugin ทุกตัว, ฟังก์ชัน `pytest_generate_tests` ใน module และใน class
3. ถ้าไม่มีใครเรียก `metafunc.parametrize` ผลคือ `Function` ตัวเดียว ถ้ามี ผลคือหนึ่ง `Function` ต่อหนึ่ง callspec ชื่อ `name[id]`

`@pytest.mark.parametrize` เป็นแค่ marker ที่ `pytest_generate_tests` ของ pytest เองอ่านแล้วเรียก `metafunc.parametrize` ให้ ผลคือ `test_qty[1]` กับ `test_qty[2]` เป็น node คนละตัวในต้นไม้ มี nodeid ของตัวเอง และล้มแยกกันได้ ([บท 4](/pytest/parametrize/in-depth/) ใช้ hook นี้เขียนเอง)

</Step>

## Import ไม่ได้: Collection Error

ไฟล์ที่ import ไม่ผ่านไม่ได้ทำให้ test ในไฟล์นั้นล้ม มันเป็น **collection error** (source: `importtestmodule`) ในแบบฝึกมี `broken/test_broken.py` ที่ import โมดูลที่ไม่มีอยู่ (รัน: `internals/12_collection_options.py`)

| คำสั่ง | ผล | exit code |
|---|---|---|
| `pytest` | `Interrupted: 1 error during collection` ไม่รัน test เลย | 2 |
| `pytest --continue-on-collection-errors` | รัน test ที่เหลือ สรุป `4 passed, 1 warning, 1 error` | 1 |

ค่าเริ่มต้นหยุดทั้งหมดโดยตั้งใจ: ถ้ารันต่อ test ที่หายไปเงียบๆ จะไม่ถูกสังเกต CI ที่เขียว 200 test โดยไม่มีไฟล์หนึ่งเลยเป็นสิ่งที่ผิด ([บท 1](/pytest/first-test/) เรื่อง exit code 5)

อีกกรณีของ import คือชื่อไฟล์ซ้ำในโฟลเดอร์ที่ไม่มี `__init__.py` ด้วย import mode ค่าเริ่มต้น (`prepend`) `a/test_same.py` กับ `b/test_same.py` ชนกันและ pytest ฟ้อง `import file mismatch` แก้ได้ด้วย `__init__.py` ในทั้งสองโฟลเดอร์ หรือ `--import-mode=importlib` ทั้งสองวิธีผ่าน 2 tests (รัน: `internals/09_config_layout.py`)

<Callout type="try" title="ลองทำใน repo นี้">
รัน `uv run python internals/12_collection_options.py` แล้วแก้ `FILES` ใน `internals/03_collection_tree.py` เพิ่ม class `TestZ` ที่มี `__init__` ดูว่ามี warning ขึ้นและต้นไม้ไม่เปลี่ยน จากนั้นรัน `uv run pytest exercises/04_parametrize --collect-only -q` เพื่อดู nodeid ที่ parametrize สร้าง
</Callout>

</Step>

## เช็กตัวเอง

- ทำไม `pytest shop/test_cart.py::TestRemove::test_drop` ไม่ต้อง import ไฟล์อื่นในโปรเจกต์
- class ชื่อ `Test_Cart` ถูก collect ไหม ส่วน `CartTests` ล่ะ และทำไม
- ถ้า CI เห็นว่าเขียวทั้งที่ไฟล์หนึ่ง import ไม่ได้ ตั้งค่าอะไรไว้

</Step>
