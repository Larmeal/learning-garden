## Collection คือการสร้างต้นไม้

ในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/) เราเห็นแล้วว่า Collection เสร็จทั้งหมดก่อนรัน Test ตัวแรก ซึ่งผลของมันคือต้นไม้ของ **Node** ที่ `--collect-only` พิมพ์ออกมา (รัน: `internals/03_collection_tree.py`)

```text
<Dir tmp0eq8na2k>
  <Package shop>
    <Module test_cart.py>
      <Class TestRemove>
        <Function test_drop>
        <Function test_missing>
      <Function test_qty[1]>
      <Function test_qty[2]>
  <Module test_top.py>
    <Function test_top>
```

Node มีสองชนิดด้วยกัน (Source: `_pytest/nodes.py`)

- Collector คือ Node ที่มี Method `collect()` คืน Node ลูกออกมา ได้แก่ `Session`, `Dir`, `Package`, `Module`, `Class`
- Item คือใบของต้นไม้ มี `runtest()` ที่รันจริง ซึ่ง `Function` ก็คือ Test ที่เราเขียน

Node แต่ละตัวมี `parent` และมี `listchain()` ที่คืนสายจากรากลงมาถึงตัวมันเอง ในตัวอย่างนี้ `test_drop` จะได้ `Session > Dir > Package > Module > Class > Function` (รัน: `internals/03_collection_tree.py`) ส่วน `nodeid` ที่เราคุ้นเคย อย่าง `shop/test_cart.py::TestRemove::test_drop` ก็คือที่อยู่ของ Node ในต้นไม้ โดยคั่นด้วย `::`

สายนี้สำคัญกับ[บทถัดไป](/pytest/fixture-engine/#กฎของ-scope) เพราะ Fixture ระดับ Module, Class และ Session ผูกกับ Node ในสายนี้ ([บท 11](/pytest/fixture-engine/#กฎของ-scope))

</Step>

## ต้นไม้ถูกเดินอย่างไร

`Session.collect` รับ Argument ที่พิมพ์บนบรรทัดคำสั่งทีละตัว แล้วเดินจากรากลงไปทีละชั้น (Source: `Session.collect` ใน `main.py`) Argument หนึ่งตัวแยกเป็นส่วน ๆ ได้ เช่น `shop/test_cart.py::TestRemove::test_drop` ประกอบด้วย Path ของโฟลเดอร์, Path ของไฟล์, ชื่อ Class และชื่อ Test ซึ่งในแต่ละชั้น Pytest จะเก็บ Node ลูกที่ชื่อตรงกับส่วนนั้นไว้ แล้วทิ้งที่เหลือ

วิธีเดินแบบนี้ทำให้เกิดสามอย่าง

- Node id ที่ระบุเจาะจงไม่ต้อง Import ทุกไฟล์ Pytest จะ Import เฉพาะไฟล์ที่อยู่บนเส้นทาง
- ส่วนที่เป็นชื่อ Test ไม่จำเป็นต้องใส่ Parameter โดย `::test_qty` เลือกทุก Parameter ส่วน `::test_qty[1]` เลือกตัวเดียว (Source: `Session.collect` ตรงที่ตัด `[` ออกก่อนเทียบชื่อ)
- ถ้า Node id ไม่ตรงอะไรเลย (`test_x.py::no_such_test`) Pytest จะจบด้วย Exit Code 4 และ `ERROR: not found: ...` (รัน: `internals/12_collection_options.py`)

</Step>

## โฟลเดอร์และไฟล์: Hook สองตัวที่ตัดสิน

เมื่อเจอโฟลเดอร์ Pytest จะถาม Hook `pytest_collect_directory` ถ้าโฟลเดอร์มี `__init__.py` ผลคือ `Package` แต่ถ้าไม่มีก็เป็น `Dir` ธรรมดา (Source: `pytest_collect_directory` ใน `python.py`) และเมื่อเจอไฟล์ก็จะถาม `pytest_collect_file` ซึ่งยอมรับเฉพาะ `.py` ที่ชื่อเข้ากับ `python_files` ยกเว้นไฟล์ที่ระบุตรง ๆ บนบรรทัดคำสั่ง ซึ่งไม่ต้องเช็กชื่อ (Source: `isinitpath` ในฟังก์ชันเดียวกัน ตรงกับที่บท [First Test](/pytest/first-test/#pytest-หา-test-เจอได้อย่างไร) แสดงด้วย `cart_extra.py`)

การเดินโฟลเดอร์จะข้ามบางโฟลเดอร์ตามค่า `norecursedirs` ในแบบฝึก `build/` และ `node_modules/` จะไม่ถูกเดินตอนรัน `pytest` เฉย ๆ แต่ถ้าระบุ Path ในโฟลเดอร์นั้นบนบรรทัดคำสั่ง ก็จะถูก Collect (รัน: `internals/12_collection_options.py`) ส่วนตัวเลือกที่ใช้บ่อยมีดังนี้

| Option | ทำอะไร | ยืนยัน |
|---|---|---|
| `--ignore=sub` | ไม่ Collect Path นั้น | ทั้งโฟลเดอร์หายไป |
| `--deselect <node id>` | Collect แล้วตัดทิ้ง | `3/4 tests collected (1 deselected)` |
| `-o norecursedirs=sub` | เปลี่ยนรายการโฟลเดอร์ที่ข้าม | โฟลเดอร์ `sub` ไม่ถูกเดิน |

</Step>

## ชื่ออะไรถึงเป็น Test

เมื่อ Import ไฟล์ได้แล้ว `PyCollector.collect` ไล่ดู `__dict__` ของ Module (หรือของ Class) ตามลำดับที่นิยามไว้ และถามทุกชื่อผ่าน Hook `pytest_pycollect_makeitem` (Source: `PyCollector.collect`) กติกาเริ่มต้นคือ `python_classes = Test`, `python_functions = test` โดยชื่อต้อง **ขึ้นต้นด้วย** ค่านั้น

```text
Test_Cart            collect เพราะขึ้นต้นด้วย Test
CartTests            ไม่ collect (ขึ้นต้นด้วย Cart)
TestWithInit         ไม่ collect: class ที่มี __init__
test_f               collect
spec_f               ไม่ collect
```

(รัน: `internals/12_collection_options.py` ผลคือ `Test_Cart::test_a` กับ `test_f`) ส่วน Class `TestWithInit` จะได้ Warning `cannot collect test class 'TestWithInit' because it has a __init__ constructor` เพราะ Pytest สร้าง Instance ของ Class เองโดยไม่ส่ง Argument

ค่าเหล่านี้เปลี่ยนได้ (รัน: `internals/12_collection_options.py`)

```toml
python_files = ["check_*.py"]
python_classes = ["Spec"]
python_functions = ["check_*"]
```

ด้วยสามบรรทัดนี้ `check_cart.py` จะให้ `Spec::check_a` กับ `check_total` ชื่อที่ขึ้นต้นด้วยค่านั้นผ่านเสมอ และถ้าค่ามี `*`, `?` หรือ `[` ก็จะถูกใช้เป็น Glob ด้วย (Source: `_matches_prefix_or_glob_option`)

นอกจากนี้ Pytest ยังเช็กเงื่อนไขอื่นอีก (Source: `istestfunction`, `istestclass`) คือฟังก์ชันที่ถูกตกแต่งด้วย `@pytest.fixture` ไม่ใช่ Test, Class ที่เป็น Abstract จะไม่ถูก Collect และ `__test__ = False` ปิดได้ทั้ง Class และ Module

</Step>

## หนึ่งฟังก์ชัน หลาย Function: Parametrize ทำงานตรงนี้

เมื่อชื่อผ่านเกณฑ์แล้ว `_genfunctions` จะสร้าง `Function` ให้ โดยมีขั้นตอนดังนี้ (Source: `_genfunctions` ใน `python.py`)

1. สร้าง `FunctionDefinition` เพื่ออ่านว่าฟังก์ชันขอ Fixture อะไร (ได้ `fixtureinfo`)
2. สร้าง `Metafunc` แล้วเรียก Hook `pytest_generate_tests` สำหรับ Plugin ทุกตัว, ฟังก์ชัน `pytest_generate_tests` ใน Module และใน Class
3. ถ้าไม่มีใครเรียก `metafunc.parametrize` จะได้ `Function` ตัวเดียว แต่ถ้ามี จะได้หนึ่ง `Function` ต่อหนึ่ง Callspec ชื่อ `name[id]`

`@pytest.mark.parametrize` เป็นแค่ Marker ที่ `pytest_generate_tests` ของ Pytest เองอ่านแล้วเรียก `metafunc.parametrize` ให้ เพราะฉะนั้น `test_qty[1]` กับ `test_qty[2]` จึงเป็น Node คนละตัวในต้นไม้ มี Nodeid ของตัวเอง และล้มแยกกันได้ ([บท 4](/pytest/parametrize/in-depth/#pytest_generate_tests-เขียนตัวสร้างเอง) จะใช้ Hook นี้เขียนเอง)

</Step>

## Import ไม่ได้: Collection Error

ไฟล์ที่ Import ไม่ผ่านจะกลายเป็น **Collection Error** (Source: `importtestmodule`) ซึ่งไม่ได้ทำให้ Test ในไฟล์นั้นล้ม ในแบบฝึกมี `broken/test_broken.py` ที่ Import โมดูลที่ไม่มีอยู่ (รัน: `internals/12_collection_options.py`)

| คำสั่ง | ผล | Exit Code |
|---|---|---|
| `pytest` | `Interrupted: 1 error during collection` ไม่รัน Test เลย | 2 |
| `pytest --continue-on-collection-errors` | รัน Test ที่เหลือ สรุป `4 passed, 1 warning, 1 error` | 1 |

ค่าเริ่มต้นจะหยุดทั้งหมดโดยตั้งใจ เพราะถ้ารันต่อ Test ที่หายไปเงียบ ๆ จะไม่มีใครสังเกต และ CI ที่เขียว 200 Test โดยไม่มีไฟล์หนึ่งเลยก็เป็นสิ่งที่ผิด ([บท 1](/pytest/first-test/#exit-code-สิ่งที่-ci-อ่าน) เรื่อง Exit Code 5)

อีกกรณีของ Import คือชื่อไฟล์ซ้ำในโฟลเดอร์ที่ไม่มี `__init__.py` ซึ่งด้วย Import Mode ค่าเริ่มต้น (`prepend`) `a/test_same.py` กับ `b/test_same.py` จะชนกัน และ Pytest ฟ้อง `import file mismatch` แก้ได้ด้วย `__init__.py` ในทั้งสองโฟลเดอร์ หรือ `--import-mode=importlib` ซึ่งทั้งสองวิธีผ่าน 2 Tests (รัน: `internals/09_config_layout.py`)

<Callout type="try" title="ลองทำใน Repo นี้">
ลองรัน `uv run python internals/12_collection_options.py` แล้วแก้ `FILES` ใน `internals/03_collection_tree.py` เพิ่ม Class `TestZ` ที่มี `__init__` เข้าไป จะเห็นว่ามี Warning ขึ้นและต้นไม้ไม่เปลี่ยน จากนั้นลองรัน `uv run pytest exercises/04_parametrize --collect-only -q` เพื่อดู Nodeid ที่ Parametrize สร้าง
</Callout>

</Step>

## เช็กตัวเอง

- ทำไม `pytest shop/test_cart.py::TestRemove::test_drop` ไม่ต้อง Import ไฟล์อื่นในโปรเจกต์
- Class ชื่อ `Test_Cart` ถูก Collect ไหม ส่วน `CartTests` ล่ะ และทำไม
- ถ้า CI เห็นว่าเขียวทั้งที่ไฟล์หนึ่ง Import ไม่ได้ ตั้งค่าอะไรไว้

</Step>
