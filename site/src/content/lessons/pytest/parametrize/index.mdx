## Test เดียว หลายค่า

การลดราคา 10% ของ 100 ควรได้ 90 แล้ว 0%, 100% และ 20% ของ 250 ล่ะ ถ้าเราเขียนทีละ Test ก็จะได้ฟังก์ชันที่ต่างกันแค่ตัวเลข แต่ถ้าใช้ `@pytest.mark.parametrize` เราเขียนตัว Test แค่ตัวเดียวแล้วส่งตารางค่าเข้าไปแทนได้

```python
@pytest.mark.parametrize(
    "total, percent, expected",
    [
        (100, 0, 100),
        (100, 10, 90),
        (100, 100, 0),
        (250, 20, 200),
    ],
)
def test_apply_discount(total, percent, expected):
    assert apply_discount(total, percent) == pytest.approx(expected)
```

อาร์กิวเมนต์แรกคือชื่อ Parameter คั่นด้วยจุลภาค ส่วนอาร์กิวเมนต์ที่สองคือรายการของแถว โดยหนึ่งแถวจะเป็นหนึ่ง Test ที่เป็นอิสระต่อกัน ในแบบฝึก Pytest เก็บฟังก์ชันนี้ไว้เป็น 4 Test (รัน: `exercises/04_parametrize/test_parametrize.py`)

```text
test_apply_discount[100-0-100]
test_apply_discount[100-10-90]
test_apply_discount[100-100-0]
test_apply_discount[250-20-200]
```

</Step>

## หนึ่งแถวล้ม แถวอื่นยังรัน

เพราะทุกแถวเป็น Test แยกกัน แถวที่ผิดจึงไม่บังแถวอื่น `demos/04_one_row_fails` มีแถวที่ตั้งใจให้ผิดอยู่หนึ่งแถว (50% ของ 100 ไม่ใช่ 40) ผลที่ได้คือ `1 failed, 2 passed` และชื่อ Test ที่ล้มก็บอกแถวนั้นให้เราเลย (รัน: `demos/04_one_row_fails`)

```text
FAILED demos/04_one_row_fails/test_rows.py::test_rows[100-50-40]
E       assert 50.0 == 40 ± 4.0e-05
```

แต่ถ้าเราใช้ `for` วน Assert ใน Test เดียว แถวแรกที่ผิดจะหยุดทั้ง Test และแถวหลังจะไม่ถูกลอง เราจึงเห็นปัญหาได้ทีละอย่างเท่านั้น

</Step>

## Ids: ตั้งชื่อให้อ่านรู้เรื่อง

Pytest สร้าง id จากค่าให้เอง เช่น `[100-10-90]` ซึ่งใช้ได้เมื่อค่าอ่านง่าย แต่ถ้าอ่านยาก เราก็ตั้งชื่อเองได้ด้วย `pytest.param(..., id="...")` (รัน: `exercises/04_parametrize/test_parametrize.py`)

```python
@pytest.mark.parametrize(
    "total, fee",
    [
        pytest.param(499.99, 50.0, id="just-below-the-line"),
        pytest.param(500, 0.0, id="exactly-on-the-line"),
        pytest.param(0, 50.0, id="empty"),
    ],
)
def test_shipping_fee(total, fee):
    assert shipping_fee(total) == fee
```

เมื่อ Test ล้ม ชื่อ `test_shipping_fee[exactly-on-the-line]` ก็บอกกรณีที่ผิดได้เลยโดยไม่ต้องเปิดโค้ด และเรายังใช้ id ร่วมกับ `-k` ได้ เช่น `pytest -k exactly` ([บท 7](/pytest/project/#เลือกรัน-path-node-id-และ--k)) ถ้าอยากดู id ทั้งหมดก่อนรัน ให้รัน `pytest --collect-only -q`

</Step>

<Step>

## กรณีล้มเหลวก็เป็นแถว

ตารางไม่จำเป็นต้องมีแต่กรณีที่สำเร็จ เราใส่ค่าที่ต้องถูกปฏิเสธลงไปได้ด้วย โดยให้ตัว Test ใช้ `pytest.raises` ([บท 2](/pytest/assertions/#เช็กว่าโค้ดโยน-exception-ด้วย-raises))

```python
@pytest.mark.parametrize("percent", [-1, 101, 1000])
def test_apply_discount_rejects_bad_percent(percent):
    with pytest.raises(ValueError, match="between 0 and 100"):
        apply_discount(100, percent)
```

เราแยกเป็น Test คนละตัวกับกรณีที่สำเร็จ เพราะเป็นพฤติกรรมคนละแบบ (ผู้เขียน) ถ้าเอา "คืนค่า" กับ "โยน Exception" มาปนในตารางเดียว ตัว Test ก็จะต้องมี if

</Step>

## ซ้อนหลายตัว: ได้ทุกคู่

ถ้าเราวาง `parametrize` สองตัวบน Test เดียว จะได้ผลคูณ (Cartesian Product)

```python
@pytest.mark.parametrize("percent", [0, 50])
@pytest.mark.parametrize("total", [100, 200, 300])
def test_stacked_parametrize_makes_every_combination(total, percent):
    assert apply_discount(total, percent) <= total
```

3 คูณ 2 ได้ 6 Test และ id จะเรียง `total` ก่อน (ตัวที่อยู่ใกล้ฟังก์ชันที่สุดมาก่อน) (รัน: `exercises/04_parametrize/test_parametrize.py`)

```text
[100-0]  [100-50]  [200-0]  [200-50]  [300-0]  [300-50]
```

ต้องระวังเรื่องจำนวนที่โตเร็วด้วยนะ ถ้าซ้อนสามตัว ตัวละ 10 ค่า จะได้ 1,000 Test เราจึงควรซ้อนเมื่ออยากได้ทุกคู่จริง ๆ เท่านั้น ถ้าต้องการแค่คู่เฉพาะ ให้ใช้ตารางแถวเดียวที่ระบุคู่ตรง ๆ

</Step>

## ใส่ Mark ให้บางแถวด้วย pytest.param

`pytest.param` ใส่ `marks=` ได้ เช่น ทำเครื่องหมายว่าแถวนี้ "ยังไม่รองรับ" โดยไม่ต้องลบทิ้ง ([บท 5](/pytest/markers/#xfail-รู้ว่าล้ม-แต่ยังรันอยู่) พูดถึง `xfail` ไว้)

```python
pytest.param("NOPE", None,
             marks=pytest.mark.xfail(raises=KeyError, reason="unknown code is not handled yet"))
```

แถวนี้ขึ้นเป็น `XFAIL` ส่วนอีกสองแถวผ่านตามปกติ (รัน: `exercises/04_parametrize/test_parametrize.py` ได้ 21 Passed และ 1 Xfailed)

</Step>

## เลือกรันเฉพาะแถว และเมื่อไรไม่ควรใช้

เพราะ id เป็นส่วนของชื่อ Test เราจึงเลือกด้วย `-k` ได้ ในแบบฝึก `-k coupon` จะเลือกเฉพาะ Test ที่ชื่อมีคำว่า Coupon ได้ 3 Passed และข้ามอีก 19 (รัน: `verify.py`)

ส่วนกรณีที่ไม่ควรใช้ `parametrize` มีอยู่สามแบบ

- ถ้าตัว Test เริ่มมี `if` ตามค่าของ Parameter แสดงว่าเป็นพฤติกรรมสองแบบ ให้แยก Test ออกจากกัน
- ถ้าค่าทุกแถวต้องอธิบายด้วยคอมเมนต์ยาว ๆ ตารางอาจกำลังซ่อนเจตนาอยู่ ลองตั้ง id ที่เล่าเรื่องให้เข้าใจ
- ถ้าต้องการให้ **Fixture** ทั้งชุดเปลี่ยนตามค่า (เช่น ใช้ Database สองชนิด) ให้ใช้ Fixture ที่มี `params` แทน ([บท 3](/pytest/fixtures/#autouse-factory-และ-params))

<Callout type="try" title="ลองทำใน Repo นี้">
ลองเพิ่มแถว `(250, 100, 0)` ในตาราง `test_apply_discount` แล้วรัน `uv run pytest exercises/04_parametrize/test_parametrize.py --collect-only -q` เพื่อดูว่า id ใหม่คืออะไรและจำนวน Test เพิ่มเป็นเท่าไร จากนั้นลองใส่แถวที่ผิดหนึ่งแถวแล้วอ่านผลที่ล้ม
</Callout>

## เช็กตัวเอง

- ถ้าใช้ `for row in rows: assert ...` ใน Test เดียว แทน Parametrize ผลต่างกันอย่างไรเมื่อแถวที่สองผิด
- `parametrize` สองตัวที่มี 4 และ 5 ค่า ได้กี่ Test
- แถวไหนในตาราง shipping_fee ที่เป็น Boundary และทำไมจึงควรมี
