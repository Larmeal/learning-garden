## ปัญหา: Setup เหมือนกันทุก Test

สมมติว่า Test ของตะกร้าต้องมีแอปเปิล 3 ผลกับลูกแพร์ 1 ผลก่อนเริ่ม เราก็ต้องเริ่มด้วยโค้ดชุดเดิมในทุก Test

```python
def test_total():
    cart = Cart()
    cart.add("apple", price=10, qty=3)
    cart.add("pear", price=20)
    assert cart.total() == 50
```

ถ้ามีสิบ Test ก็ต้องคัดลอกสิบครั้ง และเมื่อ `Cart()` เปลี่ยนวิธีสร้างก็ต้องแก้สิบที่ **Fixture** คือฟังก์ชันที่เตรียมของให้ Test โดย Test จะขอได้ด้วยการใส่ชื่อ Fixture เป็น Parameter

```python
@pytest.fixture
def cart():
    return Cart()

@pytest.fixture
def filled_cart(cart):          # fixture ขอ fixture อื่นได้ ด้วยวิธีเดียวกัน
    cart.add("apple", price=10, qty=3)
    cart.add("pear", price=20)
    return cart

def test_fixture_that_uses_another_fixture(filled_cart):
    assert filled_cart.total() == 50
```

เมื่อ Pytest เห็นชื่อ `filled_cart` ใน Parameter มันจะรัน Fixture ก่อน แล้วส่งค่าที่คืนเข้ามาให้ Test

</Step>

## แต่ละ Test ได้ของใหม่

ค่าเริ่มต้นคือ Fixture จะทำงาน **ใหม่ทุก Test** ซึ่งแบบฝึกยืนยันด้วยสอง Test ที่รันต่อกัน (รัน: `exercises/03_fixtures/test_fixtures.py`)

```python
def test_every_test_gets_a_fresh_cart(filled_cart):
    filled_cart.add("kiwi", price=5)
    assert filled_cart.qty("kiwi") == 1

def test_the_previous_test_did_not_leak(filled_cart):
    assert filled_cart.qty("kiwi") == 0
```

Test แรกเพิ่ม Kiwi แต่ Test ที่สองไม่เห็น นี่คือเหตุผลที่ Test อิสระต่อกัน ([บท 15](/pytest/test-design/#test-ต้องอิสระต่อกัน) จะกลับมาเรื่องนี้)

</Step>

<Step>

## conftest.py: ใช้ร่วมกันโดยไม่ต้อง Import

ถ้า Fixture ถูกใช้โดยหลายไฟล์ ให้ใส่ใน `conftest.py` Pytest จะโหลดไฟล์นี้ให้เอง และ Test ทุกไฟล์ในโฟลเดอร์นั้น (และโฟลเดอร์ลูก) เรียกใช้ได้เลยโดยไม่ต้อง Import ในแบบฝึก `cart` และ `filled_cart` อยู่ใน `exercises/03_fixtures/conftest.py` และ `test_fixtures.py` ใช้โดยไม่ Import อะไร

ถ้ามีชื่อซ้ำ `conftest.py` ที่อยู่ใกล้ Test กว่าจะชนะ และ Fixture ที่เขียนในไฟล์ Test เองจะชนะทั้งสองอย่าง เราจึง Override เฉพาะที่ได้ ในโฟลเดอร์ `nested/` ของแบบฝึกมี `cart` ที่ Override สองชั้น และ Test จะได้ตะกร้าที่ใกล้ที่สุดเสมอ (รัน: `exercises/03_fixtures/nested`)

</Step>

<Step>

## Yield: Setup และ Teardown ในที่เดียว

บางอย่างต้องเก็บกวาดหลัง Test เช่น ปิด Connection หรือลบไฟล์ ซึ่งเราใช้ `yield` แทน `return` ได้ โค้ดก่อน `yield` คือ Setup ส่วนโค้ดหลัง `yield` คือ Teardown ที่ **รันแม้ Test ล้ม** (รัน: `demos/03_teardown` เหตุการณ์คือ Setup แล้ว Teardown แม้ Test ล้ม)

```python
@pytest.fixture
def transaction(connection):
    EVENTS.append("begin")
    yield connection
    EVENTS.append("rollback")
```

ดูลำดับจริงด้วย `--setup-show` (รัน: `exercises/03_fixtures/test_fixtures.py`)

```text
SETUP    M connection
    SETUP    F count_tests
    SETUP    F transaction (fixtures used: connection)
    ...::test_first_user_of_the_fixtures .
    TEARDOWN F transaction
    TEARDOWN F count_tests
    SETUP    F count_tests
    SETUP    F transaction (fixtures used: connection)
    ...::test_second_user_of_the_fixtures .
    TEARDOWN F transaction
    TEARDOWN F count_tests
    ...
TEARDOWN M connection
```

Teardown จะไล่ย้อนกลับจาก Setup เสมอ (ตัวที่ตั้งทีหลังจะเก็บก่อน)

</Step>

## Scope: สร้างบ่อยแค่ไหน

`connection` ด้านบนตั้ง `scope="module"` (ตัวอักษร `M` ในผล) จึงถูกสร้างครั้งเดียวสำหรับทั้งไฟล์ ส่วน `transaction` เป็น Function Scope (`F`) ซึ่งสร้างใหม่ทุก Test

| Scope | สร้างใหม่เมื่อ | ใช้กับ |
|---|---|---|
| `function` (ค่าเริ่มต้น) | ทุก Test | ของที่ Test แก้ไขได้ เช่น ตะกร้า |
| `class` | ทุก Class | |
| `module` | ทุกไฟล์ | ของที่สร้างแพง และ Test ไม่แก้ |
| `package` | ทุก Package | |
| `session` | ครั้งเดียวทั้งการรัน | เช่น เริ่ม Database Container |

แบบฝึกพิสูจน์ด้วย List `EVENTS` (รัน: `exercises/03_fixtures/test_fixtures.py`)

```python
def test_the_events_show_scope():
    assert EVENTS == ["connect", "begin", "test 1", "rollback", "begin", "test 2", "rollback"]
```

จะเห็นว่า Connect เกิดครั้งเดียว Begin/Rollback เกิดสองครั้ง และ Disconnect ยังไม่เกิดจนกว่าไฟล์จะจบ

<Callout type="warn" title="Scope ใหญ่ขึ้นแลกกับการแชร์สถานะ">
Fixture ระดับ Module หรือ Session ที่คืน Object ที่แก้ได้ (เช่น ตะกร้า) จะถูกแชร์ให้ทุก Test ถ้า Test หนึ่งแก้ค่า Test ถัดไปก็จะเห็นค่าที่ถูกแก้ ซึ่งเป็นที่มาของ Test ที่ผ่านเมื่อรันรวมแต่ล้มเมื่อรันเดี่ยว ([บท 15](/pytest/test-design/#test-ต้องอิสระต่อกัน)) ดังนั้นให้ใช้ Scope ใหญ่กับของที่ไม่ถูกแก้ หรือเตรียมให้ Test รีเซ็ตด้วย Fixture ระดับ Function ซ้อนอีกชั้น
</Callout>

</Step>

## Fixture ที่มากับ Pytest: tmp_path

`tmp_path` จะให้โฟลเดอร์ชั่วคราวที่ว่างและไม่ซ้ำกันต่อ Test เหมาะกับโค้ดที่เขียนไฟล์ (รัน: `exercises/03_fixtures/test_fixtures.py`)

```python
def test_save_and_load_with_tmp_path(filled_cart, tmp_path):
    path = tmp_path / "cart.json"
    filled_cart.save(path)
    assert path.exists()
    again = Cart.load(path)
    assert again.total() == filled_cart.total()
```

Test ไม่ต้องลบไฟล์เอง และไม่ชนกับ Test อื่น ส่วน Fixture ที่มากับ Pytest และใช้บ่อยตัวอื่น ๆ คือ `monkeypatch`, `capsys`, `caplog` ([บท 6](/pytest/isolation/#monkeypatch-แทนชั่วคราว-คืนให้เองหลังจบ)) และ `request` (ข้อมูลของ Test ที่กำลังรัน)

</Step>

## Autouse, Factory และ Params

**Autouse** จะรันให้ทุก Test ในขอบเขตโดยไม่ต้องขอ เหมาะกับสิ่งที่ต้องเกิดเสมอ (ล้างสถานะ ตั้งเวลา) ในแบบฝึกเราใช้บันทึกชื่อ Test ที่กำลังรัน

```python
@pytest.fixture(autouse=True)
def count_tests(request):
    COUNT.append(request.node.name)
```

**Factory Fixture** จะคืนฟังก์ชันออกมา ใช้เมื่อ Test ต้องการหลายตัวหรือต้องกำหนดเนื้อหาเอง

```python
@pytest.fixture
def make_cart():
    def make(**items):
        cart = Cart()
        for sku, price in items.items():
            cart.add(sku, price=price)
        return cart
    return make

def test_factory_fixture(make_cart):
    assert make_cart(apple=10).total() == 10
    assert make_cart(apple=10, pear=20).total() == 30
```

**Fixture ที่มี Params** จะทำให้ Test ที่ใช้มันรันซ้ำหนึ่งครั้งต่อค่า

```python
@pytest.fixture(params=["SAVE10", "SAVE20"])
def coupon(request):
    return request.param
```

`test_a_parametrized_fixture_runs_the_test_once_per_param` จึงรัน 2 ครั้ง ไฟล์ `test_fixtures.py` เลยมีฟังก์ชัน Test 11 ตัวแต่รายงาน **12 Passed** (รัน: `exercises/03_fixtures/test_fixtures.py`) ส่วน[บท 4](/pytest/parametrize/#test-เดียว-หลายค่า) จะสอนวิธีที่ตรงไปตรงมากว่าสำหรับกรณี Test ทั่วไป

<Callout type="try" title="ลองทำใน Repo นี้">
ลองรัน `uv run pytest exercises/03_fixtures/test_fixtures.py --setup-show` แล้วอ่านลำดับดู จากนั้นลองเปลี่ยน `scope="module"` ของ `connection` เป็น `"function"` แล้วดูว่า `test_the_events_show_scope` ล้มเพราะอะไร และ `EVENTS` ที่ได้หน้าตาอย่างไร
</Callout>

</Step>

## เช็กตัวเอง

- Fixture ที่ต่อ Database ควรเป็น Scope ไหน ถ้าทุก Test แก้ข้อมูลในตาราง และคุณจะกันไม่ให้ Test รบกวนกันอย่างไร
- Teardown หลัง `yield` รันไหมถ้า Test ล้ม แล้วถ้า Setup ก่อน `yield` โยน Exception ล่ะ
- ทำไมการใส่ Fixture ใน `conftest.py` ไม่ต้อง Import แต่ Helper Function ธรรมดาต้อง Import

</Step>
