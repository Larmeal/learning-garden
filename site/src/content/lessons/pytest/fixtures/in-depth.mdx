## `request`: Fixture ถามได้ว่าใครเรียกมัน

Fixture ที่ประกาศ Parameter ชื่อ `request` จะได้ Object ที่บอกบริบทของ Test ที่ขอมัน (รัน: `exercises/03_fixtures/test_fixtures_in_depth.py`)

```python
@pytest.fixture
def who_asked(request):
    return {
        "name": request.node.name,
        "scope": request.scope,
        "fixturename": request.fixturename,
        "module": request.module.__name__.split(".")[-1],
        "has_cls": request.cls is not None,
    }
```

เมื่อ Test ชื่อ `test_request_describes_the_asking_test` ขอ Fixture นี้ จะได้ `scope == "function"`, `fixturename == "who_asked"` และ `has_cls` เป็น `False` ส่วนถ้า Test อยู่ใน Class จะเป็น `True` (รัน) ตัวที่ใช้บ่อยคือ `request.node` (ตัว Test), `request.config` (Config ของ Pytest) และ `request.param` ([บทถัดไป](/pytest/parametrize/)) บท [เครื่องยนต์ของ Fixture](/pytest/fixture-engine/#รัน-fixture-หนึ่งตัว) อธิบายว่าตัวนี้คือ `SubRequest` ซึ่ง Pytest สร้างให้ทีละ Fixture

</Step>

## Indirect: ให้ Test ส่งค่าเข้า Fixture

`parametrize` ปกติจะส่งค่าเข้า Test ตรง ๆ แต่ถ้าใส่ `indirect` ค่าจะไปที่ Fixture ที่ชื่อเดียวกันแทน และ Fixture จะอ่านจาก `request.param`

```python
@pytest.fixture
def cart_of(request):
    cart = Cart()
    cart.add("apple", price=10, qty=request.param)
    return cart

@pytest.mark.parametrize("cart_of, total", [(1, 10), (3, 30)], indirect=["cart_of"])
def test_indirect_hands_the_value_to_the_fixture(cart_of, total):
    assert cart_of.total() == total
```

`cart_of` จะได้ตะกร้าที่สร้างจากค่า 1 และ 3 ส่วน `total` ส่งตรงเข้า Test วิธีนี้ใช้เมื่อต้องสร้างของที่ต้องใช้ Setup/Teardown ตามค่า เช่น Database ที่มี Row n แถว (รัน)

</Step>

## `addfinalizer`: ลงทะเบียนการเก็บกวาดหลายจุด

`yield` เหมาะเมื่อ Setup กับ Teardown อยู่ที่เดียวกัน แต่เมื่อ Fixture ทำของหลายอย่างตามเงื่อนไข เราสามารถใช้ `request.addfinalizer(fn)` ลงทะเบียนการเก็บกวาดทีละชิ้นขณะ Setup ไปได้

```python
@pytest.fixture
def resource(request):
    ORDER.append("open")
    request.addfinalizer(lambda: ORDER.append("close first-registered"))
    request.addfinalizer(lambda: ORDER.append("close second-registered"))
    return "res"
```

หลัง Test จบ ORDER จะได้ `open, test, close second-registered, close first-registered` ซึ่งก็คือ **ย้อนลำดับที่ลงทะเบียน** (รัน) ข้อดีเหนือ `yield` คือ Finalizer ที่ลงทะเบียนไปแล้วจะยังรันแม้โค้ด Setup หลังจากนั้นพัง

</Step>

## `getfixturevalue`: เลือกชื่อ Fixture ตอนรัน

`request.getfixturevalue(name)` ใช้ขอ Fixture ด้วยชื่อที่เป็นสตริง เหมาะเมื่อชื่อมาจากข้อมูล (รัน)

```python
@pytest.mark.parametrize("name, empty", [("small", True), ("large", False)])
def test_getfixturevalue_looks_up_by_name(request, name, empty):
    assert request.getfixturevalue(name).is_empty() is empty
```

ถ้าชื่อไม่มีจริง จะได้ `FixtureLookupError` ซึ่งเป็น `LookupError` ที่ `.argname` บอกชื่อที่หา (ชนิดนี้ไม่ได้ Export ที่ `pytest.` จึงตรวจด้วย `pytest.raises(LookupError)` แล้วอ่าน `info.type.__name__`) แต่ก็มีข้อแลกเปลี่ยนคือ Fixture ที่ขอแบบนี้จะไม่อยู่ใน Closure ที่คำนวณตอน Collection ([บท 11](/pytest/fixture-engine/#รายการที่-test-ต้องใช้-closure)) จึงอ่านยากกว่าการประกาศเป็น Parameter ดังนั้นใช้เมื่อจำเป็นเท่านั้นนะ

</Step>

## `usefixtures`, `name=` และ Scope แบบคำนวณ

**`usefixtures`** จะรัน Fixture โดยไม่ต้องมี Parameter ในฟังก์ชัน เหมาะเมื่อเราสนใจแค่ผลข้างเคียงของมัน

```python
@pytest.mark.usefixtures("sets_flag")
def test_usefixtures_runs_the_fixture_without_a_parameter():
    assert ORDER[-1] == "flag set"
```

ใช้บน Class หรือ Module ก็ได้ (`pytestmark = pytest.mark.usefixtures(...)`)

**`name=`** ให้เราตั้งชื่อ Fixture ต่างจากชื่อฟังก์ชันได้ ช่วยหลีกเลี่ยงการที่ Parameter ของ Test ไปบังชื่อ Fixture ในไฟล์เดียวกัน

```python
@pytest.fixture(name="shopping_cart")
def make_shopping_cart():
    return Cart()
```

**Scope แบบคำนวณ** คือการส่งฟังก์ชันที่รับ `fixture_name` กับ `config` และคืนชื่อ Scope โดยฟังก์ชันนี้จะถูกเรียกครั้งแรกที่ Fixture ถูกใช้

```python
def scope_from_config(fixture_name, config):
    return "session" if config.getoption("--setup-show", default=False) else "function"

@pytest.fixture(scope=scope_from_config)
def maybe_shared():
    return object()
```

วิธีนี้ใช้เมื่อต้องการให้ Fixture ที่แพง (เช่น Container) ใช้ร่วมกันบน CI แต่แยกเป็นต่อ Test บนคอมพิวเตอร์ของเรา (รัน: ทั้งสามแบบผ่านใน `test_fixtures_in_depth.py`)

</Step>

## เมื่อ Fixture พัง และ `autouse` ใน Conftest

- ถ้า Fixture โยน Exception ตอน Setup Test จะได้ **Error** และตัว Test จะไม่ถูกเรียก (ข้อความใน Test ไม่ถูกพิมพ์) ซึ่งแบบฝึกยืนยันด้วย `pytester` ที่ได้ `errors=1` (รัน)
- Fixture `autouse=True` ใน `conftest.py` จะใช้กับ **ทุก Test ในโฟลเดอร์นั้นและโฟลเดอร์ลูก** โดยไม่ต้องขอ ในแบบฝึกเราสร้าง Conftest ที่พิมพ์ชื่อ Test ทุกตัว ผลคือ `NOTE test_a` และ `NOTE test_b` (รัน) เหมาะกับสิ่งที่ต้องเกิดกับทั้งโฟลเดอร์ เช่น รีเซ็ตเวลาหรือ Environment แต่ควรใช้เท่าที่จำเป็น เพราะคนอ่าน Test จะไม่เห็นมันในตัว Test

</Callout>
