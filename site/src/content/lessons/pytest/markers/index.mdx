## ป้ายบน Test

ทุกทีมจะมี Test ที่ "ยังรันไม่ได้" อยู่สักตัว เช่น ฟีเจอร์ยังไม่เสร็จ รันได้เฉพาะบางระบบปฏิบัติการ หรือเป็น Bug ที่รู้แล้วแต่ยังไม่ได้แก้ ทางลัดที่แย่ที่สุดคือคอมเมนต์ Test ทิ้ง เพราะมันจะหายไปจากรายงานเลย แต่ถ้าใช้ **Marker** Test จะยังอยู่ในรายงานพร้อมเหตุผลที่เราบอกไว้

แบบฝึก `exercises/05_markers/test_markers.py` มี 10 Test ผลที่ได้คือ 6 Passed, 2 Skipped, 2 Xfailed (รัน: `exercises/05_markers/test_markers.py`) และบรรทัดผลแบบย่อ `s.sxx.....` ก็เรียงตามลำดับ Test ในไฟล์

</Step>

## Skip และ Skipif: ไม่รัน

```python
@pytest.mark.skip(reason="the invoice PDF feature is not built yet")
def test_invoice_pdf(): ...

@pytest.mark.skipif(sys.version_info < (3, 99), reason="needs a Python that does not exist yet")
def test_skipped_because_the_condition_is_true(): ...
```

`skip` จะข้ามเสมอ ส่วน `skipif` จะข้ามเมื่อเงื่อนไขเป็นจริง ในแบบฝึกเงื่อนไข `sys.platform == "plan9"` เป็นเท็จ Test จึงรัน ส่วน `sys.version_info < (3, 99)` เป็นจริง Test จึงถูกข้าม

ที่บรรทัดสรุปท้ายรายงานบอกเหตุผลให้ด้วย ก็เพราะเราตั้ง `-ra` ไว้ใน `addopts` ของโปรเจกต์ ([บท 7](/pytest/project/#ตั้งค่าครั้งเดียว-ใน-pyprojecttoml))

```text
SKIPPED [1] exercises\05_markers\test_markers.py:10: the invoice PDF feature is not built yet
SKIPPED [1] exercises\05_markers\test_markers.py:20: needs a Python that does not exist yet
```

ถ้าต้องตัดสินใจระหว่างรัน (หลังจากอ่านข้อมูลบางอย่างแล้ว) เราก็เรียก `pytest.skip("เหตุผล")` ในตัว Test ได้ แบบฝึกมีตัวอย่าง `test_imperative_skip` ซึ่งในรอบนี้เงื่อนไขไม่เป็นจริง มันจึงรันจนจบและผ่าน

<Callout type="warn" title="Skip ที่ไม่มีวันหมดอายุ">
Test ที่ถูก Skip นาน ๆ ก็เหมือนตายไปแล้ว เราควรใส่ `reason` ที่ระบุว่ารออะไรอยู่ (ตั๋วงาน หรือเวอร์ชัน) และตรวจรายการ SKIPPED ทุกครั้งที่ปล่อยเวอร์ชัน (ผู้เขียน)
</Callout>

</Step>

## Xfail: รู้ว่าล้ม แต่ยังรันอยู่

`xfail` บอกว่า Test นี้ **คาดว่าจะล้ม** Pytest ยังคงรันมันอยู่ แต่ถ้าล้มจะนับเป็น `xfailed` และไม่ทำให้ชุดทดสอบแดง

```python
@pytest.mark.xfail(reason="coupons stack, which the business has not decided on yet")
def test_two_coupons_should_not_stack():
    cart = Cart()
    cart.add("apple", price=100)
    after_one = cart.apply_coupon("SAVE10")
    after_two = cart.apply_coupon("SAVE20")
    assert after_two == after_one
```

Test นี้เขียนพฤติกรรมที่ **ต้องการ** เอาไว้ก่อน วันนี้มันล้ม (90 กับ 80) จึงเป็น Xfailed และเมื่อมีคนแก้โค้ดจนผ่าน เราก็จะรู้ เพราะสถานะของมันเปลี่ยนไป

แต่มีปัญหาอยู่ข้อหนึ่ง คือถ้า Xfail ธรรมดาเริ่มผ่านขึ้นมา ก็ไม่มีใครถูกบังคับให้มาลบเครื่องหมายออก ซึ่ง `strict=True` ช่วยจัดการข้อนี้ได้ (รัน: `demos/05_markers`)

```python
@pytest.mark.xfail(strict=True, reason="was a known bug")
def test_strict_xfail_that_now_passes():
    assert Cart().is_empty()
```

```text
[XPASS(strict)] was a known bug
FAILED demos/05_markers/test_marker_problems.py::test_strict_xfail_that_now_passes
```

เมื่อ Xfail แบบ Strict ผ่าน มันจะกลายเป็นล้ม เพื่อเตือนให้เราลบ Marker ออก เราจึงควรใช้ Strict กับ Bug ที่รู้แล้ว ส่วน Xfail ธรรมดาเหมาะกับกรณีที่ผลไม่แน่นอน (ผู้เขียน) นอกจากนี้เรายังใส่ `raises=KeyError` เพื่อให้ Xfail จับเฉพาะ Exception ชนิดที่คาดไว้ได้ด้วย ([บท 4](/pytest/parametrize/#ใส่-mark-ให้บางแถวด้วย-pytestparam) ใช้แบบนี้)

</Step>

## Marker ของเราเอง

เราตั้งชื่อ Marker เองได้ เช่น `slow` และ `integration` แล้วแปะบน Test

```python
@pytest.mark.slow
def test_a_slow_one(): ...

@pytest.mark.slow
@pytest.mark.integration
def test_both_marks(): ...
```

จากนั้นเลือกรันด้วย `-m` ซึ่งรับนิพจน์ได้ (รัน: `verify.py`)

| คำสั่ง | ผล (จาก 10 Test ใน `05_markers`) |
|---|---|
| `-m "not slow"` | 4 passed, 2 skipped, 2 xfailed, 2 deselected |
| `-m slow` | 2 passed, 8 deselected |
| `-m "slow and integration"` | 1 passed, 9 deselected |

ตอนทำ CI แยกชั้น เราก็รัน `-m "not slow"` ทุก Commit แล้วรันทั้งหมดตอนกลางคืนได้

</Step>

## ลงทะเบียน Marker กันพิมพ์ผิด

ถ้าเราพิมพ์ `@pytest.mark.slwo` (สะกดผิด) Pytest จะไม่ถือว่าเป็น Error แต่เป็นแค่ Warning และ Test ก็ไม่ถูกจัดกลุ่มตามที่เราตั้งใจ (รัน: `demos/05_markers`)

```text
PytestUnknownMarkWarning: Unknown pytest.mark.slwo - is this a typo?
```

วิธีแก้มีสองขั้น **ขั้นแรก** ให้ลงทะเบียน Marker ในไฟล์ตั้งค่า

```toml
[tool.pytest.ini_options]
markers = [
    "slow: a test that takes a while",
    "integration: a test that uses more than one module",
]
```

**ขั้นที่สอง** ให้เปิด `--strict-markers` เพื่อให้ Marker ที่ไม่ได้ลงทะเบียนกลายเป็น Error ตั้งแต่ตอน Collect

```text
'slwo' not found in `markers` configuration option
!!!!!!!!!!!!!!!!!!! Interrupted: 1 error during collection !!!!!!!!!!!!!!!!!!!!
```

(รัน: `verify.py`) เพราะเมื่อเลือกด้วย `-m slow` แล้ว Test ที่สะกดผิดจะหายไปเงียบ ๆ เราจึงควรเปิด `--strict-markers` ในโปรเจกต์จริง

<Callout type="try" title="ลองทำใน Repo นี้">
ลองรัน `uv run pytest exercises/05_markers/test_markers.py -m "not slow" -rs` แล้วอ่านรายการ SKIPPED จากนั้นลบ `strict=True` ออกจาก `test_strict_xfail_that_now_passes` ใน `demos/05_markers/test_marker_problems.py` แล้วรัน `uv run pytest demos/05_markers` เพื่อดูว่าสถานะของ Test นี้เปลี่ยนเป็นอะไร (แก้กลับเมื่อเสร็จนะ)
</Callout>

</Step>

<Step>

## เช็กตัวเอง

- ฟีเจอร์ที่ยังไม่เสร็จ ควรใช้ `skip` หรือ `xfail` เมื่อไหร่ และต่างกันอย่างไรในรายงาน
- ทำไม Bug ที่รู้แล้วควรใช้ `xfail(strict=True)`
- ถ้าลืมลงทะเบียน `slow` แล้วรัน `-m "not slow"` จะเกิดอะไรกับ Test ที่แปะ `slwo`

</Step>
