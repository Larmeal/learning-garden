## Assert ธรรมดา แต่ได้ข้อมูลมากกว่าที่คิด

ใน[บท 1](/pytest/first-test/#อ่าน-traceback-ตอน-test-ล้ม) เราเห็นว่าเมื่อ `assert cart.total() == 31` ล้ม Pytest จะพิมพ์ `assert 30 == 31` ให้ ทั้งที่เราไม่ได้เขียน Message เอาไว้เลย นั่นเป็นเพราะ Pytest เปลี่ยนโค้ด `assert` ใน Test ไฟล์ **ก่อน** รัน (Assertion Rewriting) เพื่อเก็บค่าของนิพจน์ย่อยไว้แสดง เราจึงใช้ `assert` เปล่า ๆ ได้เลย โดยไม่ต้องจำ `assertEqual`, `assertIn`, `assertAlmostEqual` ของ Unittest

แต่มีสามเรื่องที่ `==` เปล่า ๆ เอาไม่อยู่ คือทศนิยม, Exception และ Warning ซึ่งเราจะดูกันก่อน แล้วค่อยมาดูวิธีอ่าน Diff

</Step>

## ทศนิยมต้องใช้ Approx

```python
def test_float_sums_need_approx():
    assert 0.1 + 0.2 != 0.3
    assert 0.1 + 0.2 == pytest.approx(0.3)
```

`0.1 + 0.2` ใน Float ไม่เท่ากับ `0.3` พอดี (รัน: `exercises/02_assertions/test_assertions.py`) `pytest.approx` จะเทียบโดยยอมให้มีความคลาดเคลื่อนได้ ค่าเริ่มต้นคือ Relative 1e-6 ซึ่งเราจะเห็นในผลตอนที่ Test ล้ม

```text
E       assert 0.5 == 0.3 ± 3.0e-07
E         Obtained: 0.5
E         Expected: 0.3 ± 3.0e-07
```

เรากำหนดความคลาดเคลื่อนเองได้ และใช้กับ List หรือ Dict ได้ด้วย (รัน: `exercises/02_assertions/test_assertions.py`)

```python
assert 100.04 == pytest.approx(100, abs=0.05)    # ห่างได้ไม่เกิน 0.05
assert 100.04 != pytest.approx(100, abs=0.01)
assert 100.04 == pytest.approx(100, rel=1e-3)    # ห่างได้ไม่เกิน 0.1% ของ 100
assert [0.1 + 0.2, 1.1 + 2.2] == pytest.approx([0.3, 3.3])
assert {"a": 0.1 + 0.2} == pytest.approx({"a": 0.3})
```

ถ้าเป็นเรื่องเงิน ควรใช้ `Decimal` หรือเก็บเป็นสตางค์ (จำนวนเต็ม) ตั้งแต่แรกนะ เพราะ `approx` แค่ช่วยตอนทดสอบผลคำนวณ Float ที่หลีกเลี่ยงไม่ได้ มันไม่ได้ทำให้ Float ปลอดภัยสำหรับเงินขึ้นมา (ผู้เขียน)

</Step>

## เช็กว่าโค้ดโยน Exception ด้วย Raises

Test ที่ดีต้องเช็กทั้งทางที่สำเร็จและทางที่ล้มด้วย ซึ่งทางที่ล้มเราใช้ `pytest.raises` ที่เป็น Context Manager

```python
def test_raises_checks_the_type():
    with pytest.raises(ValueError):
        Cart().add("apple", price=10, qty=0)

def test_raises_with_match_checks_the_message():
    with pytest.raises(ValueError, match=r"qty must be positive, got -1"):
        Cart().add("apple", price=10, qty=-1)
```

| สิ่งที่ต้องการ | ใช้ | ผล (รัน: `exercises/02_assertions/test_assertions.py`) |
|---|---|---|
| เช็กชนิดของ Exception | `pytest.raises(ValueError)` | ผ่านเมื่อโยน `ValueError` หรือ Subclass |
| เช็กข้อความ | `match="positive"` | เป็น Regular Expression ที่ **ค้นหา** ในข้อความ ขอแค่ตรงกับส่วนหนึ่งของข้อความก็พอ ไม่ต้องตรงทั้งหมด |
| อ่านค่าใน Exception | `with pytest.raises(E) as info:` แล้วใช้ `info.value`, `info.type` | เช็กได้ทั้งข้อความและ Attribute |
| ตัวแม่ก็จับได้ | `pytest.raises(LookupError)` | `KeyError` เป็น `LookupError` จึงผ่าน |

มีสองจุดที่พลาดกันบ่อย

1. จุดแรกคือโค้ดไม่ได้โยน ถ้าโค้ดไม่โยน Exception ที่เราคาดไว้ Test จะล้มด้วยข้อความ `Failed: DID NOT RAISE ValueError` (รัน: `demos/02_assertions`) ซึ่งก็ถูกต้องแล้ว เพราะ Test บอกว่ารับประกันว่าจะโยน
2. จุดที่สองคือบรรทัดในบล็อก บรรทัดหลังบรรทัดที่โยนในบล็อกเดียวกันจะไม่ถูกรัน ส่วนบรรทัดก่อนหน้ามีผลจริง ในแบบฝึก `add("apple")` สำเร็จก่อนบรรทัดที่โยน จึงยังเหลือ `qty("apple") == 1` หลังบล็อก (รัน: `exercises/02_assertions/test_assertions.py`) เพราะฉะนั้นเราควรใส่ในบล็อกเฉพาะบรรทัดที่คาดว่าจะโยนเท่านั้น

</Step>

## Warnings

โค้ดเก่าที่ถูกเลิกใช้มักโยน `DeprecationWarning` ออกมา ซึ่งเราใช้ `pytest.warns` เช็กได้

```python
def test_warns_catches_a_deprecation():
    with pytest.warns(DeprecationWarning, match="old_total"):
        assert old_total([1, 2, 3]) == 6
```

ในทางกลับกัน ถ้าอยากให้โค้ดใหม่ **ไม่มี** Warning เลย เราสามารถใช้ `warnings.simplefilter("error")` ให้ Warning กลายเป็น Exception ใน Test นั้นได้ (รัน: `exercises/02_assertions/test_assertions.py` ตัว `test_no_warning_for_the_new_code`) วิธีนี้ช่วยจับการเรียก API ที่กำลังจะเลิกใช้ ก่อนที่มันจะพังจริง

</Step>

## อ่าน Diff

เมื่อเราเทียบ Dict, List หรือ String ที่ใหญ่ Pytest จะแสดงเฉพาะส่วนที่ต่างกัน (รัน: `demos/02_assertions`)

```text
E       AssertionError: assert {'sku': 'appl..., 'price': 10} == {'sku': 'appl...note': 'gift'}
E         Omitting 2 identical items, use -vv to show
E         Differing items:
E         {'qty': 3} != {'qty': 2}
E         Right contains 1 more item:
E         {'note': 'gift'}
```

เราอ่านได้ทันทีว่า `qty` ต่างกัน (3 กับ 2) และฝั่งขวามี Key `note` เพิ่มมา ส่วน `-vv` ใช้ขยายข้อความที่ถูกย่อ

ถ้า String ต่างกันแค่ตัวเดียว Pytest จะชี้ตำแหน่งด้วย `^`

```text
E         - total: 31 THB
E         ?         ^
E         + total: 30 THB
E         ?         ^
```

ถ้าสิ่งที่เทียบไม่สนลำดับ เช่น รายการ SKU ให้แปลงเป็น `set` ก่อนเทียบ แต่ถ้าลำดับเป็นส่วนหนึ่งของสัญญา (เช่น `skus()` คืนตามตัวอักษร) ก็เทียบ List ตรง ๆ ได้เลย (รัน: `exercises/02_assertions/test_assertions.py`)

</Step>

## เมื่อไรควรเขียน Message เอง

Pytest บอก **ค่า** ให้เราอยู่แล้ว Message ที่เขียนเองจึงมีประโยชน์เมื่อมันอธิบาย **เหตุผล** ที่ค่าสองฝั่งควรเท่ากัน

```python
assert cart.qty("apple") == 1, "one apple was added, so qty must be 1"
```

ถ้า Message แค่พูดซ้ำกับค่า เช่น `"total is wrong"` ก็ไม่ต้องเขียน และถ้า Test หนึ่งตัวมี Assert หลายบรรทัด ลองดูว่า Message ช่วยแยกได้ไหมว่าบรรทัดไหนล้มจริง (ผู้เขียน)

<Callout type="try" title="ลองทำใน Repo นี้">
ลองเปิด `demos/02_assertions/test_diffs.py` แล้วรัน `uv run pytest demos/02_assertions` อ่านทั้งห้าผลที่ล้มดู จากนั้นลองแก้ `test_raises_not_raised` ให้ผ่าน (คำใบ้: `int("42")` ไม่โยนอะไร ควรเรียกอะไรแทน)
</Callout>

## เช็กตัวเอง

- ทำไม `assert price * qty == 0.3` จึงไม่ควรใช้เปล่า ๆ เมื่อ Price เป็น 0.1 และ Qty เป็น 3 และควรเขียนใหม่อย่างไร
- `with pytest.raises(ValueError, match="positive")` ผ่านเมื่อข้อความคือ `qty must be positive, got 0` ได้ไหม ทำไม
- ถ้าใส่โค้ดสิบบรรทัดในบล็อก `raises` ปัญหาคืออะไร

</Step>
