## ใช้ข้อมูลใน `excinfo`

`with pytest.raises(E) as info` ให้ Object `ExceptionInfo` ที่มีข้อมูลมากกว่า `.value` และ `.type` (รัน: `exercises/02_assertions/test_assertions_in_depth.py`)

```python
with pytest.raises(ValueError) as info:
    Cart().add("apple", price=-1)
assert info.type is ValueError
assert str(info.value) == "price must not be negative, got -1"
assert info.traceback[-1].name == "add"      # frame สุดท้ายของ traceback คือฟังก์ชันที่โยน
assert info.match("negative")                # เช็ก regex ทีหลังได้
```

ถ้าข้อความอย่างเดียวไม่พอ เช่น Exception มี Attribute ของตัวเอง เราสามารถใช้อาร์กิวเมนต์ `check=` ส่งฟังก์ชันที่คืน `True` เมื่อ Exception ถูกต้องเข้าไปได้

```python
with pytest.raises(CartError, check=lambda e: e.sku == "kiwi"):
    boom()
```

ถ้า `check` คืน `False` Test จะล้ม แม้ชนิดของ Exception จะตรงก็ตาม (รัน)

</Step>

## Exception Group

Python 3.11 เพิ่ม `ExceptionGroup` สำหรับกรณีที่มีหลายความผิดพร้อมกัน เช่น งานที่รันคู่ขนาน ถ้าใช้ `pytest.raises` ธรรมดาจะตรวจได้แค่ว่าเป็น Group แต่ไม่ได้ดูข้างใน เมื่อต้องตรวจสมาชิกจึงต้องใช้ `RaisesGroup` กับ `RaisesExc` (Source: `_pytest/raises.py`)

```python
def collect_errors():
    raise ExceptionGroup("several", [ValueError("a"), ValueError("b"), KeyError("k")])

with pytest.RaisesGroup(ValueError, ValueError, KeyError):
    collect_errors()

with pytest.RaisesGroup(
    pytest.RaisesExc(ValueError, match="a"),
    pytest.RaisesExc(ValueError, match="b"),
    pytest.RaisesExc(KeyError),
):
    collect_errors()
```

สิ่งที่เรารันยืนยันแล้วมีดังนี้ (รัน)

- `RaisesGroup` เข้มงวดเรื่องสมาชิกที่เกินมา ถ้า Group มี `ValueError` กับ `KeyError` แต่เราประกาศไว้แค่ `ValueError` Test จะล้ม
- ถ้า Group ซ้อนอยู่ใน Group ต้องใส่ `flatten_subgroups=True` ถึงจะตรวจสมาชิกข้ามชั้นได้
- ถ้าใช้ `pytest.raises(ExceptionGroup) as info` ธรรมดา เราสามารถใช้ `info.group_contains(KeyError)` และ `info.group_contains(ValueError, match="b")` ถามว่ามีสมาชิกชนิดนั้นหรือไม่ ซึ่ง `group_contains(TypeError)` จะได้ `False`

</Step>

## Warning หลายตัว

`pytest.warns(...) as record` จะเก็บทุก Warning ที่เกิดในบล็อกไว้เป็นรายการ (รัน)

```python
with pytest.warns(UserWarning) as record:
    warnings.warn("first", UserWarning)
    warnings.warn("second", UserWarning)
assert [str(w.message) for w in record] == ["first", "second"]
assert record[0].category is UserWarning
```

`pytest.deprecated_call()` เป็นทางลัดที่รับทั้ง `DeprecationWarning` และ `PendingDeprecationWarning` และถ้า `pytest.warns` ไม่เจอ Warning ในบล็อก Test จะล้ม

</Step>

## สั่งผลจากโค้ด: `fail`, `skip`, `xfail`, `importorskip`

บางครั้งเราก็รู้เงื่อนไขตอนรันเท่านั้น ตอนเขียนยังไม่รู้ Pytest จึงมีฟังก์ชันที่จบ Test ด้วยผลที่เรากำหนด (Source: `_pytest/outcomes.py`) ซึ่งแต่ละตัวจะโยน Exception พิเศษ Test จึงจบที่บรรทัดนั้น (รัน)

| ฟังก์ชัน | ผล |
|---|---|
| `pytest.fail("stop here", pytrace=False)` | ล้ม พร้อมข้อความ `stop here` และไม่มี Traceback |
| `pytest.skip("reason")` | Skipped (เทียบกับ Marker ที่บท [Marker](/pytest/markers/#skip-และ-skipif-ไม่รัน)) |
| `pytest.xfail("known")` | Xfailed ทันที บรรทัดหลังจากนั้นไม่รัน |
| `pytest.importorskip("module")` | คืน Module ที่ Import ได้ หรือ Skip ทั้ง Test ถ้า Import ไม่ได้ |

`importorskip` เหมาะกับ Test ที่ใช้ไลบรารีเสริม เช่น `np = pytest.importorskip("numpy")` ถ้าไม่ได้ติดตั้ง Test จะถูก Skip แทนที่จะล้ม ผลที่ได้ในแบบฝึกคือ `importorskip("json")` คืน Module ที่ใช้งานได้ ส่วนชื่อที่ไม่มีจริงจะได้ skipped=1

</Step>

## ซ่อน Frame ของ Helper ด้วย __tracebackhide__

ฟังก์ชันช่วยที่เช็กเงื่อนไขแทน Test ทำให้ Traceback ชี้ที่บรรทัดใน Helper แทนที่จะชี้ที่ Test ซึ่งเรียกมัน ถ้าใส่ `__tracebackhide__ = True` ในฟังก์ชันนั้น Pytest ก็จะซ่อน Frame นี้ให้

```python
def assert_total(cart_total, want):
    __tracebackhide__ = True
    assert cart_total == want, "total differs"

def test_x():
    assert_total(1, 2)
```

ถ้ารัน `--tb=short` เราจะเห็นบรรทัด `assert_total(1, 2)` ใน Test แต่ไม่เห็น `assert cart_total == want` ใน Helper (รัน) และเมื่อสงสัยว่าซ่อนอะไรไป ก็ใช้ `--full-trace` เพื่อดูทุก Frame ได้

อย่าลืมเรื่องจากบท [Assertion Rewriting](/pytest/assertion-rewriting/#วิธีแก้เมื่อ-helper-ไม่มีรายละเอียด) ด้วยนะ Helper ที่อยู่ในไฟล์อื่นจะไม่มีรายละเอียดของ `assert` ถ้าไม่ได้ลงทะเบียน และการซ่อน Frame ก็ไม่ได้ทำหน้าที่แทนการลงทะเบียน

</Step>

## มุมแปลกของ `approx`

(รัน: `exercises/02_assertions/test_assertions_in_depth.py`)

- ค่าเริ่มต้นของความคลาดเคลื่อนคือ Relative 1e-6 บวกค่าต่ำสุดแบบ Absolute 1e-12 ยกตัวอย่าง `1_000_000.5 == approx(1_000_000)` ผ่านเพราะ 1e-6 ของหนึ่งล้านคือ 1 ส่วน `1_000_001.5` ไม่ผ่าน และเมื่อค่าใกล้ศูนย์ ค่า Relative จะเล็กมาก จึงใช้ค่า Absolute แทน เช่น `1e-13 == approx(0)` ผ่าน แต่ `1e-11` ไม่ผ่าน
- `nan` จะไม่เท่ากับตัวเองเสมอ เว้นแต่จะใส่ `nan_ok=True`
- `Decimal` ก็ใช้ได้ เช่น `Decimal("0.30") == approx(Decimal("0.3"))` และกำหนด `abs=Decimal("0.02")` ได้ด้วย
- Dict จะผ่อนปรนให้เฉพาะค่า ส่วน Key ต้องตรงกัน เช่น `{"a": 1.0} != approx({"b": 1.0})` เพราะ Key ไม่ตรง
