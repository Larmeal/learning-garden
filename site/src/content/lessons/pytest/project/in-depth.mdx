## ไฟล์ Config ไหนชนะ

pytest ใช้ไฟล์ config ไฟล์เดียว ไม่รวมหลายไฟล์ ถ้ามีหลายชนิดในโฟลเดอร์เดียว ลำดับคือ `pytest.ini`, `pyproject.toml` (ที่มี `[tool.pytest]`), `tox.ini` แล้ว `setup.cfg` (ใน `setup.cfg` ใช้หัวข้อ `[tool:pytest]`) พิสูจน์ด้วยโปรเจกต์ที่มีครบสี่ไฟล์ แต่ละไฟล์ตั้ง `minversion` ต่างกัน แล้วลบไฟล์ที่ชนะทีละไฟล์ (รัน: `internals/09_config_layout.py`)

| ไฟล์ที่เหลืออยู่ | ไฟล์ที่ pytest ใช้ | `minversion` ที่เห็น |
|---|---|---|
| ครบสี่ไฟล์ | `pytest.ini` | 1.0 |
| ไม่มี `pytest.ini` | `pyproject.toml` | 2.0 |
| ไม่มี `pyproject.toml` | `tox.ini` | 3.0 |
| เหลือ `setup.cfg` | `setup.cfg` | 4.0 |

กรณีพิเศษสองข้อที่ยืนยันแล้ว

- `pyproject.toml` ที่ **ไม่มี** ตาราง `[tool.pytest]` (หรือ `[tool.pytest.ini_options]`) ถูกข้าม และ `tox.ini` ชนะแทน
- `pytest.ini` ที่ **ว่างเปล่า** ก็ยังชนะ `tox.ini` ที่มี `[pytest]` เพราะการมีไฟล์นี้คือการประกาศว่านี่คือ root ของโปรเจกต์

แบบฝึกของเส้นทางนี้ใช้ `[tool.pytest.ini_options]` ใน `pyproject.toml` ซึ่งใช้ได้เช่นกัน

</Step>

## Rootdir

**rootdir** คือโฟลเดอร์ที่ pytest ถือเป็นราก ใช้เป็นฐานของ node id, ที่เก็บ `.pytest_cache` และขอบเขตของการหา `conftest.py` pytest หาไฟล์ config โดยไล่ขึ้นจากโฟลเดอร์ของ argument ที่ให้ และ rootdir คือโฟลเดอร์ที่มีไฟล์นั้น

ในแบบฝึกวาง `pytest.ini` ไว้ที่ราก และ test ไว้ใน `sub/` แล้วรัน pytest จาก `sub/` ผลคือยังใช้ `pytest.ini` ของราก และ rootdir เป็นโฟลเดอร์ราก ไม่ใช่ `sub` (รัน) หัวรายงานของ pytest พิมพ์ `rootdir:` และ `configfile:` ให้ดูทุกครั้ง

ถ้าไม่มีไฟล์ config เลย `inipath` เป็น `None` (รัน) และ rootdir มาจากบรรทัดคำสั่ง จึงควรมีไฟล์ config อย่างน้อยไฟล์ว่าง เพื่อให้ rootdir ไม่ขึ้นกับว่ารันจากที่ไหน

</Step>

## ลำดับ: ไฟล์ แล้ว PYTEST_ADDOPTS แล้วบรรทัดคำสั่ง

| ชั้น | ตัวอย่าง | ผลที่ยืนยัน |
|---|---|---|
| `addopts` ในไฟล์ | `addopts = -v` | ผลรันมี `PASSED` |
| `PYTEST_ADDOPTS` | `PYTEST_ADDOPTS=-v` (environment) | ผลรันมี `PASSED` แม้ไฟล์ไม่มี `addopts` |
| `-o key=value` บนบรรทัดคำสั่ง | `-o minversion=9.0` | ชนะค่าในไฟล์ `minversion` เป็น `9.0` |

(รัน: `internals/09_config_layout.py`) `-o` ใช้ทดลองค่าโดยไม่แก้ไฟล์ และเหมาะกับ CI ที่อยากทับค่าชั่วคราว

</Step>

## Key ที่พิมพ์ผิดใน Config

key ที่ pytest ไม่รู้จักใน config ไม่ใช่ error แต่เป็น warning ที่เห็นได้ง่ายว่าพลาด (รัน)

```text
PytestConfigWarning: Unknown config option: no_such_key
```

test ยังรัน exit code ยังเป็น 0 ซึ่งเป็นปัญหา: พิมพ์ `testpath` แทน `testpaths` แล้วการตั้งค่าไม่มีผลโดยไม่มีใครแดง ใส่ `--strict-config` เพื่อให้ key ที่ไม่รู้จักทำให้ pytest จบด้วย exit code ไม่ใช่ศูนย์ (รัน) แนะนำให้ตั้งไว้ใน `addopts` คู่กับ `--strict-markers` ([บท 5](/pytest/markers/#ลงทะเบียน-marker-กันพิมพ์ผิด))

</Step>

## Import Mode: ชื่อไฟล์ซ้ำ

pytest ต้อง import ไฟล์ test เป็น module โหมดเริ่มต้นคือ `prepend` ซึ่งใส่โฟลเดอร์ของไฟล์ไว้หน้า `sys.path` แล้ว import ด้วยชื่อไฟล์ ถ้ามีสองไฟล์ชื่อ `test_same.py` ในโฟลเดอร์ `a/` กับ `b/` ที่ไม่มี `__init__.py` ชื่อ module ชนกัน (รัน)

| วิธี | ผล |
|---|---|
| ค่าเริ่มต้น (`prepend`) | ล้ม เกิด `import file mismatch` (exit code ไม่ใช่ 0) |
| ใส่ `__init__.py` ในทั้ง `a/` และ `b/` | ผ่าน 2 test |
| `--import-mode=importlib` | ผ่าน 2 test โดยไม่ต้องมี `__init__.py` |

`importlib` ไม่แตะ `sys.path` จึงไม่ชนกัน แต่ test ที่ import ไฟล์ test อีกไฟล์โดยตรง (เช่น helper ที่วางข้างกัน) อาจ import ไม่ได้ เพราะโฟลเดอร์ไม่อยู่ใน `sys.path` ในโหมดนี้ ทางเลือกสำหรับโปรเจกต์ใหม่คือวางโค้ดไว้ใน package (เช่น `src/`) และตั้ง `pythonpath` ([บท 7](/pytest/project/#ตั้งค่าครั้งเดียว-ใน-pyprojecttoml)) แล้วตั้งชื่อไฟล์ test ไม่ให้ซ้ำ

</Step>

## conftest.py ซ้อนกัน

`conftest.py` มีผลกับโฟลเดอร์ของมันและโฟลเดอร์ลูก ตัวที่ใกล้ test กว่าทับตัวที่ไกลกว่า แบบฝึกมี fixture `where` ใน `conftest.py` ราก (คืน `'root'`) และใน `sub/conftest.py` (คืน `'sub'`) (รัน)

```text
test_top.py          : where == 'root'
sub/test_deep.py     : where == 'sub'
other/test_other.py  : where == 'root'     (โฟลเดอร์ที่ไม่มี conftest ของตัวเองใช้ตัวราก)
```

3 test ผ่านทั้งหมด `conftest.py` ถูกโหลดเป็น plugin ที่ผูกกับโฟลเดอร์ ([บท 14](/pytest/plugins/#ลงทะเบียนอย่างไร)) และไม่ต้อง import ที่ไหน ข้อควรระวังคือ conftest ที่ซ้อนกันหลายชั้นทำให้ยากรู้ว่า fixture มาจากตัวไหน `pytest --fixtures-per-test` หรือ `--setup-show` ช่วยบอก

<Callout type="try" title="ลองทำใน repo นี้">
รัน `uv run python internals/09_config_layout.py` แล้วเพิ่มกรณีใหม่ในสคริปต์: ตั้ง `testpaths` ใน `pytest.ini` แล้วรัน pytest จากโฟลเดอร์ที่ไม่ใช่ราก ดูว่า pytest เลือก test อะไรบ้าง
</Callout>

## ที่มาของหน้านี้

| ข้อความ | ที่มา |
|---|---|
| ลำดับ `pytest.ini` > `pyproject.toml` > `tox.ini` > `setup.cfg`, `pyproject.toml` ที่ไม่มีตารางถูกข้าม, `pytest.ini` ว่างชนะ | รัน: `internals/09_config_layout.py` |
| รันจากโฟลเดอร์ย่อยแล้วใช้ไฟล์ของราก, ไม่มีไฟล์ config แล้ว `inipath` เป็น `None` | รัน: เหมือนข้างบน |
| `addopts`, `PYTEST_ADDOPTS`, `-o`, key ที่ไม่รู้จัก, `--strict-config` | รัน: เหมือนข้างบน |
| import mode: `prepend` ชนกัน, `__init__.py`, `importlib`, การซ้อน `conftest.py` | รัน: เหมือนข้างบน |
| ข้อจำกัดของ `importlib` เมื่อ import ไฟล์ test อื่น, คำแนะนำให้มีไฟล์ config และ `--strict-config`, rootdir เป็นฐานของ `.pytest_cache` และ conftest, เหตุผลที่ `pytest.ini` ว่างยังชนะ | ผู้เขียน |

</Step>
