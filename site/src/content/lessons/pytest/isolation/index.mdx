## Test ที่พึ่งโลกภายนอกจะเชื่อไม่ได้

`rates.convert(100, "USD")` แปลงเงินบาทเป็นดอลลาร์ โดยจะถามอัตราแลกเปลี่ยนผ่านเครือข่าย ถ้า Test เรียกของจริง ผลที่ได้ก็จะขึ้นอยู่กับอินเทอร์เน็ต เซิร์ฟเวอร์ปลายทาง และอัตราของวันนี้ ซึ่งทำให้ Test ช้า ล้มแบบสุ่ม และให้ตัวเลขไม่เหมือนเดิม

ในแบบฝึก `shop/net.py` จะโยน `ConnectionError` เสมอ เพื่อให้ Test ที่ลืมแทนของจริงล้มดัง ๆ แทนที่จะเรียกออกไปจริง (รัน: `exercises/06_isolation/test_isolation.py`)

```python
def test_without_a_replacement_the_network_call_fails():
    with pytest.raises(ConnectionError, match="no network"):
        rates.convert(100, "USD")
```

ในบทนี้เราจะลองแทนของสามอย่างที่ทำให้ผลเปลี่ยนไปโดยเราควบคุมไม่ได้ คือ **เครือข่าย**, **สภาพแวดล้อม (Environment Variable)** และ **เวลา** และจะดูวิธีอ่านสิ่งที่โค้ดส่งออกทาง Print และ Log ด้วย

</Step>

## Monkeypatch: แทนชั่วคราว คืนให้เองหลังจบ

`monkeypatch` เป็น Fixture ที่ Pytest ให้มา ทุกอย่างที่เราแก้ผ่านมันจะถูกคืนค่าเดิมเมื่อ Test จบ เราจึงไม่ต้องเก็บกวาดเอง

```python
def test_monkeypatch_replaces_the_function_used_by_convert(monkeypatch):
    monkeypatch.setattr(rates, "fetch_rate", lambda currency: 0.03)
    assert rates.convert(100, "USD") == 3.0

def test_monkeypatch_setenv_sets_the_default_currency(monkeypatch):
    monkeypatch.setenv("SHOP_CURRENCY", "USD")
    monkeypatch.setattr(rates, "fetch_rate", lambda currency: 0.5)
    assert rates.convert(100) == 50.0
```

Test ถัดไปจึงไม่เห็นการแก้ไขนั้น แบบฝึกยืนยันไว้ว่า `SHOP_CURRENCY` ไม่อยู่ใน Environment หลังจาก Test ก่อนหน้าจบ (รัน: `exercises/06_isolation/test_isolation.py`) เมธอดที่ใช้บ่อยมี `setattr`, `setenv`, `delenv`, `setitem` และ `chdir`

</Step>

## unittest.mock และกฎข้อสำคัญ: Patch ที่ที่ชื่อถูกใช้

`unittest.mock` มากับ Python และใช้แทนของพร้อมบันทึกการเรียกได้ ปัญหาที่เจอบ่อยที่สุดคือ Patch ผิดที่ ลองดูตัวอย่างที่ `rates.py` เขียนว่า

```python
from shop.net import fetch_json
```

คำสั่งนี้ทำให้ `rates` มีชื่อ `fetch_json` เป็นของตัวเอง ซึ่งชี้ไปที่ฟังก์ชันตัวเดียวกับใน `net` แต่เป็นคนละชื่อกัน ดังนั้นถ้า Patch ที่ `net` แล้ว `rates` ก็ยังเรียกตัวเดิมอยู่ (รัน: `exercises/06_isolation/test_isolation.py`)

```python
def test_patching_the_wrong_place_does_nothing():
    with mock.patch.object(net, "fetch_json", return_value={"rate": 0.03}):
        with pytest.raises(ConnectionError):      # ยังเรียกของจริงอยู่
            rates.convert(100, "USD")

def test_patching_where_the_name_is_used_works():
    with mock.patch.object(rates, "fetch_json", return_value={"rate": 0.03}) as fake:
        assert rates.convert(100, "USD") == 3.0
    fake.assert_called_once()
    (url,), _ = fake.call_args
    assert url.endswith("to=USD")
```

กฎที่ต้องจำคือให้ Patch ที่โมดูลที่ **ใช้** ชื่อนั้น แทนที่จะ Patch ที่โมดูลซึ่งนิยามมัน นอกจากนี้เรายังดู `fake.call_args` ได้ว่าถูกเรียกด้วยอะไร ซึ่งเป็นหลักฐานว่าโค้ดของเราถามอัตราของสกุลเงินที่ถูกต้อง

</Step>

## Fake ที่ส่งเข้าไปเอง มักง่ายกว่า Patch

`checkout(cart, gateway, order_id)` รับ Gateway เป็น Parameter ดังนั้น Test จึงส่งของปลอมเข้าไปได้เลย โดยไม่ต้อง Patch อะไร

```python
class FakeGateway:
    def __init__(self, accept: bool):
        self.accept = accept
        self.charges = []

    def charge(self, amount, order_id):
        self.charges.append((amount, order_id))
        return self.accept

def test_a_declined_payment_keeps_the_cart():
    cart = Cart()
    cart.add("apple", price=100)
    with pytest.raises(PaymentDeclined):
        checkout(cart, FakeGateway(accept=False), "A-2")
    assert cart.qty("apple") == 1
```

`FakeGateway` มี Logic จริงอยู่เล็กน้อย (บันทึกการเรียกและตอบตามที่ตั้งไว้) ส่วน `mock.Mock()` เป็นวัตถุที่ยอมรับทุกการเรียกแล้วจำไว้

```python
gateway = mock.Mock()
gateway.charge.return_value = True
checkout(cart, gateway, "A-3")
gateway.charge.assert_called_once_with(100, "A-3")
```

ทั้งสองแบบผ่านในแบบฝึก (รัน: `exercises/06_isolation/test_isolation.py`) แล้วเราควรเลือกแบบไหน ถ้าต้องการเช็ก **ผลลัพธ์** ของโค้ดของเรา Fake จะอ่านง่ายกว่า แต่ถ้าอยากเช็กแค่ว่ามีการเรียกด้วย Argument ที่ถูกต้อง Mock จะสั้นกว่า (ผู้เขียน) และการออกแบบให้รับ Dependency เป็น Parameter ก็ทำให้ทดสอบง่ายโดยไม่ต้อง Patch

</Step>

## เวลา

`is_sale_day(today=None)` ใช้วันที่ที่ส่งเข้าไป และจะใช้วันนี้ก็ต่อเมื่อไม่ได้ส่งมา Test จึงไม่ต้องไปยุ่งกับนาฬิกา (รัน: `exercises/06_isolation/test_isolation.py`)

```python
def test_an_argument_beats_patching_the_clock():
    assert is_sale_day(dt.date(2026, 11, 11))
    assert is_sale_day(dt.date(2026, 11, 13))      # วันศุกร์ที่ 13
    assert not is_sale_day(dt.date(2026, 11, 12))
```

ส่วน `greeting_now()` ฝังนาฬิกาไว้ในตัวเอง Test จึงต้องแทน `datetime` ด้วยคลาสที่คืนเวลาที่เรากำหนด

```python
class FakeNow(dt.datetime):
    @classmethod
    def now(cls, tz=None):
        return cls(2026, 11, 11, 8, 0)

monkeypatch.setattr("shop.sale.dt.datetime", FakeNow)
assert greeting_now() == "good morning"
```

วิธีนี้ทำได้ แต่ยุ่งกว่ามาก และเป็นสัญญาณเตือนว่าโค้ดควรรับเวลาเป็น Parameter ตั้งแต่ต้น เพราะเวลาเป็นหนึ่งในต้นเหตุหลักของ Test ที่ล้มแบบสุ่ม (ผู้เขียน)

</Step>

## อ่านสิ่งที่โค้ดพิมพ์และ Log

ฟังก์ชันที่ไม่คืนค่าแต่ Print หรือ Log นั้นทดสอบได้ด้วย `capsys` และ `caplog` (รัน: `exercises/06_isolation/test_isolation.py`)

```python
def test_capsys_reads_what_was_printed(capsys):
    cart = Cart()
    cart.add("apple", price=10, qty=2)
    print_receipt(cart)
    out = capsys.readouterr().out
    assert out.splitlines() == ["apple x2", "TOTAL 20.00"]

def test_caplog_reads_what_was_logged(caplog):
    cart = Cart()
    cart.add("tv", price=2000)
    with caplog.at_level(logging.WARNING, logger="shop.receipt"):
        print_receipt(cart)
    assert [r.levelname for r in caplog.records] == ["WARNING"]
    assert "large order" in caplog.text
```

<Callout type="warn" title="อย่า Mock จนไม่เหลืออะไรให้ทดสอบ">
ถ้า Test แทนทุกอย่างรอบฟังก์ชัน แล้วเช็กแค่ว่า Mock ถูกเรียก Test นั้นก็พิสูจน์ได้แค่ว่าโค้ดเรียกตามที่เขียนไว้ แต่ไม่ได้พิสูจน์ว่าระบบทำงานถูก เราควรแทนเฉพาะ **ขอบ** ของระบบ (เครือข่าย เวลา ดิสก์ ผู้ให้บริการภายนอก) แล้วปล่อยให้โค้ดของเราเองทำงานจริง (ผู้เขียน)
</Callout>

<Callout type="try" title="ลองทำใน Repo นี้">
ลองเปลี่ยน `rates` เป็น `net` ใน `mock.patch.object` ของ `test_patching_where_the_name_is_used_works` แล้วรัน เพื่อดูว่ามันล้มด้วยอะไร จากนั้นค่อยเปลี่ยนกลับ
</Callout>

## เช็กตัวเอง

- ทำไม `mock.patch.object(net, "fetch_json", ...)` ไม่ช่วยเมื่อ `rates` ใช้ `from shop.net import fetch_json`
- อะไรทำให้ `is_sale_day(today)` ทดสอบง่ายกว่า `greeting_now()`
- Fake กับ Mock ต่างกันอย่างไร และคุณเลือกอะไรสำหรับ Test ที่เช็กว่า "ปฏิเสธการจ่ายแล้วตะกร้ายังอยู่"

</Step>
