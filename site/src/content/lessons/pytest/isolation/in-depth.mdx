## Mock ธรรมดารับทุกอย่าง แม้พิมพ์ผิด

`mock.Mock()` สร้าง Attribute และ Method ให้เองทุกชื่อที่เราเรียก ผลก็คือ Test ที่เรียกชื่อผิดก็ยังผ่านได้ (รัน: `exercises/06_isolation/test_mocking_in_depth.py`)

```python
gateway = mock.Mock()
gateway.chargee(100, "A-1")      # พิมพ์ผิดจาก charge และไม่มีอะไรฟ้อง
gateway.chargee.assert_called_once()
```

Test นี้ผ่าน แต่ไม่ได้พิสูจน์อะไรเกี่ยวกับ Gateway จริงเลย เราป้องกันเรื่องนี้ได้สองระดับ

| วิธี | ผล |
|---|---|
| `mock.Mock(spec=["charge"])` | ถ้าเรียกชื่ออื่นจะเกิด `AttributeError` แต่ไม่ตรวจ Argument |
| `mock.create_autospec(RealGateway, instance=True)` | ตรวจทั้งชื่อ **และ Signature** ตามคลาสจริง |

เมื่อใช้ Autospec การเรียก `gateway.charge(1)` (ที่ขาด `order_id`) จะเกิด `TypeError` ตามที่ Signature ของ `RealGateway.charge(amount, order_id)` กำหนด (รัน) และถ้าเรียกถูก ก็ใช้กับ `checkout(...)` ได้ตามปกติ ข้อดีคือ Mock จะพังตามเมื่อคลาสจริงเปลี่ยน Signature ซึ่งเป็นสิ่งที่เราอยากให้เกิดอยู่แล้ว

</Step>

## side_effect: ตอบต่างกันแต่ละครั้ง

`return_value` ให้คำตอบเดียวเสมอ แต่ `side_effect` ทำได้สามแบบ (รัน)

```python
fake = mock.Mock(side_effect=[0.03, 0.04])                  # รายการ: ค่าหนึ่งต่อการเรียก
assert (fake(), fake()) == (0.03, 0.04)                      # เรียกครั้งที่สามเกิด StopIteration

fake = mock.Mock(side_effect=ConnectionError("down"))       # exception: โยนทุกครั้ง
fake = mock.Mock(side_effect=lambda c: {"USD": 0.03, "EUR": 0.025}[c])   # ฟังก์ชัน: คำนวณคำตอบ
```

รูปแบบที่มีประโยชน์มากอีกแบบคือ **ล้มก่อนแล้วฟื้น** ซึ่งทำได้โดยใช้ List ที่ผสม Exception กับค่าเข้าด้วยกัน

```python
fake = mock.Mock(side_effect=[ConnectionError("blip"), {"rate": 0.03}])
with pytest.raises(ConnectionError):
    fake()
assert fake() == {"rate": 0.03}
assert fake.call_count == 2
```

แบบนี้ใช้ทดสอบโค้ดที่ Retry ได้ เพราะครั้งแรกเครือข่ายสะดุด ครั้งที่สองผ่าน และ `call_count` ก็ยืนยันว่าเรียกสองครั้งพอดี

</Step>

## อ่านการเรียก

Mock จำทุกการเรียก (รัน)

```python
fake = mock.Mock(return_value=True)
fake(1, "a", flag=True)
fake(2, "b")
assert fake.call_args == mock.call(2, "b")                  # การเรียกล่าสุด
assert fake.call_args_list == [mock.call(1, "a", flag=True), mock.call(2, "b")]
fake.assert_any_call(1, "a", flag=True)                     # มีการเรียกแบบนี้ที่ไหนสักที่
fake.assert_called_with(2, "b")                             # การเรียกล่าสุดต้องเป็นแบบนี้
```

จำได้ง่าย ๆ ว่า `assert_called_with` ดูแค่ครั้งล่าสุด ส่วน `assert_any_call` ดูทุกครั้ง และ `call_args_list` จะให้ทั้งรายการมาเพื่อเช็กลำดับ

</Step>

## `patch.dict` และ `patch` แบบ Decorator

`mock.patch.dict(os.environ, {...})` ตั้งค่าใน Dict ชั่วคราวแล้วคืนค่าให้ตอนออกจากบล็อก (รัน: `SHOP_MODE` ไม่อยู่ใน `os.environ` หลังบล็อก) ซึ่งต่างจาก `monkeypatch.setenv` ที่ผูกกับอายุของ Test

`mock.patch.object(...)` ใช้เป็น Decorator ได้ด้วย โดย Mock จะถูกส่งเข้ามาเป็น Argument **ตัวแรก** ของ Test

```python
@mock.patch.object(rates, "fetch_rate", return_value=0.5)
def test_patch_as_a_decorator_passes_the_mock_as_an_argument(fake):
    assert rates.convert(10, "USD") == 5.0
    fake.assert_called_once_with("USD")
```

มีข้อควรระวังเมื่อใช้ร่วมกับ Fixture คือ Argument จาก Decorator จะมาก่อน Fixture ในลำดับ Parameter

</Step>

## ส่วนที่เหลือของ `monkeypatch`

(รัน)

| เมธอด | ทำอะไร |
|---|---|
| `delenv("X")` | ลบตัวแปร ถ้าไม่มีเกิด `KeyError` ยกเว้น `raising=False` |
| `setitem(d, k, v)` | ตั้งค่าใน Dict ชั่วคราว |
| `chdir(path)` | เปลี่ยนโฟลเดอร์ทำงาน (ใช้คู่กับ `tmp_path`) |
| `syspath_prepend(path)` | เพิ่มโฟลเดอร์ใน `sys.path` ทำให้ Import Module ใหม่ได้ |
| `setattr("shop.rates.fetch_rate", fn)` | ระบุเป้าเป็นสตริงได้ |
| `setattr(rates, "no_such_attribute", 1)` | ค่าเริ่มต้น `raising=True` เกิด `AttributeError` กันพิมพ์ชื่อผิด |
| `pytest.MonkeyPatch.context()` | ใช้นอก Test: คืนค่าเมื่อออกจากบล็อก ไม่ต้องรอ Test จบ |

ตัวสุดท้ายมีประโยชน์ใน Fixture ที่ Scope ใหญ่กว่า Function (ซึ่งใช้ Fixture `monkeypatch` ไม่ได้) และใช้ได้เมื่อเราต้องการยกเลิกการแทนกลางทางใน Test

</Step>

## กันเครือข่ายจริงในทุก Test

เราตั้ง Fixture `autouse` ที่แทนจุดเรียกเครือข่ายด้วยตัวที่ล้มดัง ๆ ได้ เพื่อไม่ให้ Test ที่ลืมแทนแอบเรียกของจริง

```python
@pytest.fixture(autouse=True)
def no_real_network(monkeypatch):
    def refuse(url):
        raise AssertionError(f"a test tried to reach the network: {url}")
    monkeypatch.setattr(net, "fetch_json", refuse)
```

ในแบบฝึกยืนยันไว้สองอย่าง (รัน) อย่างแรก ถ้า `rates` Import ชื่อมาเองด้วย `from shop.net import fetch_json` การแทนที่ `net` จะไม่ไปถึง `rates.fetch_json` ซึ่งยังเป็นตัวเดิมที่โยน `ConnectionError` นี่คือกฎ "Patch ที่ที่ชื่อถูกใช้" จาก[บทแยก Test](/pytest/isolation/#unittestmock-และกฎข้อสำคัญ-patch-ที่ที่ชื่อถูกใช้) อย่างที่สอง เมื่อ Patch ถูกที่ (`monkeypatch.setattr(rates, "fetch_json", net.fetch_json)` ซึ่ง `net.fetch_json` ตอนนั้นคือตัว Guard) Test จะล้มด้วยข้อความ `a test tried to reach the network`

สิ่งที่ได้เรียนรู้คือ Guard ที่ Patch แค่ที่นิยามนั้นไม่พอ เราต้องครอบทุกจุดที่ชื่อถูกใช้ หรือไม่ก็ออกแบบให้ส่ง Dependency เข้ามาเป็น Parameter แทน (บท [แยก Test](/pytest/isolation/#fake-ที่ส่งเข้าไปเอง-มักง่ายกว่า-patch))

<Callout type="try" title="ลองทำใน Repo นี้">
ลองแก้ Fixture `no_real_network` ใน `test_mocking_in_depth.py` ให้ `monkeypatch.setattr(net, "fetch_json", refuse)` Patch `rates` แทน `net` แล้วดูว่า Test ที่ชื่อ `test_the_guard_turns_a_forgotten_replacement_into_a_clear_failure` ให้ผลเปลี่ยนไปอย่างไร จากนั้นลองเขียน Test ใหม่ที่ใช้ `side_effect` แบบ "ล้มก่อนแล้วฟื้น" กับ `rates.fetch_json` เพื่อดูว่า `convert` ที่ไม่มี Retry จะล้มทันที
</Callout>
