## Plugin คือไฟล์ที่มี Hook

จากสี่บทที่แล้ว เราได้รู้ว่า Pytest ประกอบขึ้นจาก Plugin และ Hook ทั้งหมด การเขียนของตัวเองจึงไม่ต้องใช้เครื่องมือพิเศษอะไร เพราะ Plugin ก็คือ Module หรือ Object ที่มีฟังก์ชันชื่อ `pytest_...` และถูกลงทะเบียนกับ Plugin Manager

แบบฝึกของเราคือ `plugins/shop_plugin.py` (76 บรรทัด) ซึ่งทำหกอย่างพร้อมกัน

| อยากได้ | Hook หรือกลไก |
|---|---|
| Option ใหม่ `--run-slow` และค่า Ini `shop_slow_limit` | `pytest_addoption` |
| Marker `slow` ที่ลงทะเบียนเอง | `pytest_configure` |
| ข้าม Test ที่แปะ `slow` เว้นแต่ใส่ `--run-slow` | `pytest_collection_modifyitems` |
| วัดเวลาแต่ละ Test และเติมลงใน Report | ตัวครอบ `pytest_runtest_makereport` |
| ส่วนสรุปท้ายรายงาน "Slow Tests" | `pytest_terminal_summary` |
| ข้อความ `Cart == Cart` ที่อ่านง่าย | `pytest_assertrepr_compare` |
| Fixture `cart_factory` | `@pytest.fixture` ในไฟล์ Plugin เอง |

</Step>

## ลงมือทีละ Hook

**Option และ Config** (Source: `pytest_addoption` ใน `hookspec.py`)

```python
def pytest_addoption(parser):
    group = parser.getgroup("shop")
    group.addoption("--run-slow", action="store_true", default=False, help="also run the tests marked slow")
    parser.addini("shop_slow_limit", "seconds after which a test is listed in the slow section", default="0.05")
```

`addoption` ใช้ Argparse ส่วน `addini` ลงทะเบียนค่าที่ตั้งได้ใน `pytest.ini` หรือ `pyproject.toml` และเราอ่านค่าด้วย `config.getini("shop_slow_limit")` และ `config.getoption("--run-slow")`

ต่อมาคือ **Marker** ซึ่งเราลงทะเบียนใน `pytest_configure` ด้วย `config.addinivalue_line("markers", "slow: ...")` เหตุผลคือจะได้ผ่าน `--strict-markers` (บท [Marker](/pytest/markers/#ลงทะเบียน-marker-กันพิมพ์ผิด)) แบบฝึกยืนยันว่าเมื่อรัน `--strict-markers` กับ Plugin นี้แล้วผ่าน (รัน: `exercises/09_plugins`)

ส่วนการ **เลือก Test** ทำใน `pytest_collection_modifyitems(config, items)` ซึ่งถูกเรียกหลัง Collection ตามที่เห็นในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/#ลำดับ-hook-จริงสำหรับ-test-สองตัว) Test ที่มี `slow` ใน `item.keywords` จะได้ Marker `skip`

```python
skip = pytest.mark.skip(reason="need --run-slow to run")
for item in items:
    if "slow" in item.keywords:
        item.add_marker(skip)
```

ผลที่ได้คือถ้าไม่มี `--run-slow` สอง Test จะผ่านและหนึ่ง Test ถูก Skipped พร้อมเหตุผล แต่เมื่อใส่ `--run-slow` ก็ผ่านทั้งสาม (รัน: `exercises/09_plugins`)

</Step>

## ตัวครอบ: ทำงานก่อนและหลัง Hook ตัวอื่น

Hook แบบ Wrapper ใช้ `@pytest.hookimpl(wrapper=True)` และ `yield` หนึ่งครั้ง โค้ดส่วนก่อน `yield` จะรันก่อน Implementation อื่น ส่วนหลัง `yield` จะรันหลังสุด และได้ผลลัพธ์ของทุกตัวที่รันไปแล้ว

```python
@pytest.hookimpl(wrapper=True)
def pytest_runtest_makereport(item, call):
    report = yield            # implementation อื่นสร้าง TestReport เสร็จแล้ว
    if report.when == "call":
        item.config.stash[TIMINGS].append((item.nodeid, call.duration))
        report.user_properties.append(("duration_ms", round(call.duration * 1000)))
    return report             # ต้องคืนค่า ไม่เช่นนั้นผลหาย
```

นี่คือรูปแบบเดียวกับที่ Plugin `skipping` ใช้เปลี่ยน Outcome ของ Xfail ([บท 12](/pytest/run-protocol/#skip-และ-xfail-เป็น-hook-ไม่ใช่เวทมนตร์)) แบบฝึกตรวจว่า Report ของ Test ได้ Property `duration_ms` (รัน: `exercises/09_plugins`)

ถ้าต้องการที่เก็บข้อมูลระหว่าง Hook ให้ใช้ `config.stash` กับ `StashKey` (`pytest.StashKey`) ซึ่งมีชนิดกำกับและไม่ชนกับ Attribute ของคนอื่น ดีกว่าตัวแปร Global หรือการแปะ Attribute บน `config`

ส่วน **ลำดับการเรียก** เราพิสูจน์ได้ด้วยสคริปต์ที่ลงทะเบียนสอง Plugin (รัน: `internals/14_hook_order_control.py`)

| สถานการณ์ | ลำดับที่เรียก |
|---|---|
| `one` ลงทะเบียนก่อน `two` | `two`, `one` (ตัวที่ลงทะเบียนทีหลังถูกเรียกก่อน) |
| `one` เป็น `tryfirst=True` | `one`, `two` |
| `one` เป็น `trylast=True` | `two`, `one` |
| มีตัวครอบคั่นกลาง | `wrapper before`, `two`, `one`, `wrapper after` |

Hook แบบ `firstresult` จะหยุดที่ตัวแรกที่คืนค่าไม่ใช่ `None` ในแบบฝึก Plugin ที่คืน `True` จาก `pytest_ignore_collect` สำหรับ `test_a.py` ทำให้ไม่มี Test เหลือเลย ผลที่ได้คือ `no tests ran` และ Exit Code 5

</Step>

## ส่วนสรุปและข้อความ Assert

`pytest_terminal_summary(terminalreporter, config)` ให้เราพิมพ์ส่วนของตัวเองท้ายรายงานได้ (ถูกเรียกหลัง `sessionfinish` ตามที่เห็นในบท [Pytest ทำงานอย่างไร](/pytest/how-pytest-runs/#ลำดับ-hook-จริงสำหรับ-test-สองตัว))

```python
def pytest_terminal_summary(terminalreporter, config):
    limit = float(config.getini("shop_slow_limit"))
    slow = sorted(((n, d) for n, d in config.stash[TIMINGS] if d > limit), key=lambda x: -x[1])
    if not slow:
        return
    terminalreporter.section("slow tests")
    for nodeid, duration in slow:
        terminalreporter.line(f"{duration * 1000:7.0f} ms  {nodeid}")
```

Test ที่หลับ 0.08 วินาทีจะขึ้นในส่วน `slow tests` ส่วน Test ที่เร็วจะไม่ขึ้น และถ้าตั้ง `shop_slow_limit = 5` ใน Ini ส่วนนี้ก็จะหายไป (รัน: `exercises/09_plugins`)

ส่วน `pytest_assertrepr_compare(op, left, right)` ซึ่งถูกเรียกจากโค้ดที่ถูกเขียนใหม่ ([บท 13](/pytest/assertion-rewriting/#โค้ดที่ถูกเขียนใหม่หน้าตาอย่างไร)) เปิดให้เราคืน List ของบรรทัดสำหรับชนิดของเราเองได้ ในแบบฝึก `Cart == Cart` ที่ไม่เท่ากันจะแสดงดังนี้ (รัน: `exercises/09_plugins`)

```text
E       AssertionError: assert Cart == Cart
E           skus : ['apple', 'pear'] != ['apple', 'kiwi']
E           total: 30 != 15
E           qty of kiwi: 0 != 1
E           qty of pear: 1 != 0
```

ซึ่งดีกว่า `<shop.cart.Cart object at 0x...> == <shop.cart.Cart object at 0x...>` ที่ไม่บอกอะไรเราเลย (ต้องมี `Cart.__eq__` ด้วย ซึ่งเพิ่มไว้ในแบบฝึกแล้ว)

</Step>

## ลงทะเบียนอย่างไร

Plugin ถูกโหลดได้หกทาง (Source: `consider_*`, `import_plugin` ใน `config/__init__.py`)

| ทาง | ใช้เมื่อ | ยืนยัน |
|---|---|---|
| `-p shop_plugin` | ลองหรือใช้ครั้งเดียว Module ต้องหาเจอใน `sys.path` | รัน: `exercises/09_plugins`, `internals/07_entry_point.py` |
| `conftest.py` | ใช้กับโฟลเดอร์หนึ่ง (และลูก) | บท [Fixture](/pytest/fixtures/#conftestpy-ใช้ร่วมกันโดยไม่ต้อง-import) |
| `pytest_plugins = ["shop_plugin"]` ใน Conftest ชั้นบนสุด | ใช้กับทั้งโปรเจกต์โดยไม่ต้องพิมพ์ `-p` | แบบฝึกใช้ `pytest_plugins = ["pytester"]` ใน `conftest.py` ราก |
| Entry Point กลุ่ม `pytest11` ของ Package ที่ลงด้วย Pip | แจกจ่ายให้คนอื่น: ลงแล้วโหลดเอง | รัน: `internals/07_entry_point.py` |
| `PYTEST_PLUGINS=shop_plugin` | ตั้งผ่าน Environment | Source: `consider_env` |
| `pytest.main([...], plugins=[obj])` | ฝัง Pytest ในโปรแกรม ส่ง Object เข้าไปตรง ๆ | รัน: `internals/02_hook_order.py` |

ทางที่สี่เราทดลองได้โดยไม่ต้อง `pip install` เพียงสร้าง Folder ที่มี `shop_plugin-0.1.dist-info/entry_points.txt` เขียนว่า `[pytest11]` / `shop = shop_plugin` แล้วใส่ Folder นั้นใน `PYTHONPATH` (รัน: `internals/07_entry_point.py`)

- ไม่ต้องใส่ `-p` Pytest ก็โหลดให้เอง และ `--trace-config` จะแสดง `PLUGIN registered: <module 'shop_plugin' ...>`
- ถ้าตั้ง `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` Pytest จะไม่อ่าน Entry Point เลย ทำให้ Fixture `cart_factory` หายไป (`fixture 'cart_factory' not found`)
- ถ้าใช้ `-p no:shop` จะปิดเฉพาะตัวนี้ โดยใช้ชื่อ Entry Point (`shop` ไม่ใช่ `shop_plugin`)
- ถ้าตั้ง Autoload ปิดแล้วใส่ `-p shop_plugin` Plugin ก็กลับมาทำงานได้

ข้อสุดท้ายนี้สำคัญกับทีมที่ปิด Autoload เพื่อให้ผลทำซ้ำได้ เพราะ Plugin ที่ต้องการให้ทำงานต้องระบุเองให้ชัดเจน

</Step>

## ทดสอบ Plugin ด้วย `pytester`

Plugin ที่ไม่มี Test ก็เหมือนโค้ดอื่นที่ไม่มี Test คือยังไว้ใจไม่ได้ `pytester` เป็น Plugin ในตัว (อยู่ใน `builtin_plugins` แต่ไม่ได้โหลดโดยค่าเริ่มต้น) เราเปิดด้วย `pytest_plugins = ["pytester"]` ใน `conftest.py` ชั้นบนสุด (Source: `config/__init__.py`) แล้วมันจะให้ Fixture `pytester` ที่สร้างโฟลเดอร์ชั่วคราว เขียนไฟล์ แล้วรัน Pytest ให้ โดย `runpytest` จะรันในโปรเซสเดียวกันเป็นค่าเริ่มต้น (Source: `Pytester.runpytest` เลือกวิธีตาม `--runpytest`)

```python
def test_slow_tests_are_skipped_by_default(pytester):
    pytester.makepyfile(TESTS)
    result = pytester.runpytest("-p", "shop_plugin", "-rs")
    result.assert_outcomes(passed=2, skipped=1)
    result.stdout.fnmatch_lines(["*need --run-slow to run*"])
```

เครื่องมือที่ใช้บ่อยในแบบฝึกมีดังนี้ (รัน: `exercises/09_plugins` ทั้งโฟลเดอร์ 9 Test ผ่าน)

| ต้องการ | ใช้ |
|---|---|
| สร้างไฟล์ Test, Ini, Conftest | `makepyfile`, `makeini`, `makeconftest` |
| รัน Pytest แล้วได้ผล | `runpytest(...)` คืน `RunResult` |
| เช็กจำนวน Passed, Failed ฯลฯ | `result.assert_outcomes(passed=2, skipped=1)` |
| เช็กข้อความที่พิมพ์ | `result.stdout.fnmatch_lines([...])` (Glob ทีละบรรทัดตามลำดับ) |
| ดักรายงานเป็นข้อมูล | `inline_run(..., plugins=[obj])` แล้วอ่านจาก Hook |

<Callout type="try" title="ลองทำใน Repo นี้">
ลองเพิ่ม Option `--slow-only` ใน `plugins/shop_plugin.py` ที่ทำตรงข้ามกับ `--run-slow` คือข้าม Test ที่ **ไม่** มี Marker `slow` โดยเขียน Test ใน `exercises/09_plugins/test_shop_plugin.py` ก่อนด้วย `pytester` แล้วค่อยเขียนโค้ดให้ผ่าน จากนั้นลองรัน `internals/14_hook_order_control.py` โดยเปลี่ยนตัวที่เป็น `tryfirst` แล้วดูผล
</Callout>

## เช็กตัวเอง

- Plugin A ลงทะเบียนก่อน Plugin B ทั้งคู่ Implement `pytest_sessionstart` ตัวไหนถูกเรียกก่อน และจะให้ A ก่อนต้องทำอะไร
- ทำไมตัวครอบของ `pytest_runtest_makereport` ต้อง `return report`
- ทีมปิด `PYTEST_DISABLE_PLUGIN_AUTOLOAD` ใน CI Plugin ที่ลงด้วย Pip จะยังทำงานไหม และแก้อย่างไร
