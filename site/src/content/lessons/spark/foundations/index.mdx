## เริ่มจากอะไรได้บ้าง

Spark ไม่ต้องใช้พื้นฐานเยอะ ถ้าคุณเขียน SQL ได้ (`select`, `where`, `group by`, `join`) และอ่านโค้ด Python รู้เรื่อง ก็ข้ามไปบทถัดไปได้เลย แต่ยังมีอีกสองเรื่องที่ควรทำความรู้จักไว้ก่อน คือรูปแบบของไฟล์ข้อมูล กับคำว่า Partition และ Serialization ซึ่งเราจะเจอไปตลอดเส้นทางนี้

<Callout type="tip" title="ถ้าเคยใช้ Pandas">
ถ้าคุณมาจาก Pandas จะเรียนได้เร็วเลย มีแค่สองอย่างที่ต้องปรับตัว อย่างแรกคือข้อมูลไม่ได้อยู่ในหน่วยความจำของคอมพิวเตอร์เครื่องเดียวอีกแล้ว อย่างที่สองคือคำสั่งส่วนใหญ่จะไม่รันทันที ซึ่งอย่างหลังนี้อธิบายไว้ใน[บทที่ 2](/spark/lazy-evaluation/#สองประเภทของคำสั่ง)
</Callout>

## ไฟล์ข้อมูล: CSV กับ Parquet

สองรูปแบบนี้ต่างกันที่วิธีวางข้อมูลบน Disk ซึ่งส่งผลโดยตรงต่อปริมาณข้อมูลที่ Spark ต้องอ่าน

- CSV เป็นข้อความธรรมดาที่เก็บข้อมูลแถวละบรรทัด ไม่มีชนิดข้อมูลอยู่ในไฟล์ ทุกอย่างจึงเป็นข้อความไปหมดจนกว่าจะมีคนมาเดาชนิดให้ ส่วน JSON ก็เป็นข้อความเหมือนกันและเก็บทีละระเบียน แต่สามารถซ้อนโครงสร้างได้
- Parquet เก็บข้อมูลทีละคอลัมน์ โดยมีชนิดข้อมูลเก็บอยู่ในไฟล์ด้วย และบีบอัดต่อคอลัมน์ได้ดี

## ทำไมงานจริงเลือก Parquet

Parquet อ่านเฉพาะคอลัมน์ที่ Query ใช้ (เรียกว่า Column Pruning) ไม่ต้องเดาชนิดข้อมูล และไฟล์มักเล็กกว่า CSV ที่มีข้อมูลเท่ากัน งานจริงจึงมักเก็บเป็น Parquet ส่วน CSV จะเหมาะกับข้อมูลก้อนเล็ก หรือข้อมูลที่รับมาจากระบบอื่น

ยิ่งตารางกว้าง ความต่างก็ยิ่งมาก ลองนึกถึงตารางที่มี 200 คอลัมน์ แต่ Query ใช้แค่ 3 คอลัมน์ Parquet จะอ่านประมาณ 3 ใน 200 ส่วน แต่ CSV ต้องอ่านทุกบรรทัดจนครบ

สำหรับตัวเลขจริงที่วัดได้ ตารางขนาด 600,000 แถว 9 คอลัมน์ เมื่อเขียนเป็น CSV จะมีขนาด 71.7 MiB และเมื่อเขียนเป็น Parquet จะมีขนาด 48.9 MiB พอเรารวมค่าของคอลัมน์เดียว (`sum(amount)`) CSV ต้องอ่าน **73.3 MiB** (ทั้งไฟล์) แต่ Parquet อ่านเพียง **0.10 MiB** ส่วนรายละเอียดและวิธีวัดอยู่ใน [Data I/O แบบเจาะลึก](/spark/data-io/in-depth/)

</Step>

## Partition และ Serialization

Partition คือก้อนของข้อมูลที่ Spark ส่งให้ Task หนึ่งตัวประมวลผล ข้อมูลชุดหนึ่งจะแบ่งเป็นหลาย Partition และ Partition ต่างก้อนกันก็รันพร้อมกันได้ ยกตัวอย่างจากคอมพิวเตอร์ที่ใช้ทดสอบ `spark.range(1_000_000)` แตกเป็น 16 Partition (เห็นเป็น `splits=16` ในผล `explain()` ของ[บทที่ 5](/spark/execution-model/#ดูมันทำงานทีละขั้น)) ซึ่งตรงกับจำนวน Core ของคอมพิวเตอร์เครื่องนั้น

Serialization คือการแปลงข้อมูลในหน่วยความจำให้เป็นไบต์ เพื่อส่งข้ามคอมพิวเตอร์หรือเขียนลง Disk แล้วค่อยแปลงกลับตอนอ่าน ข้อมูลที่ต้องย้ายระหว่างคอมพิวเตอร์จึงมีต้นทุนส่วนนี้เสมอ และเป็นเหตุผลหนึ่งที่ทำให้ Shuffle แพง ([บทที่ 5](/spark/execution-model/#ทำไม-shuffle-ถึงแพง))

</Step>
