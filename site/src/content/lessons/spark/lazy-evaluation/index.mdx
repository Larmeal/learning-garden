## สองประเภทของคำสั่ง

| ประเภท | ตัวอย่าง | สิ่งที่เกิดขึ้น |
|---|---|---|
| transformation | `filter`, `select`, `withColumn`, `groupBy().agg()`, `join` | คืน DataFrame ใหม่ที่จำแผนไว้ ยังไม่ประมวลผลข้อมูล |
| action | `show`, `count`, `collect`, `write` | ลงมือทำงานจริงทั้งแผน |

DataFrame เปลี่ยนค่าไม่ได้ ทุก transformation จึงคืน DataFrame ตัวใหม่ที่จำคำสั่งของตัวเก่าไว้ สายของคำสั่งที่ต่อกันอยู่นี้เรียกว่า lineage

</Step>

<Step>

## ลองจดแผนเอง

<LazyLab client:visible />

Spark ทำแบบนี้เพราะพอเห็นแผนทั้งก้อนก่อนรัน มันเลือกวิธีรันที่ถูกกว่าได้ เช่น ข้ามคอลัมน์ที่ไม่มีใครใช้ (บทที่ 6)

</Step>

<Step>

## action ซ้ำคือคำนวณซ้ำ

Spark ไม่เก็บผลของ action ที่ผ่านมา เรียก `count()` สองครั้งบน DataFrame เดียวกัน จะอ่านไฟล์และประมวลผลสองรอบ ถ้าต้องใช้ผลกลางทางซ้ำ ให้ `cache()` ไว้ รอบถัดไปจะไม่อ่านไฟล์ใหม่ วิธีเลือกว่าควร cache ตรงไหนอยู่ในบทที่ 7

<Callout type="tip" title="cache() เองก็ lazy">
การเรียก `cache()` ไม่ได้เก็บข้อมูลทันที ข้อมูลถูกเก็บตอนที่ action แรกรันผ่านจุดนั้น ดังนั้น action แรกยังช้าเท่าเดิม ประโยชน์เริ่มตั้งแต่ action ที่สอง
</Callout>

</Step>

<Step>

## error โผล่ตอนไหน

กลไกเดียวกันนี้ทำให้ error สองแบบโผล่ไม่พร้อมกัน

<ErrorTiming client:visible />

ชื่อคอลัมน์ผิดถูกจับทันทีที่เขียนคำสั่ง เพราะตรวจกับ schema ได้โดยไม่ต้องแตะข้อมูล ส่วนค่าผิดรูปในข้อมูลจะรู้ก็ต่อเมื่อ action อ่านถึงแถวนั้น ผลคือบางครั้ง error ปรากฏที่ `show()` บรรทัดเดียว แต่ต้นเหตุอยู่ในคำสั่งที่เขียนไว้หลายบรรทัดก่อนหน้า

<Callout type="note" title="เรื่อง cast ที่ error">
การที่ `cast("int")` กับ `abc` โยน error มาจากโหมด ANSI ซึ่งเป็นค่าเริ่มต้นของ Spark 4 ถ้าปิดโหมดนี้ ผลที่ได้จะเป็น NULL แทน
</Callout>

</Step>

## ลองในเครื่อง

<Callout type="try" title="เห็น error ที่โผล่ช้า">

```python
from pyspark.sql import functions as F
from spark_session import get_spark

spark = get_spark("lazy")
bad = spark.createDataFrame([("1",), ("abc",)], "x string")

step = bad.select(F.col("x").cast("int").alias("n"))   # ไม่ error
print("นิยามแล้ว ยังไม่ error")
step.show()                                            # error ตรงนี้
```

อีกการทดลอง เปิด http://localhost:4040 ระหว่างที่ session ยังอยู่ แล้วเรียก `count()` ซ้ำหลายครั้ง จะเห็นรายการ job ในแท็บ Jobs เพิ่มขึ้นทุกครั้งที่เรียก action

</Callout>
