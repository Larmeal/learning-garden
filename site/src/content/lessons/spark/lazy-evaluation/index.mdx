## สองประเภทของคำสั่ง

| ประเภท | ตัวอย่าง | สิ่งที่เกิดขึ้น |
|---|---|---|
| Transformation | `filter`, `select`, `withColumn`, `groupBy().agg()`, `join` | คืน DataFrame ใหม่ที่จำแผนไว้ แต่ยังไม่ประมวลผลข้อมูล |
| Action | `show`, `count`, `collect`, `write` | ลงมือทำงานจริงตามแผนทั้งหมด |

DataFrame เปลี่ยนค่าไม่ได้ ดังนั้นทุก Transformation จึงคืน DataFrame ตัวใหม่ที่จำคำสั่งของตัวเก่าไว้ด้วย สายของคำสั่งที่ต่อกันอยู่แบบนี้เรียกว่า Lineage

</Step>

## ลองจดแผนเอง

<LazyLab client:visible />

## Action ซ้ำคือคำนวณซ้ำ

Spark ไม่เก็บผลของ Action ที่ผ่านมาไว้ ถ้าเราเรียก `count()` สองครั้งบน DataFrame เดียวกัน Spark จะอ่านไฟล์และประมวลผลสองรอบ แต่ถ้าต้องใช้ผลกลางทางซ้ำ เราสามารถ `cache()` ไว้ได้ แล้วรอบถัดไปจะไม่ต้องอ่านไฟล์ใหม่ สำหรับวิธีเลือกว่าควร Cache ตรงไหน อยู่ใน[บทที่ 7](/spark/performance-tuning/#cache-ช่วยเมื่อไร)

<Callout type="tip" title="cache() เองก็ Lazy">
การเรียก `cache()` ไม่ได้เก็บข้อมูลทันที ข้อมูลจะถูกเก็บตอนที่ Action แรกรันผ่านจุดนั้น ดังนั้น Action แรกจึงยังช้าเท่าเดิม ประโยชน์จะเริ่มตั้งแต่ Action ที่สองเป็นต้นไป
</Callout>

</Step>

## Error โผล่ตอนไหน

กลไกเดียวกันนี้ทำให้ Error สองแบบโผล่ขึ้นมาไม่พร้อมกัน

<ErrorTiming client:visible />

ชื่อคอลัมน์ที่ผิดจะถูกจับได้ทันทีที่เขียนคำสั่ง เพราะ Spark ตรวจกับ Schema ได้โดยไม่ต้องแตะข้อมูล แต่ค่าผิดรูปที่อยู่ในข้อมูลจะรู้ก็ต่อเมื่อ Action อ่านไปถึงแถวนั้น เพราะฉะนั้นบางครั้ง Error จึงปรากฏที่ `show()` บรรทัดเดียว ทั้งที่ต้นเหตุอยู่ในคำสั่งที่เขียนไว้หลายบรรทัดก่อนหน้า

<Callout type="note" title="เรื่อง Cast ที่ Error">
ที่ `cast("int")` กับ `abc` โยน Error ออกมา เป็นเพราะโหมด ANSI ซึ่งเป็นค่าเริ่มต้นของ Spark 4 ถ้าปิดโหมดนี้ ผลที่ได้จะเป็น NULL แทน
</Callout>

</Step>

## ลองในเครื่อง

<Callout type="try" title="เห็น Error ที่โผล่ช้า">

```python
from pyspark.sql import functions as F
from spark_session import get_spark

spark = get_spark("lazy")
bad = spark.createDataFrame([("1",), ("abc",)], "x string")

step = bad.select(F.col("x").cast("int").alias("n"))   # ไม่ error
print("นิยามแล้ว ยังไม่ error")
step.show()                                            # error ตรงนี้
```

ยังมีอีกการทดลองหนึ่ง ให้เปิด http://localhost:4040 ระหว่างที่ Session ยังอยู่ แล้วลองเรียก `count()` ซ้ำหลายครั้ง เราจะเห็นรายการ Job ในแท็บ Jobs เพิ่มขึ้นทุกครั้งที่เรียก Action

</Callout>
