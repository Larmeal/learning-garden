## ใครทำอะไร

แอปพลิเคชัน Spark มีสามบทบาท driver ที่ถือโปรแกรมของคุณและวางแผน executor ที่ลงมือคำนวณ และ cluster manager ที่จัดสรรเครื่องให้

<ArchitectureLab client:visible />

โค้ด PySpark ของคุณรันใน Python process แล้วคุยกับ JVM ของ Spark ผ่าน Py4J การคำนวณหนักเกิดใน JVM ฝั่ง executor ยกเว้น Python UDF ที่ต้องเรียก Python process เพิ่ม (บทที่ 8)

</Step>

<Step>

## เครื่องคุณรันแบบไหน

`get_spark()` ใน `spark_session.py` สร้าง session แบบ `local[*]` driver และ executor อยู่ใน process เดียว และ executor คือ thread จำนวนเท่า core ของเครื่อง

<Callout type="try" title="ลองดูในเครื่อง">

```python
from spark_session import get_spark

spark = get_spark("arch")
sc = spark.sparkContext
print(sc.master, sc.defaultParallelism, spark.version)
```

บนเครื่องที่ใช้ทดสอบบทนี้ ได้ `local[*] 16 4.2.0` เลข 16 คือจำนวน core ของเครื่องนั้น เครื่องคุณอาจได้เลขอื่น

</Callout>

เพราะเหตุนี้ การเรียนแนวคิดแบบกระจายบนเครื่องเดียวจึงทำได้ task หลายตัวรันพร้อมกันจริง แต่ไม่มีเครือข่ายคั่นกลาง ใน cluster จริง ต้นทุนการส่งข้อมูลข้ามเครื่องจะสูงกว่าที่เห็นที่นี่

</Step>

<Step>

## SparkSession

`SparkSession` เป็นจุดเข้าใช้งานเดียวสำหรับอ่านข้อมูล สร้าง DataFrame และรัน SQL สร้างด้วย `SparkSession.builder...getOrCreate()` ถ้ามี session อยู่แล้วจะได้ตัวเดิมกลับมา ใน notebook หรือ Databricks มักมีตัวแปร `spark` ให้ใช้เลย

</Step>

<Step>

## ข้อมูลมาถึง driver เมื่อไร

โดยปกติข้อมูลอยู่ที่ executor และไม่ผ่าน driver คำสั่งที่ดึงข้อมูลมาที่ driver มีไม่กี่ตัว

- `show()` ดึง 20 แถวแรกมาพิมพ์
- `collect()` และ `toPandas()` ดึงผลทั้งหมด
- `write` ให้ executor เขียนไฟล์เอง ไม่ผ่าน driver

<Callout type="warn" title="ระวัง collect() กับข้อมูลใหญ่">
ผลของ `collect()` และ `toPandas()` ต้องไปอยู่ในหน่วยความจำของ driver ตัวเดียว ถ้าผลใหญ่กว่าหน่วยความจำที่ driver มี โปรแกรมจะล้ม ให้กรองหรือรวมข้อมูลให้เล็กลงก่อนเรียกสองคำสั่งนี้
</Callout>

</Step>
