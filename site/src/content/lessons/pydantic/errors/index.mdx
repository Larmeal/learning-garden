## หนึ่ง Exception ที่พกทุกปัญหา

ลองส่งข้อมูลที่ผิดสี่จุดในโครงสร้างซ้อนกันสามชั้น (รัน: `exercises/06_errors.py`)

```python
class Item(BaseModel):
    sku: str
    qty: int

class Order(BaseModel):
    id: int
    items: list[Item]
    meta: dict[str, int] = {}

bad = {"id": "x",
       "items": [{"sku": "A", "qty": 1}, {"sku": 5, "qty": "y"}],
       "meta": {"k": "v"}}
Order.model_validate(bad)
```

`ValidationError` ที่ได้ถือสี่ error `e.error_count()` ได้ 4 และ `e.title` เป็น `"Order"` และเพราะ `ValidationError` เป็น subclass ของ `ValueError` ตัว `except ValueError` ของโค้ดเก่าจะจับมันได้ด้วย

`e.errors()` คืน list ของ dict หนึ่งตัวต่อหนึ่งปัญหา

```python
{'type': 'int_parsing',
 'loc': ('id',),
 'msg': 'Input should be a valid integer, unable to parse string as an integer',
 'input': 'x',
 'url': 'https://errors.pydantic.dev/2.13/v/int_parsing'}
```

| key | ความหมาย |
|---|---|
| `type` | รหัสของปัญหา เสถียรกว่าข้อความ ใช้ในโค้ดที่ต้องตัดสินใจตามชนิดของปัญหา |
| `loc` | ตำแหน่งใน input เป็น tuple ของ key และดัชนี |
| `msg` | ข้อความสำหรับคนอ่าน |
| `input` | ค่าที่ทำให้ล้ม |
| `ctx` | ข้อมูลประกอบ (ถ้ามี) เช่น `{'gt': 0}` |
| `url` | ลิงก์ไปหน้าเอกสารของ error ชนิดนั้น |

</Step>

## Loc: ตามรอยลงไปในโครงสร้างซ้อน

สี่ error ของตัวอย่างข้างบนมี `loc` ดังนี้

```python
[('id',), ('items', 1, 'sku'), ('items', 1, 'qty'), ('meta', 'k')]
```

อ่านว่า field `id`, สมาชิกตัวที่ 1 (นับจาก 0) ของ `items` ที่ field `sku`, ตัวเดียวกันที่ `qty`, และ key `k` ของ `meta` loc ใน `list` ใช้ดัชนีเป็นตัวเลข ใน `dict` ใช้ key เป็นข้อความ ในการแสดงผลแบบข้อความจะเขียนต่อกันด้วยจุด เช่น `items.1.sku`

ถ้า input มาเป็น JSON ผ่าน `model_validate_json` ตำแหน่งก็รายงานแบบเดียวกัน `'{"id": 1, "items": [{"sku": "A"}]}'` ได้ `loc == ("items", 0, "qty")` ชนิด `missing`

ถ้า JSON ผิดไวยากรณ์ ก็เป็น `ValidationError` เหมือนกัน ชนิด `json_invalid` โดย `loc` ว่างและข้อความบอกตำแหน่งในข้อความ เช่น `Invalid JSON: EOF while parsing a list at line 1 column 20` ผู้เรียกจึงไม่ต้องจับ `json.JSONDecodeError` แยกต่างหาก

</Step>

## errors(), json() และ str() ใช้ต่างกัน

| เมธอด | คืน | ใช้เมื่อ |
|---|---|---|
| `str(e)` | ข้อความหลายบรรทัดอ่านง่าย | แสดงให้คน เช่นใน log หรือ traceback |
| `e.errors()` | `list[dict]` | โค้ดที่ต้องประมวลผลต่อ เช่น แปลงเป็นรูปแบบ response ของ API |
| `e.json()` | JSON string | ส่งต่อเป็นข้อความ |

บรรทัดแรกของ `str(e)` คือ `4 validation errors for Order` ตามด้วยชื่อ field ที่ผิดทีละบรรทัด (ตามแบบที่เห็นใน [บท 1](/pydantic/first-model/#เมื่อข้อมูลผิด-validationerror))

`errors()` ปรับได้สามทาง

```python
e.errors(include_url=False)       # ไม่เอา url
e.errors(include_input=False)     # ไม่เอาค่าที่ผิด
e.errors(include_context=False)   # ไม่เอา ctx
```

<Callout type="warn" title="errors() ที่มี ctx ไม่ได้เป็น JSON เสมอไป">
เมื่อ validator โยน `ValueError` เราจะเห็น exception ตัวเดิมอยู่ใน `ctx["error"]` (แบบฝึกยืนยัน `isinstance(ctx["error"], ValueError)`) แต่ exception object ส่งเข้า `json.dumps` ไม่ได้ จะได้ `TypeError` ถ้าต้องการ JSON ใช้ `e.json()` ซึ่งแปลง `ctx["error"]` เป็นข้อความ `{"error": "too big"}` ให้ หรือใช้ `include_context=False`
</Callout>

</Step>

## สร้าง Error ของตัวเอง

`raise ValueError("...")` ใน validator ได้ `type` เป็น `value_error` เสมอ และข้อความมี `Value error, ` นำหน้า ถ้าอยากได้รหัสของตัวเองและข้อความที่ปรับได้ ใช้ `PydanticCustomError` จาก `pydantic_core`

```python
from pydantic_core import PydanticCustomError

@field_validator("code")
@classmethod
def known(cls, v):
    if v not in {"SAVE10"}:
        raise PydanticCustomError(
            "unknown_coupon",                        # type
            "coupon {code} does not exist",          # template
            {"code": v},                             # ctx
        )
    return v
```

`Coupon(code="NOPE")` ได้ `type='unknown_coupon'`, `msg='coupon NOPE does not exist'`, `ctx={'code': 'NOPE'}` ข้อความเป็น template ที่เติมค่าจาก `ctx` และ `type` เป็นรหัสที่ฝั่ง client เอาไปจับคู่กับข้อความภาษาของตัวเองได้

ถ้าอยากใช้ error ชนิดที่ Pydantic มีอยู่แล้ว ใช้ `PydanticKnownError("greater_than", {"gt": 0})` ได้ `type` เป็น `greater_than` พร้อมข้อความมาตรฐาน

**exception ที่ไม่ถูกแปลงเป็น `ValidationError`** มีแค่ `ValueError` กับ `AssertionError` (และสองคลาสข้างบน) exception อื่นหลุดออกไปเหมือนเดิม แบบฝึกโยน `ZeroDivisionError` ใน validator แล้วได้ `ZeroDivisionError` ออกมาตรง ๆ แนวคิดเดียวกับ `TypeError` ใน [บท 5](/pydantic/validators/#exception-ชนิดไหนกลายเป็น-validationerror)

</Step>

## ซ่อนค่าที่ผิด: อย่าให้ Password หลุดเข้า Log

`str(e)` แสดง `input_value` ของทุก error ถ้า input คือ password ที่พิมพ์ผิด มันจะถูกเขียนลง log ไปด้วย แบบฝึกยืนยันด้วย field `pw: int` ที่ส่ง `"hunter2"`

มีสองระดับ ระดับเรียก `errors()` ใช้ `include_input=False` (ค่าจะหายจากผลที่ได้) ระดับ model ตั้งใน config

```python
class Hidden(BaseModel):
    model_config = {"hide_input_in_errors": True}
    pw: int

Hidden(pw="hunter2")
```

ข้อความที่ได้ไม่มี `hunter2` เหลืออยู่ บรรทัดของ error เหลือ `Input should be a valid integer, unable to parse string as an integer [type=int_parsing]` และไม่มีส่วน `input_value`

ถ้าเป็น `SecretStr` ([บท 3](/pydantic/types/#ชนิดสำเร็จรูป-ตัวเลขที่มีเงื่อนไข-url-email-secretstr)) ซึ่งไม่ใช่ชนิดเดียวกับ `int` ค่าก็ถูกซ่อนใน `repr` อยู่แล้ว แต่ error จาก validator ที่คุณเขียนเองควรระวังไม่ใส่ค่าลงใน message ดังที่ capstone ใน [บท 12](/pydantic/capstone/#วิธีจ่ายเงิน-discriminated-union-และความลับ) ทำกับเลขบัตร (ข้อความ `card number must be 16 digits` ไม่เอาตัวเลขมาด้วย)

</Step>

## แปลง Error เป็น Response ของ API

รูปแบบที่ใช้บ่อยคือแปลง `errors()` เป็นรายการที่ client เอาไปแสดงต่อได้ ไม่เปิดเผยค่าที่ส่งมา ตัวอย่างจาก capstone

```python
def problems(raw: str) -> list[dict]:
    try:
        Order.model_validate_json(raw)
    except ValidationError as e:
        return [
            {"field": ".".join(str(p) for p in x["loc"]),
             "code": x["type"],
             "message": x["msg"]}
            for x in e.errors(include_url=False, include_context=False, include_input=False)
        ]
    return []
```

ฝั่ง client ได้ `field` สำหรับชี้จุดในฟอร์ม `code` สำหรับแปลเป็นภาษาของผู้ใช้ และ `message` เป็นข้อความสำรอง ข้อมูลที่ผู้ใช้พิมพ์ไม่ถูกสะท้อนกลับไป [บท 12](/pydantic/capstone/#เมื่อข้อมูลผิดทุกจุด-รายการปัญหา) ใช้โครงเดียวกันนี้กับ order ที่ผิดเก้าจุด

</Step>

## เช็กตัวเอง

- ส่ง `{"id": "x", "items": [{"sku": 5}]}` เข้า `Order` คาดว่า `loc` ของแต่ละ error เป็นอะไร (ลองเขียนก่อนรัน)
- ทำไม `json.dumps(e.errors())` ถึงล้มเมื่อ error มาจาก `raise ValueError` ใน validator และคุณแก้ได้สองวิธีอย่างไร
- ทีมของคุณอยากให้แอปมือถือแสดงข้อความ "คูปองนี้ไม่มีอยู่" เป็นภาษาไทย ควรผูกกับ `msg` หรือ `type` เพราะอะไร

</Step>
