## เมื่อเงื่อนไขของ Field ไม่พอ

`Field(gt=0)` และ `pattern` ตรวจได้ทีละค่า แต่บางกฎต้องการตรรกะ เช่น username ต้องเป็นตัวอักษรกับตัวเลขเท่านั้นแล้วแปลงเป็นตัวเล็ก หรือ password สองช่องต้องตรงกัน Pydantic ให้ validator สำหรับกรณีนี้ สองตัวหลักคือ `field_validator` (ตรวจ field) และ `model_validator` (ตรวจทั้ง model)

```python
class Signup(BaseModel):
    username: str
    password: str
    password2: str

    @field_validator("username")
    @classmethod
    def clean_username(cls, v: str) -> str:
        if not v.isalnum():
            raise ValueError("must be letters and digits only")
        return v.lower()

    @field_validator("password2")
    @classmethod
    def same_password(cls, v: str, info: ValidationInfo) -> str:
        if "password" in info.data and v != info.data["password"]:
            raise ValueError("passwords do not match")
        return v
```

(รัน: `exercises/05_validators.py`) สามอย่างที่ต้องจำ ค่าที่ validator **คืน** จะแทนค่าเดิม (`"Ann99"` กลายเป็น `"ann99"`) validator จะโยน `ValueError` เมื่อไม่ผ่าน และต้องใส่ `@classmethod` ใต้ `@field_validator`

ส่ง `username="a b", password="x", password2="y"` ได้สอง error ทั้งคู่ชนิด `value_error` ข้อความขึ้นต้นว่า `Value error, ` ตามด้วยข้อความที่เราเขียน

</Step>

## After, Before, Wrap, Plain

`field_validator` มีสี่ mode ต่างกันที่ว่าทำงานตอนไหนเทียบกับการตรวจชนิดของ Pydantic

| mode | ทำงานเมื่อ | รับอะไร | ใช้กับ |
|---|---|---|---|
| `after` (ค่าเริ่มต้น) | หลัง Pydantic ตรวจชนิดผ่านแล้ว | ค่าที่ตรวจแล้ว (ชนิดถูกต้อง) | กฎของธุรกิจ, ทำความสะอาดค่า |
| `before` | ก่อนตรวจชนิด | input ดิบ ชนิดอะไรก็ได้ | แปลงรูปแบบ input ให้ Pydantic รับได้ |
| `wrap` | ห่อรอบการตรวจ | input ดิบ และ `handler` ที่เรียกการตรวจเดิม | ดักผลหรือ error ของการตรวจเดิม |
| `plain` | แทนที่การตรวจเดิมทั้งหมด | input ดิบ | ชนิดที่ Pydantic ไม่รู้จัก |

**after** ไว้ใจชนิดของค่าได้เสมอ ส่ง `username=123` เข้า model ข้างบน validator ไม่ถูกเรียกเลย เพราะ Pydantic ตัดที่ `string_type` ไปแล้ว ผลคือ error เดียวที่ไม่มี `Value error, ` นำหน้า ทำให้ validator แบบ after เขียนสั้นได้ ไม่ต้องกลัวว่าค่าจะผิดชนิด

**before** ใช้เมื่อ input ต้องจัดรูปก่อนเข้าตรวจ

```python
class Tags(BaseModel):
    tags: list[str]

    @field_validator("tags", mode="before")
    @classmethod
    def split(cls, v):
        return v.split(",") if isinstance(v, str) else v

Tags(tags="a,b").tags      # ['a', 'b']
Tags(tags=["c"]).tags      # ['c']
```

เมื่อคืนค่าจาก before แล้ว Pydantic ยังตรวจชนิดต่อ ถ้าฟังก์ชันคืน list ของตัวเลข จะติดที่ `list[str]` ตามปกติ

</Step>

## ValidationInfo: อ่าน Field ที่ผ่านมาแล้ว และ Context

validator รับ argument ตัวที่สองเป็น `ValidationInfo` ได้ ข้างในมี `data` (field ที่ตรวจเสร็จและผ่านแล้ว) `field_name` และ `context`

`info.data` มีข้อจำกัดสองข้อที่ต้องรู้ ข้อแรก มีเฉพาะ field ที่ **ประกาศก่อน** field ที่กำลังตรวจ (ตามลำดับในคลาส) เพราะ Pydantic ตรวจตามลำดับนั้น ข้อสอง field ที่ตรวจไม่ผ่านจะ **ไม่อยู่ใน** `info.data` แบบฝึกพิสูจน์ข้อสอง

```python
class Order(BaseModel):
    qty: int
    note: str

    @field_validator("note")
    @classmethod
    def look(cls, v, info: ValidationInfo):
        seen["keys"] = sorted(info.data)
        return v

Order(qty="x", note="n")   # ล้มที่ qty → seen["keys"] == []
Order(qty=1, note="n")     # → seen["keys"] == ["qty"]
```

ตัวอย่าง `same_password` ข้างบนจึงเขียน `"password" in info.data` ก่อนอ่านค่า ถ้า `password` ล้ม ตัวนี้จะไม่อยู่ และถ้าไม่เช็กจะเจอ `KeyError`

**context** คือ dict ที่ผู้เรียกส่งเข้ามาตอน validate เพื่อให้ validator ใช้ข้อมูลที่ไม่ได้อยู่ในตัว input

```python
class Ctx(BaseModel):
    price: float

    @field_validator("price")
    @classmethod
    def vat(cls, v, info: ValidationInfo):
        rate = (info.context or {}).get("vat", 0)
        return round(v * (1 + rate), 2)

Ctx.model_validate({"price": 100}).price                          # 100
Ctx.model_validate({"price": 100}, context={"vat": 0.07}).price   # 107.0
```

ระวังว่า `info.context` เป็น `None` ถ้าผู้เรียกไม่ส่งมา จึงต้องจัดการกรณีนั้น

</Step>

## Validator แบบ Annotated: ใช้ซ้ำและซ้อนกันได้

validator ที่ผูกกับ field ผ่านชื่อจำกัดอยู่ในคลาสเดียว ถ้าอยากใช้กฎเดียวกันกับหลายคลาส ให้ผูกกับ **ชนิด** ด้วย `Annotated` แบบที่ [บท 2](/pydantic/fields/#annotated-เอาเงื่อนไขไปติดกับชนิด-แล้วใช้ซ้ำ) ทำกับ `Field`

```python
from pydantic import AfterValidator, BeforeValidator, PlainValidator, WrapValidator

Stacked = Annotated[
    int,
    BeforeValidator(mark("before1")),
    BeforeValidator(mark("before2")),
    AfterValidator(mark("after1")),
    AfterValidator(mark("after2")),
]
```

เมื่อซ้อนหลายตัว ลำดับการทำงานของแบบฝึกคือ

```text
['before2', 'before1', 'after1', 'after2']
```

`after` ทำงานตามลำดับที่เขียน (บนลงล่าง) ส่วน `before` ทำงานย้อนกลับ (ล่างขึ้นบน) จำง่าย ๆ ว่า validator ถูกห่อซ้อนกันเป็นชั้น ตัวที่เขียนทีหลังอยู่นอกสุดสำหรับ before และอยู่ในสุดสำหรับ after

**WrapValidator** ได้ `handler` ที่เรียกการตรวจเดิมแล้วจับผลหรือ error ได้

```python
def default_on_error(v, handler):
    try:
        return handler(v)
    except ValidationError:
        return 0

class Lenient(BaseModel):
    n: Annotated[int, WrapValidator(default_on_error)]

Lenient(n="x").n    # 0
Lenient(n="7").n    # 7
```

**PlainValidator** แทนที่การตรวจเดิมทั้งหมด `Annotated[int, PlainValidator(lambda v: int(v) * 2)]` รับ `"4"` แล้วได้ `8` Pydantic ไม่ได้ตรวจอะไรอีก ถ้าฟังก์ชันคืนผิดชนิด ก็ถือว่าผ่าน ใช้เมื่อคุณรู้ว่ากำลังทำอะไรเท่านั้น

</Step>

## model_validator: กฎที่คร่อมหลาย Field

กฎอย่าง "low ต้องไม่เกิน high" เกี่ยวกับสอง field จึงตรวจที่ระดับ model

```python
class Range(BaseModel):
    low: int
    high: int

    @model_validator(mode="after")
    def ordered(self):
        if self.low > self.high:
            raise ValueError("low must not be above high")
        return self
```

validator แบบ `after` ได้ instance ที่สร้างเสร็จแล้ว (`self`) และต้องคืน `self` ผลจาก `Range(low=5, high=1)` คือ error เดียว ที่ `loc` ว่าง (ไม่ผูกกับ field ไหน) ข้อความ `Value error, low must not be above high`

ข้อควรรู้: ถ้ามี field ใดตรวจไม่ผ่าน `after` validator **ไม่ทำงาน** เลย `Range(low="x", high=1)` ได้ `int_parsing` อย่างเดียว กฎคร่อม field จึงไม่รบกวนรายงานของข้อผิดพื้นฐาน และเขียนโดยไว้ใจได้ว่าทุก field ถูกต้องแล้ว

`mode="before"` ได้ input ดิบของทั้ง model ซึ่งเป็นอะไรก็ได้ ไม่จำเป็นต้องเป็น dict

```python
class Point(BaseModel):
    x: int
    y: int

    @model_validator(mode="before")
    @classmethod
    def from_tuple(cls, data):
        if isinstance(data, (list, tuple)):
            return {"x": data[0], "y": data[1]}
        return data

Point.model_validate((1, 2))    # Point(x=1, y=2)
```

</Step>

## Exception ชนิดไหนกลายเป็น ValidationError

ใน validator เราโยน exception ได้หลายแบบ แต่ Pydantic จับแค่บางชนิด แบบฝึกลองโยนสามแบบ

| โยน | ผล |
|---|---|
| `ValueError` | `ValidationError` ชนิด `value_error` |
| `AssertionError` (ผ่าน `assert`) | `ValidationError` ชนิด `assertion_error` |
| `TypeError` | **หลุดออกมาเป็น `TypeError` ตรง ๆ** ไม่ถูกห่อ |

เหตุผลของข้อสาม: `TypeError` ใน validator มักเป็นบั๊กของโค้ด (เรียกฟังก์ชันผิด argument) ไม่ใช่ข้อมูลผิด Pydantic จึงปล่อยให้มันดังขึ้นมา ไม่ให้ไปปนกับข้อผิดของผู้ใช้ ([บท 6](/pydantic/errors/#สร้าง-error-ของตัวเอง) ยืนยันแบบเดียวกันกับ `ZeroDivisionError`)

<Callout type="warn" title="assert ถูกตัดทิ้งเมื่อรันด้วย -O">
ถ้ารัน Python ด้วย `python -O` คำสั่ง `assert` ถูกตัดออก validator ที่ใช้ `assert` เป็นตัวตรวจจะไม่ตรวจเลย ใช้ `raise ValueError(...)` สำหรับกฎที่ต้องทำงานเสมอ ข้อนี้เป็นพฤติกรรมของ Python ที่เอกสาร Pydantic เตือนไว้เช่นกัน แบบฝึกในบทนี้ไม่ได้รันด้วย `-O`
</Callout>

</Step>

## ที่ควรรู้เพิ่ม

**ตรวจสมาชิกของ list หรือหลาย field พร้อมกัน** ชื่อ field ใน `@field_validator` ใส่ได้หลายตัว และ validator ของ field ที่เป็น list ได้ list ทั้งก้อน

```python
@field_validator("skus")
@classmethod
def unique(cls, v):          # v คือ list ทั้งหมด
    if len(set(v)) != len(v):
        raise ValueError("duplicate sku")
    return v

@field_validator("first", "second")
@classmethod
def upper(cls, v):           # ใช้กับสอง field
    return v.upper()
```

**Validator ไม่ทำงานกับ default** `code: str = "abc"` ที่มี validator แปลงเป็นตัวใหญ่ `D().code` ยังเป็น `"abc"` แต่ `D(code="abc").code` เป็น `"ABC"` ถ้าอยากให้ default ผ่านด้วย ใช้ `validate_default=True` ใน `Field` ([บท 2](/pydantic/fields/#default-ทำงานยังไง))

**ไม่ทำงานตอน assign** เว้นแต่เปิด `validate_assignment` ([บท 8](/pydantic/models-config/#configdict-ตั้งค่าทั้ง-model))

**ใช้ใน subclass ได้** validator ถูกสืบทอดจากคลาสแม่ และ subclass override โดยประกาศฟังก์ชันชื่อเดียวกันได้

</Step>

## เช็กตัวเอง

- validator แบบ after บน field `n: int` ถูกเรียกไหม ถ้าผู้ใช้ส่ง `"abc"` เข้ามา แล้ว validator แบบ before ล่ะ
- ทำไม `same_password` ต้องเช็ก `"password" in info.data` ก่อนอ่าน และ field ไหนที่ไม่อยู่ใน `info.data`
- คุณต้องการ model ที่เรียก `Order.model_validate(raw, context={"vat": 0.07})` แล้ว validator ใช้อัตราภาษีนั้น ถ้าผู้เรียกลืมส่ง context validator ควรทำอะไร

</Step>

| `model_validator` after ไม่ทำงานเมื่อ field ล้ม, before รับ input ดิบ | รัน: `exercises/05_validators.py` |

| validator ถูกสืบทอดและ override ได้ | ผู้เขียน |
| ชนิด validator จัดเก็บและเรียกผ่าน `function.rs` (before, after, plain, wrap) | source: `function.rs` ใน knowledge graph |
