## ภาพรวม: สามระดับของการเปลี่ยน

เมื่อเอาโค้ดที่เขียนสำหรับ Pydantic V1 ไปรันบน V2 สิ่งที่เจอแบ่งได้เป็นสามพวก (รัน: `exercises/11_migration.py`)

1. **ยังทำงาน แต่ warning** ชื่อเมธอดเก่าอย่าง `.dict()` ผ่าน shim ไปหาชื่อใหม่
2. **พังชัดเจน** ใช้ keyword หรือ import ที่ถูกถอดออก จะได้ error ที่บอกเหตุผล
3. **ทำงานต่างจากเดิมโดยไม่มีสัญญาณ** อันตรายที่สุด เพราะ test ที่ไม่ครอบคลุมจะไม่เห็น

บทนี้เรียงตามสามพวกนั้น ฝั่ง Python มี module ที่ทำหน้าที่ shim อยู่หลายตัว (กราฟ source จัดเป็นชั้น "V1 Compatibility Shims" 21 ไฟล์) หัวใจคือ `pydantic/_migration.py` ที่เก็บตารางสี่ชุด: ชื่อที่ย้ายที่ (`MOVED_IN_V2`), ชื่อที่ย้ายที่และ deprecated (`DEPRECATED_MOVED_IN_V2`), ชื่อที่ต้องไปใช้จาก `pydantic.v1` (`REDIRECT_TO_V1`) และชื่อที่ถูกลบ (`REMOVED_IN_V2`) แล้วใช้ `__getattr__` ของ module คัดว่าแต่ละชื่อควร warn, redirect หรือ error

</Step>

<Step>

## พวกที่ 1: ชื่อเมธอดเก่ายังใช้ได้ พร้อม Warning

เมธอดของ model ใน V1 ยังเรียกได้ และแต่ละตัวออก `PydanticDeprecatedSince20` ซึ่งระบุชื่อใหม่ในข้อความ

| V1 | V2 |
|---|---|
| `.dict()` | `.model_dump()` |
| `.json()` | `.model_dump_json()` |
| `.copy()` | `.model_copy()` |
| `Model.parse_obj(d)` | `Model.model_validate(d)` |
| `Model.parse_raw(s)` | `Model.model_validate_json(s)` |
| `Model.schema()` | `Model.model_json_schema()` |
| `Model.construct(...)` | `Model.model_construct(...)` |

ตัวอย่างข้อความที่แบบฝึกได้ `The `construct` method is deprecated; use `model_construct` instead. Deprecated in Pydantic V2.0 to be removed in V3.0.` สังเกต "to be removed in V3.0" ผู้เขียนอ่านเป็นว่าชื่อเก่าจะหายในรุ่นใหญ่ถัดไป จึงไม่ควรปล่อยไว้

`parse_raw` ได้ warning สองตัว เพราะข้างในเรียกฟังก์ชันที่ deprecated อีกตัว (`load_str_bytes`) ถ้า test ของคุณนับจำนวน warning ให้ระวัง

**`@validator` ยังทำงาน**

```python
@validator("n")
def pos(cls, v):
    if v < 0:
        raise ValueError("negative")
    return v
```

คืน `PydanticDeprecatedSince20` ตอนประกาศคลาส แต่ `Legacy(n=-1)` ยังได้ `ValidationError` ชนิด `value_error` ตามเดิม ให้ย้ายไป `@field_validator` ([บท 5](/pydantic/validators/)) ซึ่งต้องใส่ `@classmethod` ด้วย

</Step>

## พวกที่ 2: พังชัดเจน

**`@root_validator` โดยไม่ระบุ mode** ใน V1 ใช้ได้เลย ใน V2 ต้องบอกว่าเป็น `pre=True` หรือ `skip_on_failure=True` ถ้าไม่บอก ได้ `PydanticUserError` ที่ `e.code == "root-validator-pre-skip"` ตอนประกาศคลาส (และยังมี warning ว่า `@root_validator` deprecated) ทางที่ถูกคือเปลี่ยนไปใช้ `@model_validator` ([บท 5](/pydantic/validators/#model_validator-กฎที่คร่อมหลาย-field))

**keyword ที่ถูกลบ** `Field("a", regex="^a$")` ได้ `PydanticUserError` ที่ `e.code == "removed-kwargs"` ชื่อใหม่คือ `pattern` ([บท 2](/pydantic/fields/))

**`BaseSettings` ย้ายออกไป** `from pydantic import BaseSettings` ได้ `PydanticImportError` ข้อความบอกว่าย้ายไปที่ package `pydantic-settings` พร้อมลิงก์คู่มือ

error ทั้งสามชนิดมีข้อดีคือบอกทางแก้ในข้อความ และเกิดตอน import หรือประกาศคลาส ไม่ต้องรอถึง runtime ที่ข้อมูลผ่านเข้ามา

</Step>

<Step>

## พวกที่ 3: เปลี่ยนเงียบ ๆ

พวกนี้ไม่มี warning ต้องมี test จับ แบบฝึกยืนยันสามเรื่อง

**1. `Optional[X]` ไม่ได้แปลว่าไม่ต้องส่งอีกแล้ว** V1: `a: Optional[int]` ไม่ต้องส่ง และ default เป็น `None` (แบบฝึกรันผ่าน `pydantic.v1`: `V1Opt().a is None`) V2: ต้องส่ง ไม่ส่งได้ error `missing` ([บท 2](/pydantic/fields/#required-optional-และ-nullable-คนละเรื่องกัน))

**2. ตัวเลขไม่ถูกแปลงเป็น `str`** V1: `V1Str(s=123).s == "123"` V2: `Num(f=1, s=123)` ได้ `string_type`

**3. `class Config` เก่าทำงานแค่บางคีย์** คลาสนี้ยังอ่านได้ (มี warning ว่า class-based config deprecated) แต่ key ที่ **เปลี่ยนชื่อ** ถูกเมิน พร้อม `UserWarning` ว่า key ใดเปลี่ยนชื่อเป็นอะไร

```python
class Old(BaseModel):
    class Config:
        orm_mode = True                      # เปลี่ยนชื่อเป็น from_attributes
        allow_population_by_field_name = True  # เปลี่ยนชื่อเป็น validate_by_name
        extra = "forbid"                     # ชื่อเดิม ยังใช้ได้

Old(a=1, z=2)             # error extra_forbidden   ← extra ทำงาน
Old.model_validate(Row()) # error model_type        ← orm_mode ถูกเมิน
```

ข้อความ warning ของแบบฝึก: `'orm_mode' has been renamed to 'from_attributes'` และ `'allow_population_by_field_name' has been renamed to 'validate_by_name'` ถ้าคุณปิด warning ไว้ (หรือ log ถูกกรอง) จะไม่รู้เลยว่า ORM mode ไม่ทำงาน แล้วไปเจอ `model_type` ตอน runtime

<Callout type="warn" title="รัน test ด้วย warning เป็น error ระหว่างย้าย">
`pytest -W error::DeprecationWarning` ไม่พอ เพราะ `PydanticDeprecatedSince20` เป็นคลาส warning ของ Pydantic เอง (และ warning เรื่อง config key เป็น `UserWarning`) ในช่วงย้ายให้เปิด warning ทุกชนิดเป็น error แล้วค่อยไล่แก้ทีละอัน เป็นข้อแนะนำของผู้เขียน ไม่ได้รันแบบเต็มกับโปรเจกต์จริง
</Callout>

</Step>

## pydantic.v1: ย้ายทีละส่วน

Pydantic V2 ส่ง V1 ทั้งชุดมาด้วยใน `pydantic.v1` (กราฟระบุว่าเป็นสำเนาเต็มของ V1 มี model, field, validators, types และ schema ของตัวเอง ประมาณ 26 ไฟล์ ใน layer "Legacy Pydantic V1") ใช้ในช่วงที่โปรเจกต์ใหญ่และเปลี่ยนทีเดียวไม่ไหว

```python
from pydantic.v1 import BaseModel as V1Model

class Old1(V1Model):
    n: int

Old1(n="3").n                 # 3
Old1(n=1).dict()              # {'n': 1}    ชื่อเมธอด V1 ใช้ได้ตามปกติ
issubclass(Old1, BaseModel)   # False       คนละคลาสกับ BaseModel ของ V2
```

สิ่งสำคัญคือ **model ของ V1 กับ V2 เป็นคนละโลก** field ของ V2 model ที่ชนิดเป็น V1 model (หรือกลับกัน) ใช้ไม่ได้ ต้องย้ายเป็นชั้น ๆ จากใบไม้เข้าหาราก หรือแปลงที่ขอบด้วย dict

ข้อจำกัดอย่างหนึ่งที่ควรรู้: ผู้เขียนไม่ได้ตรวจนโยบายการ support `pydantic.v1` กับ Python เวอร์ชันใหม่ ๆ ก่อนจะวางแผนอยู่กับมันนาน ให้เช็กเอกสาร release ของเวอร์ชันที่ใช้

</Step>

## ลำดับที่แนะนำ

คำแนะนำของผู้เขียน เรียงจากเสี่ยงน้อยไปมาก

1. อัปเกรดเป็น V2 แล้วรัน test ด้วย warning ทุกชนิดเป็น error ดูรายการที่พัง
2. แก้พวกที่ 2 ก่อน เพราะเห็นชัดและบอกทางแก้ (`regex` เป็น `pattern`, `root_validator` เป็น `model_validator`, `BaseSettings` ไปที่ `pydantic-settings`)
3. ไล่ `Optional[X]` ทุกจุด ตัดสินใจทีละ field ว่าต้องส่งไหม ถ้าไม่ต้องส่ง เติม `= None`
4. เปลี่ยน `class Config` เป็น `model_config = ConfigDict(...)` โดยแปลงชื่อคีย์ตามตารางใน warning
5. เปลี่ยนชื่อเมธอด (`dict` ไปเป็น `model_dump` ฯลฯ) ซึ่งทำด้วยการค้นแทนที่ได้
6. เขียน test ที่ใช้ข้อมูลจริงจากระบบ สำหรับพวกที่ 3 (`str` จากตัวเลข, ค่าที่คลุมเครือระหว่าง `int` กับ `float`) เพราะมันเงียบ

</Step>

<Step>

## เช็กตัวเอง

- โค้ดเก่ามี `a: Optional[int]` และ caller ไม่เคยส่ง `a` ย้ายไป V2 แล้วเกิดอะไรขึ้น และแก้อย่างไร
- `class Config: orm_mode = True` บน V2 ทำให้ `Model.model_validate(orm_object)` สำเร็จไหม แล้วรู้ได้อย่างไรว่าอะไรผิด
- ทำไม V1 model ไม่ควรเป็น field ของ V2 model

</Step>
