## สองโหมดของขาออก

บทก่อนหน้าเราดูขาเข้ากันไปแล้ว ส่วนบทนี้จะดูขาออก โดยตัวอย่างในบทใช้ Model ชุดนี้ (รัน: `exercises/07_serialization.py`)

```python
class Order(BaseModel):
    id: int
    placed: date
    color: Color              # Enum
    lines: list[Line]         # Line มี sku, qty, price: Decimal
    note: str | None = None
    tags: set[str] = set()
```

`model_dump()` ให้ Dict ที่ยังเก็บชนิดของ Python ไว้ครบ ส่วน `model_dump(mode="json")` ให้ Dict ที่มีแต่ชนิดที่ JSON เก็บได้

| field | `model_dump()` | `model_dump(mode="json")` |
|---|---|---|
| `placed` | `date(2026, 3, 1)` | `"2026-03-01"` |
| `color` | `Color.RED` | `"red"` |
| `lines[0]["price"]` | `Decimal("9.50")` | `"9.50"` |
| `tags` | `{"x"}` | `["x"]` |

ทั้งสองโหมดแปลง Model ที่ซ้อนอยู่ข้างในเป็น Dict ด้วย (`lines[0]` เป็น `dict` ไม่ใช่ `Line`) ส่วน `Decimal` ใน JSON จะออกมาเป็น String เพื่อไม่ให้เสียความละเอียด

`model_dump_json()` ให้ JSON String ตรง ๆ แบบกะทัดรัด ผลเท่ากับ `json.dumps` ของ `mode="json"` และใส่ `indent=2` ได้ถ้าอยากให้อ่านง่าย

```text
{"id":1,"placed":"2026-03-01","color":"red","lines":[{"sku":"A","qty":2,"price":"9.50"}],"note":null,"tags":["x"]}
```

ผลที่ได้อ่านกลับได้ทั้งสองทางเลย เช่น `Order.model_validate_json(text) == o` และ `Order.model_validate(js) == o`

</Step>

## เลือก Field: Include, Exclude และ exclude_*

```python
o.model_dump(include={"id", "note"})            # เอาแค่สอง field
o.model_dump(exclude={"lines"})                 # ทุกอย่างยกเว้น lines
o.model_dump(include={"lines": {0: {"sku"}}})["lines"]            # [{'sku': 'A'}]
o.model_dump(exclude={"lines": {"__all__": {"price"}}})["lines"]  # [{'sku': 'A', 'qty': 2}]
```

ถ้าอยู่ในโครงสร้างที่ซ้อนกัน เราใช้ Dict ระบุชั้นถัดไป โดยเลขดัชนีจะเลือกสมาชิกของ List ตัวนั้น ส่วน `"__all__"` หมายถึงทุกสมาชิก

อีกชุดหนึ่งจะเลือกตามสถานะของค่า

| ตัวเลือก | ตัด Field ที่... |
|---|---|
| `exclude_unset=True` | ผู้เรียกไม่ได้ส่งมา (ดู `model_fields_set` ใน [บท 1](/pydantic/first-model/#สิ่งที่-model-ทำเมื่อไม่ได้สั่ง)) |
| `exclude_defaults=True` | ค่าเท่ากับ Default |
| `exclude_none=True` | ค่าเป็น `None` |

สองตัวแรกต่างกันตรงที่ผู้เรียกส่งค่าที่เท่ากับ Default มาหรือเปล่า ยกตัวอย่างถ้าสร้าง `Order(..., note=None)` โดยส่ง `note=None` มาตรง ๆ `exclude_unset` จะ **เก็บ** `note` ไว้ (เพราะผู้เรียกส่งมา) แต่ `exclude_defaults` จะ **ตัด** ทิ้ง (เพราะเท่ากับ Default) ดังนั้น PATCH Request ควรใช้ `exclude_unset` เพื่อแก้เฉพาะที่ผู้ใช้ส่งมา

</Step>

## Alias ตอน Dump

ตามค่าเริ่มต้น Dump จะใช้ชื่อ Field จริง ถ้าอยากได้ Alias ให้ใส่ `by_alias=True` ([บท 2](/pydantic/fields/#alias-ชื่อใน-input-ไม่ตรงกับชื่อใน-python))

```python
a = Aliased(userId=1)
a.model_dump()                        # {'user_id': 1}
a.model_dump(by_alias=True)           # {'userId': 1}
a.model_dump_json(by_alias=True)      # '{"userId":1}'
```

พฤติกรรมนี้ตรงข้ามกับตอนรับ Input (ที่ใช้ Alias เป็นค่าเริ่มต้น) เราจึงต้องจำให้ตรงกันตอน Round Trip ถ้าเขียนไฟล์ด้วย `by_alias=True` ก็ต้องอ่านกลับด้วยชื่อ Alias

</Step>

## field_serializer และ PlainSerializer

เปลี่ยนวิธีเขียนค่าของ Field เดียวด้วย `field_serializer`

```python
class Event(BaseModel):
    at: datetime
    price: Decimal

    @field_serializer("at")
    def fmt(self, v: datetime) -> str:
        return v.strftime("%d/%m/%Y")

    @field_serializer("price", when_used="json")
    def money(self, v: Decimal) -> float:
        return float(v)
```

`at` ถูกแปลงในทุกโหมด ส่วน `price` มี `when_used="json"` จึงแปลงเป็น `float` เฉพาะตอนออก JSON ผลของแบบฝึกคือ `model_dump()["price"]` ยังเป็น `Decimal("1.5")` แต่ `model_dump_json()` ได้ `{"at":"01/03/2026","price":1.5}`

ตัวเลือก `when_used` มีสี่ค่าคือ `"always"` (ค่าเริ่มต้น), `"json"`, `"json-unless-none"` และ `"unless-none"`

ถ้าอยากใช้ซ้ำกับหลาย Field เราผูกกับชนิดด้วย `Annotated` และ `PlainSerializer` ได้ แบบเดียวกับ Validator ใน [บท 5](/pydantic/validators/#validator-แบบ-annotated-ใช้ซ้ำและซ้อนกันได้)

```python
Baht = Annotated[Decimal, PlainSerializer(lambda v: f"{v:.2f} THB", return_type=str)]

class Price(BaseModel):
    amount: Baht

Price(amount="3").model_dump()    # {'amount': '3.00 THB'}
```

`return_type` ใช้บอกชนิดของสิ่งที่ฟังก์ชันคืน เพื่อให้ JSON Schema ([บท 9](/pydantic/adapters/#json-schema-จาก-model)) ระบุชนิดของ Field นี้ได้ถูกต้อง

</Step>

## computed_field: เอา Property เข้าไปในผลลัพธ์

`@property` ธรรมดาไม่ปรากฏใน Dump ถ้าอยากให้ปรากฏ ให้ครอบด้วย `@computed_field`

```python
class Rect(BaseModel):
    w: int
    h: int

    @computed_field
    @property
    def area(self) -> int:
        return self.w * self.h

Rect(w=2, h=3).model_dump()     # {'w': 2, 'h': 3, 'area': 6}
```

Computed Field มีผลต่อขาออกเท่านั้น โดย JSON Schema แบบ Serialization จะมี `area` แต่แบบ Validation ไม่มี และถ้าส่ง `area=99` เข้ามาตอนสร้าง ค่านั้นจะถูกเมิน (`Rect(w=1, h=1, area=99).area` ได้ 1) เพราะมันไม่ใช่ Field ขาเข้า เรายังต้องใส่ Type Hint ของค่าที่คืนไว้เสมอ เพราะ Pydantic ใช้มันสร้าง Schema

</Step>

## model_serializer: คุมทั้งก้อน

เมื่อรูปร่างของผลลัพธ์ต่างจากโครงสร้าง Field ไปมาก เราใช้ `model_serializer` เขียนเองได้ ซึ่งตัวอย่างนี้ใช้ `SerializationInfo` ดูว่าอยู่โหมดไหน

```python
class Money(BaseModel):
    amount: int
    currency: str

    @model_serializer
    def ser(self, info: SerializationInfo) -> str | dict[str, Any]:
        return f"{self.amount} {self.currency}" if info.mode == "json" else {"a": self.amount}

Money(amount=5, currency="THB").model_dump_json()   # '"5 THB"'
Money(amount=5, currency="THB").model_dump()        # {'a': 5}
```

ตัวอย่างนี้แกล้งให้สองโหมดต่างกันมากเพื่อให้เห็นว่า `info.mode` ใช้ทำอะไร ส่วนงานจริงมักคืนรูปเดียวกันทั้งสองโหมด

</Step>

## Subclass ถูก Serialize ตามชนิดที่ประกาศ

มีกับดักที่เจอบ่อยเมื่อใช้ Inheritance

```python
class Animal(BaseModel):
    name: str

class Dog(Animal):
    tricks: int = 0

class Owner(BaseModel):
    pet: Animal

Owner(pet=Dog(name="r", tricks=3)).model_dump()
# {'pet': {'name': 'r'}}      tricks หายไป
```

Field ประกาศว่าเป็น `Animal` Pydantic จึง Serialize ตาม Schema ของ `Animal` ถึงค่าจริงจะเป็น `Dog` ก็ตาม ถ้าต้องการให้ตามชนิดจริง มีสองวิธีซึ่งแบบฝึกยืนยันว่าได้ผลเท่ากัน

```python
pet: SerializeAsAny[Animal]                                  # ที่ field
Owner(...).model_dump(serialize_as_any=True)                 # ตอนเรียก
```

อีกทางคือเปลี่ยนมาใช้ Discriminated Union ของ [บท 4](/pydantic/unions/#discriminated-union-ดู-field-เดียวแล้วเลือกให้ตรง) ซึ่งเลือก Model ตาม Tag ทั้งขาเข้าและขาออก (ข้อนี้ผู้เขียนไม่ได้รันในแบบฝึก)

<Callout type="warn" title="ข้อมูลหายเงียบ ๆ">
กรณี Subclass ข้างบนไม่มีทั้ง Error และ Warning เลย ข้อมูลของ `Dog` หายไปจากผลลัพธ์เฉย ๆ ดังนั้นถ้า API ของคุณรับ Model แบบ Polymorphic ให้เขียน Test ที่ Dump แล้วเทียบ Field ของ Subclass ด้วยนะ
</Callout>

</Step>

## ค่าที่ผิดชนิดตอน Dump: Warning ไม่ใช่ Error

เพราะ `validate_assignment` ปิดอยู่ตามค่าเริ่มต้น ([บท 1](/pydantic/first-model/#สิ่งที่-model-ทำเมื่อไม่ได้สั่ง)) เราจึงใส่ค่าผิดชนิดเข้า Model ได้ และค่านั้นจะถูกส่งต่อมาถึงขา Dump

```python
m = N(n=1)         # n: int
m.n = "not an int"
m.model_dump()     # {'n': 'not an int'}  พร้อม warning
```

```text
Pydantic serializer warnings:
  PydanticSerializationUnexpectedValue(Expected `int` - serialized value may not be as expected [field_name='n', input_value='not an int', input_type=str])
```

ค่าจะถูก Dump ออกไปตามที่เป็น พร้อม Warning หนึ่งครั้ง ถ้ารัน Test ด้วย `-W error` Warning นี้จะกลายเป็นความล้มเหลว ซึ่งเป็นวิธีจับการ Assign ผิดชนิดโดยไม่ต้องเปิด `validate_assignment`

</Step>

## model_copy: แก้โดยไม่ Mutate

```python
c = o.model_copy(update={"id": 2})
c.id           # 2
o.id           # 1
c.lines is o.lines            # True   copy แบบตื้น
o.model_copy(deep=True).lines is not o.lines   # True
```

`update` **ไม่ผ่านการตรวจ** ค่าที่ใส่เข้าไปจะถูกใช้ตามที่เป็น (ต่างจากการสร้าง Model ใหม่) และ Copy ตามค่าเริ่มต้นเป็นแบบตื้น ทำให้ List ข้างในใช้ร่วมกัน ถ้าจะแก้ List ใน Copy โดยไม่กระทบต้นฉบับ ให้ใช้ `deep=True`

รัน `uv run python exercises/07_serialization.py` แล้วลองเปลี่ยน `when_used="json"` ของ `money` เป็น `"always"` ดูว่า `assert` บรรทัดไหนล้ม พร้อมคิดดูว่าทำไม
</Callout>

## เช็กตัวเอง

- API ของคุณรับ PATCH ที่ผู้ใช้ส่งมาแค่ `{"name": "x"}` จะเลือก `exclude_unset` หรือ `exclude_none` เพราะอะไร
- `model_dump()` กับ `model_dump(mode="json")` ต่างกันกับ Field ชนิด `Decimal` และ `set` อย่างไร
- `Owner.pet: Animal` เก็บ `Dog` ไว้ แล้ว Dump ได้อะไร และคุณจะแก้ได้กี่วิธี

</Step>
