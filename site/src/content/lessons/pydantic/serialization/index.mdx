## สองโหมดของขาออก

บทก่อนหน้าดูขาเข้า บทนี้ดูขาออก ตัวอย่างในบทใช้ model ชุดนี้ (รัน: `exercises/07_serialization.py`)

```python
class Order(BaseModel):
    id: int
    placed: date
    color: Color              # Enum
    lines: list[Line]         # Line มี sku, qty, price: Decimal
    note: str | None = None
    tags: set[str] = set()
```

`model_dump()` ให้ dict ที่ยังเก็บชนิดของ Python ไว้ครบ ส่วน `model_dump(mode="json")` ให้ dict ที่มีแต่ชนิดที่ JSON เก็บได้

| field | `model_dump()` | `model_dump(mode="json")` |
|---|---|---|
| `placed` | `date(2026, 3, 1)` | `"2026-03-01"` |
| `color` | `Color.RED` | `"red"` |
| `lines[0]["price"]` | `Decimal("9.50")` | `"9.50"` |
| `tags` | `{"x"}` | `["x"]` |

ทั้งสองโหมดแปลง model ที่ซ้อนอยู่ข้างในเป็น dict ด้วย (`lines[0]` เป็น `dict` ไม่ใช่ `Line`) `Decimal` ใน JSON ออกมาเป็น string เพื่อไม่ให้เสียความละเอียด

`model_dump_json()` ให้ JSON string ตรง ๆ แบบกะทัดรัด ผลเท่ากับ `json.dumps` ของ `mode="json"` และใส่ `indent=2` ได้ถ้าอยากให้อ่านง่าย

```text
{"id":1,"placed":"2026-03-01","color":"red","lines":[{"sku":"A","qty":2,"price":"9.50"}],"note":null,"tags":["x"]}
```

ผลที่ได้อ่านกลับได้ทั้งสองทาง `Order.model_validate_json(text) == o` และ `Order.model_validate(js) == o`

## เลือก Field: include, exclude และ exclude_*

```python
o.model_dump(include={"id", "note"})            # เอาแค่สอง field
o.model_dump(exclude={"lines"})                 # ทุกอย่างยกเว้น lines
o.model_dump(include={"lines": {0: {"sku"}}})["lines"]            # [{'sku': 'A'}]
o.model_dump(exclude={"lines": {"__all__": {"price"}}})["lines"]  # [{'sku': 'A', 'qty': 2}]
```

ข้างในโครงสร้างซ้อน ใช้ dict ระบุชั้นถัดไป เลขดัชนีเลือกสมาชิกของ list ตัวนั้น `"__all__"` หมายถึงทุกสมาชิก

อีกชุดหนึ่งเลือกตามสถานะของค่า

| ตัวเลือก | ตัด field ที่... |
|---|---|
| `exclude_unset=True` | ผู้เรียกไม่ได้ส่งมา (ดู `model_fields_set` ใน [บท 1](/pydantic/first-model/#สิ่งที่-model-ทำเมื่อไม่ได้สั่ง)) |
| `exclude_defaults=True` | ค่าเท่ากับ default |
| `exclude_none=True` | ค่าเป็น `None` |

สองตัวแรกต่างกันตรงที่ส่งค่าเท่า default มาหรือเปล่า ถ้าสร้าง `Order(..., note=None)` โดยส่ง `note=None` มาตรง ๆ `exclude_unset` **เก็บ** `note` ไว้ (เพราะผู้เรียกส่งมา) แต่ `exclude_defaults` **ตัด** ทิ้ง (เพราะเท่ากับ default) PATCH request ควรใช้ `exclude_unset` เพื่อแก้เฉพาะที่ผู้ใช้ส่งมา

</Step>

## Alias ตอน Dump

ตามค่าเริ่มต้น dump ใช้ชื่อ field จริง ใส่ `by_alias=True` เมื่ออยากได้ alias ([บท 2](/pydantic/fields/#alias-ชื่อใน-input-ไม่ตรงกับชื่อใน-python))

```python
a = Aliased(userId=1)
a.model_dump()                        # {'user_id': 1}
a.model_dump(by_alias=True)           # {'userId': 1}
a.model_dump_json(by_alias=True)      # '{"userId":1}'
```

พฤติกรรมนี้ตรงข้ามกับตอนรับ input (ที่ alias เป็นค่าเริ่มต้น) ทำให้ round trip ต้องจำให้ตรงกัน ถ้าเขียนไฟล์ด้วย `by_alias=True` ก็ต้องอ่านกลับด้วยชื่อ alias

</Step>

## field_serializer และ PlainSerializer

เปลี่ยนวิธีเขียนค่าของ field เดียวด้วย `field_serializer`

```python
class Event(BaseModel):
    at: datetime
    price: Decimal

    @field_serializer("at")
    def fmt(self, v: datetime) -> str:
        return v.strftime("%d/%m/%Y")

    @field_serializer("price", when_used="json")
    def money(self, v: Decimal) -> float:
        return float(v)
```

`at` ถูกแปลงในทุกโหมด ส่วน `price` มี `when_used="json"` จึงแปลงเป็น `float` เฉพาะตอนออก JSON ผลของแบบฝึกคือ `model_dump()["price"]` ยังเป็น `Decimal("1.5")` แต่ `model_dump_json()` ได้ `{"at":"01/03/2026","price":1.5}`

ตัวเลือก `when_used` มี `"always"` (ค่าเริ่มต้น), `"json"`, `"json-unless-none"` และ `"unless-none"`

ถ้าอยากใช้ซ้ำกับหลาย field ผูกกับชนิดด้วย `Annotated` และ `PlainSerializer` แบบเดียวกับ validator ใน [บท 5](/pydantic/validators/#validator-แบบ-annotated-ใช้ซ้ำและซ้อนกันได้)

```python
Baht = Annotated[Decimal, PlainSerializer(lambda v: f"{v:.2f} THB", return_type=str)]

class Price(BaseModel):
    amount: Baht

Price(amount="3").model_dump()    # {'amount': '3.00 THB'}
```

`return_type` บอกชนิดของสิ่งที่ฟังก์ชันคืน เพื่อให้ JSON Schema ([บท 9](/pydantic/adapters/)) ระบุชนิดของ field นี้ได้ถูก

</Step>

## computed_field: เอา property เข้าไปในผลลัพธ์

`@property` ธรรมดาไม่ปรากฏใน dump ถ้าอยากให้ปรากฏ ครอบด้วย `@computed_field`

```python
class Rect(BaseModel):
    w: int
    h: int

    @computed_field
    @property
    def area(self) -> int:
        return self.w * self.h

Rect(w=2, h=3).model_dump()     # {'w': 2, 'h': 3, 'area': 6}
```

computed field มีผลต่อขาออกเท่านั้น JSON Schema แบบ serialization มี `area` ส่วนแบบ validation ไม่มี และถ้าส่ง `area=99` เข้ามาตอนสร้าง ค่านั้นถูกเมิน (`Rect(w=1, h=1, area=99).area` ได้ 1) เพราะมันไม่ใช่ field ขาเข้า ต้องใส่ type hint ของค่าที่คืนไว้เสมอ Pydantic ใช้มันสร้าง schema

</Step>

## model_serializer: คุมทั้งก้อน

เมื่อรูปร่างของผลลัพธ์ต่างจากโครงสร้าง field ไปมาก ใช้ `model_serializer` เขียนเอง ตัวอย่างนี้ใช้ `SerializationInfo` ดูว่าอยู่โหมดไหน

```python
class Money(BaseModel):
    amount: int
    currency: str

    @model_serializer
    def ser(self, info: SerializationInfo) -> str | dict[str, Any]:
        return f"{self.amount} {self.currency}" if info.mode == "json" else {"a": self.amount}

Money(amount=5, currency="THB").model_dump_json()   # '"5 THB"'
Money(amount=5, currency="THB").model_dump()        # {'a': 5}
```

ตัวอย่างนี้แกล้งให้สองโหมดต่างกันมากเพื่อให้เห็นว่า `info.mode` ใช้ทำอะไร งานจริงมักคืนรูปเดียวกันทั้งสองโหมด

</Step>

## Subclass ถูก Serialize ตามชนิดที่ประกาศ

กับดักที่เจอบ่อยเมื่อใช้ inheritance

```python
class Animal(BaseModel):
    name: str

class Dog(Animal):
    tricks: int = 0

class Owner(BaseModel):
    pet: Animal

Owner(pet=Dog(name="r", tricks=3)).model_dump()
# {'pet': {'name': 'r'}}      tricks หายไป
```

field ประกาศว่า `Animal` ดังนั้น Pydantic serialize ตาม schema ของ `Animal` ถึงค่าจริงจะเป็น `Dog` ก็ตาม ถ้าต้องการให้ตามชนิดจริง มีสองวิธีที่แบบฝึกยืนยันว่าได้ผลเท่ากัน

```python
pet: SerializeAsAny[Animal]                                  # ที่ field
Owner(...).model_dump(serialize_as_any=True)                 # ตอนเรียก
```

อีกทางคือเปลี่ยนมาใช้ discriminated union ของ [บท 4](/pydantic/unions/) ซึ่งเลือก model ตาม tag ทั้งขาเข้าและขาออก (ข้อนี้ผู้เขียนไม่ได้รันในแบบฝึก)

<Callout type="warn" title="ข้อมูลหายเงียบ ๆ">
กรณี subclass ข้างบนไม่มี error และไม่มี warning ข้อมูลของ `Dog` หายไปจากผลลัพธ์เฉย ๆ ถ้า API ของคุณรับ model แบบ polymorphic ให้เขียน test ที่ dump แล้วเทียบ field ของ subclass
</Callout>

</Step>

## ค่าที่ผิดชนิดตอน Dump: Warning ไม่ใช่ Error

เพราะ `validate_assignment` ปิดอยู่ตามค่าเริ่มต้น ([บท 1](/pydantic/first-model/#สิ่งที่-model-ทำเมื่อไม่ได้สั่ง)) เราใส่ค่าผิดชนิดเข้า model ได้ แล้วค่านั้นถูกส่งต่อมาถึงขา dump

```python
m = N(n=1)         # n: int
m.n = "not an int"
m.model_dump()     # {'n': 'not an int'}  พร้อม warning
```

```text
Pydantic serializer warnings:
  PydanticSerializationUnexpectedValue(Expected `int` - serialized value may not be as expected [field_name='n', input_value='not an int', input_type=str])
```

ค่าถูก dump ออกไปตามที่เป็น พร้อม warning หนึ่งครั้ง ถ้ารัน test ด้วย `-W error` warning นี้จะกลายเป็นความล้มเหลว ซึ่งเป็นวิธีจับการ assign ผิดชนิดโดยไม่ต้องเปิด `validate_assignment`

</Step>

## model_copy: แก้โดยไม่ mutate

```python
c = o.model_copy(update={"id": 2})
c.id           # 2
o.id           # 1
c.lines is o.lines            # True   copy แบบตื้น
o.model_copy(deep=True).lines is not o.lines   # True
```

`update` **ไม่ผ่านการตรวจ** ค่าที่ใส่เข้าไปใช้ตามที่เป็น (ต่างจากการสร้าง model ใหม่) และ copy ตามค่าเริ่มต้นเป็นแบบตื้น list ข้างในใช้ร่วมกัน ถ้าจะแก้ list ใน copy โดยไม่กระทบต้นฉบับ ใช้ `deep=True`

<Callout type="try" title="ลองทำใน repo นี้">
รัน `uv run python exercises/07_serialization.py` แล้วลองเปลี่ยน `when_used="json"` ของ `money` เป็น `"always"` ดูว่า `assert` บรรทัดไหนล้ม และทำไม
</Callout>

</Step>

## เช็กตัวเอง

- API ของคุณรับ PATCH ที่ผู้ใช้ส่งมาแค่ `{"name": "x"}` จะเลือก `exclude_unset` หรือ `exclude_none` เพราะอะไร
- `model_dump()` กับ `model_dump(mode="json")` ต่างกันกับ field ชนิด `Decimal` และ `set` อย่างไร
- `Owner.pet: Animal` เก็บ `Dog` ไว้ แล้ว dump ได้อะไร และคุณจะแก้ได้กี่วิธี

</Step>
