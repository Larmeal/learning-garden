## ตารางแปลงของ Lax Mode

ใน [บท 1](/pydantic/first-model/#lax-mode-แปลงให้ถ้าแปลงได้อย่างปลอดภัย) เราเห็น `int` กับ `bool` ไปแล้ว ในบทนี้จะขยายไปดูชนิดอื่น ๆ ด้วย โดยแบบฝึกในบทนี้ใช้ `TypeAdapter` ซึ่งตรวจชนิดใดก็ได้โดยไม่ต้องสร้าง Model ([บท 9](/pydantic/adapters/#typeadapter-ตรวจชนิดอะไรก็ได้) จะอธิบายเต็ม ๆ) ตอนนี้ให้อ่านว่า "ตรวจค่านี้กับชนิดนี้" ไปก่อน (รัน: `exercises/03_types.py`)

| ชนิดปลายทาง | รับได้ | ปฏิเสธ |
|---|---|---|
| `int` | `"42"`, `7.0`, `b"5"` | `7.5` (`int_from_float`), `None` (`int_type`), `"7x"` (`int_parsing`) |
| `float` | `"1e3"`, `3` (ได้ `3.0` ชนิด `float`) | |
| `str` | `b"bytes"` | `123` (`string_type`) |
| `bool` | `"true"`, `0` | `2` (`bool_parsing`) |
| `list[int]` | `("1", 2)` ได้ `[1, 2]` | |
| `set[int]` | `[1, 1, 2]` ได้ `{1, 2}` | |
| `tuple[int, str]` | `["1", "a"]` ได้ `(1, "a")` | |
| `dict[str, int]` | `{"a": "1"}` ได้ `{"a": 1}` | |

ข้อสังเกตที่ควรจำคือ Pydantic จะแปลง "ภายในโครงสร้าง" ให้ด้วย (สมาชิกของ List, ค่าของ Dict) และ Container ที่ได้จะเป็นชนิดที่ประกาศ ไม่ใช่ชนิดที่ส่งมา เช่นถ้าส่ง `tuple` เข้า `list[int]` ก็จะได้ `list`

อีกข้อคือ Pydantic จะ **คัดลอก** Container ไม่ได้ถือ Reference ของผู้เรียกไว้

```python
src = [1, 2]
box = Box(items=src)
src.append(3)
box.items    # [1, 2]
```

## Strict Mode: ปิดการแปลง

ถ้าไม่อยากให้ `"42"` เป็น `42` เราเปิด Strict ได้สามที่ ซึ่งผลเหมือนกันหมด

```python
TypeAdapter(int).validate_python("42", strict=True)   # วิธี 1: ตอนเรียก
TypeAdapter(StrictInt).validate_python("42")          # วิธี 2: ชนิดสำเร็จรูป StrictInt, StrictStr, ...
TypeAdapter(Annotated[int, Strict()]).validate_python("42")  # วิธี 3: ติด Strict() ที่ชนิด
```

ทั้งสามวิธีได้ Error `int_type` เหมือนกัน และเรายังตั้งทั้ง Model ด้วย `ConfigDict(strict=True)` หรือตั้งทีละ Field ด้วย `Field(strict=True)` ได้

```python
class Mixed(BaseModel):
    a: int = Field(strict=True)
    b: int

Mixed(a=1, b="2")    # ผ่าน b เป็น 2
Mixed(a="1", b=2)    # error int_type ที่ a
```

Strict เข้มกว่าที่คิด แม้แต่ `True` ก็ถูกปฏิเสธจาก Field `int` (`int_type`) ทั้งที่ใน Python `True` เป็น Subclass ของ `int` และใน Lax Mode ก็ผ่าน แต่ก็มีข้อยกเว้นที่สมเหตุสมผลอยู่ คือ `int` ยังผ่านเข้า Field `float` ใน Strict Mode ได้ เพราะจำนวนเต็มทุกตัวเป็นทศนิยมได้โดยไม่เสียข้อมูล

ใน Model ที่ตั้ง `strict=True` ถ้าส่ง `n="1"` และ `when="2026-01-01T00:00:00"` จะได้สอง Error คือ `int_type` กับ `datetime_type` เพราะ String ที่หน้าตาเป็นวันที่ก็ไม่ผ่าน ต้องส่ง Object `datetime` จริง ๆ

<Callout type="tip" title="เมื่อไหร่ควรใช้ Strict">
ถ้าข้อมูลมาจากโค้ดภายในซึ่งควรมีชนิดถูกอยู่แล้ว ให้ใช้ Strict เพื่อจับบั๊กที่ชนิดผิด ส่วนข้อมูลจากภายนอกที่เป็น JSON หรือฟอร์ม ซึ่งตัวเลขมักมาเป็น String ปล่อยให้เป็น Lax จะสะดวกกว่า เพราะไม่ต้องสั่งแปลงเอง ทั้งนี้เป็นคำแนะนำของผู้เขียน ไม่มีกฎตายตัวนะ
</Callout>

</Step>

## Strict กับข้อมูลจาก JSON ไม่เหมือนกับข้อมูลจาก Python

JSON มีชนิดน้อยกว่า Python เพราะไม่มีวันที่และไม่มี Tuple ถ้า Strict ใช้กฎเดียวกันทั้งสองฝั่ง ข้อมูลที่ถูกต้องที่สุดใน JSON ก็จะไม่มีทางผ่าน Pydantic จึงใช้กฎ Strict ที่ต่างกัน

```python
class StrictDate(BaseModel):
    model_config = ConfigDict(strict=True)
    d: date

StrictDate.model_validate_json('{"d": "2026-01-31"}').d   # date(2026, 1, 31)  ผ่าน
StrictDate.model_validate({"d": "2026-01-31"})            # error date_type
```

JSON ไม่มีชนิด Date จึงต้องเขียนเป็น String ได้ ส่วนข้อมูลจาก Python ที่ส่ง String เข้ามาถือเป็นการส่งผิดชนิดจริง ๆ และแบบเดียวกัน Array ใน JSON ผ่านเข้า `tuple` ใน Strict Mode ได้ แต่ `list` ของ Python ไม่ผ่าน (`tuple_type`) ซึ่ง [บท 10](/pydantic/under-the-hood/#input-ทำไมข้อมูลจาก-python-กับ-json-ต่างกันที่-strict) จะอธิบายว่าเกิดจากการที่ Validator อ่าน Input ผ่านชั้น Input ที่แยกตามแหล่ง

</Step>

## วันที่และเวลา

```python
ok(datetime, "2026-03-01T10:00:00Z")   # datetime(2026, 3, 1, 10, 0, tzinfo=timezone.utc)
ok(datetime, 0)                         # datetime(1970, 1, 1, tzinfo=timezone.utc)  ตัวเลขคือ unix seconds
ok(date, "2026-03-01")                  # date(2026, 3, 1)
ok(timedelta, "PT1H30M")                # timedelta(hours=1, minutes=30)  รูปแบบ ISO 8601 duration
ok(timedelta, 90)                       # timedelta(seconds=90)
```

(`ok` คือฟังก์ชันช่วยในแบบฝึกที่เรียก `TypeAdapter(tp).validate_python(value)`) ตัวเลขที่ส่งเข้า `datetime` จะถูกอ่านเป็น Unix Timestamp แบบวินาที ซึ่งสะดวกเมื่อรับจากระบบอื่น แต่ก็เป็นกับดักเมื่อมีคนส่งปี `2026` มาแล้วได้วันที่ปี 1970 ถ้าไม่อยากให้เป็นแบบนั้นให้ใช้ Strict

String วันที่ที่ไม่มีจริง เช่น `"2026-02-30"` จะถูกปฏิเสธ โดยแบบฝึกได้ Error ชนิด `date_from_datetime_parsing`

</Step>

## Decimal, UUID, Path, Enum และ Literal

```python
ok(Decimal, "19.90")      # Decimal('19.90')
ok(Decimal, 0.1)          # Decimal('0.1')
ok(uuid.UUID, str(u))     # UUID object
ok(Path, "/tmp/x")        # Path('/tmp/x')
```

`Decimal` เหมาะกับเงิน เพราะไม่มีปัญหา `0.1 + 0.2 != 0.3` ของ `float` และถ้าสังเกตดู `Decimal` รับ `0.1` ที่เป็น `float` แล้วได้ `Decimal('0.1')` ไม่ใช่ `Decimal('0.1000000000000000055...')` เพราะ Pydantic แปลงผ่านการเขียนเป็นข้อความสั้นสุดของ Float ก่อน

**Enum** จะรับค่าของ Member และปฏิเสธค่าอื่น

```python
class Status(enum.Enum):
    NEW = "new"
    PAID = "paid"

ok(Status, "paid")   # Status.PAID
ok(Status, "late")   # error ชนิด enum
```

**Literal** เหมาะเมื่อมีค่าที่ยอมรับไม่กี่ค่าและไม่อยากสร้างคลาส `ok(Literal["a", "b"], "c")` ได้ `literal_error` และ Literal ยังมีบทบาทสำคัญใน Discriminated Union ([บท 4](/pydantic/unions/#discriminated-union-ดู-field-เดียวแล้วเลือกให้ตรง))

</Step>

## ชนิดสำเร็จรูป: ตัวเลขที่มีเงื่อนไข, URL, Email, SecretStr

```python
PositiveInt                   # gt=0
NonNegativeFloat              # ge=0
conint(ge=1, le=5)            # สร้างชนิดแบบเรียกฟังก์ชัน (ปัจจุบันนิยมเขียน Annotated แทน)
```

`ok(PositiveInt, 0)` ได้ `greater_than` และ `ok(conint(ge=1, le=5), 9)` ได้ `less_than_equal` ชนิดพวกนี้คือ `Annotated` ที่ใส่เงื่อนไขไว้แล้วตามที่เห็นใน [บท 2](/pydantic/fields/#annotated-เอาเงื่อนไขไปติดกับชนิด-แล้วใช้ซ้ำ)

**URL** จะแยกส่วนให้เป็น Attribute

```python
url = ok(HttpUrl, "https://example.com/a?x=1#top")
url.scheme, url.host, url.path, url.query, url.fragment
# ('https', 'example.com', '/a', 'x=1', 'top')
str(ok(HttpUrl, "https://example.com"))   # 'https://example.com/'   เติม / ให้
```

`HttpUrl` ปฏิเสธ `ftp://example.com` (`url_scheme`) ส่วน `AnyUrl` รับทุก Scheme แต่ปฏิเสธ `"not a url"` (`url_parsing`) สังเกตว่าค่าที่ได้เป็น Object ชนิดพิเศษ ไม่ใช่ `str` ดังนั้นถ้าต้องการ String ให้เรียก `str(url)`

**Email** ใช้ `EmailStr` ซึ่งต้องติดตั้ง `email-validator` เพิ่ม (`pip install "pydantic[email]"`) โดยมันจะปรับส่วน Domain เป็นตัวพิมพ์เล็ก เช่น `"Ann@Example.COM"` กลายเป็น `"Ann@example.com"` และปฏิเสธ `"ann@"`

**SecretStr** จะซ่อนค่าจาก `repr`, Log และ Dump

```python
class Login(BaseModel):
    user: str
    password: SecretStr

login = Login(user="u", password="hunter2")
repr(login)                       # "Login(user='u', password=SecretStr('**********'))"
login.password.get_secret_value() # 'hunter2'
login.model_dump_json()           # '{"user":"u","password":"**********"}'
```

ค่าจริงออกมาได้ทางเดียวคือเรียก `.get_secret_value()` อย่างตั้งใจ ทำให้ความลับหลุดได้ยากขึ้นจากความพลาดเล็กน้อย เช่น `print(login)` หรือการ Log ทั้ง Object และ `model_dump()` (โหมด Python) ก็ยังคืนค่าที่ถูกซ่อน ไม่ได้คืน `"hunter2"`

<Callout type="warn" title="SecretStr ไม่ใช่การเข้ารหัส">
`SecretStr` แค่ป้องกันการพิมพ์ออกโดยไม่ตั้งใจ ค่ายังอยู่ใน Memory เป็นข้อความธรรมดา และอ่านได้ด้วย `get_secret_value()` นะ อย่าเข้าใจผิดว่ามันเก็บความลับอย่างปลอดภัยในระดับระบบ
</Callout>

</Step>

## เช็กตัวเอง

- ส่ง `{"d": "2026-01-31"}` เข้า Model ที่ `strict=True` และ Field `d: date` ด้วย `model_validate` กับ `model_validate_json` ได้ผลต่างกันยังไง และทำไมจึงออกแบบอย่างนั้น
- ทำไม `Decimal` ถึงเหมาะกับราคามากกว่า `float` และ `Decimal` ในแบบฝึกรับ `0.1` แล้วได้ค่าอะไร
- ถ้า API ที่คุณรับข้อมูลมักส่งตัวเลขมาเป็น String คุณจะเปิด Strict ทั้ง Model ไหม เพราะอะไร

</Step>
