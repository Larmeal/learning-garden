## ผลหนึ่งผล สี่ความหมาย

เวลาอ่านผลของ Suite เราต้องแยกให้ออกว่าเป็นแบบไหนในสี่แบบนี้ เพราะแต่ละแบบต้องรับมือต่างกัน

| แบบ | เกิดจาก | ควรทำอะไร |
|---|---|---|
| ข้อมูลมีปัญหา | ค่าในข้อมูลผิดกฎ (`success=False`) | ตามหาแถวที่ผิด ตัดสินใจหยุดหรือกักข้อมูล |
| Expectation พัง | กฎใช้ไม่ได้ เช่นคอลัมน์หาย (`success=False` พร้อม `exception_info`) | แก้กฎ หรือสืบว่าโครงสร้างข้อมูลเปลี่ยนไหม |
| Suite ว่าง | ไม่มีกฎให้ประเมินเลย (`success=True`, `evaluated_expectations=0`) | ถือว่าล้ม หาสาเหตุที่กฎหาย |
| ผ่านเงียบบนตารางว่าง | ทุกกฎเป็นแบบ Column Map (`success=True`) | เพิ่มกฎจำนวนแถว ดูหน้า "[ผ่านโดยไม่มีข้อมูล](/great-expectations/reading-results/vacuous/)" |

สองแบบหลังทำให้ `success` เป็น `True` ทั้งที่ยังไม่ได้ตรวจอะไรจริง ๆ เพราะฉะนั้นการดูแค่ค่า `success` จึงไม่พอ

</Step>

## ฟังก์ชันที่ทดลองแล้ว

```python
def triage(result) -> str:
    if result.statistics["evaluated_expectations"] == 0:
        return "empty suite"
    broken = [
        x for x in result.results
        if any(isinstance(v, dict) and v.get("raised_exception")
               for v in (x.exception_info or {}).values())
    ]
    if broken:
        return f"broken expectation ({len(broken)})"
    if not result.success:
        return "data problem"
    return "ok"
```

ตารางนี้คือผลจาก `21_formats_empty.py` ส่วนที่ 5 (GX 1.24.1)

| กรณี | ผลของ `triage` |
|---|---|
| ข้อมูลดี กฎ `age` ไม่ว่าง | `ok` |
| ค่า 20 เกินกฎ `max=15` | `data problem` |
| กฎอ้างคอลัมน์ `nope` ที่ไม่มี | `broken expectation (1)` |
| Suite ที่ไม่มี Expectation เลย | `empty suite` |

โค้ดต้องเดินผ่านค่าของ `exception_info` และกรองด้วย `isinstance(v, dict)` เพราะรูปของมันต่างกันสองแบบ ข้อที่พังจะได้ Dict ที่ Key คือ Metric ที่ล้ม (ดูได้ในหน้า "[Defects GX Can Catch](/great-expectations/foundations/defects/)" ของ[บทที่ 0](/great-expectations/foundations/)) ส่วนข้อที่ไม่พังจะได้ Dict แบน `raised_exception: False, exception_traceback: None, exception_message: None` ซึ่งค่าข้างในเป็น Boolean และ `None` ไม่ใช่ Dict

<Callout type="note" title="ขอบเขต">
เราทดลองบน Pandas และ Context แบบ Ephemeral เท่านั้น ฟังก์ชันนี้เป็นเพียงตัวอย่างการจัดกลุ่ม ไม่ใช่ API ของ GX
</Callout>

## Expectation ตัวเดียวใช้สอง Suite ไม่ได้

เมื่อ Expectation ถูกเพิ่มเข้า Suite หนึ่งแล้ว เราจะเอาไปเพิ่มใน Suite อื่นตรง ๆ ไม่ได้ (ส่วนที่ 6 ของสคริปต์)

```text
RuntimeError: Cannot add Expectation because it already belongs to an ExpectationSuite.
              If you want to update an existing Expectation, please call Expectation.save().
              If you are copying this Expectation to a new ExpectationSuite, please copy it first ...
after copy + id=None: second suite has 1 expectation(s)
```

ทางที่เราทดลองแล้วคือ `copied = shared.copy()` จากนั้นตั้ง `copied.id = None` ก่อน `add_expectation` ซึ่งทำให้ Suite ที่สองมีข้อนี้ 1 ข้อ แต่ทางที่ง่ายกว่าคือสร้างอ็อบเจ็กต์ใหม่ด้วยพารามิเตอร์เดิมทุกครั้ง สคริปต์ `21` ก็ใช้ฟังก์ชัน Factory แบบนี้

</Step>
