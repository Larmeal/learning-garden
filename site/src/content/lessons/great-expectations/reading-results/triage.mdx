## ผลหนึ่งผล สี่ความหมาย

เมื่ออ่านผลของ suite มีสี่แบบที่ต้องแยกออก เพราะแต่ละแบบต้องการการตอบสนองต่างกัน

| แบบ | เกิดจาก | ควรทำอะไร |
|---|---|---|
| ข้อมูลมีปัญหา | ค่าในข้อมูลผิดกฎ (`success=False`) | ตามหาแถวที่ผิด ตัดสินใจหยุดหรือกักข้อมูล |
| expectation พัง | กฎใช้ไม่ได้ เช่นคอลัมน์หาย (`success=False` พร้อม `exception_info`) | แก้กฎ หรือสืบว่าโครงสร้างข้อมูลเปลี่ยนไหม |
| suite ว่าง | ไม่มีกฎให้ประเมินเลย (`success=True`, `evaluated_expectations=0`) | ถือว่าล้ม หาสาเหตุที่กฎหาย |
| ผ่านเงียบบนตารางว่าง | ทุกกฎเป็นแบบ column map (`success=True`) | เพิ่มกฎจำนวนแถว ดูหน้า "[ผ่านโดยไม่มีข้อมูล](/great-expectations/reading-results/vacuous/)" |

สองแบบหลังทำให้ `success` เป็น `True` ทั้งที่ยังไม่ได้ตรวจอะไรจริง การดูแค่ค่า `success` จึงไม่พอ

</Step>

## ฟังก์ชันที่ทดลองแล้ว

```python
def triage(result) -> str:
    if result.statistics["evaluated_expectations"] == 0:
        return "empty suite"
    broken = [
        x for x in result.results
        if any(isinstance(v, dict) and v.get("raised_exception")
               for v in (x.exception_info or {}).values())
    ]
    if broken:
        return f"broken expectation ({len(broken)})"
    if not result.success:
        return "data problem"
    return "ok"
```

ผลจาก `21_formats_empty.py` ส่วนที่ 5 (GX 1.24.1)

| กรณี | ผลของ `triage` |
|---|---|
| ข้อมูลดี กฎ `age` ไม่ว่าง | `ok` |
| ค่า 20 เกินกฎ `max=15` | `data problem` |
| กฎอ้างคอลัมน์ `nope` ที่ไม่มี | `broken expectation (1)` |
| suite ที่ไม่มี expectation เลย | `empty suite` |

โค้ดต้องเดินผ่านค่าของ `exception_info` และกรองด้วย `isinstance(v, dict)` เพราะรูปของมันต่างกันสองแบบ ข้อที่พังได้ dict ที่ key คือ metric ที่ล้ม (เห็นในหน้า "[ข้อมูลเสียแบบไหน GX จับได้](/great-expectations/foundations/defects/)" ของ[บทที่ 0](/great-expectations/foundations/)) ส่วนข้อที่ไม่พังได้ dict แบน `raised_exception: False, exception_traceback: None, exception_message: None` ซึ่งค่าเป็น boolean และ `None` ไม่ใช่ dict

<Callout type="note" title="ขอบเขต">
ทดลองบน pandas และ context แบบ ephemeral ฟังก์ชันนี้เป็นตัวอย่างการจัดกลุ่ม ไม่ใช่ API ของ GX
</Callout>

## expectation ตัวเดียวใช้สอง suite ไม่ได้

เมื่อ expectation ถูกเพิ่มเข้า suite หนึ่งแล้ว เอาไปเพิ่มใน suite อื่นตรงๆ ไม่ได้ (ส่วนที่ 6 ของสคริปต์)

```text
RuntimeError: Cannot add Expectation because it already belongs to an ExpectationSuite.
              If you want to update an existing Expectation, please call Expectation.save().
              If you are copying this Expectation to a new ExpectationSuite, please copy it first ...
after copy + id=None: second suite has 1 expectation(s)
```

ทางที่ทดลองแล้ว: `copied = shared.copy()` แล้วตั้ง `copied.id = None` ก่อน `add_expectation` ทำให้ suite ที่สองมีข้อนี้ 1 ข้อ ทางที่ง่ายกว่าคือสร้างอ็อบเจ็กต์ใหม่ด้วยพารามิเตอร์เดิมทุกครั้ง สคริปต์ `21` ใช้ฟังก์ชัน factory แบบนี้

</Step>
