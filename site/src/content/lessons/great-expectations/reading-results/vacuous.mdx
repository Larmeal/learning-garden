## ทำไมถึงผ่านได้

Expectation แบบ Column Map ตัดสินจากแถวที่ผิด ถ้าไม่มีแถวให้พิจารณา ก็ไม่มีแถวที่ผิด จึงผ่านตามนิยาม (ในศัพท์ตรรกะเรียกว่า Vacuously True) ในบทหลักเราดูตารางผลของสามกฎ ส่วนหน้านี้ขยายเป็นแปดกฎกับข้อมูลสองแบบ ซึ่งทดลองใน `21_formats_empty.py` ส่วนที่ 4 (GX 1.24.1, Pandas)

- ตารางว่าง คือคอลัมน์ `v` ชนิด Float ที่มี 0 แถว
- ว่างทั้งคอลัมน์ คือคอลัมน์ `v` ที่มี Null 3 แถว

</Step>

ผลที่ล้มบน Aggregate ไม่ได้มาจาก Exception (ไม่มี `raised_exception`) แต่ GX ได้ `observed_value=None` แล้วเอาไปเทียบกับช่วงไม่ผ่าน ผลจึงบอกแค่ว่า "ไม่ผ่าน" โดยไม่บอกเหตุผล เราต้องเปิดดู `observed_value` เองถึงจะเห็นว่าเป็น `None`

## กฎที่ควรเขียนคู่กัน

| ต้องการกันเรื่อง | กฎที่ใช้ |
|---|---|
| ไฟล์หรือตารางมาว่าง | `ExpectTableRowCountToBeBetween(min_value=1)` |
| คอลัมน์ว่างทั้งคอลัมน์ | `ExpectColumnValuesToNotBeNull(column=..., mostly=...)` คู่กับกฎช่วงค่า |
| ค่าเฉลี่ยหรือค่าสูงสุดคำนวณไม่ได้ | ดู `observed_value` ในผลของข้อที่ล้ม |

เราใช้ `mostly` ของ `NotBeNull` ตั้งสัดส่วน Null ที่ยอมรับได้ เช่น `mostly=0.95` ยอมให้ Null ได้ไม่เกิน 5% ของแถว (สูตรเดียวกับ `mostly` ของกฎอื่น ในที่นี้ไม่ได้ทดลองค่า 0.95 โดยตรง)

<Callout type="warn" title="ผ่านทั้งหมดไม่ได้พิสูจน์ว่ามีข้อมูล">
Suite ที่มีแต่กฎแบบ Column Map อาจผ่านทั้งชุดบนตารางว่าง ส่วนตัวเลข `result.statistics["evaluated_expectations"]` นับจำนวน Expectation ที่ถูกประเมิน ไม่ได้นับจำนวนแถว จึงมากกว่า 0 ได้แม้ตารางว่าง ตัวที่จับกรณีนี้ได้คือกฎจำนวนแถว
</Callout>
