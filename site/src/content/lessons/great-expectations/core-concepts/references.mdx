## json ของ validation definition

object ใน GX serialize เป็น json ได้ ลองดู validation definition ที่รันแล้ว (ตัด id ให้สั้น)

```json
{
  "name": "people_vd",
  "data":  { "id": "e12a128a-...", "name": "whole", "partitioner": null },
  "suite": { "name": "people_suite", "id": "3bd890de-..." },
  "id": "d7f67960-..."
}
```

ผลจริงจาก `17_object_chain.py` (GX 1.24.1) validation definition ไม่ได้ฝัง suite ทั้งก้อนหรือ DataFrame ไว้ข้างใน มันจำแค่ชื่อกับ id ของ suite และ batch definition พอรัน GX ค่อยไปหา object จริงจาก context

ฝั่ง `data` ของ json นี้ (จาก `.json()` ใน memory) มีแค่ id กับชื่อของ batch definition ไม่มี asset หรือ data source ส่วนไฟล์ที่ file context เขียนลงดิสก์เก็บเต็มกว่า คือ datasource, asset และ batch definition อย่างละ id + ชื่อ ([บทที่ 5 หน้า "เดินดูโฟลเดอร์ gx/"](/great-expectations/context-stores/tour/#สามข้อที่เห็นจากไฟล์))

## ผลต่อวิธีทำงานจริง

ใน context แบบ ephemeral ชื่อซ้ำไม่เกิดจากการรันสคริปต์ซ้ำ เพราะ context เริ่มว่างทุกครั้ง แต่ context แบบ file จำชื่อข้ามการรัน สคริปต์ `17` ส่วนที่ 5 ทดลองแล้ว

```text
first run  : suites = ['kept']
second run : suites already there = ['kept']
add the same name again: DataContextError | Cannot add ExpectationSuite with name kept because it already exists.
```

สคริปต์ที่เรียก `context.suites.add(...)` ตรงๆ จึงรันครั้งที่สองใน file context ไม่ได้ สคริปต์เดียวกันทดลองต่อ: `context.suites.get("kept")` คืน suite เดิมพร้อม id และ `context.suites.add_or_update(...)` ไม่ error คืน suite ที่ id เดิม จำนวน suite ยังเป็น 1 ตัว (add_or_update ใช้แทนค่าเนื้อหาของ suite เดิมหรือไม่ ไม่ได้ตรวจ)

ตั้งชื่อให้คงที่และบอกเนื้อหา เพราะชื่อคือสิ่งที่ใช้ค้นกลับมา และเป็นสิ่งที่เห็นใน Data Docs

<Callout type="warn" title="ที่ยังไม่ได้ทดลอง">
การเปลี่ยนชื่อ object ที่มีของอื่นอ้างอยู่ (เช่น เปลี่ยนชื่อ suite ที่ validation definition ชี้อยู่) ยังไม่ได้รัน ไม่รู้ว่าผลเป็นอย่างไร
</Callout>
