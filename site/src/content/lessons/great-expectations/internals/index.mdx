## ทำไมต้องอ่านซอร์ส

บทก่อนหน้านี้สอนวิธีใช้ GX จากพฤติกรรมที่เราสังเกตเห็นได้ แต่หลายเรื่องในเส้นทางนี้ (ตารางว่างผ่าน, Suite ว่างจาก Custom Expectation, ลำดับของ Action) ไม่มีอยู่ในเอกสาร และเราพบได้ก็เพราะเปิดซอร์สขึ้นมาแล้วทดลองตามนั่นเอง บทนี้จึงให้แผนที่ไว้สำหรับทำแบบนั้นต่อ ซึ่งจะมีประโยชน์เมื่อ

- ผลของ GX ไม่ตรงกับที่เราคาดไว้ และเอกสารก็ไม่ได้ตอบเรื่องนั้น
- เราต้องเขียน Expectation, Action หรือ Metric ขึ้นมาเอง
- เราอยากรู้ว่ารุ่นใหม่เปลี่ยนอะไรไปบ้างก่อนจะอัปเกรด

</Step>

## เทคนิค: ซอร์สคู่กับการดักฟัง

แทนที่จะอ่านอย่างเดียว เราสามารถครอบ (Monkeypatch) ฟังก์ชันที่สนใจ เพื่อดูว่ามันถูกเรียกจริงด้วยอะไรบ้าง เทคนิคนี้เองที่ใช้สร้างแล็บ Metric ใน[บทที่ 8](/great-expectations/metrics-engines/#ลองดูมันคำนวณ)

```python
from great_expectations.execution_engine import ExecutionEngine

calls = []
original = ExecutionEngine.resolve_metrics

def spy(self, metrics_to_resolve, metrics=None, runtime_configuration=None):
    calls.append(sorted(m.metric_name for m in metrics_to_resolve))
    return original(self, metrics_to_resolve, metrics, runtime_configuration)

ExecutionEngine.resolve_metrics = spy
```

เราใช้วิธีเดียวกันนี้กับ `SqlAlchemyExecutionEngine.execute_query` เพื่อดู SQL ที่ถูกส่งไป (`05_sql_bundling.py`) หรือกับเมธอดของ Action เพื่อดูลำดับการทำงานได้เหมือนกัน

</Step>

## อ่านความต่างระหว่างรุ่น

ก่อนอัปเกรด GX เราเทียบโค้ดของสองรุ่นตรง ๆ ได้เลย โดยไม่ต้องรอ Changelog วิธีทำคือติดตั้งทั้งสองรุ่น แล้วเปรียบเทียบไฟล์แกนของมัน

```bash
diff -u --strip-trailing-cr old/great_expectations/core/validation_definition.py \
                            new/great_expectations/core/validation_definition.py
```

ตารางนี้คือผลของการเทียบ 1.9.3 กับ 1.24.1 ที่ใช้ในเส้นทางนี้ โดยตัวเลขเป็นจำนวนบรรทัดที่เปลี่ยน มาจาก `32_version_diff.py` ส่วนตารางเต็มอยู่ในหน้า "[Version Differences](/great-expectations/internals/version-diff/)"

| ไฟล์ | บรรทัดที่เปลี่ยน | สาระ |
|---|---|---|
| `validator/validation_graph.py` | 0 | แกนของการคำนวณเป็นรอบไม่เปลี่ยน |
| `validator/metrics_calculator.py` | 2 | |
| `core/validation_definition.py` | 199 | Object จำ Context เจ้าของ (`owner_resolution`) และมี `get_unexpected_rows` |
| `validator/v1_validator.py` | 35 | เลือก Context จาก Owner และสร้าง Validator ด้วย Lock ต่อ Instance |
| `core/batch_definition.py` | 53 | หา Data Source ผ่าน Context เจ้าของ และเพิ่มคำอธิบายว่าพารามิเตอร์ตัวเลขควรเป็นจำนวนเต็ม |
| `expectations/expectation.py` | 558 | ส่วนที่เปลี่ยนมากที่สุด |

จะเห็นว่าแกนของระบบ (กราฟ Metric, Engine) แทบไม่ขยับ ส่วนที่เปลี่ยนคือการเชื่อม Object เข้ากับ Context ซึ่งตรงกับพฤติกรรมที่ต่างกันใน[บทที่ 5](/great-expectations/context-stores/#หลาย-context-ใน-process-เดียว) (Context ซ้อน) และ[บทที่ 6](/great-expectations/datasources-batches/#ชนิดของพารามิเตอร์-และ-dataframe) (พารามิเตอร์ตัวเลข)

## ลำดับที่แนะนำสำหรับอ่านเอง

1. `checkpoint/checkpoint.py`: `run`, `_run_validation_definitions`, `_run_actions`
2. `core/validation_definition.py`: `run` และ `is_fresh`
3. `validator/validator.py`: `graph_validate` และสามเมธอด `_generate_...`/`_resolve_...`
4. `validator/validation_graph.py`: `_resolve` กับ `_parse` (สั้นและอ่านสนุกที่สุดในกลุ่มนี้)
5. `execution_engine/execution_engine.py`: `resolve_metrics`, `_build_direct_and_bundled_...`
6. `expectations/expectation.py`: `MetaExpectation`, `metrics_validate`, `ColumnMapExpectation`
7. `expectations/metrics/column_aggregate_metrics/column_max.py` และ `metric_provider.py`: การลงทะเบียน
8. `data_context/data_context/context_factory.py`: `ProjectManager` และ `get_context`

ยังมีบางส่วนที่เส้นทางนี้ไม่ได้อ่านและไม่ได้ตรวจ ได้แก่โค้ดของ `render/` (เราอ่านเฉพาะข้อความในหน้า Data Docs ที่สร้างออกมา) `experimental/` และ Expectation ส่วนใหญ่ใน Catalog (`profile/` ไม่มีใน 1.24.1 แล้ว และ GX Cloud ก็ปิดบริการแล้ว) รวมถึงพฤติกรรมของ Spark ตอนรันจริง

## เช็กตัวเอง

- Graph บอกเราได้ว่า `Checkpoint` กับ `ValidationDefinition` อยู่ Layer ไหน แต่มีอะไรที่ Graph ไม่ได้บอก และเราควรไปหาคำตอบนั้นที่ไหน
- ถ้าอยากรู้ว่า Expectation ข้อหนึ่งทำให้ SQL ออกมากี่คำสั่ง เราจะครอบฟังก์ชันไหน
- เมื่อรุ่นใหม่ออก เราควรเทียบไฟล์ไหนก่อน เพื่อให้รู้ว่า Pipeline ของคุณได้รับผลกระทบหรือไม่

</Step>
