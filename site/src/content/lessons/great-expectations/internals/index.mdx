## ทำไมต้องอ่านซอร์ส

บทก่อนหน้าสอนวิธีใช้ GX จากพฤติกรรมที่สังเกตได้ แต่หลายเรื่องในเส้นทางนี้ (ตารางว่างผ่าน, suite ว่างจาก custom expectation, ลำดับของ action) ไม่มีในเอกสาร และพบได้เพราะเปิดซอร์สแล้วทดลองตาม บทนี้ให้แผนที่สำหรับทำแบบนั้นต่อ เหมาะเมื่อ

- ผลของ GX ไม่ตรงที่คาดและเอกสารไม่ตอบ
- ต้องเขียน expectation, action หรือ metric เอง
- อยากรู้ว่ารุ่นใหม่เปลี่ยนอะไรก่อนอัปเกรด

</Step>

## เทคนิค: ซอร์สคู่กับการดักฟัง

แทนที่จะอ่านอย่างเดียว ให้ครอบ (monkeypatch) ฟังก์ชันที่สนใจเพื่อดูว่ามันถูกเรียกจริงด้วยอะไร เทคนิคนี้สร้างแล็บ metric ใน[บทที่ 8](/great-expectations/metrics-engines/#ลองดูมันคำนวณ)

```python
from great_expectations.execution_engine import ExecutionEngine

calls = []
original = ExecutionEngine.resolve_metrics

def spy(self, metrics_to_resolve, metrics=None, runtime_configuration=None):
    calls.append(sorted(m.metric_name for m in metrics_to_resolve))
    return original(self, metrics_to_resolve, metrics, runtime_configuration)

ExecutionEngine.resolve_metrics = spy
```

ใช้แบบเดียวกันกับ `SqlAlchemyExecutionEngine.execute_query` เพื่อเห็น SQL ที่ส่งไป (`05_sql_bundling.py`) หรือกับเมธอดของ action เพื่อดูลำดับ

</Step>

## อ่านความต่างระหว่างรุ่น

ก่อนอัปเกรด GX เทียบโค้ดสองรุ่นตรงๆ ไม่ต้องรอ changelog ติดตั้งสองรุ่นแล้วเปรียบเทียบไฟล์แกน

```bash
diff -u --strip-trailing-cr old/great_expectations/core/validation_definition.py \
                            new/great_expectations/core/validation_definition.py
```

ผลของการเทียบ 1.9.3 กับ 1.24.1 ที่ใช้ในเส้นทางนี้ (จำนวนบรรทัดที่เปลี่ยน จาก `32_version_diff.py` หน้า "[สิ่งที่เปลี่ยนจาก 1.9.3 ถึง 1.24.1](/great-expectations/internals/version-diff/)" มีตารางเต็ม)

| ไฟล์ | บรรทัดที่เปลี่ยน | สาระ |
|---|---|---|
| `validator/validation_graph.py` | 0 | แกนของการคำนวณเป็นรอบไม่เปลี่ยน |
| `validator/metrics_calculator.py` | 2 | |
| `core/validation_definition.py` | 199 | object จำ context เจ้าของ (`owner_resolution`) และมี `get_unexpected_rows` |
| `validator/v1_validator.py` | 35 | เลือก context จาก owner และสร้าง validator ด้วย lock ต่อ instance |
| `core/batch_definition.py` | 53 | หา data source ผ่าน context เจ้าของ และเพิ่มคำอธิบายว่าพารามิเตอร์ตัวเลขควรเป็นจำนวนเต็ม |
| `expectations/expectation.py` | 558 | ส่วนที่เปลี่ยนมากที่สุด |

แกนของระบบ (กราฟ metric, engine) นิ่ง ส่วนที่เปลี่ยนคือการเชื่อม object กับ context ซึ่งตรงกับพฤติกรรมที่ต่างใน[บทที่ 5](/great-expectations/context-stores/#หลาย-context-ใน-process-เดียว) (context ซ้อน) และ[บทที่ 6](/great-expectations/datasources-batches/#ชนิดของพารามิเตอร์-และ-dataframe) (พารามิเตอร์ตัวเลข)

## ลำดับที่แนะนำสำหรับอ่านเอง

1. `checkpoint/checkpoint.py`: `run`, `_run_validation_definitions`, `_run_actions`
2. `core/validation_definition.py`: `run` และ `is_fresh`
3. `validator/validator.py`: `graph_validate` และสามเมธอด `_generate_...`/`_resolve_...`
4. `validator/validation_graph.py`: `_resolve` กับ `_parse` (สั้นและอ่านสนุกที่สุดในกลุ่มนี้)
5. `execution_engine/execution_engine.py`: `resolve_metrics`, `_build_direct_and_bundled_...`
6. `expectations/expectation.py`: `MetaExpectation`, `metrics_validate`, `ColumnMapExpectation`
7. `expectations/metrics/column_aggregate_metrics/column_max.py` และ `metric_provider.py`: การลงทะเบียน
8. `data_context/data_context/context_factory.py`: `ProjectManager` และ `get_context`

ส่วนที่เส้นทางนี้ไม่ได้อ่านและไม่ได้ตรวจ: โค้ดของ `render/` (อ่านเฉพาะข้อความในหน้า Data Docs ที่สร้างออกมา) `experimental/` และ expectation ส่วนใหญ่ใน catalog (`profile/` ไม่มีใน 1.24.1 แล้ว และ GX Cloud ปิดบริการแล้ว) กับพฤติกรรมของ Spark ตอนรันจริง

## เช็กตัวเอง

- graph บอกได้ว่า `Checkpoint` กับ `ValidationDefinition` อยู่ layer ไหน แต่ไม่บอกอะไร แล้วควรไปหาคำตอบนั้นที่ไหน
- อยากรู้ว่า expectation ข้อหนึ่งทำให้ SQL ออกมากี่คำสั่ง จะครอบฟังก์ชันไหน
- รุ่นใหม่ออก ควรเทียบไฟล์ไหนก่อนเพื่อรู้ว่า pipeline ของคุณกระทบไหม

</Step>
