## วิธีบันทึก

การอ่านซอร์สบอกเราได้ว่าฟังก์ชันหนึ่งสามารถเรียกอะไรได้บ้าง แต่ไม่ได้บอกว่าในรอบนี้มันเรียกอะไรจริง ๆ สคริปต์ `31_call_trace.py` จึงใช้ `sys.setprofile` ตั้งตัวดักไว้ที่ทุกการเรียกและการคืนค่าของฟังก์ชัน Python แล้วเก็บเฉพาะฟังก์ชันของ GX ที่คัดไว้ 17 ตำแหน่ง ทำให้ได้ทั้งลำดับและความลึกของการเรียก

```python
sys.setprofile(profiler)
result = cp.run(batch_parameters={"dataframe": df})
sys.setprofile(None)
```

Suite ที่ใช้มีสองกฎ (`id` ไม่เป็น Null และ `age` มีค่าสูงสุดอยู่ในช่วง) บนข้อมูล 2 แถว ผลที่ได้คือบันทึกการเรียก 33 ครั้ง ซึ่งเมื่อยุบการเรียกซ้ำที่ความลึกเดียวกันแล้วจะเหลือ 19 บรรทัด (GX 1.24.1)

## เทียบกับที่อ่านจากซอร์ส

ลำดับที่บทนี้ใช้มาตลอด (`Checkpoint.run` ไป `ValidationDefinition.run` ไป `Validator` ไป `ValidationGraph` ไป Engine ไป Expectation) ตรงกับที่บันทึกได้ และการรันจริงยังเผยให้เห็นอีกสี่เรื่อง

1. `process_expectations_for_validation` ถูกเรียกก่อน `graph_validate` โดยทำหน้าที่จัดกลุ่ม Expectation ตามคอลัมน์ ซึ่งอธิบายได้ว่าทำไมลำดับของผลถึงไม่ตรงกับ Suite ([บทที่ 3](/great-expectations/expectations-suites/nulls-and-order/#ลำดับของผลไม่ใช่ลำดับของ-suite))
2. `get_validation_dependencies` ถูกเรียกซ้อนกันสามระดับ (x2, x4, x3 ในบันทึก) เพราะคลาสของ Expectation แต่ละตัวจะเรียกเมธอดของคลาสแม่ต่อกันไปตามลำดับชั้น (`ExpectColumnValuesToNotBeNull` ไป `ColumnMapExpectation` ไป `BatchExpectation` ไป `Expectation` ตามกราฟสืบทอดในหน้า "[Knowledge Graph Queries](/great-expectations/internals/graph-queries/#คำถามที่สาม-คลาสสืบทอดจากอะไร)") โดยตัวเลขเหล่านี้นับครั้งของทั้งสอง Expectation รวมกัน
3. `resolve_metrics` ถูกเรียก 5 ครั้ง เท่ากับ 5 รอบของกราฟ Metric ใน[บทที่ 8](/great-expectations/metrics-engines/#ลองดูมันคำนวณ) (รอบที่ห้าเป็นรอบว่าง) ส่วน `resolve_metric_bundle` ของ Pandas ถูกเรียก 4 ครั้ง ซึ่งก็คือรอบที่มี Metric จริง
4. `store_validation_results` ถูกเรียกก่อน `_run_actions` ซึ่งยืนยันสิ่งที่[บทที่ 9](/great-expectations/actions-data-docs/#ลำดับและเงื่อนไข) บอกไว้ว่าผลถูกเก็บก่อนที่ Action จะทำงาน

นอกจากนี้ `_validate` ของสองกฎอยู่ในไฟล์ของแต่ละ Expectation (`expect_column_values_to_not_be_null.py` และ `expect_column_max_to_be_between.py`) ไม่ได้อยู่ในไฟล์ฐาน

<Callout type="note" title="ขอบเขตของบันทึก">
บันทึกนี้มาจาก Pandas และ Suite เล็ก ๆ เท่านั้นนะ ถ้าเป็นเส้นทางบน SQL หรือ Spark จะผ่านฟังก์ชันอื่นในชั้น Engine (เช่น `resolve_metric_bundle` ของ SQL) และการรันที่มี Action ก็จะมีฟังก์ชันเพิ่มเข้ามา อีกอย่างคือ `sys.setprofile` ทำให้การรันช้าลง จึงเหมาะกับการใช้ศึกษา ไม่ใช่ใช้ในงานจริง
