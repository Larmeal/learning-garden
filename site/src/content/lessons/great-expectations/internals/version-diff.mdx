## วิธีเทียบ

สคริปต์ `32_version_diff.py` เทียบไฟล์ `.py` ของ package `great_expectations` ที่ checkout รุ่น 1.9.3 (รุ่นที่ knowledge graph วิเคราะห์) กับรุ่น 1.24.1 ที่ติดตั้งในโปรเจกต์ นับบรรทัดที่เพิ่มรวมกับบรรทัดที่ลบด้วย `difflib` และตัดความต่างของการขึ้นบรรทัดใหม่ (CRLF กับ LF) ออก

| | จำนวน |
|---|---|
| ไฟล์ `.py` ใน 1.9.3 | 482 |
| ไฟล์ `.py` ใน 1.24.1 | 497 |
| มีในทั้งสองรุ่น | 473 |
| เหมือนกันทุกบรรทัด | 242 |
| ต่างกัน | 231 |
| มีเฉพาะ 1.9.3 | 9 |
| มีเฉพาะ 1.24.1 | 24 |

ไฟล์ที่ติดตั้งมาจาก PyPI ส่วน 1.9.3 มาจาก checkout ของ repo ผลที่ต่างอาจรวมความต่างของการบรรจุ (เช่นไฟล์ `_version.py`) ด้วย

</Step>

## ไฟล์ที่ถูกเพิ่มและลบ

ตัวอย่างจากสคริปต์ (ไม่ใช่รายการเต็ม)

| มีเฉพาะ 1.24.1 | มีเฉพาะ 1.9.3 |
|---|---|
| `core/owner_resolution.py` | `data_context/store/database_store_backend.py` |
| `datasource/fluent/batch_parameter_normalization.py` | `data_context/store/query_store.py` |
| `datasource/fluent/fabric_datasource.py` | `expectations/regex_based_column_map_expectation.py` |
| `agent_skills/installer.py` | `expectations/set_based_column_map_expectation.py` |
| `compatibility/pyodbc.py` | `profile/` (ทั้ง package) |

ที่เกี่ยวกับสิ่งที่เรียนมา

- `owner_resolution.py` ตรงกับพฤติกรรมที่ context เจ้าของถูกจำใน object ([บทที่ 5](/great-expectations/context-stores/): การสร้าง context ที่สองไม่ทำให้ object เก่าพังใน 1.24.1)
- `batch_parameter_normalization.py` ตรงกับเรื่องพารามิเตอร์ตัวเลขที่ควรเป็นจำนวนเต็มพร้อมคำเตือนเลิกสนับสนุน ([บทที่ 6](/great-expectations/datasources-batches/)) ข้อนี้เป็นการเชื่อมจากชื่อไฟล์กับพฤติกรรมที่ทดลองเห็น ไม่ได้อ่านเนื้อไฟล์
- `regex_based_column_map_expectation.py` และ `set_based_column_map_expectation.py` ที่หายไปคือคลาสแม่แบบสำหรับเขียน expectation แบบ regex หรือแบบชุดค่า ใน 1.24.1 ไม่มีสองไฟล์นี้ [บทที่ 12](/great-expectations/custom-expectations/) ใช้ `ColumnMapExpectation` ตรงๆ ซึ่งยังมีอยู่ ตัวอย่างบนเว็บที่สืบทอดจากสองคลาสนี้จึงรันไม่ได้ใน 1.24.1 (สรุปจากการที่ไฟล์หายไป ไม่ได้ลองสืบทอดคลาสนั้น)
- `profile/` ทั้ง package หายไป ใครเคยใช้ profiler ของรุ่นเก่าต้องหาทางอื่น

<Callout type="warn" title="ก่อนอัปเกรด pipeline จริง">
ตารางนี้บอกว่าอะไรเปลี่ยน ไม่ได้บอกว่า pipeline ของคุณได้รับผลอย่างไร เทียบไฟล์ที่ pipeline ของคุณเรียก แล้วรัน suite ทดสอบของ gate ([บทที่ 10](/great-expectations/pipeline-integration/)) บนรุ่นใหม่ก่อนปล่อย
</Callout>
