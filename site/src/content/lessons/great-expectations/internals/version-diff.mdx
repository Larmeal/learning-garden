## วิธีเทียบ

สคริปต์ `32_version_diff.py` เทียบไฟล์ `.py` ของ Package `great_expectations` ที่ Checkout รุ่น 1.9.3 (รุ่นที่ Knowledge Graph วิเคราะห์) กับรุ่น 1.24.1 ที่ติดตั้งในโปรเจกต์ โดยนับบรรทัดที่เพิ่มรวมกับบรรทัดที่ลบด้วย `difflib` และตัดความต่างของการขึ้นบรรทัดใหม่ (CRLF กับ LF) ออกไปก่อน

| | จำนวน |
|---|---|
| ไฟล์ `.py` ใน 1.9.3 | 482 |
| ไฟล์ `.py` ใน 1.24.1 | 497 |
| มีในทั้งสองรุ่น | 473 |
| เหมือนกันทุกบรรทัด | 242 |
| ต่างกัน | 231 |
| มีเฉพาะ 1.9.3 | 9 |
| มีเฉพาะ 1.24.1 | 24 |

ไฟล์ของรุ่นที่ติดตั้งมาจาก PyPI ส่วน 1.9.3 มาจาก Checkout ของ Repo เพราะฉะนั้นผลที่ต่างกันอาจรวมความต่างของการบรรจุ (เช่นไฟล์ `_version.py`) เข้ามาด้วย

</Step>

## ไฟล์ที่ถูกเพิ่มและลบ

ตารางนี้เป็นเพียงตัวอย่างจากสคริปต์ ไม่ได้เป็นรายการเต็ม

| มีเฉพาะ 1.24.1 | มีเฉพาะ 1.9.3 |
|---|---|
| `core/owner_resolution.py` | `data_context/store/database_store_backend.py` |
| `datasource/fluent/batch_parameter_normalization.py` | `data_context/store/query_store.py` |
| `datasource/fluent/fabric_datasource.py` | `expectations/regex_based_column_map_expectation.py` |
| `agent_skills/installer.py` | `expectations/set_based_column_map_expectation.py` |
| `compatibility/pyodbc.py` | `profile/` (ทั้ง Package) |

ไฟล์ที่เกี่ยวข้องกับสิ่งที่เราเรียนมามีดังนี้

- `owner_resolution.py` ตรงกับพฤติกรรมที่ Object จำ Context ที่เป็นเจ้าของมันไว้ ([บทที่ 5](/great-expectations/context-stores/#หลาย-context-ใน-process-เดียว) ที่ว่าการสร้าง Context ที่สองไม่ทำให้ Object เก่าพังใน 1.24.1)
- `batch_parameter_normalization.py` ตรงกับเรื่องพารามิเตอร์ตัวเลขที่ควรเป็นจำนวนเต็ม พร้อมคำเตือนเลิกสนับสนุน ([บทที่ 6](/great-expectations/datasources-batches/#ชนิดของพารามิเตอร์-และ-dataframe)) ข้อนี้เป็นการเชื่อมจากชื่อไฟล์เข้ากับพฤติกรรมที่เราทดลองเห็น ไม่ได้อ่านเนื้อไฟล์นะ
- `regex_based_column_map_expectation.py` และ `set_based_column_map_expectation.py` ที่หายไปคือคลาสแม่แบบสำหรับเขียน Expectation แบบ Regex หรือแบบชุดค่า ซึ่งใน 1.24.1 ไม่มีสองไฟล์นี้แล้ว [บทที่ 12](/great-expectations/custom-expectations/column-map/#ทำไมต้องเป็นสองคลาส) จึงใช้ `ColumnMapExpectation` ตรง ๆ ที่ยังมีอยู่ และตัวอย่างบนเว็บที่สืบทอดจากสองคลาสนี้ก็จะรันไม่ได้ใน 1.24.1 (สรุปจากการที่ไฟล์หายไป ไม่ได้ลองสืบทอดคลาสนั้นจริง)
- `profile/` หายไปทั้ง Package ดังนั้นใครที่เคยใช้ Profiler ของรุ่นเก่าต้องหาทางอื่นแทน

<Callout type="warn" title="ก่อนอัปเกรด Pipeline จริง">
ตารางนี้บอกได้แค่ว่าอะไรเปลี่ยนไปบ้าง แต่ไม่ได้บอกว่า Pipeline ของคุณจะได้รับผลอย่างไร เราจึงควรเทียบไฟล์ที่ Pipeline ของคุณเรียกใช้ แล้วรัน Suite ทดสอบของ Gate ([บทที่ 10](/great-expectations/pipeline-integration/#ทดสอบ-suite-เหมือนทดสอบโค้ด)) บนรุ่นใหม่ก่อนปล่อยจริง
</Callout>
