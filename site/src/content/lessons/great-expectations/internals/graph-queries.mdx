## หน้าตาของไฟล์

`subjects/great-expectations/graphs/gx-current/knowledge-graph.json` เป็น JSON ที่มี 6 ส่วน คือ `version`, `project`, `nodes` (1,664), `edges` (5,462), `layers` (9) และ `tour` (14 ขั้น) โดยแต่ละ Node จะมี `id`, `type` (Class 796, File 544, Function 320, Document 4), `name`, `filePath`, `summary`, `tags`, `complexity` ส่วนแต่ละ Edge จะมี `source`, `target`, `type`, `weight` สคริปต์ `33_graph_queries.py` เปิดไฟล์นี้ด้วย `json.load` ธรรมดา ๆ ไม่ได้ใช้เครื่องมือพิเศษอะไร

</Step>

## คำถามที่สอง: ใครนำเข้า validation_definition.py

```python
target = "file:great_expectations/core/validation_definition.py"
who = [e["source"] for e in g["edges"] if e["type"] == "imports" and e["target"] == target]
```

จะได้ 4 ไฟล์ คือ `__init__.py` (ที่ราก), `checkpoint/checkpoint.py`, `core/__init__.py` และ `core/factory/validation_definition_factory.py` ซึ่งตรงกับแผนภาพของ[บทที่ 7](/great-expectations/validation-checkpoints/#สองชั้นของการรัน) ที่ว่า Checkpoint พึ่ง Validation Definition และ Factory ของ Context เป็นตัวสร้างมันขึ้นมา

## คำถามที่สาม: คลาสสืบทอดจากอะไร

คราวนี้เราไล่ Edge ชนิด `inherits` ขึ้นไปจาก `ExpectColumnValuesToNotBeNull`

```text
ExpectColumnValuesToNotBeNull -> ColumnMapExpectation -> BatchExpectation -> Expectation
```

ผลนี้ตรงกับที่[บทที่ 12](/great-expectations/custom-expectations/column-map/#ทำไมต้องเป็นสองคลาส) บอกไว้ว่า `ColumnMapExpectation` สืบจาก `BatchExpectation` ที่สืบจาก `Expectation` อีกทอดหนึ่ง และเป็นสาเหตุที่ `get_validation_dependencies` ในบันทึกการเรียกถูกเรียกซ้อนกันสามระดับ (ดูได้ที่หน้า "[ตามรอยฟังก์ชันของ GX](/great-expectations/internals/trace-a-run/)")

</Step>

## สิ่งที่ Graph ตอบไม่ได้

จาก Edge ทั้งหมด 5,462 เส้น มีเส้น `calls` เพียง 44 เส้น (ส่วนที่ 6 ของสคริปต์) Graph จึงตอบคำถามเรื่องโครงสร้างได้ดี เช่น ใครนำเข้าใคร ใครสืบทอดใคร และไฟล์ไหนอยู่ Layer ไหน แต่ตอบเรื่องลำดับการเรียกไม่ได้ ซึ่งเราต้องใช้การบันทึกอย่างที่ทำในหน้าก่อนหน้า

อีกอย่างคือ Graph นี้เป็นของรุ่น 1.9.3 ไม่ใช่ 1.24.1 ดังนั้นไฟล์ที่ถูกเพิ่มหรือลบในรุ่นหลัง (ดูหน้า "[สิ่งที่เปลี่ยนจาก 1.9.3 ถึง 1.24.1](/great-expectations/internals/version-diff/#ไฟล์ที่ถูกเพิ่มและลบ)") จึงไม่ตรงกับใน Graph

<Callout type="note" title="Tour ของ Graph">
Graph มี Tour 14 ขั้น ตั้งแต่ "Project Overview and Entry Point" จนถึง "Profiling, Metric Repository, Self-Check" ซึ่งเป็นลำดับอ่านที่สร้างขึ้นตอนวิเคราะห์ จึงมีประโยชน์ในฐานะหัวข้อให้เราไล่ตาม แต่เนื้อหาในแต่ละขั้นไม่ได้ตรวจเทียบกับการรันนะ
</Callout>
