## หน้าตาของไฟล์

`subjects/great-expectations/graphs/gx-current/knowledge-graph.json` เป็น JSON ที่มี 6 ส่วน: `version`, `project`, `nodes` (1,664), `edges` (5,462), `layers` (9) และ `tour` (14 ขั้น) แต่ละ node มี `id`, `type` (class 796, file 544, function 320, document 4), `name`, `filePath`, `summary`, `tags`, `complexity` และแต่ละ edge มี `source`, `target`, `type`, `weight` สคริปต์ `33_graph_queries.py` เปิดไฟล์นี้ด้วย `json.load` ธรรมดา

## คำถามที่สอง: ใครนำเข้า validation_definition.py

```python
target = "file:great_expectations/core/validation_definition.py"
who = [e["source"] for e in g["edges"] if e["type"] == "imports" and e["target"] == target]
```

ได้ 4 ไฟล์: `__init__.py` (ที่ราก), `checkpoint/checkpoint.py`, `core/__init__.py` และ `core/factory/validation_definition_factory.py` ตรงกับแผนภาพของ[บทที่ 7](/great-expectations/validation-checkpoints/#สองชั้นของการรัน): checkpoint พึ่ง validation definition และ factory ของ context สร้างมัน

## คำถามที่สาม: คลาสสืบทอดจากอะไร

ไล่ edge ชนิด `inherits` ขึ้นไปจาก `ExpectColumnValuesToNotBeNull`

```text
ExpectColumnValuesToNotBeNull -> ColumnMapExpectation -> BatchExpectation -> Expectation
```

ตรงกับที่[บทที่ 12](/great-expectations/custom-expectations/column-map/#ทำไมต้องเป็นสองคลาส) บอกว่า `ColumnMapExpectation` สืบจาก `BatchExpectation` ที่สืบจาก `Expectation` และเป็นสาเหตุที่ `get_validation_dependencies` ในบันทึกการเรียกถูกเรียกซ้อนกันสามระดับ (หน้า "[ตามรอยฟังก์ชันของ GX](/great-expectations/internals/trace-a-run/)")

</Step>

## สิ่งที่ graph ตอบไม่ได้

จาก edge ทั้งหมด 5,462 เส้น มีเส้น `calls` เพียง 44 เส้น (ส่วนที่ 6 ของสคริปต์) graph จึงตอบคำถามเรื่องโครงสร้างได้ดี (ใครนำเข้าใคร ใครสืบทอดใคร ไฟล์ไหนอยู่ layer ไหน) แต่ตอบเรื่องลำดับการเรียกไม่ได้ ซึ่งต้องใช้การบันทึกอย่างหน้าก่อนหน้า

graph ยังเป็นของรุ่น 1.9.3 ไม่ใช่ 1.24.1 ไฟล์ที่เพิ่มหรือลบในรุ่นหลัง (หน้า "[สิ่งที่เปลี่ยนจาก 1.9.3 ถึง 1.24.1](/great-expectations/internals/version-diff/#ไฟล์ที่ถูกเพิ่มและลบ)") จึงไม่ตรง

<Callout type="note" title="tour ของ graph">
graph มี tour 14 ขั้น ตั้งแต่ "Project Overview and Entry Point" จนถึง "Profiling, Metric Repository, Self-Check" เป็นลำดับอ่านที่สร้างตอนวิเคราะห์ มีประโยชน์เป็นหัวข้อ แต่เนื้อหาในแต่ละขั้นไม่ได้ตรวจเทียบกับการรัน
</Callout>
