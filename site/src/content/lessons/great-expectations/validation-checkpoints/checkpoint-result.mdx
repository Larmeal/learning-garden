## สองทางอ่านผล

เราอ่าน `CheckpointResult` ได้สองทาง ซึ่งให้ข้อมูลคนละระดับกัน

| ทาง | คืนอะไร | ใช้เมื่อ |
|---|---|---|
| `result.describe()` | JSON สรุป (สตริง) ของทั้ง Checkpoint | ส่งออกเป็นข้อความ Log หรือ API |
| `result.run_results` | Dict: `ValidationResultIdentifier` ไปยัง `ExpectationSuiteValidationResult` | เขียนโค้ดวนดูผลเอง เข้าถึงทุกฟิลด์ของผล |

จากผลของสคริปต์ `25_checkpoint_shapes.py` ส่วนที่ 2 และ 7 (GX 1.24.1) เราพบว่า `describe()` มี Key ระดับบน 3 ตัว คือ `success`, `statistics` และ `validation_results`

</Step>

describe() เป็นสรุปที่ตัดข้อมูลบางอย่างออกไป (เช่น `meta`, `exception_info` ของแต่ละข้อ) จึงเหมาะกับการดูภาพรวม ถ้าต้องการ `exception_info` เราต้องเข้าทาง `run_results` แทน

ส่วนที่ว่า describe() ตัด `exception_info` ออกจริงหรือไม่ เราตรวจได้จาก Key ที่พิมพ์ออกมา ซึ่ง `expectations[0]` มี 4 Key คือ `expectation_type`, `success`, `kwargs`, `result` และไม่มี `exception_info`

## ดึงรายการที่ล้มออกมา

เราวนอ่านผ่าน `run_results` ตรง ๆ ได้เลย

```python
def failed_expectations(res):
    out = []
    for key, vres in res.run_results.items():
        for r in vres.results:
            if not r.success:
                out.append((
                    key.expectation_suite_identifier.name,
                    r.expectation_config.type,
                    r.expectation_config.kwargs.get("column"),
                    r.result.get("unexpected_count"),
                ))
    return out
```

เมื่อรันกับ Checkpoint ข้างบนจะได้ผลแบบนี้

```text
('suite_age', 'expect_column_values_to_not_be_null', 'age', 1)
('suite_age', 'expect_column_values_to_be_between', 'age', 1)
```

ข้อ `suite_ids` ผ่าน จึงไม่ถูกลิสต์ออกมา และฟังก์ชันนี้ไม่ได้แยกว่าล้มเพราะข้อมูลหรือเพราะ Exception ถ้าต้องแยก ให้ใช้ลำดับคำถามจาก[บทที่ 4 หน้า "อ่านผลที่ไม่ผ่านอย่างเป็นระบบ"](/great-expectations/reading-results/triage/#ลำดับคำถาม)

<Callout type="note" title="ตั้งชื่อ Run ได้">
`cp.run(..., run_id=RunIdentifier(run_name="nightly-2024-02-01"))` ใช้ตั้งชื่อรอบรัน และเราทดลองแล้วว่าชื่อนี้ไปอยู่ใน `run_results` ทุกรายการ (`RunIdentifier` Import จาก `great_expectations.core.run_identifier`) ส่วน `Checkpoint.run` รับพารามิเตอร์สามตัวเท่านั้น คือ `batch_parameters`, `expectation_parameters` และ `run_id`
</Callout>
