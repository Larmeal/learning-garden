## สองตัว หนึ่ง checkpoint

สคริปต์ `25_checkpoint_shapes.py` สร้าง validation definition สองตัวและใส่ใน checkpoint เดียว (GX 1.24.1, pandas)

| validation definition | suite | ข้อมูลที่ตรวจ |
|---|---|---|
| `vd_ids` | `id` ต้องไม่ซ้ำ | DataFrame `id=[1,2,3]` |
| `vd_age` | `age` ไม่เป็น null และอยู่ใน 0 ถึง 120 | `age=[10, None, 400]` |

```python
cp = context.checkpoints.add(gx.Checkpoint(name="cp", validation_definitions=[vd_ids, vd_age]))
result = cp.run(batch_parameters={"dataframe": frame})
```

ผลที่พิมพ์ออกมา

```text
type: CheckpointResult | success: False
run_results entries: 2
  suite=suite_ids  success=True   evaluated=1
  suite=suite_age  success=False  evaluated=2
distinct run ids across validations: 1
results stored by this run: 2
```

- `success` ของ checkpoint เป็น `False` เพราะตัวที่สองไม่ผ่าน ผลรวมคือ "ทุกตัวผ่านเท่านั้นจึงผ่าน"
- `run_results` มีหนึ่งรายการต่อ validation definition
- ทั้งสองได้ `run_id` เดียวกัน (distinct = 1) ตัวนี้บอกว่าอยู่ในรอบรันเดียวกัน
- ผลถูกเก็บลง store สองรายการ หนึ่งต่อ validation

</Step>

## พารามิเตอร์ชุดเดียวไปถึงทุกตัว

`batch_parameters` ที่ส่งให้ `cp.run(...)` ถูกส่งต่อให้ทุก validation definition ถ้า validation หนึ่งใช้ DataFrame asset (ต้องการ key `dataframe`) กับอีกตัวใช้ตาราง SQL ทั้งตาราง (ไม่ต้องมี key) ชุดพารามิเตอร์เดียวเข้ากับทั้งคู่ไม่ได้ ส่วนที่ 4 ของสคริปต์ทดลองตรงนี้

```text
raised: InvalidBatchRequestError | batch parameters should only contain keys from the following set: set()
        but your specified keys contain {'dataframe'} which is not valid.
```

ข้อความบอกว่า batch ของ SQL รับ key ได้ศูนย์ตัว แต่ได้ `dataframe` มา ผลคือ `cp.run(...)` raise ทั้งก้อน ไม่ได้คืนผลของตัวที่ผ่านไปแล้ว ส่วนว่าตัวแรกของคู่ถูกรันก่อนหรือไม่ ไม่ได้ตรวจ

แนวทางที่ปลอดภัยคือจัดกลุ่ม validation definition ใน checkpoint ตามชนิดของ batch definition (ที่ใช้ key ชุดเดียวกัน) และมี checkpoint แยกต่อกลุ่ม

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
ไม่ได้ทดลองกรณีที่ validation สองตัวใช้ key ชุดเดียวกันแต่ความหมายต่างกัน (เช่น ตัวหนึ่งไฟล์รายวัน อีกตัวไฟล์รายเดือน) และไม่ได้ทดลองการรันขนานกันของ validation ในหนึ่ง checkpoint
