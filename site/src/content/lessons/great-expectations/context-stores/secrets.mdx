## ปัญหา: ค่าลับไม่ควรอยู่ใน git

connection string ของฐานข้อมูลมักมีรหัสผ่าน ถ้าเขียนลงใน `great_expectations.yml` ซึ่ง commit เข้า git รหัสผ่านก็รั่วไปกับ repo GX แก้ด้วยการให้เขียนเป็นตัวแปร `${NAME}` แล้วแทนค่าตอนใช้งาน

```python
src = context.data_sources.add_sqlite("viafile", connection_string="${MY_DB_URL}")
```

สคริปต์ `23_persistence_config.py` ส่วน config_variables ทดลองสองแหล่งของค่า (GX 1.24.1, SQLite)

## วิธีใช้ที่แนะนำ

1. เขียนเป็น `${NAME}` ใน connection string ทุกตัวที่มีค่าลับ
2. บนเครื่องพัฒนา ใส่ค่าใน `uncommitted/config_variables.yml` (อยู่ใน `.gitignore` แล้ว)
3. บน server หรือ CI ตั้ง environment variable ซึ่งชนะไฟล์ จึงไม่ต้องมีไฟล์นั้นบนเครื่องเหล่านั้น

ข้อ 3 อาศัยผลที่ทดลองแล้วว่า environment variable ชนะ ส่วนข้อ 1 และ 2 ทดลองแล้วทั้งคู่

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
ไม่ได้ทดลองตัวแปรแบบซ้อน (dict) ในไฟล์ ไม่ได้ทดลองรูป `$NAME` แบบไม่มีปีกกา และไม่ได้ตรวจว่าค่าลับรั่วลงใน Data Docs หรือผลตรวจหรือไม่ ควรเปิดดู `uncommitted/` ด้วยตัวเองก่อนแชร์
</Callout>
