## สร้างแล้วดูของที่ได้

สคริปต์ `22_file_context_tour.py` สร้าง file context ในโฟลเดอร์ชั่วคราว เพิ่ม data source, suite สองกฎ, validation definition, checkpoint ที่มี `UpdateDataDocsAction` แล้วรันหนึ่งรอบ (GX 1.24.1)

```python
context = gx.get_context(mode="file", project_root_dir=root)
# ... add_pandas, suites.add, validation_definitions.add, checkpoints.add ...
result = checkpoint.run(batch_parameters={"dataframe": df})
```

## สามข้อที่เห็นจากไฟล์

1. validation definition ที่เก็บในไฟล์อ้างสามชั้นด้วยชื่อ + id: datasource, asset และ batch definition ต่างจากผลของ `.json()` ใน memory ที่หน้า "[อ้างอิงกันด้วยชื่อและ id](/great-expectations/core-concepts/references/)" ([บทที่ 1](/great-expectations/core-concepts/)) ซึ่งมีแค่ batch definition การ serialize ลงไฟล์จึงเก็บสายอ้างอิงเต็มกว่า
2. ผลตรวจไม่เก็บข้อมูลจริง ที่ `batch_parameters.dataframe` เขียนไว้ว่า `<DATAFRAME>` มีแค่ลายนิ้วมือของข้อมูล (`pandas_data_fingerprint`) ไว้ตรวจว่าเป็นข้อมูลก้อนเดียวกันหรือไม่ (ไม่ได้ทดลองกรณีลายนิ้วมือเปลี่ยน)
3. `.gitignore` ที่ GX สร้างมีบรรทัดเดียวคือ `uncommitted/` ผลตรวจ รายงาน และ `config_variables.yml` จึงไม่เข้า git โดยค่าเริ่มต้น ส่วน `expectations/`, `checkpoints/`, `validation_definitions/` และ `great_expectations.yml` เข้า git ได้ ทีมจึงรีวิว suite ผ่าน pull request ได้เหมือนโค้ด

<Callout type="note" title="ไม่ได้เปิดดู">
ไม่ได้เปิดไฟล์ HTML ของ Data Docs ในเบราว์เซอร์ และไม่ได้ทดลองว่าไฟล์ JSON ของ suite ที่แก้ด้วยมือถูกโหลดกลับถูกต้องหรือไม่
</Callout>
