## Expectation มีหกตระกูล

Expectation ที่ GX ให้มาอยู่ในโฟลเดอร์ `expectations/core/` และแบ่งเป็นตระกูลตามชนิดคำถาม ซึ่งตระกูลเป็นตัวกำหนดว่า GX ต้องคำนวณอะไร ([บทที่ 8](/great-expectations/metrics-engines/#ประกาศ-แล้วค่อยตัดสิน))

| ตระกูล | ถามอะไร | ตัวอย่าง | จำนวนใน 1.9.3* |
|---|---|---|---|
| Column Map | ถามทุกแถวของคอลัมน์ แล้วนับสัดส่วนที่ผิด | `ExpectColumnValuesToNotBeNull`, `...ToBeBetween`, `...ToMatchRegex` | 26 |
| Column Aggregate | ถามค่าสรุปหนึ่งค่าของคอลัมน์ | `ExpectColumnMaxToBeBetween`, `ExpectColumnMeanToBeBetween` | 15 |
| Table (Batch) | ถามเรื่องทั้งตาราง | `ExpectTableRowCountToEqual`, `ExpectTableColumnsToMatchSet` | 13 |
| column pair map | เทียบสองคอลัมน์ทีละแถว | `ExpectColumnPairValuesAToBeGreaterThanB` | 3 |
| Multicolumn Map | ถามหลายคอลัมน์ทีละแถว | `ExpectCompoundColumnsToBeUnique` | 3 |
| Query | ถามผลของ SQL ที่เขียนเอง | `ExpectQueryResultsToMatchComparison` | 1 |

\* นับจากการอ่านซอร์ส 1.9.3 ตัวเลขใน 1.24.1 อาจต่างเล็กน้อย รายการทางการอยู่ที่ Expectations Gallery บน greatexpectations.io

คำถามที่ควรถามตัวเองก่อนเลือกคือ ข้อผิดพลาดที่เรากลัวเป็นปัญหา "บางแถว" (Column Map), "ภาพรวมของคอลัมน์" (Aggregate) หรือ "ทั้งตาราง" (Table)

</Step>

<Step>

## Column Map กับ Aggregate ตัดสินต่างกัน

- Column Map นับว่าแถวไหนผิด ผลจึงบอก `unexpected_count`, `unexpected_percent` และตัวอย่างค่าที่ผิด และใช้ `mostly` ได้
- Aggregate ได้ค่าเดียว เช่น `column.max` แล้วเทียบกับช่วงที่กำหนด ผลบอก `observed_value`

ตัวอย่าง `ExpectColumnMaxToBeBetween(column="age", min_value=0, max_value=120)` กับ `age = [10, None, 30, 400]` ได้ `observed_value = 400.0` และไม่ผ่าน โดยมันไม่บอกว่าแถวไหนผิด ถ้าต้องรู้แถว ก็ให้ใช้ `ExpectColumnValuesToBeBetween`

</Step>

<Step>

## Mostly: ยอมให้ผิดได้เท่าไร

ข้อมูลจริงไม่เคยสะอาด 100 เปอร์เซ็นต์ ดังนั้น Expectation แบบ Column Map จึงรับ `mostly` (ค่า 0 ถึง 1) เป็นสัดส่วนขั้นต่ำของแถวที่ต้องถูก โดยสูตรจากซอร์สคือ

`(แถวที่พิจารณา - แถวที่ผิด) / แถวที่พิจารณา ≥ mostly`

แถวที่เป็น Null จะไม่ถูกนับในแถวที่พิจารณา (สำหรับ Expectation ส่วนใหญ่ในตระกูลนี้) ทดลองแล้ว: `age = [10, None, 30, 400]` กับ `ExpectColumnValuesToBeBetween(0..120)` จะพิจารณา 3 แถว ผิด 1 แถว สัดส่วน 0.667 ซึ่งผ่านเมื่อ `mostly=0.66` และไม่ผ่านเมื่อ `mostly=0.67`

<MostlyLab client:visible />

<Callout type="warn" title="Mostly ไม่ได้ซ่อน Null ให้">
Null ไม่ถูกนับ ดังนั้นถ้า `age` เป็น Null เกือบทั้งคอลัมน์ Expectation ช่วงค่าจะยังผ่านอยู่ เราจึงต้องมี `ExpectColumnValuesToNotBeNull` (อาจใส่ `mostly` ของมันเอง) แยกอีกข้อ
</Callout>

</Step>

<Step>

## Suite ทำตัวเหมือนเซ็ต

`ExpectationSuite` เก็บ Expectation ที่ "ไม่ซ้ำกัน" ถ้าเพิ่ม Expectation ที่เหมือนกันทุกอย่างซ้ำ GX จะข้ามให้เงียบ ๆ ไม่ Error

```python
suite.add_expectation(gxe.ExpectColumnValuesToNotBeNull(column="id"))
suite.add_expectation(gxe.ExpectColumnValuesToNotBeNull(column="id"))
len(suite.expectations)   # 1
```

และถ้า Suite ถูก Add เข้า Context แล้ว `add_expectation` จะบันทึกลง Store ให้ทันที ไม่ต้องเรียก Save เอง

พารามิเตอร์ที่ยังไม่รู้ค่าตอนเขียน Suite ให้ใส่เป็น Suite Parameter แล้วส่งค่าตอนรัน

```python
suite.add_expectation(gxe.ExpectTableRowCountToEqual(value={"$PARAMETER": "expected_rows"}))
vd.run(batch_parameters={"dataframe": df}, expectation_parameters={"expected_rows": 3})
```

(ทดลองแล้วใน `04_batches.py`: ส่ง 3 ได้ผ่าน ส่ง 5 ได้ไม่ผ่าน)

</Step>

## เขียน Expectation จากอะไร

| แหล่ง | เหมาะกับ | ข้อควรระวัง |
|---|---|---|
| ถามเจ้าของข้อมูล | กฎของธุรกิจ (สถานะมีแค่ห้าค่า, ราคาไม่ติดลบ) | ได้กฎที่ถูกต้องที่สุด แต่ใช้เวลา |
| ดูข้อมูลจริง | ช่วงค่า, สัดส่วน Null ปกติ | ถ้าข้อมูลวันนี้เสียอยู่แล้ว จะเขียนกฎจากข้อมูลเสีย |
| สถิติย้อนหลัง | จำนวนแถวต่อวัน | ต้องเผื่อฤดูกาลและวันหยุด |

เราควรเริ่มจากกฎที่ถ้าผิดแล้วเสียหายมากที่สุด (Key ห้ามซ้ำ จำนวนแถวห้ามเป็นศูนย์) ไม่จำเป็นต้องเขียนให้ครบทุกคอลัมน์ตั้งแต่รอบแรก

</Step>

<Step>

## เช็กตัวเอง

- ถ้าต้องการรู้ว่า "อายุเกิน 120 กี่แถว" ควรใช้ Expectation ตระกูลไหน
- ถ้า `mostly=0.9` กับข้อมูล 10 แถว ผิดได้กี่แถวพอดีจึงจะยังผ่าน (ไม่มี Null)
- ถ้าเพิ่ม Expectation เดิมซ้ำสองครั้ง `len(suite.expectations)` จะเป็นเท่าไร

</Step>

<Step>

## หน้าย่อยของบทนี้

1. ตระกูลของ Expectation ที่เห็นจากผลจริง: รัน 13 Expectation แล้วเทียบผล พร้อมผังเลือกตระกูล
2. Null และลำดับของผล: แต่ละตระกูลปฏิบัติต่อ Null ต่างกัน และผลไม่เรียงตาม Suite
3. แก้ Suite ที่อยู่ใน Context แล้ว: อะไรนับว่าซ้ำ แก้ ลบ และบันทึกอย่างไร

</Step>
