## Null ในคอลัมน์ Age

สคริปต์ `19_catalog_nulls.py` ใช้ `age = [10, None, 30, 40, 400]` (Null หนึ่งแถว) กับ `plan` ที่มี Null หนึ่งแถว ส่วนผลของแต่ละ Expectation (GX 1.24.1) เป็นดังนี้

| Expectation | ผล | `element_count` | `missing_count` | `unexpected_count` / `observed_value` |
|---|---|---|---|---|
| `ExpectColumnValuesToNotBeNull(age)` | ไม่ผ่าน | 5 | ไม่มี Key นี้ | Unexpected 1 (แถว Null) |
| `ExpectColumnValuesToBeNull(age)` | ไม่ผ่าน | 5 | ไม่มี Key นี้ | Unexpected 4 (แถวที่ไม่ใช่ Null) |
| `ExpectColumnValuesToBeBetween(age, 0..120)` | ไม่ผ่าน | 5 | 1 | Unexpected 1 (ค่า 400) |
| `ExpectColumnValuesToBeInSet(plan, [free, pro])` | ไม่ผ่าน | 5 | 1 | Unexpected 1 (`gold`) |
| `ExpectColumnValuesToBeUnique(id)` | ผ่าน | 5 | 0 | Unexpected 0 |
| `ExpectColumnValuesToMatchRegex(plan)` | ผ่าน | 5 | 1 | Unexpected 0 |
| `ExpectColumnMaxToBeBetween(age, 0..120)` | ไม่ผ่าน | | | Observed 400.0 |
| `ExpectColumnMeanToBeBetween(age, 0..120)` | ผ่าน | | | Observed 120.0 |

สิ่งที่เห็นจากตารางมีดังนี้

1. Expectation ที่ทดสอบช่วง ชุดค่า หรือรูปแบบ จะไม่นับ Null เป็นผิด แต่จะรายงาน `missing_count` แยกให้
2. คู่ `NotBeNull` กับ `BeNull` ถือว่า Null เป็นเป้าของตัวเอง จึงไม่มี `missing_count` ในผล และ `BeNull` จะนับแถวที่ไม่ใช่ Null เป็นผิด
3. Aggregate (`max`, `mean`) คิดจากค่าที่ไม่ใช่ Null โดยค่าเฉลี่ยที่รายงานคือ 120.0 ซึ่งเท่ากับ (10 + 30 + 40 + 400) ÷ 4 ถ้าหาร 5 จะได้ 96.0

</Step>

## ลำดับของผลไม่ใช่ลำดับของ Suite

ตอนอ่านผลเป็นลิสต์ เรามักสมมติว่า `result.results[i]` ตรงกับ `suite.expectations[i]` สคริปต์ `19` จึงพิมพ์สองลำดับมาเทียบกัน

```text
suite order : not_be_null(age), be_null(age), between(age), in_set(plan), unique(id),
              regex(plan), max(age), mean(age), distinct(plan), pair, compound, row_count, column_count
result order: not_be_null(age), be_null(age), between(age), max(age), mean(age),
              in_set(plan), regex(plan), distinct(plan), unique(id), pair, compound, row_count, column_count
```

`max(age)` และ `mean(age)` ย้ายขึ้นมาอยู่ติดกับกฎ `age` ตัวอื่น ส่วน `in_set`, `regex`, `distinct` ของ `plan` ก็ไปอยู่ด้วยกันเช่นกัน

สาเหตุอยู่ในซอร์สของ `Validator.process_expectations_for_validation` ซึ่งรวม Expectation ตามค่า Argument ชื่อ `column` ก่อนประเมิน (ชื่อเมธอดบอกไว้ว่า "sort by column") โดยลำดับของกลุ่มคือลำดับที่แต่ละคอลัมน์โผล่ครั้งแรก และภายในกลุ่มจะคงลำดับเดิมไว้ ส่วน Expectation ที่ไม่มี Argument `column` (กฎของตาราง กฎของคู่คอลัมน์) จะถูกรวมเป็นอีกกลุ่มหนึ่งที่ใช้กติกาเดียวกัน คือเรียงตามที่โผล่ครั้งแรก
