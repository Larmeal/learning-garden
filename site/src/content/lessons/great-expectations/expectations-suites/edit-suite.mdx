## อะไรนับว่าเป็น expectation ตัวเดียวกัน

บทหลักบอกว่า suite ข้ามการเพิ่ม expectation ที่เหมือนกันทุกอย่าง สคริปต์ `20_suite_edit.py` ทดลองว่า "เหมือนกัน" หมายถึงอะไร (GX 1.24.1) ทุกข้อใช้ `ExpectColumnValuesToBeBetween(column="age", min_value=0, max_value=120)` เป็นฐาน

| เพิ่มอะไร | จำนวน expectation ใน suite หลังเพิ่ม |
|---|---|
| ตัวฐาน | 1 |
| ตัวเดิมเป๊ะอีกครั้ง | 1 (ไม่เพิ่ม) |
| เปลี่ยน `max_value` เป็น 200 | 2 |
| ตัวฐานแต่ใส่ `mostly=0.9` | 3 |
| ตัวฐานแต่ใส่ `severity="warning"` | 4 |

`mostly` และ `severity` นับเป็นส่วนของตัวตน ตัวที่ต่างกันแค่สองค่านี้อยู่ใน suite พร้อมกันได้ ซึ่งมีประโยชน์ เช่น ใส่กฎเดียวกันสองระดับ: ผ่านที่ 0.9 เป็นคำเตือน และผ่านเมื่อไม่มีผิดเลยเป็นข้อบังคับ ส่วนผลข้างเคียงคือ suite บวมได้โดยไม่รู้ตัวถ้าทำซ้ำหลายรอบพร้อมแก้พารามิเตอร์เล็กน้อย

</Step>

## ลบ และ suite ที่ยังไม่ add

ลบด้วย `suite.delete_expectation(expectation)` สคริปต์ทดลองลบข้อสุดท้าย จำนวนใน suite ลดจาก 4 เป็น 3 และ `context.suites.get("s")` ก็เห็น 3 เหมือนกัน แปลว่าการลบบันทึกลง store ทันที

suite ที่สร้างด้วย `gx.ExpectationSuite(name="loose")` แล้วเพิ่ม expectation เข้าไปมีข้อมูลในตัวมันเอง (len เป็น 1) แต่ไม่อยู่ใน `context.suites.all()` จนกว่าจะ `context.suites.add(...)` และการ `add_expectation` บันทึกลง store ให้ก็ต่อเมื่อ suite อยู่ใน context แล้ว (ทดลองในบทหลัก)

<Callout type="warn" title="ที่ยังไม่ได้ทดลอง">
ไม่ได้ทดลองว่ากฎที่ถูกแก้ด้วย `save()` มีผลกับ validation definition ที่สร้างไว้ก่อนหน้านี้อย่างไร และไม่ได้ทดลองกับ file context ว่าไฟล์ JSON ของ suite เปลี่ยนจริง
</Callout>

</Step>
