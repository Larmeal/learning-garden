## สามหน้าที่ต้องรู้จัก

`28_data_docs_text.py` สร้าง file context ที่มี suite สองกฎ (`name` ไม่เป็น null, `age` ระหว่าง 0 ถึง 120) และ checkpoint ที่มี `UpdateDataDocsAction` รันกับข้อมูลที่ล้มทั้งสองข้อ แล้วดึงข้อความที่มองเห็นจาก HTML (GX 1.24.1) ผลที่เห็น

| หน้า | ข้อความที่เห็น |
|---|---|
| `index.html` | หัว "Data Docs created by Great Expectations" แท็บ "Validation Results" กับ "Expectation Suites" ปุ่ม Clear Filters และส่วนท้ายเชิญสมัครข่าวสาร (ปิดได้ด้วย `show_how_to_buttons`) |
| `expectations/people_suite.html` | ชื่อ suite, เวอร์ชัน GX, "This Expectation suite currently contains 2 total Expectations across 2 columns." แล้วแยกตามคอลัมน์ เช่น `age`: "values must be greater than or equal to 0.0 and less than or equal to 120.0." และ `name`: "values must never be null." |
| `validations/.../<run>/<batch>.html` | สถานะ Failed หรือ Passed ตาราง Statistics (Evaluated, Successful, Unsuccessful, Success Percent) ข้อมูล run และ batch แล้วแยกตามคอลัมน์ |

หน้า suite เป็นภาษามนุษย์ของ expectation ซึ่งเจ้าของข้อมูลอ่านแล้วตรวจกฎได้โดยไม่ต้องอ่านโค้ด

</Step>

## หน้าผลตรวจ: result_format เปลี่ยนสิ่งที่เห็น

ถ้าเอา Data Docs ไปให้ทีมดู ระดับ `BOOLEAN_ONLY` ให้หน้าที่บอกได้แค่ว่าล้ม ทีมต้องไปหาเหตุเอง ระดับ `COMPLETE` ให้ค่าที่ผิดและแถวที่ผิดในหน้าเดียว ดังที่[บทที่ 4](/great-expectations/reading-results/#result_format-ยิ่งละเอียด-ยิ่งแพง) บอกว่าผลละเอียดแลกกับการคำนวณเพิ่ม

<Callout type="note" title="อ่านจากข้อความ ไม่ใช่จากภาพ">
ส่วนนี้ได้จากการดึงข้อความของ HTML ด้วยสคริปต์ ไม่ได้เปิดดูหน้าในเบราว์เซอร์ จึงไม่ได้ตรวจสี การจัดวาง หรือการกรอง "Failed Only" ที่ใช้งานได้จริง และไม่ได้ทดลองการตั้ง site ไปยัง object storage
