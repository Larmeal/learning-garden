## เปลี่ยนแค่ DataFrame

สคริปต์ `18_result_anatomy.py` ส่วนที่ 3 ใช้ Validation Definition ตัวเดิมรันสองครั้ง

```python
day1 = pd.DataFrame({"id": [1, 2, 3, 4], "age": [10, None, 30, 400], "name": ["a", "b", None, "d"]})
day2 = pd.DataFrame({"id": [1, 2, 3, 4], "age": [10, 20, 30, 40],   "name": ["a", "b", "c", "d"]})

r1 = vd.run(batch_parameters={"dataframe": day1})
r2 = vd.run(batch_parameters={"dataframe": day2})
```

ผลที่พิมพ์ออกมา (GX 1.24.1)

```text
day1 success: False | day2 success: True
run ids differ: True
results kept in the store: 2
```

ทั้งที่ใช้ Suite ชุดเดียวและ Validation Definition ตัวเดียว เรากลับได้ผลคนละแบบตามข้อมูล และผลทั้งสองรอบถูกเก็บไว้ในที่เก็บผล (Validation Results Store) โดยไม่ทับกัน

</Step>

## ข้อควรรู้เมื่อรันทุกวัน

1. ทุกรอบคำนวณใหม่ทั้งหมด เพราะ GX ไม่จำ Metric ข้ามรอบ (ทดลองใน `02` แล้ว รันซ้ำได้ 19 กับ 19 Metric)
2. `run_id` มี `run_time` ของแต่ละรอบ ซึ่งใช้แยกผลเก่าออกจากผลใหม่ได้
3. Results Store ใน Ephemeral Context อยู่ใน Memory จึงหายไปเมื่อสคริปต์จบ ถ้าอยากเก็บผลข้ามวันก็ต้องใช้ File Context ([บทที่ 5](/great-expectations/context-stores/#context-ที่ใช้ได้จริงมีสองชนิด))
4. ข้อมูลใน DataFrame ต้องมาจากโค้ดของเราเอง ในตัวอย่างนี้เราส่งเป็นตัวแปร แต่ถ้าข้อมูลมาจากไฟล์หรือตาราง Batch Definition จะทำหน้าที่เลือกก้อนให้ ([บทที่ 6](/great-expectations/datasources-batches/#batch-definition-เป็นสูตร-ไม่ใช่ข้อมูล))
