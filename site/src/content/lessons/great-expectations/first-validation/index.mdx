## ข้อมูลที่จะตรวจ

เราจะใช้ตารางเล็ก ๆ สี่แถวที่ตั้งใจให้มีปัญหา โดย `age` ว่างอยู่หนึ่งแถว มีค่า 400 อยู่หนึ่งแถว และ `name` ว่างอยู่หนึ่งแถว

```python
import great_expectations as gx
import great_expectations.expectations as gxe
import pandas as pd

df = pd.DataFrame({
    "id": [1, 2, 3, 4],
    "age": [10, None, 30, 400],
    "name": ["a", "b", None, "d"],
})
```

โค้ดเต็มอยู่ใน `subjects/great-expectations/code/01_first_validation.py` ซึ่งเปิดคู่กับบทนี้แล้วรันตามได้เลย

</Step>

<Step>

## 1. Context และข้อมูล

```python
context = gx.get_context()
```

เมื่อไม่มีโฟลเดอร์ `gx/` และไม่มีค่าตั้งของ GX Cloud เราจะได้ Ephemeral Context ซึ่งอยู่ใน Memory ([บทที่ 5](/great-expectations/context-stores/#context-ที่ใช้ได้จริงมีสองชนิด) อธิบายตัวเลือกอื่นไว้)

```python
source = context.data_sources.add_pandas("my_source")
asset = source.add_dataframe_asset("users")
batch_definition = asset.add_batch_definition_whole_dataframe("all_users")
```

สามบรรทัดนี้บอก GX ว่า "มีข้อมูลแบบ Pandas ชื่อ `users` และให้ตรวจทั้ง DataFrame" ซึ่งตรงนี้ยังไม่มี DataFrame จริงเข้ามาเกี่ยวข้องเลย

</Step>

<Step>

## 2. Expectation และ Suite

```python
suite = context.suites.add(gx.ExpectationSuite(name="users_suite"))
suite.add_expectation(gxe.ExpectColumnValuesToNotBeNull(column="id"))
suite.add_expectation(gxe.ExpectColumnValuesToNotBeNull(column="age"))
suite.add_expectation(gxe.ExpectColumnValuesToBeBetween(column="age", min_value=0, max_value=120))
suite.add_expectation(gxe.ExpectTableRowCountToEqual(value=4))
```

`context.suites.add(...)` จะเก็บ Suite เข้า Context ซึ่งเป็นขั้นที่ต้องทำก่อนเสมอ ไม่อย่างนั้นขั้นต่อไปจะ Error ([บทที่ 7](/great-expectations/validation-checkpoints/))

</Step>

<Step>

## 3. Validation Definition แล้วรัน

```python
vd = gx.ValidationDefinition(name="users_vd", data=batch_definition, suite=suite)
result = vd.run(batch_parameters={"dataframe": df})
```

DataFrame เข้ามาตรงนี้เป็นพารามิเตอร์ตอนรัน ไม่ใช่ส่วนหนึ่งของการตั้งค่า ก่อน `run()` ค่า `vd.id` เป็น `None` แต่หลังรันจะมี id เพราะ `run()` เพิ่ม Validation Definition เข้า Context ให้ (เมื่อ Suite กับ Data Source ถูก Add แล้ว)

</Step>

<Step>

## 4. อ่านผล

```python
print(result.success)        # False
print(result.statistics)
# {'evaluated_expectations': 4, 'successful_expectations': 2,
#  'unsuccessful_expectations': 2, 'success_percent': 50.0}

for r in result.results:
    print(r.expectation_config.type, r.success, r.result)
```

ผลที่ได้จากการรันจริงเป็นดังนี้

| Expectation | Success | สิ่งที่เห็นใน `result` |
|---|---|---|
| Not Null `id` | True | unexpected_count = 0 |
| Not Null `age` | False | unexpected_count = 1 (แถวที่ `age` เป็น Null) |
| Between `age` 0..120 | False | unexpected_count = 1 (ค่า 400) |
| row count = 4 | True | observed_value = 4 |

`result.success` ของทั้ง Suite จะเป็น True ก็ต่อเมื่อทุก Expectation ผ่าน ข้อมูลของเราจึงไม่ผ่านโดยรวม

</Step>

<Step>

## เช็กตัวเอง

- ก่อนเรียก `run()` GX อ่าน DataFrame ไปหรือยัง เพราะอะไร
- `result.success` เป็น False ได้เพราะอะไรบ้าง (นึกให้ได้อย่างน้อยสองแบบ)
- ถ้าจะตรวจ DataFrame ก้อนใหม่ในวันพรุ่งนี้ ต้องสร้างอะไรใหม่ และใช้ของเดิมได้อะไรบ้าง

</Step>

<Step>

## หน้าย่อยของบทนี้

1. ผลลัพธ์หนึ่งก้อนมีอะไรอยู่ข้างใน เราจะเปิดต้นไม้ของ Result ดูทีละ Key
2. รันซ้ำกับข้อมูลของวันถัดไป ใช้ Validation Definition ตัวเดียวรันสองรอบ แล้วดูว่าผลถูกเก็บไว้ที่ไหน
3. โจทย์ฝึกสี่ข้อ ลองเขียนเองก่อนแล้วค่อยเปิดเฉลยที่รันแล้ว

</Step>
