## สองชั้น

`vd.run(...)` คืน `ExpectationSuiteValidationResult` มาก้อนเดียว ซึ่งข้างในมีรายการ `results` ที่แต่ละตัวคือผลของ Expectation หนึ่งข้อ สคริปต์ `18_result_anatomy.py` เรียก `to_json_dict()` แล้วพิมพ์ Key ของทั้งสองชั้นออกมา (GX 1.24.1)

ชั้นนอก

```text
['success', 'results', 'suite_name', 'suite_parameters', 'statistics', 'meta', 'id']
```

ชั้นของ Expectation หนึ่งข้อ

```text
['success', 'expectation_config', 'result', 'meta', 'exception_info']
```

</Step>

## ชั้นนอก: Key ที่มักถูกมองข้าม

```text
statistics: {'evaluated_expectations': 4, 'successful_expectations': 2,
             'unsuccessful_expectations': 2, 'success_percent': 50.0}
suite_name: users_suite
meta keys: great_expectations_version, batch_spec, batch_markers,
           active_batch_definition, validation_id, checkpoint_id,
           run_id, validation_time, batch_parameters
```

- `statistics` มีสี่ค่า โดยค่า `evaluated_expectations` สำคัญกว่าที่ดู เพราะมันเท่ากับ 0 ได้ถ้า Suite ว่างเปล่า (หน้า "[Suite โหลดมาว่างเปล่า](/great-expectations/custom-expectations/registry-loading/#ตอนโหลด-suite-จากไฟล์-error-ถูกกลืน)" ใน[บทที่ 12](/great-expectations/custom-expectations/)) ซึ่งในกรณีนั้น `success` จะเป็น True
- `meta.run_id` มี `run_name` กับ `run_time` ซึ่งใช้แยกผลของแต่ละรอบได้
- `meta.validation_id` และ `checkpoint_id` ก็ตามชื่อเลย คือบอกว่า Validation Definition และ Checkpoint ตัวไหนเป็นผู้รันผลนี้ (เรายังไม่ได้ตรวจค่าของมัน)
- ส่วน `result_url` เป็น `None` ในการทดลองนี้

<Callout type="note" title="ตัวเลขใน Result ขึ้นกับ result_format">
ตัวอย่างข้างบนเป็นรูป SUMMARY ซึ่งเป็นค่าเริ่มต้นของ `ValidationDefinition.run` ถ้าขอ BOOLEAN_ONLY ก็จะได้ `result` ว่าง ซึ่ง [บทที่ 4](/great-expectations/reading-results/#result_format-ยิ่งละเอียด-ยิ่งแพง) เทียบทั้งสี่ระดับไว้ให้
</Callout>
