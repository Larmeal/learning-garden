## สองชั้น

`vd.run(...)` คืน `ExpectationSuiteValidationResult` ก้อนเดียว ข้างในมีรายการ `results` ที่แต่ละตัวคือผลของ expectation หนึ่งข้อ สคริปต์ `18_result_anatomy.py` เรียก `to_json_dict()` แล้วพิมพ์ key ของทั้งสองชั้น (GX 1.24.1)

ชั้นนอก

```text
['success', 'results', 'suite_name', 'suite_parameters', 'statistics', 'meta', 'id']
```

ชั้นของ expectation หนึ่งข้อ

```text
['success', 'expectation_config', 'result', 'meta', 'exception_info']
```

</Step>

## ชั้นนอก: key ที่มักถูกมองข้าม

```text
statistics: {'evaluated_expectations': 4, 'successful_expectations': 2,
             'unsuccessful_expectations': 2, 'success_percent': 50.0}
suite_name: users_suite
meta keys: great_expectations_version, batch_spec, batch_markers,
           active_batch_definition, validation_id, checkpoint_id,
           run_id, validation_time, batch_parameters
```

- `statistics` มีสี่ค่า ค่า `evaluated_expectations` สำคัญกว่าที่ดู เพราะมันเท่ากับ 0 ได้ถ้า suite ว่างเปล่า (หน้า "[suite โหลดมาว่างเปล่า](/great-expectations/custom-expectations/registry-loading/#ตอนโหลด-suite-จากไฟล์-error-ถูกกลืน)" ใน[บทที่ 12](/great-expectations/custom-expectations/)) ซึ่ง `success` จะเป็น True
- `meta.run_id` มี `run_name` กับ `run_time` ใช้แยกผลของแต่ละรอบ
- `meta.validation_id` และ `checkpoint_id` ตามชื่อคือตัวบอกว่า validation definition และ checkpoint ไหนรันผลนี้ (ไม่ได้ตรวจค่าของมัน)
- `result_url` เป็น `None` ในการทดลองนี้

<Callout type="note" title="ตัวเลขใน result ขึ้นกับ result_format">
ตัวอย่างข้างบนเป็นรูป SUMMARY ซึ่งเป็นค่าเริ่มต้นของ `ValidationDefinition.run` ถ้าขอ BOOLEAN_ONLY ก็จะได้ `result` ว่าง [บทที่ 4](/great-expectations/reading-results/#result_format-ยิ่งละเอียด-ยิ่งแพง) เทียบทั้งสี่ระดับ
</Callout>
