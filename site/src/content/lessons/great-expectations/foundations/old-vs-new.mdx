## ความต่างที่ทดลองเห็นจริง

| เรื่อง | 0.18.21 | 1.24.1 |
|---|---|---|
| ที่ที่ข้อมูลเข้า | `read_dataframe(df)` ได้ Validator ทันที | DataFrame เป็นพารามิเตอร์ตอน `run(batch_parameters=...)` |
| Expectation | เมธอด `validator.expect_*` รันทันที | คลาส `gxe.Expect...` เก็บใน Suite รันทีหลัง |
| ข้อที่ล้มตอนเขียน | ไม่ถูกเก็บใน Suite (เก็บ 0 ข้อหลังล้มสองข้อ) | อยู่ใน Suite ตามเดิม |
| Checkpoint | อ้าง Suite ด้วยชื่อ ถ้าชื่อไม่มีใน Context ได้ `DataContextError` (`expectation_suite default not found`) | รับ ValidationDefinition ที่ Add เข้า Context แล้ว |

ทุกแถวมาจากการรัน `08` และ `01` ส่วนบรรทัดผลของ 1.24.1 ในกรอบด้านบนเราย่อให้สั้นลง แต่ตัวเลขและค่า Success ยังตรงกับที่สคริปต์พิมพ์ออกมา

</Step>

## อ่านตัวอย่างบนเว็บให้ออกว่ารุ่นไหน

ลองดูว่าโค้ดที่เจอเรียกอะไรอยู่ แล้วเทียบกับตารางนี้

| ถ้าเห็น | รุ่น | ทำอะไรต่อ |
|---|---|---|
| `context.sources.pandas_default` หรือ `context.sources.add_*` | 0.18 | ใช้ `context.data_sources.add_*` ใน 1.x |
| `validator.expect_column_...(...)` เรียกเป็นเมธอดบน Validator | 0.18 | สร้างคลาส `gxe.Expect...` แล้ว `suite.add_expectation` |
| `add_or_update_checkpoint(... validations=[...])` | 0.18 | สร้าง `ValidationDefinition` แล้วส่งให้ `gx.Checkpoint` |
| `gx.get_context()` แล้วตามด้วย `context.suites.add(...)` | 1.x | ใช้ได้ |

สามแถวแรกเป็นรูปแบบที่ `08_legacy_018.py` ใช้จริงบน 0.18.21 แต่ Checkpoint แบบไฟล์ YAML เราไม่ได้ทดลอง

<Callout type="warn" title="รุ่นเก่าต้องใช้ Environment แยก">
0.18.21 ต้องใช้ NumPy ต่ำกว่า 2 และ Pandas ต่ำกว่า 2.2 สคริปต์ `08` จึงรันด้วย `uv run --no-project --python 3.11 --with great-expectations==0.18.21 --with "numpy<2" --with "pandas<2.2"` แทนที่จะรันใน Environment ของโปรเจกต์
</Callout>

</Step>
