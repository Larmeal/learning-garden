## ตารางตัวอย่างกับกฎแปดข้อ

ตาราง `people` มีห้าแถวและสี่คอลัมน์ ข้อมูลชุดแรกสะอาด

```text
id  age  email      country
1   31   a@x.com    TH
2   24   b@x.com    TH
3   45   c@x.com    JP
4   52   d@x.com    SG
5   38   e@x.com    TH
```

กฎที่เขียนไว้ใน suite เดียว

| กฎ | expectation |
|---|---|
| id ไม่ว่าง | `ExpectColumnValuesToNotBeNull(column="id")` |
| id ไม่ซ้ำ | `ExpectColumnValuesToBeUnique(column="id")` |
| age ไม่ว่าง | `ExpectColumnValuesToNotBeNull(column="age")` |
| age อยู่ใน 0 ถึง 120 | `ExpectColumnValuesToBeBetween(column="age", min_value=0, max_value=120)` |
| email มีรูปแบบอีเมล | `ExpectColumnValuesToMatchRegex(column="email", regex=...)` |
| country อยู่ในชุดที่รู้จัก | `ExpectColumnValuesToBeInSet(column="country", value_set=["TH", "JP", "SG"])` |
| คอลัมน์ตรงกับที่กำหนดทุกตัว | `ExpectTableColumnsToMatchSet(column_set=[...], exact_match=True)` |
| มีแถว 1 ถึง 1000 แถว | `ExpectTableRowCountToBeBetween(min_value=1, max_value=1000)` |

</Step>

## อ่านผลให้ถูกที่

กรณีเปลี่ยนชื่อคอลัมน์ให้ข้อสังเกตสามข้อ

1. สาเหตุเดียว (คอลัมน์ `age` หาย) ทำให้ล้มสามข้อ เมื่ออ่านผลให้หาสาเหตุร่วมก่อน อย่านับทีละข้อ กฎ `columns match set` บอกสาเหตุตรงที่สุด
2. สองข้อที่ล้มเพราะหาคอลัมน์ไม่เจอ GX จับ exception ไว้และรายงานเป็น `success=False` พร้อม `exception_info` ไม่ได้ raise ออกมา ผลลัพธ์แยกไม่ออกด้วย `success` อย่างเดียวว่าข้อมูลผิดหรือกฎใช้ไม่ได้ ต้องดู `exception_info`
3. ลำดับของ `result.results` ไม่ตรงกับลำดับใน suite เสมอไป ในกรณีนี้ GX เอาข้อที่เกิด exception ไว้ก่อน (สคริปต์ `16` เทียบกับลำดับเดิม ได้ `same_order=False` เฉพาะกรณีนี้) และยังมีอีกสาเหตุหนึ่งที่ไม่เกี่ยวกับ exception: GX จัดกลุ่ม expectation ตามคอลัมน์ก่อนประเมิน (หน้า "null และลำดับของผล" ในบทที่ 3) ถ้าจะนำผลไปจับคู่กับ expectation ให้จับคู่ผ่าน `expectation_config` ไม่ใช่ตำแหน่งในลิสต์ การจับคู่ตามตำแหน่งในกรณีนี้ติดป้ายผิดทั้งสามข้อ (สคริปต์ฉบับแรกทำแบบนั้นและให้ผลผิด)

</Step>

## กรณีที่ทุกกฎผ่านทั้งที่ข้อมูลผิด

กรณี "ผิดแต่ดูถูก" แก้ `age` ของแถวแรกจาก 31 เป็น 13 ค่า 13 อยู่ในช่วง 0 ถึง 120 เป็นจำนวนเต็ม ไม่ใช่ null suite จึงผ่านครบ GX ตรวจเฉพาะกฎที่เขียนไว้ ถ้าไม่มีกฎที่พูดถึงความผิดแบบนี้ มันก็ไม่มีทางเห็น

กฎที่ตรวจค่ารายแถวจับความผิดแบบนี้ไม่ได้เลย ต้องมีกฎที่พูดถึงภาพรวม เช่น ช่วงของค่าเฉลี่ยหรือสัดส่วนของค่าแต่ละกลุ่ม กฎพวกนั้นก็ยังพลาดได้ถ้าความผิดเล็กกว่าช่วงที่ตั้งไว้ จำนวนกฎที่ผ่านจึงบอกคุณภาพของข้อมูลไม่ได้ มันบอกแค่ว่าข้อมูลไม่ขัดกับสิ่งที่เรารู้จะเขียน

<Callout type="warn" title="สิ่งที่ตารางนี้ไม่ได้ทดลอง">
ทุกกรณีมี 5 แถว และใช้ pandas ล้วน จำนวนกฎที่ล้มกับข้อความ exception บน SQL หรือ Spark อาจต่าง บทที่ 11 ดูเรื่องนี้ ส่วนการที่ GX ไม่แก้ DataFrame ที่ตรวจ ทดลองทุกกรณีแล้ว (ตัว DataFrame เท่าเดิมทั้งก่อนและหลังรัน) แต่เฉพาะ pandas
</Callout>
