## GX คือผู้ตรวจ ไม่ใช่ผู้แก้

Great Expectations (GX) เป็นไลบรารี Python สำหรับเขียนสิ่งที่คาดหวังจากข้อมูลเป็นโค้ด แล้วสั่งตรวจกับข้อมูลจริง เอกสารทางการเปรียบมันกับ unit test ของข้อมูล แต่ละข้อคือ assertion เช่น "คอลัมน์ `id` ต้องไม่เป็น null" ผลที่ได้คือผ่านหรือไม่ผ่านพร้อมรายละเอียด และทำเป็นรายงานให้คนอ่านได้

สิ่งที่ต้องจำตั้งแต่ต้น: GX **ไม่แก้ข้อมูลและไม่เก็บข้อมูล** มันไปอ่านข้อมูลจากที่อื่น (DataFrame, ไฟล์, ฐานข้อมูล, Spark) คำนวณข้อเท็จจริงเกี่ยวกับข้อมูลนั้น แล้วเทียบกับสิ่งที่เราเขียนไว้ ถ้าอยากให้ข้อมูลถูกแก้ ต้องมีขั้นตอนอื่นทำ GX บอกได้แค่ว่าข้อมูลเสียหรือไม่

<Callout type="tip" title="เทียบกับ Spark ในสวนนี้">
Spark ไม่ใช่ database แต่เป็นเครื่องคำนวณที่ไปอ่านข้อมูลจากที่อื่น GX อยู่ในตำแหน่งคล้ายกัน คือไม่ใช่ที่เก็บ แต่เป็นตัวตรวจที่ไปอ่านข้อมูลจากที่อื่น และเมื่อข้อมูลใหญ่ GX ก็ฝากงานคำนวณให้ Spark หรือ SQL ทำ (บทที่ 11)
</Callout>

</Step>

## ข้อมูลเสียหน้าตาแบบไหน

ก่อนเขียน expectation ต้องรู้ว่ากำลังกันอะไร ปัญหาที่เจอบ่อยและ expectation ที่ GX มีให้

| ปัญหา | ตัวอย่างที่เกิดขึ้นจริง | expectation ที่ใช้ |
|---|---|---|
| ค่าว่าง | ระบบต้นทางส่ง `age` เป็น null | `ExpectColumnValuesToNotBeNull` |
| ซ้ำ | key ซ้ำหลังรวมสองตาราง | `ExpectColumnValuesToBeUnique` |
| นอกช่วง | อายุ 400, ราคาติดลบ | `ExpectColumnValuesToBeBetween` |
| รูปแบบผิด | อีเมลไม่มี `@` | `ExpectColumnValuesToMatchRegex` |
| โครงสร้างเปลี่ยน | คอลัมน์หายหรือถูกเปลี่ยนชื่อ | `ExpectTableColumnsToMatchSet` |
| จำนวนแถวผิดปกติ | ไฟล์ของวันนี้มาว่าง | `ExpectTableRowCountToBeBetween` |

ข้อสุดท้ายสำคัญกว่าที่คิด ในบทที่ 4 จะเห็นว่า expectation แบบ column map ผ่านโดยปริยายเมื่อตารางว่าง

</Step>

<Step>

## ต้องรู้อะไรก่อนเริ่ม

| เรื่อง | ระดับที่ต้องใช้ | ใช้ตอนไหน |
|---|---|---|
| Python | อ่านและเขียน class, keyword argument, exception ได้ | ทุกบท GX 1.x เป็น pydantic model เกือบทั้งหมด |
| pandas | สร้าง DataFrame และอ่านผลได้ | ตัวอย่างแรกทั้งหมดตรวจ DataFrame |
| ชนิดความเสียของข้อมูล | เคยเจอตารางที่ข้อมูลไม่เป็นอย่างที่คิด | ตัดสินว่าจะเขียน expectation อะไร |
| SQL พื้นฐาน | `select`, `count`, `case when` | อ่านคำสั่งที่ GX ส่งไปที่ database (บทที่ 8) |
| Spark | ผ่านเส้นทาง Spark ในสวนนี้ถึงบทที่ 5 | เฉพาะบทที่ 11 |

ไม่ต้องเคยใช้ GX มาก่อน และไม่ต้องรู้ pydantic

</Step>

## สองรุ่นที่ต้องแยกให้ออก

ถ้าค้นตัวอย่าง GX บนเว็บ จะเจอโค้ดสองสไตล์ปนกัน เพราะ GX 1.0 เปลี่ยน API ใหญ่ เอกสารทางการแยกเป็นเวอร์ชัน (ตอนเขียนบทนี้) 1.24.1 คือรุ่นล่าสุด 0.18.21 ไม่มีการดูแลแล้ว และมีลิงก์ไปรุ่น 0.17 ขึ้นไปเก่ากว่านั้น

<VersionCompare client:visible />

สัญญาณที่บอกว่าโค้ดเป็นรุ่นเก่า: `context.sources.pandas_default`, `validator.expect_column_...(...)` ที่เรียกเป็นเมธอด, `add_or_update_checkpoint(... validations=[...])`, ไฟล์ YAML ของ checkpoint ถ้าเห็นรูปแบบพวกนี้ อย่าลอกมาใช้กับ 1.x

<Callout type="warn" title="เส้นทางนี้ใช้รุ่นไหน">
ทุกตัวอย่างในเส้นทางนี้รันกับ GX **1.24.1** (ตัวอย่างโค้ดใน repo pin เวอร์ชันนี้) ส่วน knowledge graph ที่ใช้ศึกษาโครงสร้างวิเคราะห์จาก 1.9.3 ที่ต่างกันจริงจะมีบอกในบทนั้นๆ เช่น กับดักเรื่อง context ซ้อนในบทที่ 5
</Callout>

</Step>
