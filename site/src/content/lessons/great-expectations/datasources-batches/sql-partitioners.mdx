## ตารางที่ใช้ทดลอง

ตาราง `events` ใน SQLite มี 5 แถว โดยคอลัมน์ `day` เก็บวันที่เป็นข้อความ `YYYY-MM-DD`

```text
id  day         amount
1   2024-01-30  5
2   2024-01-31  7
3   2024-02-01  9
4   2024-02-01  11
5   2024-02-02  3
```

```python
src = context.data_sources.add_sqlite("sq", connection_string=f"sqlite:///{db}")
asset = src.add_table_asset("events", table_name="events")
by_month = asset.add_batch_definition_monthly("monthly", column="day")
```

ตารางเดียวกันตัดเป็น Batch ได้สามระดับ โดยชื่อเมธอดบอกระดับ และรับชื่อคอลัมน์วันที่ผ่านพารามิเตอร์ `column` ผลจาก `24_batch_details.py` ส่วนที่ 1 (GX 1.24.1) เป็นดังนี้

## Batch หนึ่งกลายเป็นแถวไหน

เมื่อเรียก `get_batch(batch_parameters={"year": 2024, "month": 2, "day": 1})` GX จะส่งเงื่อนไขไปให้ฐานข้อมูลกรองเลย โดยไม่ได้ดึงข้อมูลทั้งตารางมากรองใน Python จากที่ทดลองแล้วใน `24` Batch นี้ได้ 2 แถว ตรงกับตาราง และ `batch_spec` ของ Batch ระบุชื่อ Partitioner ว่า `partition_on_year_and_month_and_day`

## ข้อควรรู้

- ถ้าไม่ส่งพารามิเตอร์ บนไฟล์จะได้ Batch ล่าสุด ส่วนบน SQL สคริปต์ `24` เรียก `get_batch()` โดยไม่ส่งพารามิเตอร์แล้วไม่ Error แต่ไม่ได้ตรวจว่าได้ Batch ไหน ดังนั้นถ้า Pipeline รายวันของคุณอ่านตาราง ให้ส่งพารามิเตอร์ครบเสมอเหมือนกรณีไฟล์
- Identifier ของ SQL เป็นตัวเลข (`'year': 2024`) ต่างจากไฟล์ที่เป็นสตริง (บทหลัก)
- ตัวอย่างนี้เก็บวันที่เป็นข้อความใน SQLite ส่วนฐานข้อมูลอื่นที่เก็บเป็นชนิดวันที่จริงไม่ได้ทดลอง

<Callout type="warn" title="ที่ยังไม่ได้ทดลอง">
เราไม่ได้อ่าน SQL ที่ GX สร้างจริงสำหรับ Partitioner ไม่ได้ทดลองคอลัมน์วันที่ที่เป็น Timestamp มีเขตเวลา และไม่ได้ทดลองกับ Spark
</Callout>
