## เมื่ออยากลองกฎเร็ว ๆ

ขั้นปกติคือ Context, Data Source, Asset, Batch Definition, Suite, Validation Definition แล้วจึง `run()` แต่ตอนกำลังสำรวจข้อมูลหรือเขียนกฎใหม่ แบบนั้นหนักเกินไป Batch ที่ได้จาก `get_batch()` จึงมีเมธอด `validate(...)` ที่ตรวจกฎได้โดยตรง

```python
batch = batch_definition.get_batch()
batch.validate(gxe.ExpectColumnValuesToBeBetween(column="a", min_value=0, max_value=2))
```

</Step>

## ใช้เมื่อไหร่ ไม่ใช้เมื่อไหร่

| ต้องการ | ใช้ |
|---|---|
| ลองกฎใหม่กับข้อมูลจริง เห็นผลทันที | `batch.validate(expectation)` |
| ลอง Suite ทั้งชุดที่ยังร่างอยู่ | `batch.validate(suite)` |
| ตรวจทุกวันใน Pipeline และเก็บผล | `ValidationDefinition` หรือ `Checkpoint` (ผลถูกเก็บ มี Action) |

เหตุผลที่ไม่ควรใช้ `batch.validate` ใน Pipeline คือผลไม่ถูกเก็บ (ทดลองแล้วกับ Suite) และไม่มี Action เช่น แจ้งเตือนหรืออัปเดต Data Docs

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
เราทดลองกับ Batch ที่มาจากไฟล์ CSV ใน Pandas เท่านั้น ไม่ได้ลองกับ Batch ของ SQL และไม่ได้ตรวจว่า `batch.validate(expectation)` ที่ส่งตัวเดียวเก็บผลหรือไม่ (ทดลองเรื่องเก็บผลเฉพาะแบบ Suite)
</Callout>
