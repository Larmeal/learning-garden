## โฟลเดอร์ที่ไม่สะอาด

Pipeline จริงมักมีไฟล์อื่นปนอยู่ในโฟลเดอร์เดียวกับข้อมูล ดังนั้นสคริปต์ `24_batch_details.py` ส่วนที่ 2 จึงสร้างโฟลเดอร์ที่มีไฟล์เจ็ดไฟล์

```text
backup_data_2024-03-01.csv
data_2023-12-31.csv
data_2024-01-31.csv
data_2024-02-01.csv
data_2024-02-10.csv
data_2024-03-01.csv.bak
notes.txt
```

ไฟล์ข้อมูลจริงมีสี่ไฟล์ (`data_...csv` ที่ลงท้าย `.csv`) ส่วนอีกสามไฟล์เป็นไฟล์สำรองและไฟล์อื่น โดยใช้ Regex เดียวกับบทหลัก

</Step>

ผลที่เห็นคือ Regex ไม่ได้ถูกใช้แบบ "ทั้งชื่อต้องตรง" มันหาส่วนที่ตรงกับแบบแผนจากกลางชื่อไฟล์ก็ได้ และเมื่อไม่ปิดหัวท้าย ไฟล์ที่ไม่ควรเข้ามาจึงเข้ามาเป็น Batch ได้ (ในการทดลอง ไฟล์ที่ถูกจับเกินมาคือไฟล์เดียวที่ชนวันที่ 2024-03-01 ไม่ได้แยกว่าเป็น `backup_data_...csv` หรือ `...csv.bak`) เราจึงควรใส่ `^` ต้นและ `$` ท้ายเสมอ

## โฟลเดอร์ว่าง ไม่มีไฟล์ตรงกับ Regex และการอ่าน CSV

| สถานการณ์ | ผล (ส่วนที่ 3 และ 4 ของสคริปต์) |
|---|---|
| โฟลเดอร์ไม่มีไฟล์เลย แล้ว `add_csv_asset(...)` | `TestConnectionError`: `No file at base_directory path ... matched glob_directive "**/*" for DataAsset ...` ล้มตั้งแต่ตอนสร้าง Asset |
| โฟลเดอร์มีไฟล์ แต่ไม่มีไฟล์ตรงกับ Regex | `get_batch_identifiers_list()` ได้ `[]` และ `get_batch()` ได้ `NoAvailableBatchesError: No available batches found.` |
| ไฟล์ CSV คั่นด้วย `;` อ่านแบบไม่ตั้งค่า | ได้คอลัมน์เดียวชื่อ `a;b` |
| ตั้ง `add_csv_asset("x", sep=";")` | ได้คอลัมน์ `a`, `b` ตามจริง |

สองแถวสุดท้ายแสดงว่าพารามิเตอร์ของ Asset ถูกส่งต่อให้ตัวอ่านของ Pandas (`sep` เป็นพารามิเตอร์ของ `pandas.read_csv`) ตัวเลือกอื่นของ `read_csv` ไม่ได้ทดลอง

ข้อควรระวังคือ การสร้าง Asset ที่ล้มเมื่อโฟลเดอร์ว่างหมายความว่า Pipeline ที่สร้าง Asset ก่อนไฟล์ของวันมาถึง จะล้มตั้งแต่ตั้งค่า ไม่ใช่ตอนตรวจ ถ้าสร้างและรันในสคริปต์เดียวกัน ให้เช็กว่ามีไฟล์ก่อน

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
เรายังไม่ได้ทดลองไฟล์ในโฟลเดอร์ย่อย (Glob `**/*` ดูเหมือนค้นลงไปทุกชั้น) ไม่ได้ทดลองไฟล์ที่ถูกเขียนค้างอยู่ตอนอ่าน และไม่ได้ทดลองไฟล์บน S3 หรือ GCS
</Callout>
