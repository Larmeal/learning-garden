## สามส่วนของเมธอด

โค้ดข้างล่างนี้ย่อให้เหลือแค่โครง โดยตัดคอมเมนต์ Log และ Type Hint ออกไป

```python
aggregates = {}

# ส่วนที่ 1: จัดกลุ่ม metric ตาม domain
for bundled in metric_fn_bundle:
    domain_id = IDDict(bundled.compute_domain_kwargs or {}).to_id()
    if domain_id not in aggregates:
        aggregates[domain_id] = {"column_aggregates": [], "metric_ids": [], "domain_kwargs": ...}
    aggregates[domain_id]["column_aggregates"].append(bundled.metric_fn)
    aggregates[domain_id]["metric_ids"].append(bundled.metric_configuration.id)

# ส่วนที่ 2: หนึ่ง agg ต่อหนึ่ง domain
for aggregate in aggregates.values():
    df = self.get_domain_records(domain_kwargs=aggregate["domain_kwargs"])
    res = df.agg(*aggregate["column_aggregates"]).collect()
    assert len(res) == 1, "all bundle-computed metrics must be single-value statistics"

    # ส่วนที่ 3: แตกผลกลับเป็น metric ละค่า
    for idx, metric_id in enumerate(aggregate["metric_ids"]):
        resolved_metrics[metric_id] = convert_to_json_serializable(data=res[0][idx])
```

## ถ้าจะวัดเอง

ถ้าอยากเปลี่ยนข้อสรุปข้างบนให้เป็นผลที่วัดได้ เราต้องมี Spark ที่ติดตั้งแล้ว (เส้นทาง Spark ในสวนนี้มีโปรเจกต์อยู่ที่ `subjects/spark/code`) จากนั้นทำตามขั้นตอนข้างล่างนี้ ซึ่งทั้งหมดยังไม่ได้ทำนะ

1. สร้าง Spark DataFrame เล็ก ๆ ขึ้นมา แล้วรัน Validation ที่มี Suite 6 ข้อเดียวกับ `05_sql_bundling.py` (BOOLEAN_ONLY)
2. เปิด Spark UI ก่อนและหลังรัน แล้วดูแท็บ Jobs ว่ามี Job เพิ่มขึ้นมากี่ตัว
3. เอาตัวเลขนั้นไปเทียบกับจำนวน Domain ที่ Suite มี (ตาราง, ตารางที่มี row_condition ฯลฯ) ถ้าคำอธิบายข้างบนถูก เราควรเห็น Job ของ Aggregate ประมาณจำนวน Domain บวกกับ Job ของ Metric ที่ไม่ใช่ Aggregate
4. สลับ `result_format` เป็น SUMMARY แล้วเทียบอีกครั้งหนึ่ง

<Callout type="warn" title="ทำไมยังไม่ได้ทำ">
การรัน GX บน Spark ไม่ได้อยู่ในสิ่งที่เส้นทางนี้ตรวจ หน้านี้จึงอยู่ในระดับซอร์สเท่านั้น ดังนั้นตัวเลขหรือพฤติกรรมใดเกี่ยวกับ Spark ให้ถือว่ายังไม่ยืนยัน จนกว่าจะวัดตามขั้นตอนข้างบน
