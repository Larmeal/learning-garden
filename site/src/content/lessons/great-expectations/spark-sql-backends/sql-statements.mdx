## จับคำสั่งตามที่ SQLite เห็น

ตาราง `sales` มีสี่แถว โดยคอลัมน์ `d` เป็นข้อความวันที่ และ Suite มีกฎเดียวคือ `amount` ต้องไม่เป็น Null เมื่อรัน Batch ของวันที่ 2024-01-02 สคริปต์ `30_sql_where_support.py` จะครอบ `SqlAlchemyExecutionEngine.execute_query` ไว้ แล้วคอมไพล์คำสั่งด้วย Dialect ของ Engine เอง ผลที่เห็นจึงเป็น SQL ที่ SQLite ได้รับจริง (GX 1.24.1)

```sql
-- 1. ค้นหา batch ที่มี
SELECT distinct(CAST(CAST(STRFTIME('%Y', d) AS INTEGER) AS VARCHAR) || CAST(CAST(STRFTIME('%m', d) AS INTEGER) AS VARCHAR)
                || CAST(CAST(STRFTIME('%d', d) AS INTEGER) AS VARCHAR)) AS concat_distinct_values,
       CAST(CAST(STRFTIME('%Y', d) AS INTEGER) AS INTEGER) AS year,
       CAST(CAST(STRFTIME('%m', d) AS INTEGER) AS INTEGER) AS month,
       CAST(CAST(STRFTIME('%d', d) AS INTEGER) AS INTEGER) AS day
FROM sales

-- 2. นับแถวของ batch
SELECT count(*) AS "table.row_count"
FROM (SELECT * FROM sales WHERE CAST(STRFTIME('%Y', d) AS INTEGER) = 2024
        AND CAST(STRFTIME('%m', d) AS INTEGER) = 1 AND CAST(STRFTIME('%d', d) AS INTEGER) = 2) AS anon_1

-- 3. นับ null ของ amount ใน batch
SELECT sum(CASE WHEN (amount IS NULL) THEN 1 ELSE 0 END) AS "column_values.nonnull.unexpected_count"
FROM (SELECT * FROM sales WHERE ... เงื่อนไขเดิม ...) AS anon_1
```

ผลที่ได้คือ `success: False` เพราะวันที่ 2 มีแถวที่ `amount` เป็น Null อยู่หนึ่งแถว

## สิ่งที่ควรสังเกต

1. คำสั่งที่ 1 ไม่มี WHERE เพราะการหา Batch ต้องกวาดคอลัมน์ `d` ทั้งตาราง บนตารางเล็กเราจะไม่รู้สึกอะไร แต่บนตารางหลายร้อยล้านแถว นี่เป็นต้นทุนที่แยกออกมาอีกก้อนหนึ่งนอกเหนือจากการตรวจ Batch จริง ส่วนรอบการรันครั้งถัดไปจะทำซ้ำหรือไม่ เรายังไม่ได้ทดลอง
2. คำสั่งที่ 2 และ 3 มี WHERE ฐานข้อมูลจึงกรองก่อน และข้อมูลของวันอื่นก็ไม่ถูกนับรวมในผล
3. นิพจน์วันที่จะต่างกันไปตาม Dialect โดยบน SQLite เป็น `CAST(STRFTIME('%Y', d) AS INTEGER)` ส่วนฐานข้อมูลอื่นก็ใช้ฟังก์ชันของตัวเอง (ไม่ได้ทดลองกับฐานข้อมูลอื่น) และเพราะนิพจน์ครอบคอลัมน์ `d` อยู่ โดยทั่วไป Index บนคอลัมน์นี้จึงใช้ไม่ได้ ข้อนี้เป็นการอนุมานจากรูปของ SQL ไม่ได้ทดลองวัดแผนการรัน
4. บทหลักเคยแสดง SQL แบบ `EXTRACT(year FROM d)` ซึ่งเป็นรูปกลางที่ SQLAlchemy คอมไพล์ออกมาเมื่อไม่ระบุ Dialect แต่ตัวที่ SQLite ได้รับจริงคือ `STRFTIME` ด้านบน

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
เรายังไม่ได้ลองกับฐานข้อมูลที่ไม่ใช่ SQLite ไม่ได้ดูแผนการรัน (EXPLAIN) และไม่ได้วัดเวลาของคำสั่งที่ 1 เมื่อตารางโตขึ้น ข้อสรุปเรื่องต้นทุนจึงมาจากรูปของคำสั่งเท่านั้น ไม่ใช่ตัวเลขที่วัดได้
</Callout>
