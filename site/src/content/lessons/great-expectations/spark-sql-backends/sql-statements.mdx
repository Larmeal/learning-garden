## จับคำสั่งตามที่ SQLite เห็น

ตาราง `sales` มีสี่แถว คอลัมน์ `d` เป็นข้อความวันที่ suite มีกฎเดียวคือ `amount` ไม่เป็น null รัน batch ของวันที่ 2024-01-02 สคริปต์ `30_sql_where_support.py` ครอบ `SqlAlchemyExecutionEngine.execute_query` แล้วคอมไพล์คำสั่งด้วย dialect ของ engine เอง ผลที่เห็นคือ SQL ที่ SQLite ได้รับจริง (GX 1.24.1)

```sql
-- 1. ค้นหา batch ที่มี
SELECT distinct(CAST(CAST(STRFTIME('%Y', d) AS INTEGER) AS VARCHAR) || CAST(CAST(STRFTIME('%m', d) AS INTEGER) AS VARCHAR)
                || CAST(CAST(STRFTIME('%d', d) AS INTEGER) AS VARCHAR)) AS concat_distinct_values,
       CAST(CAST(STRFTIME('%Y', d) AS INTEGER) AS INTEGER) AS year,
       CAST(CAST(STRFTIME('%m', d) AS INTEGER) AS INTEGER) AS month,
       CAST(CAST(STRFTIME('%d', d) AS INTEGER) AS INTEGER) AS day
FROM sales

-- 2. นับแถวของ batch
SELECT count(*) AS "table.row_count"
FROM (SELECT * FROM sales WHERE CAST(STRFTIME('%Y', d) AS INTEGER) = 2024
        AND CAST(STRFTIME('%m', d) AS INTEGER) = 1 AND CAST(STRFTIME('%d', d) AS INTEGER) = 2) AS anon_1

-- 3. นับ null ของ amount ใน batch
SELECT sum(CASE WHEN (amount IS NULL) THEN 1 ELSE 0 END) AS "column_values.nonnull.unexpected_count"
FROM (SELECT * FROM sales WHERE ... เงื่อนไขเดิม ...) AS anon_1
```

ผล `success: False` เพราะวันที่ 2 มีแถว `amount` เป็น null หนึ่งแถว

## สิ่งที่ควรสังเกต

1. คำสั่งที่ 1 ไม่มี WHERE การหา batch ต้องกวาดคอลัมน์ `d` ทั้งตาราง บนตารางเล็กไม่รู้สึก บนตารางหลายร้อยล้านแถวนี่คือต้นทุนที่แยกออกมาต่างหากจากการตรวจ batch จริง ส่วนว่ารอบการรันครั้งถัดไปทำซ้ำหรือไม่ ไม่ได้ทดลอง
2. คำสั่งที่ 2 และ 3 มี WHERE ฐานข้อมูลกรองก่อน ข้อมูลของวันอื่นไม่ถูกนับในผล
3. นิพจน์วันที่ต่างกันตาม dialect บน SQLite เป็น `CAST(STRFTIME('%Y', d) AS INTEGER)` ฐานข้อมูลอื่นใช้ฟังก์ชันของมัน (ไม่ได้ทดลองกับฐานข้อมูลอื่น) นิพจน์ครอบคอลัมน์ `d` ทำให้ index บนคอลัมน์นี้ใช้ไม่ได้โดยทั่วไป ข้อนี้เป็นการอนุมานจากรูปของ SQL ไม่ได้ทดลองวัดแผนการรัน
4. บทหลักเคยแสดง SQL แบบ `EXTRACT(year FROM d)` ซึ่งเป็นรูปกลางที่ SQLAlchemy คอมไพล์เมื่อไม่ระบุ dialect ตัวที่ SQLite ได้รับคือ `STRFTIME` ด้านบน

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
ไม่ได้ลองฐานข้อมูลที่ไม่ใช่ SQLite ไม่ได้ดูแผนการรัน (EXPLAIN) และไม่ได้วัดเวลาของคำสั่งที่ 1 เมื่อตารางโตขึ้น ข้อสรุปเรื่องต้นทุนจึงเป็นเรื่องรูปของคำสั่ง ไม่ใช่ตัวเลขที่วัด
</Callout>
