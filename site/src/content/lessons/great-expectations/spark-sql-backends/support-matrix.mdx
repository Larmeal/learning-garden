## รายการนี้มาจากไหน

ไฟล์ของแต่ละ expectation ใน GX มีตัวแปรระดับโมดูลชื่อ `SUPPORTED_DATA_SOURCES` ที่เป็นรายชื่อ backend ที่ทีม GX ระบุว่ารองรับ ตัวแปรนี้ถูกใช้สร้างข้อความเอกสารของคลาส สคริปต์ `30_sql_where_support.py` ส่วนที่ 2 อ่านตัวแปรนี้จากโมดูลของ expectation ทุกตัวที่ GX 1.24.1 ส่งออก (ตอนแรกสคริปต์อ่านจากคลาสโดยตรงแล้วไม่พบอะไร เพราะมันเป็นตัวแปรโมดูลไม่ใช่แอตทริบิวต์ของคลาส)

| นับอะไร | จำนวน |
|---|---|
| expectation ที่โมดูลมีรายการนี้ | 54 |
| ระบุว่ารองรับ PostgreSQL | 53 |
| ระบุว่ารองรับ SQLite | 51 |
| ระบุว่ารองรับ Spark | 48 |
| ระบุว่ารองรับ Pandas | 46 |
| ระบุว่ารองรับ BigQuery | 47 |

</Step>

<Step>

## ค้นหาเอง

เลือก backend ดูว่ามี expectation ไหนที่ไม่ระบุรองรับ

<SupportLookup client:visible />

บน Spark มี 6 ตัวที่ไม่ระบุ: `ExpectColumnValuesToMatchLikePattern`, `...MatchLikePatternList`, `ExpectColumnValuesToNotMatchLikePattern`, `...NotMatchLikePatternList`, `ExpectQueryResultsToMatchComparison` และ `ExpectTableRowCountToEqualOtherTable` ตัวแรกสี่ตัวใช้รูปแบบ `LIKE` ของ SQL ส่วนสองตัวสุดท้ายเทียบกับตารางอื่นหรือรัน query

</Step>

<Step>

## ใช้อย่างระวัง

1. รายการนี้เป็นเอกสาร GX ไม่ได้ตรวจตอนรัน expectation ที่ไม่ระบุ backend ของคุณก็ยังรันได้ถ้ามี metric implementation ที่ตรงกัน และตัวที่ระบุก็ยังล้มได้ถ้า metric ไม่มี ข้อเท็จจริงของการรองรับอยู่ในทะเบียน metric ([บทที่ 8 หน้า "ทะเบียน metric ในตัว GX"](/great-expectations/metrics-engines/registry/))
2. แยกระหว่าง pandas กับ SQL: รายการระบุ Pandas 46 ตัว แต่ทะเบียน metric มี implementation ของ pandas กว้างกว่านั้น (241 metric) สองแหล่งนี้นับคนละอย่าง อย่านำตัวเลขมาเทียบกัน
3. ทางที่ได้ผลคือลองรัน suite กับข้อมูลตัวอย่างบน backend จริง แล้วอ่านผลด้วยลำดับคำถามใน[บทที่ 4 หน้า "อ่านผลที่ไม่ผ่านอย่างเป็นระบบ"](/great-expectations/reading-results/triage/)

<Callout type="warn" title="Spark ที่ยังไม่ได้ทดลอง">
ตัวเลข 48 ของ Spark คือจำนวนที่เอกสารระบุ ไม่ใช่จำนวนที่รันผ่านบน Spark เส้นทางนี้ไม่ได้รัน GX บน Spark
</Callout>
