## ตั้งสถานการณ์

โฟลเดอร์มีไฟล์ของวันที่ 1 และ 3 มกราคม 2024 ส่วนไฟล์ของวันที่ 2 ไม่เคยมา (`29_pipeline_policies.py` ส่วนที่ 2, GX 1.24.1) checkpoint ตรวจจำนวนแถวไม่ต่ำกว่า 1 ผ่าน batch definition รายวันที่ regex ปิดหัวท้าย (ตามหน้า "regex ของชื่อไฟล์" ของ[บทที่ 6](/great-expectations/datasources-batches/))

def run_for(day: date):
    return daily_cp.run(batch_parameters={"year": day.year, "month": day.month, "day": day.day})

## รันซ้ำวันเดิม

รัน `run_for(date(2024, 1, 3))` สองครั้ง จำนวนผลใน results store เพิ่มขึ้น 2 (ไม่ใช่ 1) ผลรอบเก่าไม่ถูกทับ ทุกรอบมี `run_time` ของมันเอง (หน้า "[รันซ้ำกับข้อมูลของวันถัดไป](/great-expectations/first-validation/run-again/)" ของ[บทที่ 2](/great-expectations/first-validation/)) ผลที่ตามมา

- backfill ย้อนหลังทำได้ตรงๆ แค่ส่งวันที่เก่า ผลรอบเก่าอยู่ครบ
- ถ้าต้องการรู้ว่าวันหนึ่งผ่านหรือไม่ ต้องเลือกผลล่าสุดของวันนั้นเอง GX ไม่ได้ทำให้
- ผลที่ซ้ำกันของวันเดียวกันอาจขัดกัน (รอบแรกล้ม รอบสองผ่านหลังแก้ไฟล์) ระบบที่อ่านผลต้องรู้ว่าจะเชื่อรอบไหน

<Callout type="warn" title="ที่ไม่ได้ทดลอง">
ทดลองกับไฟล์ CSV ในโฟลเดอร์เดียวและ ephemeral context เท่านั้น ไม่ได้ทดลองกับ scheduler จริง ไม่ได้ทดลองการรันสองงานพร้อมกัน และไม่ได้ทดลองแหล่งข้อมูลที่เป็นตาราง SQL แม้หลักการส่งพารามิเตอร์ครบจะใช้ได้เหมือนกัน
</Callout>
