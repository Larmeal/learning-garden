## suite ที่มีสองระดับ

บทหลักเสนอสามนโยบาย หน้านี้เขียนมันจริง (`29_pipeline_policies.py` ส่วนที่ 1, GX 1.24.1) suite ของตาราง orders มีสองกฎ

```python
gxe.ExpectColumnValuesToNotBeNull(column="order_id")          # severity เริ่มต้น: critical
gxe.ExpectColumnValuesToBeBetween(column="amount", min_value=0, max_value=1000,
                                  mostly=0.99, severity="warning")
```

และข้อมูลสามแบบ

| ข้อมูล | เป็นอย่างไร | ระดับสูงสุดของข้อที่ล้ม |
|---|---|---|
| good | `order_id=[1, 2]`, `amount=[10, 20]` | ไม่มี (`None`) |
| warning only | `amount` มี 5000 (เกิน 1000) | `warning` |
| critical | `order_id` มี null | `critical` |

ระดับสูงสุดอ่านจาก `suite_result.get_max_severity_failure()` ของแต่ละ validation ใน `run_results` (คืน `None` ถ้าผ่านหมด และมี `.value` เป็นสตริง `"warning"` หรือ `"critical"`)

</Step>

## สามนโยบาย

```python
def apply(policy, name, result, state):
    sev = severity_of(result)
    if result.success:
        state["published"].append(name)
    elif policy == "stop":
        state["stopped"].append(name)
    elif policy == "quarantine":
        state["quarantine"].append(name)
    elif policy == "warn then continue":
        if sev == "critical":
            state["stopped"].append(name)
        else:
            state["published"].append(name)
            state["alerts"].append(name)
```

## เลือกอย่างไร

- ถ้าไม่ได้ตั้ง `severity` ทุกกฎเป็น `critical` นโยบาย "เตือนแล้วไปต่อ" จึงหยุดทุกกรณีที่ล้ม ผลเท่ากับ "หยุด"
- `mostly=0.99` ทำให้กฎ `amount` ยอมให้ผิดได้ไม่เกิน 1% ข้อมูลทดลองมี 2 แถว แถวที่เกินคิดเป็น 50% จึงล้ม
- นโยบาย "กัก" ในสคริปต์เป็นเพียงลิสต์ในโปรแกรม ในงานจริงต้องมีที่พักจริงและกลไกให้ผู้ใช้เห็นรอบเก่า ส่วนนี้ไม่ได้ทดลอง
