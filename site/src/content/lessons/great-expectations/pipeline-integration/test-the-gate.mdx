## กรณีทดสอบขั้นต่ำ

gate ที่เขียนไว้ควรตอบถูกในกรณีที่รู้คำตอบอยู่แล้ว สคริปต์ `29_pipeline_policies.py` ส่วนที่ 3 รันสามกรณีด้วยตัวตรวจแบบ assert ธรรมดา (GX 1.24.1) ไม่ได้ใช้ pytest

```python
CASES = [
    ("good data passes",                 cp,       DATA["good"],     False),
    ("null id stops",                    cp,       DATA["critical"], True),
    ("suite with no expectations stops", empty_cp, DATA["good"],     True),
]
for label, checkpoint, frame, should_stop in CASES:
    try:
        gate(checkpoint, {"dataframe": frame})
        stopped = False
    except QualityGateError:
        stopped = True
    print("PASS" if stopped == should_stop else "FAIL", label)
```

ผลที่พิมพ์

```text
PASS  good data passes
PASS  null id stops
PASS  suite with no expectations stops
```

## ข้อควรรู้

1. ใช้ ephemeral context ในการทดสอบ context เริ่มว่างทุกครั้ง ไม่มีเรื่องชื่อซ้ำ (บทที่ 1)
2. แต่ละกรณีต้องสร้าง object ใหม่ ถ้าใช้ expectation ตัวเดิมซ้ำใน suite สองตัวจะได้ `RuntimeError` (บทที่ 4 หน้า "อ่านผลที่ไม่ผ่านอย่างเป็นระบบ")
3. ทดสอบ gate กับข้อมูลจำลองไม่ได้พิสูจน์ว่า suite จับข้อมูลจริงได้ ชุดทดสอบนี้บอกแค่ว่าการตัดสินใจหลังอ่านผลถูกต้อง ส่วนความเหมาะสมของกฎต้องเทียบกับข้อมูลเสียจริงที่เคยเกิด
4. ถ้าใช้ pytest ห่อสามกรณีนี้เป็นฟังก์ชัน test ได้ตรงๆ (ไม่ได้ลองรัน pytest ในเส้นทางนี้)
