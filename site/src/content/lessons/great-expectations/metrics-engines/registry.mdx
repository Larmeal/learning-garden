## ทะเบียนมีอะไรอยู่

ทุก Metric ที่เขียนเป็นคลาส (เช่น `ColumnMax`) จะลงทะเบียนตัวเองตอน Import ลงใน `registry._registered_metrics` โดยมีชื่อ Metric เป็นกุญแจ และมีรายการ `providers` ที่บอกว่ามี Implementation สำหรับ Engine ไหนบ้าง สคริปต์ `26_registry_domains.py` ส่วนที่ 1 นับตัวเลขเหล่านี้จาก GX 1.24.1 ที่ติดตั้งไว้

| นับอะไร | จำนวน |
|---|---|
| ชื่อ Metric ที่ลงทะเบียน | 315 |
| มี Implementation สำหรับ Pandas | 241 |
| มี Implementation สำหรับ SQL (SQLAlchemy) | 255 |
| มี Implementation สำหรับ Spark | 254 |
| มีครบทั้งสาม Engine | 184 |
| มีบน Pandas แต่ไม่มีบน SQL | 57 |

ตัวเลขเหล่านี้นับจาก Implementation ที่ลงทะเบียนไว้ ไม่ได้รันทุก Metric บนทุก Engine นะ และในเส้นทางนี้เราก็ไม่ได้รัน Spark เลย

</Step>

## ผลของการขาด Implementation

ถ้า Expectation ต้องใช้ Metric ที่ไม่มี Implementation สำหรับ Engine ที่กำลังรันอยู่ GX จะไม่ Raise ให้ แต่เก็บเป็นผล `success=False` พร้อมข้อความ `No provider found` ใน `exception_info` (เราทดลองแล้วกับ Custom Expectation ที่เขียนเงื่อนไขไว้เฉพาะ Pandas แล้วรันบน SQLite ใน[บทที่ 12](/great-expectations/custom-expectations/testing-shipping/#เงื่อนไขเดียวกัน-ผลต่างกันตาม-engine)) ผลที่ออกมาจึงดูเหมือน "ข้อมูลไม่ผ่าน" ทั้งที่จริง ๆ แล้วปัญหาคือ Engine ไม่รองรับ

ยกตัวอย่างจากการนับ Metric ตระกูล `column_values.dateutil_parseable.*` มีบน Pandas แต่ไม่มีบน SQL (ห้าตัวแรกในรายการ 57 ตัวคือ `column.parameterized_distribution_ks_test_p_value` และสี่ตัวของ `dateutil_parseable`) เพราะฉะนั้น Expectation ที่ต้องใช้ Metric เหล่านั้นจึงไม่ควรเอาไปรันกับข้อมูลที่อยู่ในฐานข้อมูล

<Callout type="warn" title="ก่อนวาง Suite ลง SQL หรือ Spark">
การที่มีชื่อ Expectation ให้ใช้ ไม่ได้แปลว่า Engine ของคุณรองรับ ให้ลองรัน Suite กับข้อมูลตัวอย่างบน Engine นั้นก่อน แล้วอ่านผลที่ `success=False` ทุกข้อว่ามี `No provider found` หรือไม่ (ใช้ลำดับคำถามจากหน้า "[Failure Triage](/great-expectations/reading-results/triage/#ลำดับคำถาม)" ใน[บทที่ 4](/great-expectations/reading-results/)) ส่วนทะเบียนนี้เป็นเพียงทางลัดไว้ดูล่วงหน้า
</Callout>
