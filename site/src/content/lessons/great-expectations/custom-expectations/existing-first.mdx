## เขียนเองมีค่าใช้จ่ายต่อเนื่อง

Custom Expectation ทำงานได้ดี แต่คุณรับภาระสามอย่างไปด้วย

- ต้องเขียนและทดสอบเงื่อนไขแยกทีละ Engine ที่ใช้จริง ถ้าลืมเขียนให้ Engine ไหน Expectation นั้นล้มบน Engine นั้น
- ทุกโปรเซสที่โหลด Suite ต้อง Import คลาสของคุณก่อน ไม่อย่างนั้น Suite จะโหลดมาว่าง (หน้า "[วงจรชีวิต](/great-expectations/custom-expectations/registry-loading/)")
- คุณต้องดูแลโค้ดนี้เองตอนอัปเกรด GX เพราะมันเรียกใช้ของภายในอย่าง `ColumnMapMetricProvider` และ `column_condition_partial`

ภาระข้อที่สามไม่ได้หนักเกินไป เพราะสคริปต์ `07`, `11`, `12` และ `13` ของบทนี้รันบนทั้ง GX 1.9.3 และ 1.24.1 ด้วยโค้ดชุดเดียวกัน และคลาสที่นิยามไว้ก็ทำงานได้เหมือนกัน ผลต่างที่เห็นมีแค่ชนิดตัวเลขใน Result (`np.int64` ใน 1.9.3 เทียบกับ `int` ใน 1.24.1 ในผลของ Pair และ Multicolumn) กับข้อความ Error ของกรณี `filter_column_isnull = False` ทั้งนี้เป็นผลจากสองรุ่นที่ทดลอง ไม่ได้รับประกันว่ารุ่นอื่นจะเหมือนกัน และบทนี้ไม่ได้ทดลองว่า Data Docs แสดง Expectation ที่เขียนเองอย่างไร

</Step>

## ปรับของที่มีด้วยพารามิเตอร์

เราใช้ตารางตัวอย่างหกแถว (`15_adapt_builtin.py`)

```python
orders = pd.DataFrame({
    "country": ["th", "th", "th", "jp", "jp", "sg"],
    "zip":     ["10110", "10110", "1011", "100-0001", "100-0001", "018956"],
    "amount":  [120.0, 80.0, 5000.0, 60.0, 70.0, 90.0],
})
```

### Mostly: ยอมให้ผิดได้สัดส่วนหนึ่ง

```python
gxe.ExpectColumnValuesToBeBetween(column="amount", min_value=0, max_value=1000, mostly=0.8)
```

| Mostly | ผล |
|---|---|
| 1 (ค่าเริ่มต้น) | `success=False`, ผิด 1 จาก 6 (ค่า `5000.0`) |
| 0.8 | `success=True` (ถูก 5 จาก 6 ได้ 0.833) |

### row_condition: ตรวจเฉพาะแถวที่เข้าเงื่อนไข

สมมติว่ารหัสไปรษณีย์ต้องมี 5 หลักเฉพาะแถวที่ `country` เป็น `th` ส่วนประเทศอื่นมีรูปแบบต่างกันได้

```python
from great_expectations.expectations.row_conditions import Column

gxe.ExpectColumnValuesToMatchRegex(
    column="zip", regex=r"^\d{5}$", row_condition=Column("country") == "th"
)
```

| row_condition | แถวที่ตรวจ | ผิด |
|---|---|---|
| ไม่ใส่ | 6 | 4 (`'1011'`, `'100-0001'` สองแถว, `'018956'`) |
| `Column("country") == "th"` | 3 | 1 (`'1011'`) |

### Severity: บอกว่าล้มแล้วหนักแค่ไหน

```python
gxe.ExpectColumnValuesToBeBetween(column="amount", min_value=0, max_value=1000, severity="warning")
```

ผลของ Validation มี `get_max_severity_failure()` ซึ่งคืนระดับที่หนักที่สุดในบรรดาข้อที่ล้ม (ในตัวอย่างที่ผสม `warning` กับ `critical` ได้ `FailureSeverity.CRITICAL`) ค่าที่ใช้ได้คือ `critical`, `warning`, `info` และค่าเริ่มต้นคือ `critical`

<Callout type="note" title="ไวยากรณ์ของ row_condition เปลี่ยนไปแล้ว">
ใน GX 1.24.1 `row_condition` รับอ็อบเจ็กต์อย่าง `Column("country") == "th"` โดยซอร์ส `expectations/row_conditions.py` มีทั้ง `AndCondition` และ `OrCondition` แต่จำกัดว่า AND ห้ามมี OR ซ้อนอยู่ข้างใน และ OR ห้ามซ้อน OR นอกจากนี้ซอร์สรุ่นนี้ยังมีฟิลด์ `condition_parser` และตัวแปลง row_condition แบบสตริงเก่า (`_transform_legacy_row_condition`) แต่บทนี้ไม่ได้ทดลองแบบสตริง ดังนั้นตัวอย่างจากเอกสารเก่าควรลองกับรุ่นที่ติดตั้งก่อนใช้นะ
</Callout>

</Step>

## ค้นหาก่อนเขียน

ตอน `import great_expectations.expectations` GX จะลงทะเบียน Expectation ที่มีให้ครบ ซึ่งนับได้ 59 ตัวใน 1.24.1 และเราค้นด้วยชื่อได้ทันที

```python
from great_expectations.expectations import registry

names = registry.list_registered_expectation_implementations()
[n for n in names if "pair" in n]
```

| คำค้น | ที่เจอ |
|---|---|
| `pair` | `column_pair_values_a_to_be_greater_than_b`, `column_pair_values_to_be_equal`, `column_pair_values_to_be_in_set` |
| `multicolumn` | `multicolumn_sum_to_equal`, `multicolumn_values_to_be_equal` |
| `regex` | `column_values_to_match_regex`, `..._regex_list`, `column_values_to_not_match_regex`, `..._regex_list` |
| `unique` | `column_values_to_be_unique`, `compound_columns_to_be_unique`, `select_column_values_to_be_unique_within_record` และอีกสองตัว |

ในรายการ 59 ตัวมีหลายตัวที่คนมักคิดว่าต้องเขียนเอง เช่น `column_values_to_not_be_outliers`, `column_values_to_be_json_parseable`, `column_values_to_match_strftime_format`, `table_row_count_to_equal_other_table` และ `query_results_to_match_comparison` ดังนั้นให้ลองค้นด้วยคำที่ตรงกับกฎของคุณ แล้วเปิดเอกสารหรือซอร์สของตัวที่เจอเพื่อดูพารามิเตอร์

</Step>

## กฎที่ดูเหมือนต้องเขียนเอง แต่มีของที่ใกล้เคียง

| กฎ | ลองใช้ก่อน |
|---|---|
| รหัสไปรษณีย์ เบอร์โทร รหัสสินค้า (รูปแบบตายตัว) | `ExpectColumnValuesToMatchRegex` |
| ค่าต้องอยู่ในรายการที่กำหนด | `ExpectColumnValuesToBeInSet` |
| คอลัมน์ A กับ B ต้องมีค่าเท่ากันทุกแถว | `ExpectColumnPairValuesToBeEqual` |
| A ต้องมากกว่า B | `ExpectColumnPairValuesAToBeGreaterThanB` (มี `or_equal`) |
| ผลรวมของหลายคอลัมน์ต้องเท่ากับค่าหนึ่ง | `ExpectMulticolumnSumToEqual` |
| คู่ของคอลัมน์ต้องไม่ซ้ำกัน | `ExpectCompoundColumnsToBeUnique` |
| ค่ามากสุด ค่าเฉลี่ย ค่ากลาง อยู่ในช่วง | `ExpectColumnMaxToBeBetween`, `...MeanToBeBetween`, `...MedianToBeBetween` |
| จำนวนแถวต้องเท่ากับอีกตาราง หรือผลคิวรีต้องตรงกับค่าเปรียบเทียบ | `ExpectTableRowCountToEqualOtherTable`, `ExpectQueryResultsToMatchComparison` |
| กฎที่เขียนเป็น SQL ได้และต้องไม่มีแถวผิดเลย | `UnexpectedRowsExpectation` (ไม่ต้องมีคลาสของตัวเอง) |

ตัวสุดท้ายเป็นทางเลือกที่ต้องรู้ เพราะมันเป็นทางกลางระหว่างของที่มีกับคลาสที่เขียนเอง

```python
query = "SELECT * FROM {batch} WHERE discount * 2 > price"
gxe.UnexpectedRowsExpectation(unexpected_rows_query=query)
```

เมื่อทดลองบน SQLite (`12_custom_kinds.py`) จะได้ `success=False` และ `observed_value=1` ซึ่งหมายถึงพบหนึ่งแถวที่ละเมิดกฎ ข้อจำกัดของมันคือรันได้เฉพาะ Backend ที่รับ SQL (ซอร์สมี Provider ของ SQLAlchemy และ Spark โดย Spark ไม่ได้ทดลอง) ส่วนบน Pandas จะได้ `success=False` พร้อมข้อความ `No provider found for unexpected_rows_query.table using PandasExecutionEngine`

</Step>

## ลำดับที่ควรลอง

1. ดูก่อนว่ามี Expectation ตรงตัวไหม (ค้นใน Registry ด้วยคำสำคัญสองสามคำ)
2. ลองดัดแปลงด้วย `mostly`, `row_condition`, `severity`
3. ถ้ากฎเขียนเป็น SQL ได้ และข้อมูลอยู่ในฐานข้อมูล SQL (หรือ Spark) ให้ใช้ `UnexpectedRowsExpectation`
4. ถ้ายังไม่พอ ก็เขียนคลาสเอง โดยเลือกคลาสแม่ตามตารางในหน้าแรกของบท

<Callout type="tip" title="ข้อ 3 กับข้อ 4 ต่างกันที่ผลลัพธ์">
`UnexpectedRowsExpectation` ให้ `observed_value` เป็นจำนวนแถวที่ผิด และถ้าตั้ง `result_format` เป็น `COMPLETE` จะได้แถวเต็มใน `details.unexpected_rows` ด้วย (ทดลองแล้วบน SQLite) แต่ไม่มี `mostly`, `unexpected_percent` หรือดัชนีแถวอย่าง Column Map ซอร์สกำหนด `success_keys` ของมันไว้แค่ `unexpected_rows_query`
</Callout>

</Step>
