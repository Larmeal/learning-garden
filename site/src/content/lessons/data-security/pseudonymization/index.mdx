## แทนที่อีเมลด้วย Hash ก็ปลอดภัยแล้วใช่ไหม

ทีมวิเคราะห์ของนาย A ยังอยากรู้ว่าลูกค้าคนเดียวกันสั่งของกี่ครั้ง จึงไม่ได้ลบคอลัมน์อีเมลทิ้งไปเลย แต่แทนที่ด้วย `sha256(email)` เพราะจำได้จาก[บทที่แล้วในวิชา Application Security](/app-security/crypto-basics/) ว่า Hash ย้อนกลับไม่ได้ วิธีแทนตัวระบุด้วยค่าอื่นที่ยังบอกได้ว่าเป็นคนเดิม เรียกว่า **Pseudonymization** (หนังสือ: Practical Data Privacy บทที่ 1 หน้า 22)

คำถามคือ ใครที่ได้ตารางไปแล้วอยากรู้ว่าแถวไหนเป็นใคร จะทำอย่างไร ผู้โจมตีไม่ต้องย้อนกลับ เขาแค่ลองเดา แล้ว Hash ผลลัพธ์เทียบกับตาราง ใน Application Security เราเห็นแล้วว่า PIN สี่หลักถูกเดาเจอใน 7,352 ครั้ง ทีนี้ลองของที่ใหญ่ขึ้น (รัน: `exercises/02_pseudonymization.py`)

สมมติว่าตารางเก็บเลขสมาชิก 6 หลักของแต่ละคน ซึ่งมีแค่ 1,000,000 แบบ ผู้โจมตีคำนวณ SHA-256 ของทุกเลขไว้ก่อนหนึ่งครั้ง แล้วเทียบ

```python
lookup = {sha(f"{n:06d}".encode()): f"{n:06d}" for n in range(1_000_000)}
undone = sum(1 for pid, h in hashed.items() if lookup.get(h) == members[pid])
```

แถวแรกสร้างตารางของ Hash ทั้งล้านค่า ซึ่งใช้เวลาประมาณ 1.6 วินาทีบนคอมพิวเตอร์ที่รัน แถวที่สองเอา Hash ในตารางของเราไปค้นกลับ ผลที่ได้คือถอดกลับได้ครบ 2,000 จาก 2,000 คน

อีเมลก็ไม่ปลอดภัยกว่านั้นมาก เพราะอีเมลมีรูปแบบ ชื่อ จุด นามสกุล ตัวเลข @ โดเมน แบบฝึกสร้างพจนานุกรมจากชื่อ 20 ชื่อ นามสกุล 15 ชื่อ เลข 1 ถึง 2,000 และโดเมนเดียว ได้ 600,000 ค่า ซึ่งเจออีเมลทั้ง 654 ที่อยู่ในโดเมนนั้นครบ

## สี่วิธี และสิ่งที่แต่ละวิธีแลกมา

มีทางเลือกที่ไม่ตกม้าตายแบบ Hash ธรรมดา แต่แต่ละอย่างแลกด้วยอะไรบางอย่าง ลองเลือกวิธีกับสิ่งที่ผู้โจมตีถืออยู่ในแล็บข้างล่าง แล้วกดเล่น ผู้โจมตีจะลองอีเมลที่เดาทีละอัน แถวไหนตรงก็ถูกถอดกลับมา ส่วนด้านล่างคือลูกค้าคนเดิมในอีกตารางหนึ่ง ถ้าสองค่าเท่ากัน นักวิเคราะห์ก็ Join ได้ ข้อสังเกตคือสิ่งที่ทำให้ Join ได้ ก็คือสิ่งที่ผู้โจมตีที่ถือของที่ถูกต้องใช้ได้เหมือนกัน

## Salt ต่อแถว: ปลอดภัยขึ้น แต่ Join ไม่ได้

เหมือนกับที่ Salt ช่วยเรื่อง Password ในวิชา Application Security เราใส่ Salt สุ่มต่างกันทุกแถวหน้า Hash พจนานุกรมก็ใช้ไม่ได้ แบบฝึกเช็กว่าพจนานุกรมเดิมไม่เจอ Hash ไหนเลย

แต่มีราคา สมมติว่าตารางคำสั่งซื้อกับตารางตั๋วซัพพอร์ตต่างใส่ Salt ให้อีเมลของลูกค้าคนเดียวกัน ค่าที่ได้ในสองตารางไม่เท่ากัน แบบฝึกนับว่าตรงกัน 0 จาก 2,000 คน ทีมวิเคราะห์ที่อยากรู้ว่าลูกค้าคนนี้สั่งของแล้วโทรมาถามไหม ก็ทำไม่ได้ ถ้าไม่ต้องการ Join ข้ามตารางเลย วิธีนี้ใช้ได้ แต่ส่วนมากเราต้องการ

</Step>

## HMAC: Join ได้ ตราบใดที่ Key ปลอดภัย

HMAC ผสม Key ลับเข้าไปในการคำนวณ ใครที่ไม่มี Key ก็คำนวณค่าของอีเมลที่เดาไม่ได้ แบบฝึกสร้างสองตารางด้วย Key เดียวกัน ผลคือค่าของอีเมลเดียวกันตรงกันครบ 2,000 จาก 2,000 คน จึง Join ได้ และผู้โจมตีที่มีพจนานุกรมอีเมลครบแต่ไม่มี Key ไม่เจอค่าไหนเลย

ค่าที่ได้สั้นกว่า Hash เต็ม (16 ตัวอักษรฐานสิบหก) และไม่ซ่อนส่วนใดของอีเมลเลย จำนวนคนที่ต่างกันยังเท่าเดิม (2,000 ค่า) การนับคนจึงยังถูก

ข้อเสียมีสองข้อ อย่างแรก Key เป็นจุดอ่อนเดียวของระบบนี้ ถ้ามันหลุดไปพร้อมกับตาราง ผู้โจมตีใช้พจนานุกรมคำนวณ HMAC ของอีเมลที่เดาแล้วถอดกลับได้เหมือน Hash ธรรมดา อย่างที่สอง ถ้าเปลี่ยน Key ทุกอย่างที่เคยสร้างด้วย Key เก่าหมดความหมาย แบบฝึกนับว่าหลังเปลี่ยน Key ไม่มี Token เก่าตัวไหนเท่ากับ Token ใหม่ (0 จาก 2,000) ตารางที่สร้างต่างเวลากันจึง Join กันไม่ได้อีก

</Step>

## Token สุ่ม: ไม่มีอะไรให้โจมตี แต่ต้องมี Vault

วิธีสุดท้ายคือไม่ได้คำนวณจากอีเมลเลย แต่สุ่มค่าใหม่ แล้วจดคู่ "อีเมลกับ Token" ไว้ใน Vault ที่แยกต่างหาก ผู้โจมตีที่ได้แค่ตารางไม่มีสูตรให้เดา แบบฝึกสร้างสองตารางที่ Tokenize อีเมลเดียวกันแยกกัน ค่าที่ได้ไม่ตรงกันเลย (0 จาก 2,000) เพราะต่างคนต่างสุ่ม และ Vault ต้องเก็บ 4,000 รายการที่ต้องปกป้องเอง

ที่ใช้กันจริงคือให้ Vault ตอบว่า "อีเมลนี้ได้ Token อะไร" ซ้ำค่าเดิมเมื่อเจอซ้ำ ซึ่งทำให้ Join ได้ แต่แลกด้วยการที่ทุกคนต้องเรียก Vault และ Vault กลายเป็นเป้าโจมตีที่ใหญ่ที่สุด แบบฝึกไม่ได้รัน Vault แบบนั้น

<Callout type="note" title="Pseudonymization ไม่ใช่ Anonymization">

ทั้งสี่วิธีเปลี่ยนแค่ตัวระบุตรง ๆ ส่วน Quasi Identifier อย่าง Zip วันเกิด และเพศยังอยู่ครบ ซึ่งจาก[บทที่แล้ว](/data-security/sensitive-data/) เรารู้ว่ามันเพียงพอจะทำให้คน 1,992 ใน 2,000 คนไม่มีใครซ้ำ ผู้เขียนจึงเรียกข้อมูลแบบนี้ว่า Pseudonymized ไม่ใช่ Anonymized อย่างที่หนังสือ Practical Data Privacy จัดไว้ในบทที่ 1 (หนังสือ: Practical Data Privacy บทที่ 1 หน้า 22)

</Callout>
