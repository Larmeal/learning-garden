## คำนี้ถามอะไร

DMBOK2 นิยาม accuracy ว่าระดับที่ข้อมูลแทน entity ในชีวิตจริงได้อย่างถูกต้อง และเสริมว่ามันวัดยาก เว้นแต่คุณจะทำซ้ำการเก็บข้อมูลหรือยืนยัน record ด้วยมือได้ การวัดส่วนใหญ่เทียบกับแหล่งที่ได้รับการยืนยันว่า accurate แล้ว เช่น system of record หรือ reference data ภายนอกที่เชื่อถือได้ (หนังสือ: DMBOK2 Table 29 หน้า 458) DAMA UK พูดอย่างเดียวกันด้วยคำอื่น: ระดับที่ข้อมูลอธิบายวัตถุหรือเหตุการณ์ในโลกจริงได้ถูกต้อง (หนังสือ: DMBOK2 หัวข้อ 1.3.3 หน้า 457)

นึกถึงเทอร์โมมิเตอร์ ค่า 31.4 มี format ถูกและอยู่ในช่วงที่เป็นไปได้ ส่วนว่าห้องนั้น 31.4 องศาจริงไหม ต้องมีเทอร์โมมิเตอร์ตัวที่สองที่คุณเชื่อถือ หรือคนที่รู้

Ten Steps เปิดขั้นตอน accuracy ด้วยข้อสังเกตว่าหลายคนใช้คำว่า "accuracy" เป็นคำเดียวกับ data quality ทั้งหมด ทั้งที่มืออาชีพด้านข้อมูลรู้ว่าสองคำนี้ไม่เหมือนกัน (หนังสือ: Ten Steps บทที่ 4 หน้า 135 ถึง 140)

## Profiling บอกอะไรได้ และบอกอะไรไม่ได้

Ten Steps ยกสามตัวอย่างของเส้นแบ่งระหว่างสิ่งที่ profiling แสดง กับสิ่งที่มีแต่การเทียบจึงแสดงได้ (หนังสือ: Ten Steps บทที่ 4 หน้า 135 ถึง 140):

| profiling แสดง | มีแต่การเทียบที่แสดง |
|---|---|
| ทุกชิ้นส่วนมี code ที่ valid คือ M (ผลิตเอง) หรือ B (ซื้อ) | code นั้นตรงกับวิธีที่ชิ้นส่วนนั้นได้มาจริงไหม |
| postal code อยู่ใน field postal code และมี pattern ที่ valid | เป็น postal code ที่ถูกของ customer คนนี้ไหม |
| จำนวนสินค้าคงคลังมี data type ถูก | ตัวเลขตรงกับของที่อยู่บนชั้นจริงไหม |

ใน dataset ของเราการเทียบเกิดระหว่างสองระบบ เราถือว่า payment system เป็นแหล่งความจริง และเทียบยอดของ order ที่ไม่ถูกยกเลิกแต่ละรายการกับผลรวม payment ของมัน:

```sql
WITH o AS (SELECT DISTINCT order_id, total_amount FROM orders WHERE status <> 'CANCELLED'),
     p AS (SELECT order_id, sum(amount) AS paid FROM payments GROUP BY order_id)
SELECT count(*) FILTER (WHERE abs(o.total_amount - p.paid) > 0.005), count(*)
FROM o JOIN p USING (order_id);
-- 35 จาก 2,533 หรือ accurate 98.62% เมื่อเทียบกับ payment
```

| order_id | total_amount | paid | ส่วนต่าง |
|---:|---:|---:|---:|
| 91 | 487.71 | 437.71 | -50.00 |
| 122 | 2029.28 | 1979.28 | -50.00 |
| 412 | 4147.84 | 4146.84 | -1.00 |
| 438 | 1716.14 | 1836.14 | 120.00 |

</Step>

## ความหมายที่ถูกเข้าใจผิดบ่อย

<Callout type="warn" title="1. อ่าน accuracy ออกจาก column ไม่ได้">
ถ้าไม่มี reference คุณเช็ก validity ได้ แต่เช็ก accuracy ไม่ได้ decision flow ของ Ten Steps มีสี่คำถาม: ระบุแหล่งที่มีอำนาจได้ไหม เข้าถึงมันได้ไหม stakeholder เห็นพ้องว่ามันคือแหล่งที่มีอำนาจไหม และคุณจ่ายไหวไหมกับการ assess ถ้าข้อใดตอบว่าไม่ หนังสือบอกว่าคุณทำไม่ได้หรือไม่ควรประเมิน accuracy และให้ใช้ dimension อื่นแทน (หนังสือ: Ten Steps บทที่ 4 หน้า 135 ถึง 140) ประโยค "เรา accurate 98.62%" มีอนุประโยคที่ซ่อนอยู่: "เมื่อเทียบกับ payment system"
</Callout>

**2. ความไม่ตรงบอกว่าสองแหล่งขัดกัน ไม่ได้บอกว่าแหล่งไหนผิด** 35 row ของเราอาจเป็นยอด order ที่พิมพ์ผิด หรือ payment ที่บันทึกผิดก็ได้ เราเรียกมันว่า order ที่ไม่ accurate เพราะตกลงกันว่า payment คือแหล่งที่มีอำนาจ payment 20 รายการชี้ไปหา order ที่ไม่มีอยู่จริง (รัน: `13_dimension_pitfalls.py`) ซึ่งแสดงว่า reference ก็มีปัญหาของมันเอง หนังสือย้ำว่าถ้าไม่ตกลงเรื่องแหล่งที่มีอำนาจ คุณเสี่ยงที่จะไม่มีใครเชื่อผลที่ได้

**3. ค่า tolerance กำหนดตัวเลข** check ข้างบนนับส่วนต่างที่มากกว่า 0.005 (ครึ่งหน่วยของทศนิยมสองตำแหน่ง) เปลี่ยน tolerance ผลก็ขยับ (รัน: `13_dimension_pitfalls.py`):

| Tolerance | ไม่ตรง จาก 2,533 |
|---:|---:|
| 0.005 | 35 |
| 1.00 | 27 |
| 11.00 | 18 |
| 60.00 | 11 |

ไม่มีข้อไหนเป็นคำตอบที่ถูก ส่วนต่าง 1.00 กับส่วนต่าง 120.00 เป็นคนละปัญหา และคนที่เป็นเจ้าของเงินเป็นคนกำหนดว่าเส้นอยู่ตรงไหน ให้เขียน tolerance ลงใน rule

**4. Valid ไม่ใช่ accurate** ยอดผิดทั้ง 35 รายการไม่ติดลบ จึงผ่าน rule validity DMBOK2 ใช้วันเกิดเป็นตัวอย่าง: ค่าที่อยู่ในช่วงที่อนุญาตยังผิดสำหรับคนที่มันอธิบายได้ (หนังสือ: DMBOK2 Table 29 หน้า 459)

**5. accuracy แพง จึงวัดแค่บางส่วน** หนังสือบอกว่า check accuracy มักทำมือและแพง และแนะนำให้ถามว่าจะประเมิน record น้อยลงหรือ field น้อยลงแล้วยังได้ผลที่มีความหมายไหม (หนังสือ: Ten Steps บทที่ 4 หน้า 135 ถึง 140) ใน data ของเราการเทียบเป็นแค่ join และไม่มีต้นทุน ซึ่งเป็นข้อยกเว้น

**6. คำนี้เป็นชื่อ metric ของ model ด้วย** ใน machine learning "accuracy" คือสัดส่วนของผลทำนายที่ถูก มันไม่ได้แปลว่าข้อมูลที่ใช้ train accurate ในความหมายที่ใช้ที่นี่ จึงควรบอกว่าคุณหมายถึงอย่างไหน (ข้อสังเกตนี้เป็นของผู้เขียน)

</Step>

| ดูคล้ายกับ | แยกอย่างไร | ใน data ของเรา |
|---|---|---|
| Validity | Validity ถามว่าค่าอนุญาตไหม Accuracy ถามว่าจริงไหม | ยอดผิด 35 ตัว valid ทั้ง 35 |
| Consistency | สองแหล่งที่ตรงกันไม่พิสูจน์ว่าแหล่งใดถูก | copy ย่อมตรงกับต้นฉบับ |
| Reconciliation | Reconciliation คือ process เทียบสองระบบ Accuracy คือสิ่งที่ผลการเทียบที่ดีบอกเกี่ยวกับระบบหนึ่ง ([บท 8](/data-quality/reconciliation/#reconcile-ด้วยจำนวน-row-และผลรวม)) | ยอด order เทียบกับยอด payment |

## เช็กตัวเอง

- ตัวเลขที่ทีมคุณรายงานสำคัญที่สุด แหล่งที่มีอำนาจของมันคืออะไร และใครเห็นด้วยกับมัน
- สองระบบไม่ตรงกัน 1% ของ row คุณต้องมีอะไรก่อนจะบอกได้ว่าระบบไหนผิด
- มีคนขอให้ "ทำ accuracy ให้ถึง 99%" คุณถามอะไรก่อน

</Step>
