## Check yourself

<Question
  client:visible
  lang="en"
  q="A project asks for a dependency as ^1.2.0 with no lock file. The team runs the build twice, a week apart, and version 1.9.10 appears in between. What happens?"
  options={['Both runs get 1.9.9', 'The first gets 1.9.9 and the second gets 1.9.10, with nobody changing the code', 'The second run fails']}
  answer={1}
  why="^1.2.0 means the newest 1.x version that is below 2.0.0. The exercise confirms that when 1.9.10 appears, the result changes by itself. A lock file is what makes a build repeatable."

<Question
  client:visible
  lang="en"
  q="What can the hash in a lock file protect against, and what can it not?"
  options={['It stops a file that was swapped after we checked it, but it does not promise that the file we checked in the first place holds no malicious code', 'It stops every case including a library that was bad from the start', 'It does nothing, because the version is already locked']}
  answer={0}
  why="A hash says that the file matches what we saw before. It does not say that the file is good. In the exercise a file with one line of code added has a different hash, so the installer stops. Judging whether a library can be trusted in the first place is a separate job."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="A developer commits a key by mistake, and the next commit removes it. Then a scanner is run on the files in the current folder and finds nothing. Which statement is right?"
  options={['It is safe now, because the scanner found nothing', 'It is not safe, because the key is still in the first commit and has to be revoked. A good scanner has to scan the whole history as well', 'It is safe if the repository is private']}
  answer={1}
  why="A scanner that looks at the current files sees only the latest commit. The exercise confirms that git show of the first commit still shows the key, and that git log -S finds the commit that added it. A private repository is wider than it looks when several people hold copies, and permissions can change later. The safe way is to revoke."
/>

</Step>
