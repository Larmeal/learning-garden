## Check yourself

<Question
  client:visible
  lang="en"
  q="An API updates a profile by writing every field of the JSON the user sent into the table. A user sends role admin as well. What happens, and what is the fix?"
  options={['Nothing, because the API never asked for role', 'The user becomes an admin. Accept only the fields on an allow list and ignore the rest', 'It depends on the browser']}
  answer={1}

<Question
  client:visible
  lang="en"
  q="The variable who is passed into the function that reads an order, and never used. Which flaw does this match best?"
  options={['SQL injection', 'IDOR (broken object level authorization)', 'CSRF']}
  answer={1}
  why="The function hands over what is asked for by number, without asking whether the requester has any right to that order. The user changes the number and gets someone else's data, which is the shape of an IDOR. Injection and CSRF are about text becoming a command and about the browser attaching a cookie by itself."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="A server takes a file name and joins it onto the public folder. A user sends ../secret.txt. Which fix is the most direct?"
  options={['Remove the text ../ once from the name that was sent', 'Resolve it to a full path with .. removed, and check that it is still under the public folder', 'Forbid dots in file names']}
  answer={1}
  why="Removing ../ once can fail (for example ....// becomes ../ after the removal), but resolving to a full path first and comparing it with the folder looks at the actual result and not at how the text looks. The exercise has ../secret.txt refused and hello.txt still readable."

</Step>
