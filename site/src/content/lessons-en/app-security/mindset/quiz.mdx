## Check yourself

<Question
  client:visible
  lang="en"
  q="A search function takes limit from the URL and passes it to the database without a cap. Someone sends limit 10,000,000 several times in a row. No data leaks and none is changed, but the shop gets so slow that others cannot get in. What was lost?"
  options={['Confidentiality', 'Integrity', 'Availability']}
  answer={2}
  why="Nothing leaked and nothing was changed. What went missing is that legitimate users can get in, which is availability. In the exercise the fixed function caps limit at 100, so the request for 10,000,000 rows gets 100."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="Ann changes the order number in the URL from 1 to 2 and sees Bob's order. Where should this be fixed?"
  options={['In the browser, by hiding the order number from the user', 'On the server, in the endpoint that reads the order, by comparing the owner with the logged-in user', 'In the database, by only making order numbers longer']}
  answer={1}
  why="What is wrong is that the function never asks whose the order is, so the comparison of order owner with who has to be added on the server. Longer or random numbers make guessing harder, but they do not make the function check permission. If a number leaks, the order can still be read."
/>

</Step>

  q="Which choice fits the term trust boundary best?"
  options={['A line where data crosses from a place we do not control into our system', 'A button the user presses to send a request', 'A password that has to be kept secret']}
  answer={0}
  why="A trust boundary is where the trustworthiness of data changes. Whatever crosses it has to be checked, whether it comes from a browser, the network or another system. The picture in this lesson has two: from the user's device to the internet, and from the internet into our system."
