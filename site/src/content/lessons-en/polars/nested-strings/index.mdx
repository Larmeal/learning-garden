## One cell, many values: List

In [lesson 4](/en/polars/group-by-windows/) the result of `agg(pl.col("product").unique())` was a column where each cell holds many values. That column has the type `List`, and it does not come only from `agg`. Let us make a table that keeps each customer's products and quantities as lists (run: `exercises/08_nested_and_strings.py`).

```python
per = df.group_by("customer", maintain_order=True).agg(pl.col("product"), pl.col("qty"))
per.schema["product"]     # List(String)
per.row(0)                # ('Ann', ['pen', 'pen', 'book'], [2, 5, 2])
```

Now Ann has one row, with her three products in one cell. We look inside with the `list.` group of expressions, which is a namespace just like `str.`.

```python
per.select(
    "customer",
    n=pl.col("product").list.len(),
    kinds=pl.col("product").list.n_unique(),
    biggest=pl.col("qty").list.max(),
    first=pl.col("product").list.first(),
    has_book=pl.col("product").list.contains("book"),
).row(0)
# ('Ann', 3, 2, 5, 'pen', True)
```

Ann's result is 3 items, 2 kinds, a largest quantity of 5, a first product of `pen`, and she does have `book` in her list. To calculate on every member of a list, use `list.eval` and refer to the member with `pl.element()`.

```python
per.select(d=pl.col("qty").list.eval(pl.element() * 2))["d"][0]    # [4, 10, 4]
```

</Step>

## explode: turn members into rows

To go from a list back to rows, use `explode`.

```python
per.explode("product", "qty").shape      # (8, 3)   back to the original 8 rows
```

Watch out for lists that are empty or `null`.

```python
e = pl.DataFrame({"k": [1, 2, 3], "v": [[1, 2], [], None]})
e.explode("v").rows()                          # [(1, 1), (1, 2), (3, None)]
e.explode("v", empty_as_null=True).rows()      # [(1, 1), (1, 2), (2, None), (3, None)]
e.explode("v", keep_nulls=False).rows()        # [(1, 1), (1, 2)]
```

By default in 2.1.0 the empty list (`[]`) of `k = 2` has no member to turn into a row, so that row quietly disappears. The list that is `null` keeps one row (with a `null` value). If you do not want the row of `k = 2` to vanish, pass `empty_as_null=True`, and if you do not want the `null` row at all, pass `keep_nulls=False`. We read the defaults of these two parameters from the source of `DataFrame.explode` and tried all three forms.

</Step>

## Many columns in one cell: Struct

A `Struct` is a cell that holds several named fields, like a Python dict.

```python
s = df.select("order_id", item=pl.struct("product", "qty"))
s.schema["item"]       # Struct({'product': String, 'qty': Int64})
s["item"][0]           # {'product': 'pen', 'qty': 2}
s.select(p=pl.col("item").struct.field("product"))["p"][1]     # 'ink'
s.unnest("item").columns                                        # ['order_id', 'product', 'qty']
```

`pl.struct` bundles two columns into one, `struct.field` pulls a field out, and `unnest` spreads the fields back into ordinary columns. You often meet a Struct without making one, for example in the result of `value_counts()`, which is a table of two columns (the value and its count).

```python
df["product"].value_counts(sort=True).row(0)      # ('pen', 4)
```

And when you read nested JSON, it becomes a Struct column that you open with `unnest` (we did not run a multi-level JSON example).

</Step>

## Strings and regex

A text column has the `str.` group. Try it on four messy names.

```python
names = pl.DataFrame({"s": ["  Ann Lee ", "bob_smith", "Cat-Doe", None]})
names.select(pl.col("s").str.strip_chars())["s"][0]                       # 'Ann Lee'
names.select(pl.col("s").str.contains("_|-"))["s"].to_list()              # [False, True, True, None]
names.select(pl.col("s").str.replace_all(r"[_-]", " "))["s"].to_list()[1:3]   # ['bob smith', 'Cat Doe']
names.select(pl.col("s").str.split("_"))["s"][1]                          # ['bob', 'smith']
names.select(pl.col("s").str.extract(r"(\w+)[_-](\w+)", 2))["s"].to_list()   # [None, 'smith', 'Doe', None]
```

The second line is where `null` makes the result `None` (not `False`), as in [lesson 3](/en/polars/types-and-nulls/). Passing a missing value through is the behaviour of every expression in this group, so you do not have to write an `if` to guard it. `extract` pulls group 2 out of the regex, and gives `None` when there is no match.

Two more tools for building text:

```python
df.select(label=pl.format("{} x{}", pl.col("product"), pl.col("qty")))["label"].to_list()[:2]
# ['pen x2', 'ink x1']
df.select(pl.concat_str("customer", pl.lit("@"), "region", separator="", ignore_nulls=False))["customer"].to_list()[6]
# None
```

`pl.format` fills values into a template, and `concat_str` joins several text columns. If any column is `null`, the whole string is `null`. Row 7 of our table has no `region`, so it gives `None`.

</Step>

## When an expression cannot do it: map_elements and its price

Sometimes we want to call our own Python function on every value. Polars has `map_elements` for that, but it comes with a warning label.

```python
pl.DataFrame({"x": [1, 2]}).select(pl.col("x").map_elements(lambda v: v + 1, return_dtype=pl.Int64))
```

```text
Expr.map_elements is significantly slower than the native expressions API.
Only use if you absolutely CANNOT implement your logic otherwise.
Replace this expression...
  - pl.col("x").map_elements(lambda v: ...)
with this one instead:
  + pl.col("x") + 1
```

Polars even suggests the expression to use instead. Let us measure with a very easy job: upper-casing the `product` column.

```python
big.select(label=pl.col("product").str.to_uppercase())                                          # an expression
sub.select(label=pl.col("product").map_elements(lambda x: x.upper(), return_dtype=pl.String))   # a Python function per value
```

In our runs the expression took about 25 to 48 nanoseconds per row, and `map_elements` took about 166 to 307 nanoseconds per row (two runs, and both gave a ratio of about 6; the raw numbers change with the machine and the run). The two methods give the same result for every value. It is slower because Polars has to pick each value out of its own memory, hand it to Python, call the function, and take the result back and store it, one row at a time, and Python functions cannot be called on several threads at once, while an expression works directly on the whole column.

<Callout type="tip" title="Before you use map_elements">
Look for an expression that does the same job first. The warning above usually suggests one by itself for simple arithmetic and text. If the condition is complicated, try `when / then` from [lesson 2](/en/polars/expressions/) first.
</Callout>

</Step>
