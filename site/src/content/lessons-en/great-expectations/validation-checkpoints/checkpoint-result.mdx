## Two ways to read the result

`CheckpointResult` can be read in two ways that give different levels of information.

| Way | What it returns | Use it when |
|---|---|---|
| `result.describe()` | A summary JSON (a string) of the whole checkpoint | You export it as a log message or an API response |
| `result.run_results` | A dict: `ValidationResultIdentifier` to `ExpectationSuiteValidationResult` | You write code to walk through the results yourself and reach every field of a result |

Results from script `25_checkpoint_shapes.py`, parts 2 and 7 (GX 1.24.1): `describe()` has 3 top-level keys, `success`, `statistics` and `validation_results`.

</Step>

describe() is a summary that leaves some things out (for example `meta` and the `exception_info` of each item). It is good for an overview. If you need `exception_info`, go through `run_results`.

Whether describe() really leaves out `exception_info` can be checked from the keys that can be printed: `expectations[0]` has 4 keys, `expectation_type`, `success`, `kwargs`, `result`, and no `exception_info`.

## Pull out the items that failed

Walk through `run_results` directly.

```python
def failed_expectations(res):
    out = []
    for key, vres in res.run_results.items():
        for r in vres.results:
            if not r.success:
                out.append((
                    key.expectation_suite_identifier.name,
                    r.expectation_config.type,
                    r.expectation_config.kwargs.get("column"),
                    r.result.get("unexpected_count"),
                ))
    return out
```

The result on the checkpoint above:

```text
('suite_age', 'expect_column_values_to_not_be_null', 'age', 1)
('suite_age', 'expect_column_values_to_be_between', 'age', 1)
```

The item `suite_ids` passed, so it is not listed. This function does not separate a failure caused by the data from a failure caused by an exception. If you need to separate them, use the sequence of questions from [lesson 4](/en/great-expectations/reading-results/), the page "[Read a failed result in a systematic way](/en/great-expectations/reading-results/triage/)".

<Callout type="note" title="You can name a run">
`cp.run(..., run_id=RunIdentifier(run_name="nightly-2024-02-01"))` names the run, and it was measured that this name appears in every entry of `run_results` (`RunIdentifier` is imported from `great_expectations.core.run_identifier`). `Checkpoint.run` takes only three parameters: `batch_parameters`, `expectation_parameters`, `run_id`.
</Callout>
