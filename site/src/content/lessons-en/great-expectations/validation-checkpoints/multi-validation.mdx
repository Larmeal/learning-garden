## Two validations, one checkpoint

Script `25_checkpoint_shapes.py` builds two validation definitions and puts them in one checkpoint (GX 1.24.1, pandas).

| validation definition | suite | data that is checked |
|---|---|---|
| `vd_ids` | `id` must be unique | DataFrame `id=[1,2,3]` |
| `vd_age` | `age` is not null and is within 0 to 120 | `age=[10, None, 400]` |

```python
cp = context.checkpoints.add(gx.Checkpoint(name="cp", validation_definitions=[vd_ids, vd_age]))
result = cp.run(batch_parameters={"dataframe": frame})
```

The printed result:

```text
type: CheckpointResult | success: False
run_results entries: 2
  suite=suite_ids  success=True   evaluated=1
  suite=suite_age  success=False  evaluated=2
distinct run ids across validations: 1
results stored by this run: 2
```

- The `success` of the checkpoint is `False` because the second one fails. The overall result is: it passes only if every one passes.
- `run_results` has one entry per validation definition.
- Both get the same `run_id` (distinct = 1). This tells you they are in the same run.
- Two results are stored in the store, one per validation.

</Step>

## One set of parameters reaches every validation

The `batch_parameters` that you pass to `cp.run(...)` are passed on to every validation definition. Suppose one validation uses a DataFrame asset (it needs the key `dataframe`) and another uses a whole SQL table (it needs no key). One set of parameters cannot fit both. Part 4 of the script tests this.

```text
raised: InvalidBatchRequestError | batch parameters should only contain keys from the following set: set()
        but your specified keys contain {'dataframe'} which is not valid.
```

The message says the SQL batch accepts zero keys, but it received `dataframe`. As a result `cp.run(...)` raises for the whole run. It does not return the result of the one that already passed. Whether the first of the pair was run before that was not checked.

The safe approach is to group validation definitions in a checkpoint by the kind of batch definition (the ones that use the same set of keys), and to have a separate checkpoint for each group.
