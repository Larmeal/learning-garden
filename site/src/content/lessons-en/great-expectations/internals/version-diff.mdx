## How the comparison works

The script `32_version_diff.py` compares the `.py` files of the package `great_expectations` in the checkout of version 1.9.3 (the version that the knowledge graph analyzed) with version 1.24.1, which is installed in the project. It counts the lines added plus the lines removed with `difflib`, and ignores the difference in line endings (CRLF versus LF).

| | Count |
|---|---|
| `.py` files in 1.9.3 | 482 |
| `.py` files in 1.24.1 | 497 |
| In both versions | 473 |
| Identical in every line | 242 |
| Different | 231 |
| Only in 1.9.3 | 9 |
| Only in 1.24.1 | 24 |

The installed files come from PyPI, and 1.9.3 comes from a checkout of the repo. The differences may include packaging differences (for example the `_version.py` file).

## Files that were added and removed

Examples from the script (not the full list).

| Only in 1.24.1 | Only in 1.9.3 |
|---|---|
| `core/owner_resolution.py` | `data_context/store/database_store_backend.py` |
| `datasource/fluent/batch_parameter_normalization.py` | `data_context/store/query_store.py` |
| `datasource/fluent/fabric_datasource.py` | `expectations/regex_based_column_map_expectation.py` |
| `agent_skills/installer.py` | `expectations/set_based_column_map_expectation.py` |
| `compatibility/pyodbc.py` | `profile/` (the whole package) |

What relates to what you have learned:

- `owner_resolution.py` matches the behavior where the owner context is remembered inside the object ([lesson 5](/en/great-expectations/context-stores/#more-than-one-context-in-one-process): creating a second context does not break old objects in 1.24.1).
- `batch_parameter_normalization.py` matches the topic of numeric parameters that should be integers, with a deprecation warning ([lesson 6](/en/great-expectations/datasources-batches/#types-of-the-parameters-and-dataframes)). This is a link between the file name and the behavior seen in experiments. The content of the file was not read.
- `regex_based_column_map_expectation.py` and `set_based_column_map_expectation.py` are gone. They were template parent classes for writing regex-based or set-based expectations. These two files do not exist in 1.24.1. [Lesson 12](/en/great-expectations/custom-expectations/column-map/#why-two-classes) uses `ColumnMapExpectation` directly, which still exists. So examples on the web that inherit from these two classes cannot run in 1.24.1 (this is concluded from the missing files; inheriting from those classes was not tried).
- The whole `profile/` package is gone. Anyone who used the profiler of the old version must find another way.

<Callout type="warn" title="Before you upgrade a real pipeline">
This table tells you what changed. It does not tell you how your pipeline is affected. Compare the files that your pipeline calls, and run the test suite of your gate ([lesson 10](/en/great-expectations/pipeline-integration/#test-a-suite-like-you-test-code)) on the new version before you release.
</Callout>
