## The three parts of the method

The code is cut down to its outline, without log comments and type hints.

```python
aggregates = {}

# Part 1: group the metrics by domain
for bundled in metric_fn_bundle:
    domain_id = IDDict(bundled.compute_domain_kwargs or {}).to_id()
    if domain_id not in aggregates:
        aggregates[domain_id] = {"column_aggregates": [], "metric_ids": [], "domain_kwargs": ...}
    aggregates[domain_id]["column_aggregates"].append(bundled.metric_fn)
    aggregates[domain_id]["metric_ids"].append(bundled.metric_configuration.id)

# Part 2: one agg per domain
for aggregate in aggregates.values():
    df = self.get_domain_records(domain_kwargs=aggregate["domain_kwargs"])
    res = df.agg(*aggregate["column_aggregates"]).collect()
    assert len(res) == 1, "all bundle-computed metrics must be single-value statistics"

    # Part 3: split the result back into one value per metric
    for idx, metric_id in enumerate(aggregate["metric_ids"]):
        resolved_metrics[metric_id] = convert_to_json_serializable(data=res[0][idx])
```

## If you want to measure it yourself

To turn the conclusion above into a measured result, you need a Spark installation (the Spark path in this garden has a project at `subjects/spark/code`). Then follow these steps. None of this has been done yet.

1. Create a small Spark DataFrame and run a validation with the same 6-rule suite as `05_sql_bundling.py` (BOOLEAN_ONLY).
2. Open the Spark UI before and after the run and look at the Jobs tab to see how many jobs were added.
3. Compare with the number of domains in the suite (the table, the table with a row_condition, and so on). If the explanation above is right, you should see about one aggregate job per domain, plus the jobs of the metrics that are not aggregates.
4. Switch `result_format` to SUMMARY and compare again.
