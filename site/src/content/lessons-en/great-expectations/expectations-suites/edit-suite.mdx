## What counts as the same expectation

The main lesson says that a suite skips an expectation that is identical in every way. The script `20_suite_edit.py` tests what "identical" means (GX 1.24.1). Every case uses `ExpectColumnValuesToBeBetween(column="age", min_value=0, max_value=120)` as the base.

| What was added | Number of expectations in the suite after adding |
|---|---|
| The base | 1 |
| The exact same one again | 1 (not added) |
| `max_value` changed to 200 | 2 |
| The base with `mostly=0.9` | 3 |
| The base with `severity="warning"` | 4 |

`mostly` and `severity` count as part of the identity. Expectations that differ only in these two values can be in the suite at the same time. This is useful, for example to put the same rule at two levels: passing at 0.9 is a warning, and passing with no wrong rows at all is a requirement. The side effect is that a suite can grow without you noticing if you repeat the work many times and change a parameter a little each time.

## Delete, and a suite that is not added

Delete with `suite.delete_expectation(expectation)`. The script deletes the last one. The count in the suite goes from 4 to 3, and `context.suites.get("s")` also sees 3. This means that a delete is saved to the store right away.

A suite created with `gx.ExpectationSuite(name="loose")` and then given an expectation holds the data itself (len is 1). But it is not in `context.suites.all()` until you call `context.suites.add(...)`. And `add_expectation` saves to the store only when the suite is already in the context (tested in the main lesson).
