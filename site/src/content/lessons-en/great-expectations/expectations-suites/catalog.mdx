## The table and the thirteen rules

The script `19_catalog_nulls.py` builds a table of 5 rows with the columns `id`, `age` (one null row and the value 400), `plan` (one null row), `start`, `end`, `a`, `b`. It then runs thirteen expectations in one suite (GX 1.24.1). The results are grouped by family. The query family (`UnexpectedRowsExpectation`) is not run in this script. For an example that was run, see [lesson 12](/en/great-expectations/custom-expectations/).

| Family | Examples that were run | Keys in `result` |
|---|---|---|
| column map | `ExpectColumnValuesToBeBetween`, `ExpectColumnValuesToBeInSet`, `ExpectColumnValuesToBeUnique`, `ExpectColumnValuesToMatchRegex` | `element_count`, `missing_count`, `unexpected_count`, `unexpected_percent`, `partial_unexpected_list` and the keys about index |
| column map that tests null itself | `ExpectColumnValuesToNotBeNull`, `ExpectColumnValuesToBeNull` | Same as above, but without `missing_count` |
| column aggregate | `ExpectColumnMaxToBeBetween`, `ExpectColumnMeanToBeBetween` | `observed_value` only |
| column aggregate (a set of values) | `ExpectColumnDistinctValuesToBeInSet` | `observed_value`, `unexpected_count`, `partial_unexpected_list` |
| column pair map | `ExpectColumnPairValuesAToBeGreaterThanB` | The same set of keys as column map |
| multicolumn map | `ExpectCompoundColumnsToBeUnique` | The same set of keys as column map |
| table (batch) | `ExpectTableRowCountToEqual`, `ExpectTableColumnCountToEqual` | `observed_value` only |

The three map families (column, pair, multicolumn) give results that look the same, because all of them count the rows that are wrong. Aggregate and table get a single value.

Two things were not what we expected.

- `ExpectColumnDistinctValuesToBeInSet` gives `observed_value` as `None`, both when it passes and when it fails. If you want to know which values are there, look at its `partial_unexpected_list`. (An extra test with data that has nulls and data that has none gave the same result.)
- `ExpectColumnMeanToBeBetween(0, 120)` with `age = [10, None, 30, 40, 400]` gives a mean of exactly 120.0 and passes. The range includes both ends, and the mean is computed from the 4 values that are not null (500 ÷ 4).
