## What is a domain

A metric is computed "on something". That something is called the domain: the table, the column and the row filter (`row_condition`). Metrics whose domain is exactly the same are combined into one SQL statement (see the section "Two kinds" in the main lesson). Parts 2 to 3 of the script `26_registry_domains.py` look at how the SQL changes when the domain is different (GX 1.24.1, SQLite, a `users` table with 4 rows).

## What this means for suite design

1. Rules that you split by group on purpose (for example only the pro plan) cost extra statements per group. With 10 groups, that is 10 sets. On big data in SQL, count the groups before you use this.
2. A `row_condition` that passes on pandas may fail on SQL, so test it on the real engine.
3. You can always inspect the SQL that GX sends with the method in `05_sql_bundling.py` and `26` (it wraps `SqlAlchemyExecutionEngine.execute_query` and records the statements).

<Callout type="note" title="Scope">
The numbers 2 and 4 are the result of the suite used in `26` (result_format `BOOLEAN_ONLY`) on a small table. Other suites can give a different number of statements, and I did not test with Spark.
</Callout>
