## The minimum test cases

The gate you wrote should answer correctly in cases where you already know the answer. Part 3 of the script `29_pipeline_policies.py` runs three cases with a plain assert-style checker (GX 1.24.1). It does not use pytest.

```python
CASES = [
    ("good data passes",                 cp,       DATA["good"],     False),
    ("null id stops",                    cp,       DATA["critical"], True),
    ("suite with no expectations stops", empty_cp, DATA["good"],     True),
]
for label, checkpoint, frame, should_stop in CASES:
    try:
        gate(checkpoint, {"dataframe": frame})
        stopped = False
    except QualityGateError:
        stopped = True
    print("PASS" if stopped == should_stop else "FAIL", label)
```

The printed result:

```text
PASS  good data passes
PASS  null id stops
PASS  suite with no expectations stops
```

## Good to know

1. Use an ephemeral context for testing. The context starts empty every time, so there is no problem with duplicate names (lesson 1).
2. Each case needs new objects. If you reuse the same expectation object in two suites, you get a `RuntimeError` (lesson 4, the page "Read a failed result in a systematic way").
3. Testing the gate on made-up data does not prove that the suite catches real bad data. This test set only tells you that the decision after reading the result is correct. Whether the rules are suitable must be compared with real bad data that has happened.
4. If you use pytest, you can wrap these three cases as test functions directly (I did not run pytest on this path).
