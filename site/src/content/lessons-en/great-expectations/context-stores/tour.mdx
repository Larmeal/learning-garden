## Create it, then look at what you got

The script `22_file_context_tour.py` creates a file context in a temporary folder. It adds a data source, a suite with two rules, a validation definition and a checkpoint with an `UpdateDataDocsAction`, then runs once (GX 1.24.1).

```python
context = gx.get_context(mode="file", project_root_dir=root)
# ... add_pandas, suites.add, validation_definitions.add, checkpoints.add ...
result = checkpoint.run(batch_parameters={"dataframe": df})
```

## Three things you can see from the files

1. The validation definition stored in a file refers to three levels by name + id: the datasource, the asset and the batch definition. This is different from the `.json()` output in memory on the page "[References by Name and ID](/en/great-expectations/core-concepts/references/)" ([lesson 1](/en/great-expectations/core-concepts/)), which has only the batch definition. Serializing to a file keeps the full chain of references.
2. The validation result does not store the real data. At `batch_parameters.dataframe` it says `<DATAFRAME>`. There is only a fingerprint of the data (`pandas_data_fingerprint`), used to check whether it is the same data (the case where the fingerprint changes was not tested).
3. The `.gitignore` that GX creates has one line: `uncommitted/`. So the validation results, the reports and `config_variables.yml` stay out of git by default. `expectations/`, `checkpoints/`, `validation_definitions/` and `great_expectations.yml` can go into git, so a team can review a suite in a pull request like code.
