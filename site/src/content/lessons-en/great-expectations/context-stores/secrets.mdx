## The problem: secrets should not be in git

A database connection string often contains a password. If you write it into `great_expectations.yml`, which is committed to git, the password leaks with the repo. GX solves this by letting you write a variable `${NAME}` and substituting the value when it is used.

```python
src = context.data_sources.add_sqlite("viafile", connection_string="${MY_DB_URL}")
```

The config_variables part of the script `23_persistence_config.py` tries two sources for the value (GX 1.24.1, SQLite).

</Step>

## Recommended way to use it

1. Write `${NAME}` in every connection string that contains a secret.
2. On a development machine, put the value in `uncommitted/config_variables.yml` (it is already in `.gitignore`).
3. On a server or in CI, set an environment variable. It wins over the file, so you do not need the file on those machines.

Step 3 relies on the measured result that the environment variable wins. Steps 1 and 2 were both measured.

<Callout type="warn" title="Not tested">
I did not test nested variables (a dict) in the file. I did not test the form `$NAME` without braces. I also did not check whether secrets leak into Data Docs or into the validation results. Open `uncommitted/` yourself before you share it.
</Callout>
