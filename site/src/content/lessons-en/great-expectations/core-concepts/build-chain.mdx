## Eight lines that build the workflow

```python
context = gx.get_context()
source = context.data_sources.add_pandas("people_src")
asset = source.add_dataframe_asset("people")
bdef = asset.add_batch_definition_whole_dataframe("whole")
suite = context.suites.add(gx.ExpectationSuite(name="people_suite"))
suite.add_expectation(gxe.ExpectColumnValuesToNotBeNull(column="id"))
vd = gx.ValidationDefinition(name="people_vd", data=bdef, suite=suite)
result = vd.run(batch_parameters={"dataframe": df})
```

The script `17_object_chain.py` prints the state after every line (GX 1.24.1). The column `engine_rounds` counts how many times the execution engine was called to compute a metric.

| After the line | id | In the context | engine_rounds |
|---|---|---|---|
| `get_context()` | (ephemeral context) | empty | 0 |
| `add_pandas` | yes | 1 data source | 0 |
| `add_dataframe_asset` | yes | 1 asset under the source | 0 |
| `add_batch_definition_whole_dataframe` | yes | a batch definition | 0 |
| `ExpectationSuite(name=...)` | `None` | no suite yet | 0 |
| `context.suites.add(...)` | yes | `people_suite` is there | 0 |
| `suite.add_expectation(...)` | the expectation gets an id | | 0 |
| `ValidationDefinition(...)` | `None` | no validation definition yet | 0 |
| `vd.run(...)` | yes (added during the run) | `people_vd` is there | 5 |

This table shows two things. Objects created with `add_*` get an id immediately. `ExpectationSuite(...)` and `ValidationDefinition(...)`, created with a constructor, have no id yet and are not in the context until you add them or run. The other thing is that computing on the data happens on the last line only.

## run() can add only itself

`ValidationDefinition.run` can add itself to the context when the suite and the batch definition it refers to are already in the context. If the suite has not been added, you get `ValidationDefinitionRelatedResourcesFreshnessError` with a message to call `context.suites.add(...)` first (the full message is on the page "[The first errors you will meet](/en/great-expectations/core-concepts/first-errors/)").

A validation definition refers to a suite by name and id (the page "[References by name and id](/en/great-expectations/core-concepts/references/)"). A suite that was never added has no id to refer to. This is an inference from the error message and the json shape. I did not read this part of the code line by line.
