## Two layers

`vd.run(...)` returns one `ExpectationSuiteValidationResult`. Inside it is a `results` list, and each item is the result of one expectation. The script `18_result_anatomy.py` calls `to_json_dict()` and prints the keys of both layers (GX 1.24.1).

Outer layer:

```text
['success', 'results', 'suite_name', 'suite_parameters', 'statistics', 'meta', 'id']
```

The layer of one expectation:

```text
['success', 'expectation_config', 'result', 'meta', 'exception_info']
```

</Step>

## The outer layer: keys that are often overlooked

```text
statistics: {'evaluated_expectations': 4, 'successful_expectations': 2,
             'unsuccessful_expectations': 2, 'success_percent': 50.0}
suite_name: users_suite
meta keys: great_expectations_version, batch_spec, batch_markers,
           active_batch_definition, validation_id, checkpoint_id,
           run_id, validation_time, batch_parameters
```

- `statistics` has four values. `evaluated_expectations` matters more than it looks, because it can be 0 when the suite is empty (see the page "The suite loaded empty" in [lesson 12](/en/great-expectations/custom-expectations/)), and then `success` is True.
- `meta.run_id` has `run_name` and `run_time`. Use them to tell the results of each run apart.
- `meta.validation_id` and `checkpoint_id` tell you, as the names say, which validation definition and which checkpoint ran this result (their values were not checked).
- `result_url` is `None` in this experiment.

<Callout type="note" title="The numbers in result depend on result_format">
The example above is in the SUMMARY form, which is the default of `ValidationDefinition.run`. If you ask for BOOLEAN_ONLY, `result` comes back empty. [Lesson 4](/en/great-expectations/reading-results/) compares all four levels.
</Callout>
