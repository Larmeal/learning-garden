## When you want to try a rule quickly

The normal path is context, data source, asset, batch definition, suite, validation definition, and then `run()`. When you are exploring data or writing a new rule, that is too heavy. A batch from `get_batch()` has a method `validate(...)` that checks a rule directly.

```python
batch = batch_definition.get_batch()
batch.validate(gxe.ExpectColumnValuesToBeBetween(column="a", min_value=0, max_value=2))
```

## When to use it and when not to

| What you want | Use |
|---|---|
| Try a new rule on real data and see the result right away | `batch.validate(expectation)` |
| Try a whole suite that is still a draft | `batch.validate(suite)` |
| Check every day in a pipeline and keep the results | `ValidationDefinition` or `Checkpoint` (results are stored, actions are available) |

The reason not to use `batch.validate` in a pipeline is that the result is not stored (tested with a suite) and there are no actions, such as alerts or updating Data Docs.

<Callout type="warn" title="Not tested">
We tested only with a batch from a CSV file in pandas. We did not try a SQL batch, and we did not check whether `batch.validate(expectation)` with a single expectation stores its result (we tested storing only with a suite).
</Callout>
