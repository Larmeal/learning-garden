## The differences we saw in the runs

| Topic | 0.18.21 | 1.24.1 |
|---|---|---|
| Where the data comes in | `read_dataframe(df)` gives a Validator immediately | The DataFrame is a parameter at `run(batch_parameters=...)` |
| expectation | Method `validator.expect_*`, runs immediately | Class `gxe.Expect...`, stored in a suite, run later |
| An expectation that fails when written | Not kept in the suite (0 kept after two failures) | Stays in the suite as before |
| Checkpoint | Refers to a suite by name. If the name is not in the context you get `DataContextError` (`expectation_suite default not found`) | Takes a ValidationDefinition that was added to the context |

Every row comes from running `08` and `01`. The 1.24.1 result lines in the box above are shortened. The numbers and the success values match what the script prints.

## Tell which version a web example is for

Look at what the code calls.

| If you see | Version | What to do |
|---|---|---|
| `context.sources.pandas_default` or `context.sources.add_*` | 0.18 | Use `context.data_sources.add_*` in 1.x |
| `validator.expect_column_...(...)` called as a method on a validator | 0.18 | Create a `gxe.Expect...` class and call `suite.add_expectation` |
| `add_or_update_checkpoint(... validations=[...])` | 0.18 | Create a `ValidationDefinition` and pass it to `gx.Checkpoint` |
| `gx.get_context()` followed by `context.suites.add(...)` | 1.x | You can use it |

The first three rows are patterns that `08_legacy_018.py` really uses on 0.18.21. The YAML-file style of checkpoint was not tested.

<Callout type="warn" title="The old version needs a separate environment">
0.18.21 needs NumPy below 2 and pandas below 2.2. So script `08` is run with `uv run --no-project --python 3.11 --with great-expectations==0.18.21 --with "numpy<2" --with "pandas<2.2"`, not in the project's own environment.
</Callout>
