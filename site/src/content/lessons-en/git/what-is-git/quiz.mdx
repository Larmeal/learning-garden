## Check yourself

<Question
  client:visible
  lang="en"
  q="Two friends each create a file with exactly the same text, hello and a newline, in their own folder, and ask Git to compute the name of the file. What happens?"
  options={['The names differ, because Git puts the time and the user name into the name', 'The names are the same, because the name is computed from the content alone', 'The names are the same only on the same computer']}
  answer={1}
  why="The exercise made two repositories and git hash-object gave ce013625... for hello in both. The name of a file does not depend on the time, the user or the folder. Time and user name are stored in a commit, which is a different kind of object."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="Someone edits the text of an old file inside Git's storage directly, without using a Git command. Why can Git notice that something is wrong?"
  options={['Because Git keeps a backup copy of every file somewhere else', 'Because the name is computed from the content, so after the change the name that would be computed no longer matches the name that is stored', 'Because Git locks old files so nobody can change them']}
  answer={1}
  why="Name and content are tied together. If the content changes, the name it should have changes too, but the file still carries the old name, so Git can catch it (we will see this for real in the object store lesson). Git does not keep a second copy and does not lock anything. You can edit the files Git keeps if you want to, you will just be caught."
/>

</Step>
