## Check yourself

<Question
  client:visible
  lang="en"
  q="We create a new file in the project folder and have not told Git anything yet. In which areas is the file?"
  options={['In the working tree only', 'In the working tree and the index, because Git can already see the file in the folder', 'In all three, but without a name yet']}
  answer={0}
  why="Git stores nothing by itself until we ask. The exercise checks that while the file is new its status starts with two question marks, the index is empty, and there is no new object in .git/objects. Only at Add is the content of the file written there."

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="After Add we edit the same file again. What does the short status show for it?"
  options={['An M followed by a space, because the editing is done', 'Two Ms: the index differs from the latest commit, and the working tree differs from the index', 'An A followed by a space, because it is a new file']}
  answer={1}
  why="The first letter says how the index differs from the latest commit, and the second says how the working tree differs from the index. A file that was committed, then changed and added, then changed again, differs in both pairs, so we get two Ms. The exercise checks exactly this status."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="We edited a file and ran Add. What does a plain Diff with no options show?"
  options={['The change, because the file differs from the latest commit', 'Nothing, because this form compares the working tree with the index, and they now match', 'An error, because the file was already added']}
  answer={1}
  why="A plain Diff compares the working tree with the index, and after Add both are the same, so there is nothing to see. To see what will go into the commit we compare the index with the latest commit, with the option Staged. The exercise checks all three forms of Diff."
/>

</Step>
