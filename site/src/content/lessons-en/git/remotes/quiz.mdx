<Step kind="question">

<Question
  client:visible
  lang="en"
  q="How does fetch differ from pull?"
  options={['They do not differ, they can be swapped', 'Fetch brings in the new commits and moves the remote-tracking branch, while pull does a fetch and then a merge or rebase into our own branch', 'Pull sends our work to the remote']}
  answer={1}
  why="Fetch does not touch our branches or files at all, so it is safe to run at any time. Pull is a fetch followed by combining. The exercise checks that after a fetch the files are still the old ones, and after a pull the new work is in. Sending work to the remote is the job of push."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="A push is rejected with a message telling us to fetch first. What causes it?"
  options={['The remote has commits we do not have, and if it accepted our push, the work of the others would fall off the tip of the branch', 'Our password is wrong', 'Our branch is too long']}
  answer={0}
  why="Git does not allow a push that would make the remote lose commits it has. We have to bring the other person's work in first and push again. The exercise simulates two people working at the same time and gets this message for real. A wrong password gives a different error, and length does not matter."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="We rewrote our history with a rebase and need to push over it. Why choose force with lease rather than a plain force?"
  options={['It is faster', 'It is safer, because it overwrites only if the remote is still where we last fetched it, so if someone else pushed first it refuses', 'It needs no write permission']}
  answer={1}
  why="A plain force overwrites everything without looking, so it could delete work a friend pushed after our fetch. Force with lease first checks that the remote is still as we saw it. The exercise simulates a friend pushing in between and gets the message stale info as a refusal. After a fetch and a new rebase the push goes through."
/>

</Step>
