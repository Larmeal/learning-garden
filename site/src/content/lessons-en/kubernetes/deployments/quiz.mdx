  q="We change the image in a running Deployment. What happens to the ReplicaSets?"
  options={[
    'The existing ReplicaSet is edited to use the new image and every Pod is restarted at once',
    'The Deployment makes a new ReplicaSet and slowly moves Pods from the old one to the new one, keeping the old one at 0 Pods',
    'The Deployment deletes the old ReplicaSet at once, so no resources are wasted',
    'Nothing happens until we delete the Pods ourselves'

<Question

  lang="en"
  q="A service must never have an old and a new version running at the same time, because the two would write incompatible data structures. Which strategy should we choose, and what must we accept?"
  options={[
    'A rolling update, accepting two versions side by side for a short time',
    'Recreate, accepting a moment with no Pods serving',
    'Set maxSurge as high as possible',
    'No choice is needed, because Kubernetes protects against it already'
  ]}
  answer={1}
  why="Recreate stops all the old Pods before creating the new ones, so there are never two versions together. In the exercise Ready went down to 0, which is the price. A rolling update deliberately keeps both versions side by side during the change."
/>

</Step>
