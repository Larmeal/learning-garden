  q="A producer renames the column total_amount to amount_total. Which kind does the exercise's criteria give it, and why?"
  options={['safe, because the data is the same', 'breaking, because queries that select the old name fail. A rename is deleting the old column and adding a new one', 'review (ask consumers), because some consumers may not use this column']}
  answer={1}
  why="The exercise's diff() detects that a column disappeared and a new column of the same type appeared, so it reads this as a rename, which breaks any consumer that refers to the old name at once. <Question
  lang="en"
  client:visible
  q="A new contract version adds RETURNED to the accepted values of status. The exercise's criteria file it as 'review (ask consumers)'. Why?"
  options={['Because adding a value often crashes the database', 'Because a consumer whose code handles exactly 3 values may send the new value down an unintended branch with no error at all', 'Because the contract forbids adding values']}
  answer={1}
  why="A silent error is the most dangerous kind: there is no error, but the result is wrong. Consumers need to know in advance so they can check their own code, which is why a contract should list consumers who can be contacted."
/>

</Step>

<Question

  client:visible
  q="Compare 'test after loading' with 'reject before loading' when a producer sends a schema that breaks the contract. Which statement is correct?"
  options={['Both give exactly the same result', 'With test after loading, the wrong dataset is already in the table. With reject before loading, the table is not touched', 'Reject before loading is always slower, so it should not be used']}
  answer={1}
  why="Medallion gives the example of dbt's model contract, which fails to build when it does not match the contract (unlike a test), and a contract at ingestion that rejects data that does not match. The choice depends on how much a consumer can tolerate a broken batch. There is no single answer for every case."
/>

</Step>
