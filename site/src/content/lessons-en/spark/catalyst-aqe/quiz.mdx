<Question
  client:visible
  lang="en"
  q="A groupBy on very small data shuffles into 200 partitions, from spark.sql.shuffle.partitions. With AQE on (the default), about how much do you get from getNumPartitions() of the result?"
  options={['Always 200, because AQE does not change the number that was set', '1, because AQE merges the partitions that are smaller than the target', '16, because it equals the number of cores']}
  answer={1}
  why="The target is max(min(total / parallelism, 64 MB), 1 MB) = 1 MB, and all the data is smaller than that, so it is merged down to 1. With AQE off you get 200. This number depends on data size and cores, it is not fixed."
/>

</Step>

  q="A big table joins a small table. The starting plan is SortMergeJoin, and after AQE the final plan is still SortMergeJoin. Which is a possible reason?"
  options={['The small table is bigger than spark.sql.autoBroadcastJoinThreshold (10 MB), or it is spread over partitions where fewer than 20% are non-empty', 'AQE can only merge partitions, it cannot change a join', 'You must cache the small table before it can be broadcast']}
  answer={0}
  why="AQE can change a sort-merge join to a broadcast when it knows the real size is small enough. But if the size is over the threshold, or the small side is spread over too many empty partitions (nonEmptyPartitionRatioForBroadcastJoin 0.2), it keeps the sort-merge join."
