<Question
  client:visible
  lang="en"
  q="What does Iceberg add to a table stored as Parquet files?"
  options={['A new data file format that compresses better than Parquet', 'Metadata files that say which data files the table consists of right now, plus a catalog that points to the current metadata file', 'A server that takes queries and reads the files for you']}
  answer={1}
  why="Iceberg is a table format. The data is still Parquet (or ORC, Avro). What it adds is metadata that says officially which files the table has, and a catalog that says which metadata to read. The first option is the job of a file format, and the third is the job of an engine such as Spark."

<Question
  client:visible
  lang="en"
  q="PyIceberg appends a row to a table that a Spark session holds open, and then Spark runs INSERT without refreshing. What happens?"
  options={["Spark's INSERT overwrites PyIceberg's row, which is lost", 'The INSERT succeeds on top of the latest snapshot, which includes the PyIceberg row, and every row is there', 'The INSERT always fails because Spark still holds the old table version']}
  answer={1}
  why="The exercise confirmed that Spark's snapshot has PyIceberg's snapshot as its parent and that all 8 rows are present. A commit is a conditional change of the catalog row (it must still point to the edition the writer read). If it does not, Iceberg reads the latest edition and retries. It does not overwrite, and it does not fail."
/>

</Step>
