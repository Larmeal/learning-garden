## Check yourself

<Question
  client:visible
  lang="en"
  q="A table partitioned by day holds days 1, 2 and 3. You run INSERT OVERWRITE with data for day 2 only, without touching any config (Spark defaults). What is the result?"
  options={['Only the new day 2 data is left. Days 1 and 3 are gone from the current snapshot', 'Day 2 is replaced, and days 1 and 3 are intact', 'An error, because you must always name the partition to overwrite']}
  answer={0}
  why="The exercise measured one row after the command. The default of spark.sql.sources.partitionOverwriteMode is STATIC, which replaces the whole table. You have to switch to dynamic to replace only the partitions the new data touches, or use overwritePartitions(), which says what it means more clearly."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="A Spark INSERT fails halfway because of a division by zero. What does a reader of the table see afterwards?"
  options={['The half of the data that had been written', 'The table exactly as before, with no new snapshot', 'The table is locked until someone cleans up the failed job']}
  answer={1}
  why="A reader only sees the snapshot the catalog points to. A job that fails before the commit never changed the pointer. The exercise counted snapshots and rows before and after and got the same numbers. Data files that may be left on disk are referred to by no snapshot, so they are not read, but they have to be removed later by table maintenance."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="You call t.overwrite(df, overwrite_filter='order_id = 5') in PyIceberg 0.12.0 and look at the operation of the snapshots that appear. What do you see?"
  options={['One snapshot with operation overwrite', 'Two snapshots in order: delete, then append', 'No new snapshot, because the file is edited in place']}
  answer={1}
  why="The exercise checked the operations of the last two snapshots and got delete and then append. That means a reader could see the table after the delete and before the add, in the gap between the two commits. If you need the replacement in a single commit, choose a tool that makes one snapshot, such as Spark's INSERT OVERWRITE. Data files are never edited in place in Iceberg."
/>

</Step>
