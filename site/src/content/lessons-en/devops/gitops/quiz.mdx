## Check yourself

<Question
  client:visible
  lang="en"
  q="How does the controller of this lesson work as a loop?"
  options={['It runs a deploy script written in advance, once, and stops', 'It reads what we want from Git, compares it with the real state, acts only on the difference, and goes back to reading', 'It waits for a user to command a deploy every time something must change']}

  why="This is a reconciliation loop. In the second pass of the exercise there was nothing to do (converged), and whenever somebody removed or added a container by hand the next pass made it match Git again."

<Question
  client:visible
  lang="en"
  q="In GitOps, what is releasing a new version?"
  options={['Running a deploy script on the developer\'s computer', 'Changing the file that says what we want in Git (for example the version), then committing and pushing', 'Only building a new image']}
  answer={1}
  why="In the exercise the commit that changed web to v2 and made it three replicas made the controller replace web-1 and web-2 and create web-3, with nobody running a deploy script. One file change is both the release and the record of who changed what and when."
/>

</Step>

<Question

  q="How is the rollback done in the GitOps of the exercise?"
  options={['Delete every container and create them again by hand', 'git revert the release commit and push, and the controller brings the cluster back to what it was before the release', 'Stop the controller and fix the containers by hand']}
  answer={1}
