<Question
  client:visible
  lang="en"
  q="A consumer reads all three partitions of a topic and sees 12 records, all from partition 2, before it gets any record from another partition. What can we conclude?"
  options={[
    'The producer sent those 12 records before all the records of the other partitions',
    'Kafka sorts the records of the whole topic by time and hands them to the consumer',
    'Nothing about the order of sending, because a consumer takes chunks from one partition at a time, and order is guaranteed only inside a single partition',
    'Partition 2 is a main partition that matters more than the others'
  ]}
  answer={2}
  why="Kafka guarantees order only inside a partition. The order in which a consumer receives records from several partitions depends on which one it picks up first. The exercise saw the first 12 records come from partition 2 without that meaning the producer sent them that way (ran)."
/>

</Step>

<Step kind="question">

<Question
  client:visible
  lang="en"
  q="A topic has 3 partitions. The team grows it to 6 because the data is growing. What is the effect on records that have keys?"
  options={[
    'The old records move to the new partitions by the old rule',
    'No effect, because a key always goes to the same partition',
    'The old records stay put, but the new records of some keys land in another partition, so the order of that key is cut in two',
    'Kafka refuses to add partitions when the topic already has data'
  ]}
  answer={2}
  why="Records that were written are not moved, but the divisor of the rule changes from 3 to 6, so keys whose result differs move. In the exercise 3 of 6 keys moved (for example customer c1 from partition 2 to 5). Kafka does not refuse: what it refuses is reducing the number of partitions (ran)."
/>

</Step>
