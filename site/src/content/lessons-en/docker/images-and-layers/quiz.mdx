<Question
  client:visible
  lang="en"
  q="Image A is 100 MB, built on a 90 MB base image (A's own part is 10 MB), and image B is 95 MB, built on the same base (B's own part is 5 MB). With both installed, about how much does Docker store on disk?"
  options={[
    'About 195 MB, because each image is stored separately',
    'About 105 MB: one copy of the 90 MB base, plus 10 MB of A and 5 MB of B',
    'About 90 MB, because Docker stores only the base',
    'About 15 MB, because it stores only the differences'
  ]}
  answer={1}
  why="The base layer has one id, so it is stored once. The rest is each image's own layers: 90 + 10 + 5 = 105 MB, just as in the lab. With two images the figure really stored is lower than the sum of the image sizes (ran). The 195 figure is what would happen if each kept its own copy, for example on virtual machines (book: Docker in Action section 3.3.4, page 60)."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="A first container from an image changes the file /etc/passwd. Then we create a second container from the same image and open the same file. What does the second container see?"
  options={[
    'The version the first one changed, because the file in the image was changed',
    'The original version from the image, because the first container changed a copy in its own writable layer and did not change a layer of the image',
    'No file at all, because it was moved to the first container',
    'It depends on whether the first container is still running'
  ]}
  answer={1}
  why="The layers of an image are read-only, so the change happens only on the copy in the writable layer of the first container (copy-on-write). The exercise created a new container after a delete and still saw /etc/passwd in full (ran). Every container has its own writable layer, so none sees the changes of another."
/>

</Step>

<Question
  client:visible
  lang="en"
  q="We run Docker Tag to give one image a second name, then delete the first name with Docker Rmi. What happens?"
  options={[
    'The whole image is deleted, because we deleted the name it was built with',
    'The image is deleted, but the second name stays as a dangling name',
    'The first name is gone, but the image stays and can still be used by the second name, because a tag is only a label that points at an id',
    'Docker refuses to delete, because the image has two names'
  ]}
  answer={2}
  why="A tag is a name that points at the id of an image, and it is not the image. When several names point at it, deleting one only takes that label away. The exercise deleted dlab-alias:1 and alpine:3.22 still had the same id (ran). The image is really removed when no name points at it and no container uses it (book: Docker in Action section 7.2.2, page 134)."
/>

</Step>
