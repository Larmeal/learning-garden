  q="How are the files in Blobs of an image saved with Docker Save named, and what is the advantage?"
  options={[
    'Named in order 1, 2, 3, with the advantage that they are easy to sort',
    'Named by the sha256 hash of the bytes in the file itself, with the advantage that one file can be stored once, and we can tell at once whether a file is damaged because the hash will not match',

  ]}

  q="We push an image with new content under the same tag, and a friend who noted the digest of the earlier image pulls with that digest. What do they get?"
  options={[
    'The new image, because a digest always follows to the newest',
    'The earlier image as before, because a digest is the hash of the content of the manifest, which does not change, and only the tag can move',
    'An error, because the digest was deleted together with the tag',
    'An empty image'
  ]}
  answer={1}
  why="The exercise saw the tag move to a new manifest after the second push, while a pull with the old digest brought the old image back and printed the old result (ran). A digest locks the content, unlike a tag, which is a label that can be moved."
/>

</Step>
